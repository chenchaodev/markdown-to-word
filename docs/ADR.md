## 条目
### 2026-09-26 23:20:00 验收段编排并发池:默认串行,CI 显式开 4(ADR-017)
- 决策:段编排器内引入并发池,档位由 `M2W_TEST_CONCURRENCY` 决定且**默认 1**(未设变量时 stdio 与输出格式与从前逐字一致);CI 在 `verify:ci` 步骤显式设 4。`gate-probes` 进**独占槽**——整轮先以并发 1 跑完,不进池;段内嵌套编排不消费该变量;结果按发现顺序重排后再报
- 理由:段间本就零状态串扰(每段独立 userData 目录、退出即清理),并行不改变任何判定口径。独占槽是**必需**而非优化:`gate-probes` 的工作树指纹覆盖 `output/`,而约 20 个段绿跑时都往 `output/artifacts/` 写产物,并发下它 14 秒的窗口里指纹几乎必然变动 → 确定性自判红(不是 flake)。报告重排是因为并发下完成顺序不再等于发现顺序,不重排则 `[ok]` 列表与 `[stats]` 每次都不同
- 备选:① 默认 >1(否决:默认值是安全属性,会让核数/磁盘/杀毒各异的本地机默认落进超时与句柄争抢区,而本仓历史故障形态恰是「偶发判红」);② CI 起多进程各带 `M2W_ONLY` 分片(否决:筛选词拼错一个字母 → `discoverSegments` 返回空清单 → 打印「全部 0 段通过」并 exit 0,**一个 typo 静默关掉整轮门禁**;每片各跑 `test:coverage` 会拿残缺的覆盖率判阈值;`output/tmp/runner-report-selftest` 与 `output/artifacts` 跨进程撞名);③ 并行化 `verify:ci` 链内 `typecheck`/`lint`/`test`/`smoke`/`geometry` 彼此(否决:`check-ci-contract.mjs` 靠 `&&` 串解析位置断言,并行后顺序信息消失,契约失去判据)
- 代价:并发 >1 时段内 stdout/stderr 改走管道并加 `[段名] ` 前缀(父进程成为唯一写者,反而消掉了 4 个子进程抢同一控制台句柄的交错);管道读端**必须**显式 `setEncoding("utf8")`,否则按控制台代码页解码会毁中文 —— 原先那条「Windows 管道重编码会破坏中文与制表符」的注释因果讲反了,已更正(管道只搬字节,坏在读端;制表符是单字节,任何编码都不动它;`test/segments/entry-exit-guard.test.js` 早就是 Electron 子进程 + pipe + utf8 且长期为绿);段失败日志并入既有 `failure.log`(头尾各 200KB 上限),不新建目录;独占段是串行的,Amdahl 上限受其约束
- 验证:本机 16 逻辑核,串行 134.8s → 并发 4 为 103.3s / 104.3s(约 1.30 倍,两有效样本波动 1%);并发 4 跑三遍**全部 118 段全绿且零告警**(沙盒删除失败 / 硬杀后子进程未退出 / 工作树被改动 各 0 次);非法值 `0` 与 `abc` 均回落串行(124.2s / 122.5s,与基线同档,无卡死无无限并发);独占段在并发下 14.0–14.7s 与串行 13.8s 持平。⚠️ **CI 侧真实加速比待实测**(4 vCPU 低于本机 16 核,且每段 Electron 启动耗时会随争核膨胀)
- 来源:主会话(工作项 REF-019;方案取舍裁决 @oracle)
