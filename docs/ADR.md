### 2026-09-26 23:20:00 验收段编排并发池:默认串行,CI 显式开 4(ADR-017)
- 决策:段编排器内引入并发池,档位由 `M2W_TEST_CONCURRENCY` 决定且**默认 1**(未设变量时 stdio 与输出格式与从前逐字一致);CI 在 `verify:ci` 步骤显式设 4。`gate-probes` 进**独占槽**——整轮先以并发 1 跑完,不进池;段内嵌套编排不消费该变量;结果按发现顺序重排后再报
- 理由:段间本就零状态串扰(每段独立 userData 目录、退出即清理),并行不改变任何判定口径。独占槽是**必需**而非优化:`gate-probes` 的工作树指纹覆盖 `output/`,而约 20 个段绿跑时都往 `output/artifacts/` 写产物,并发下它 14 秒的窗口里指纹几乎必然变动 → 确定性自判红(不是 flake)。报告重排是因为并发下完成顺序不再等于发现顺序,不重排则 `[ok]` 列表与 `[stats]` 每次都不同
- 备选:① 默认 >1(否决:默认值是安全属性,会让核数/磁盘/杀毒各异的本地机默认落进超时与句柄争抢区,而本仓历史故障形态恰是「偶发判红」);② CI 起多进程各带 `M2W_ONLY` 分片(否决:筛选词拼错一个字母 → `discoverSegments` 返回空清单 → 打印「全部 0 段通过」并 exit 0,**一个 typo 静默关掉整轮门禁**;每片各跑 `test:coverage` 会拿残缺的覆盖率判阈值;`output/tmp/runner-report-selftest` 与 `output/artifacts` 跨进程撞名);③ 并行化 `verify:ci` 链内 `typecheck`/`lint`/`test`/`smoke`/`geometry` 彼此(否决:`check-ci-contract.mjs` 靠 `&&` 串解析位置断言,并行后顺序信息消失,契约失去判据)
- 代价:并发 >1 时段内 stdout/stderr 改走管道并加 `[段名] ` 前缀(父进程成为唯一写者,反而消掉了 4 个子进程抢同一控制台句柄的交错);管道读端**必须**显式 `setEncoding("utf8")`,否则按控制台代码页解码会毁中文 —— 原先那条「Windows 管道重编码会破坏中文与制表符」的注释因果讲反了,已更正(管道只搬字节,坏在读端;制表符是单字节,任何编码都不动它;`test/segments/entry-exit-guard.test.js` 早就是 Electron 子进程 + pipe + utf8 且长期为绿);段失败日志并入既有 `failure.log`(头尾各 200KB 上限),不新建目录;独占段是串行的,Amdahl 上限受其约束
- 验证:本机 16 逻辑核,串行 134.8s → 并发 4 为 103.3s / 104.3s(约 1.30 倍,两有效样本波动 1%);并发 4 跑三遍**全部 118 段全绿且零告警**(沙盒删除失败 / 硬杀后子进程未退出 / 工作树被改动 各 0 次);非法值 `0` 与 `abc` 均回落串行(124.2s / 122.5s,与基线同档,无卡死无无限并发);独占段在并发下 14.0–14.7s 与串行 13.8s 持平。⚠️ **CI 侧真实加速比待实测**(4 vCPU 低于本机 16 核,且每段 Electron 启动耗时会随争核膨胀)
- 来源:主会话(工作项 REF-019;方案取舍裁决 @oracle)
- 关联:`test/common/runner.js`、`test/segments/runner-report.test.js`、`.github/workflows/ci.yml`、`docs/ROADMAP.md` 的 REF-019

### 2026-09-26 22:48:00 门禁链内全量验收只跑一遍(ADR-016)
- 决策:`verify:ci` 里的全量验收只保留**带 c8 插桩的那一遍**(`test:coverage`),删掉裸跑的 `test`;并把「插桩那遍恰 1 次、裸跑那遍 0 次」写成 `scripts/check-ci-contract.mjs` 的机器不变量 + 3 条负向夹具。`scripts.test` 保留(本地裸跑与 `test:all` 用),其内部 build 前缀也保留
- 理由:两遍跑的是同一批 118 段(重合度 100%),第二遍只为覆盖率数字;而裸跑遍进程内没有 `NODE_V8_COVERAGE`,对 c8 数据贡献恒为 0(`--all` 的分母来自 `--include` 的文件集合,与跑几遍无关)—— 删掉它四指标不变,CI 却每次白花约 109s。丢掉的那层「不带插桩也能全绿」几乎全冗余:顶层段本来就在插桩态下跑,而「不带插桩的真实 Electron 入口」由链内 `test:smoke` 承担(它本来就不带插桩)
- 备选:① 保留两段、让 `test` 只跑小子集(否决:纯超集成本 —— 换来的是与全量同断言的一段,却凭空引入第三个会静默腐化的「部分清单」概念;要一个便宜的非插桩见证,仓里已有正确器械 `test:smoke`);② 两遍并行跑(否决:`gate-probes` 的工作树指纹含 `output`,两个 pass 并发时它会看到另一遍 20 个 `saveArtifact()` 的写盘 → 稳定自判红;唯一出路是把它降级成建议项或把 `output` 移出保护路径,两者都是主动削弱既有门禁,不该由提速项顺手做掉);③ 让 c8 复用已有覆盖率数据(否决:不带插桩那遍贡献恒为 0,合并省不出时间;要「复用」得改 `--temp-directory` + `--clean=false`,新增配置面换 0 收益)
- 代价:段失败排查改为在**插桩态**下看日志(「测试是否全绿」与「覆盖率是否达标」在同一次输出里仍可分辨,acceptance 入口无论阈值红绿都打印段汇总);覆盖率四指标存在 ±0.01pp 的**环境间抖动**(同一份代码 CI 侧 branch 89.08、本机 89.07,各自稳定),故验收判据不能写成「逐位不变」这种不可达标准
- 验证:`npm run check:contract`(含 selftest,夹具 28 → 31 条)+ `npm run test:coverage`(118 段全绿,四项 93.06/89.08/93.59/93.06,阈值 90/85/90/90)
- 来源:主会话(工作项 REF-018;方案取舍裁决 @oracle)
- 关联:`package.json`、`scripts/check-ci-contract.mjs`、`scripts/check-ci-contract.selftest.mjs`、`.github/workflows/ci.yml`

### 2026-09-26 19:40:00 发布供应链与「现阶段明确不签名」(ADR-013)
- 决策:现阶段不采购/不接入代码证书,不因缺签名让 Release fail closed,未签名作为**明确风险**对外说明;发布链补 SHA-256 报告、离线 SBOM、许可证/NOTICE、action 固定到 40 位 SHA、环境指纹;自动更新继续排除,只保留手动检查/下载

### 2026-09-26 19:40:00 本地与外链图片的信任边界与资源上限(ADR-012)
- 决策:本地图片仅允许源文档目录或明确可信根目录内,校验顺序 = 原始 src → 词法根边界 → realpath → 规范根边界;拒绝绝对路径、UNC、`file://` 及其它协议 URL、越界 `..`;校验扩展名 + 魔数白名单 + 单文件大小上限。外链图片保留但严格限额(超时/单图与文档总量/并发预算/DNS 校验);缓存加 LRU + 条目数 + 字节数上限,失败不缓存
- 理由:本地图片可读绝对路径/UNC 会把本机文件嵌入产物;无上限的外链与缓存会被单个文档拖垮
- 备选:默认禁用外链图片(牺牲既有能力);信任用户 markdown 不设边界(已实证为风险)
- 代价:引用源目录外图片的文档会被拒,需调整目录或改用外链
- 验证:`test/segments/image-type.test.js`
- 来源:campaign 归档升格(REF-001)
- 关联:`src/core/markdown/precheck.ts`(策略单源)
