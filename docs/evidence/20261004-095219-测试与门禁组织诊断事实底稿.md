### `selftest` 与 `test/gates` 的真实分界

- 10 个 `*.selftest.mjs`（另 1 个 `release-notes.mutation-test.mjs` ＋ `geometry/geometry/selftest.mjs`）：**不 import 被守门禁的 CLI 入口**，走 `spawnSync` 真脚本 ＋ 以 `cwd` 指向合成夹具仓 ⇒ 守**进程边界**。
  ⚠️ 「静态 import 数为 0」这个说法**不成立**：`check-docs.selftest.mjs` import `check-pointers.mjs` 的常量、`check-coverage-zero.selftest.mjs` import `coverage-gate.mjs` 的 `auditZeroFiles`、`release-notes.selftest.mjs` import `release-notes.mjs`。成立的是「不 import 被守门禁的 CLI 入口」。
- `test/gates/*.test.js`：20 个里 16 个**直接 import 判定纯函数** ⇒ 守**函数边界**；进程级调用只作补充。

## 七、规则层的腐坏（本次诊断的关键发现）

1. **`docs/DEV-GUIDE.md` 第 26 / 177 / 185 / 206 行仍写「四个段目录」并只列 core/main/renderer/gates，实际是 7 个。** 散文规则已与代码矛盾 —— 目录规则的唯一权威本身是错的。
2. **`gates/repo/check-test-numbering.mjs` 根本不判命名**：它扫规划编号字面量（`B1`–`B13`/`F1`–`F9`/`C1`–`C4`/`D-\d\d`/`批次\d+`）在字符串字面量里的泄漏，附带复用 `checkSegmentMirrors` ＋ 扫描面等式 ＋ 下限。**名字让 AI 相信命名被守着。**
3. **`checkSegmentMirrors` 比看起来弱得多**：判据只是「顶层或顶层下一层存在同名目录」，实测 `test/docs/` `test/tools/` `test/shared/` `test/build-assets/` **全部 PASS**。它挡得住 `test/pending/`，挡不住任何语义错位。
4. 现行 5 条段目录元规则（目录组织标准 / 归属判例 / 同模块多段口径 / 段目录镜像＋三名显式排除 / fixtures 命名口径）里，**只有 1 条有机器判据**，且那一条很弱。

## 八、三条独立普查之外的一处交叉发现

`test/gates/` 20 个文件名与门禁名 1:1 的只有 17 个（`entry-exit-guard` / `observability` / `packaged-smoke` 三个无对应门禁名）。这与第四节的「7/20 未登记」是两回事：前者是命名与门禁注册表脱钩，后者是探针登记不全。

## 九、已核实但**不属本次范围**的事实

- `src/` 侧 `LAYER_RULES` 存在不一致（`convert-no-outside-src` 用 `prefix:` 而 `faces-no-outside-src` 用 `layer:`）。属 `src` 树债务，本次冻结不动。
- `test/cli/pdf-launch.test.js` 存在段间 import（`import "./options.test.js"`）。
- `test/core/` 根 6 个文件里 `ipc-contract.ts` 与 `preload-api.ts` 是跨层契约、`convert.ts` 是门面，既不属于 core 的九个主题子目录也不是普通模块；镜像后会成为扁平段，归属需在判据实跑后确认。
