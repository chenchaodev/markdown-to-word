# 注册表判据 R5c：负向载体必须真挂在链上（REQ-150 取证）

## 缺口

9 条 `*:selftest` 载体可以**从 `verify:ci` 链上被悄悄摘掉，且零判红**。已用注入式只读实验证实：把 9 条全从链上删掉，`checkGateRegistry()` 与 `checkContract()` **都返回 `[]`**；对照组删掉链上的 `check:geometry` 则立刻判红 —— 证明不是实验装置的问题。

注意被误判的方向：**不是「没人跑」，是「没人守它继续跑」**。9 条载体当前确实都在 CI 上跑（`verify:ci` → `test:coverage` → 验收段 → `test/gates/*.test.js`）。但门禁的**正常路径永远是绿的** —— 少了一条负向夹具，链上不会少任何一个 `[ok]`，只是少了一道没人发现的保险。某次链整理顺手删掉它，全链照样绿，而**没有人的全绿里看不出少了一格**。

## 成因：一处分类学不对称

- **R1** 的 `claimedScript()` 用 `script in PROBE_CARRIER_SCRIPTS` 把载体**豁免**掉，不要求它有归属。
- **R5b** 的反查过滤条件是 `entries.filter((item) => item.npmScripts.includes(hit.name))` —— 而实测**登记项里含 `selftest` 的 `npmScripts` 有 0 个**。

⇒ 载体落在 R1 的豁免里，又不在 R5b 的核对面内，成为唯一「有归属、无对账」的一类。

三类漂移里只有一种是真空：**「留在 `package.json`、退出链」**。若把整个 script 连链上引用一起删掉，反而会被 `check-ci-contract` 的 script 存在性断言抓到。另有「挪到仅 workflow 而不在链上」同样不被 R5b 核（它压根没有登记项）。

## 修法：加一条 R5c，不动既有豁免

在 R5b 循环之后加一个遍历：收集 `discovered` 里 `kind === "npm"` 且 `onChain` 的 script 名成集合，逐个核对 `PROBE_CARRIER_SCRIPTS` 的 key，不在集合中即判红，code 为 `probe-carrier-offchain`。

**为什么不改 R1 的豁免、不改 R5b 的过滤条件**：那两个是既有判据的其它语义，动它们会把改动面从「补一格」放大成「重写对账逻辑」。新判据只答「还在不在链上」，与 `probe-carrier-orphan`（有没有人认领）构成双向互补。

9 条载体当前全在链上，所以新判据落地**不判红** —— 若判红，说明前提有误，应停下报告而不是改链迁就。

## 验收：三步验法 + 段内固化

段内负向夹具把「构造 ⇒ 判红 ⇒ 撤回 ⇒ 复绿」三步固化进链，使这条判据的绿/红两态被持续证明，不依赖人工脚本：

- 构造（把某载体标成不在链上，登记项一个字节不动）⇒ 判红，且**只**出 `probe-carrier-offchain`（排除「它红得像样但理由是别的」）
- 撤回 ⇒ 复绿（排除恒红判据）
- 更强锚点：把 **9 条全摘下链**必须判红 9 条（排除「只看第一条就收工」）

三步验法用真实发现面跑：注入的是 `package.json` 的合成文本，链展开仍由 `walkChain` 真解析 —— 验证的是「链上真少一条载体」，不是手工拼的 Map。对照组「摘掉 `check:geometry`」仍如期判红。

## 覆盖了什么 / 没覆盖什么

**覆盖**：`PROBE_CARRIER_SCRIPTS` 里任一条（或全部）脱离 npm script 链 ⇒ 逐条判红；判红归因唯一性；恒绿排除；逐个求值。

**没覆盖**（写清边界，免得后来人误读成「载体全生命周期的保险」）：

- 不覆盖「载体在链上但内容被掏空」—— 那由载体自身与各门禁的 `check:*:selftest` 守，R5c 只答「它还跑不跑」。
- 只认 `PROBE_CARRIER_SCRIPTS` 这一张表。新增载体若忘了登记进这张表，R1 会把它当成无主门禁判红（`invocation-unregistered`）⇒「忘了登记」仍有网；「留在表里但忘了挂链」才是本条堵的洞。载体文件被改名/移动而表未改，由 R3 的 `probe-missing` 判红。
- 不区分「挪去 workflow」与「彻底删除」（两种都判红，文案里会打印 `onChain/onWorkflow` 实际值可据此分辨）。负向夹具必须在链内，所以这是有意的。
- **不覆盖 `TOOLCHAIN_SCRIPTS`（`build`/`typecheck`/`lint`）与 `AGGREGATOR_SCRIPTS`。** 从 R5b 的过滤条件静态推断：`lint`/`build` 摘链时 R5b 也不会响（它们的判定体在仓外，没有登记项可依）。**这一格未做注入实验，未确证**，本轮未擅自扩大范围。

## 一条被修正的既往判断

此前认定「`check:gates` 是 `access: local` ⇒ CI 失明」，**该判断是错的** —— 把「某个 CLI 入口不在链上」当成了「判定本体不在链上」。实测 `test/gates/gate-registry-gate.test.js:125` 调**同一个** `checkGateRegistry({})`，`test/gates/gate-probes.test.js:120` 调**同一个** `runGateProbes`，两者都是验收段，跑在 `verify:ci` 里。CI 没失明。

同理，`ADR-040:28` 记的「CI 看不见、只能靠显式跑 `npm run check:gates`」也不准确 —— ADR 记的是「那条 CLI 入口不在链上」，写成了「CI 看不见」。

真正失明的只有本文这一格，且成因是注册表的分类学漏洞，与 `access` 字段无关。
