# `check-docs` 自检夹具的验证语义随环境分化（REQ-147 取证）

## 现象

`gates/repo/check-docs.selftest.mjs` 有 10 条夹具，其中一条名叫「真实配置仓(不设 `M2W_GLOBAL_CONFIG`)当前未漂移 → 通过」：

```js
{ name: '真实配置仓(不设 M2W_GLOBAL_CONFIG)当前未漂移 → 通过',
  shape: 'real', expectCode: 0,
  require: /门禁结论:(已判定|未判定)/ }
```

它**不设** `M2W_GLOBAL_CONFIG`，让包装层回退到 `os.homedir()/.config/opencode`，即**宿主用户的真实目录**。判别式接受 `已判定` 与 `未判定` 两种结论。

后果是同一条夹具在两类机器上验证的不是同一件事：

- 开发机（装了配置仓）⇒ 走「载体可达 → 真委托 → 已判定」；
- CI（不装也不克隆配置仓）⇒ 走「载体不可达 → 打印跳过 → 未判定」，`expectCode: 0` 照过。

即 **CI 上这条夹具的鉴别力为零**，且输出里还带一条名为「真实配置仓…通过」的 `[ok]` 作背书。

## 附带一处反向缺陷

本机上若项目真有断指针，`check-docs` 返回 1，这条夹具会以「真实配置仓…当前未漂移 → 通过」的名字报**失败** —— 一条**文档内容问题**被显示成**包装层回归失败**，误归因方向恰好反了。

## 判定为缺陷：它逐字复现了门禁本体自己拒绝的形态

`gates/repo/check-docs.mjs:14-18` 明写该检查刻意不在 `verify:ci` 链里，理由是：

> 「留在链上等于给『文档正在被 CI 检查』的假象，实则从未校验过任何东西。」

而 `check:docs:selftest` **在**链里（`package.json:91`）。把这条真机夹具放链上，是同一个假象上移一层，且**更难发现** —— 因为它现在有 `[ok]` 输出作背书。

## 两条可能的辩护，逐条评估

**辩护①「selftest 在链上只是自检委托与退出码传出机制，载体不可达是正常态」。**
委托与退出码传出由另外 9 条确定性夹具覆盖（`exit 1` / `exit 7` / 被信号杀死 / argv 透传 / cwd 项目探针 / 首尾空白 trim），与这条无关。且该辩护与 `check-docs.mjs:14-18` 直接矛盾。**不成立。**

**辩护②「`未判定` 也是合法结论输出，判别式本就该接受它」。**
作为**包装层输出契约**的陈述成立 —— 两分支都留下可分辨痕迹，正是 REQ-097 的设计。但该契约已由 `missing` / `no-gate-file` 两条夹具**严格且确定性地**覆盖（它们 `require` 跳过文本**并 `forbid: /门禁结论:已判定/``）。放宽这条夹具的判别式**没有换来任何新覆盖**，只丢掉了唯一的真实路径断言。**范畴错误，不成立。**

区分点是：**契约层需要「两分支都可分辨」，夹具层需要「这条夹具证明它宣称的事」。**

另注：这条夹具把 `check-docs.selftest.mjs:5` 头注自己点名的**头号漂移**（「载体不可达就静默跳过 = 你以为文档被查过、其实没有」）写成了通过条件。

## 同类排查：全仓唯一一例

区分轴很干净 —— 其它 selftest 的真实仓库锚点读的都是**版本控制内的检出物**（CI 与本机逐字节相同），只有这条读的是**检出物之外的用户级目录**。

仓内已有正面样板：`gates/repo/check-ci-contract.selftest.mjs` 专门识别出「真实仓库形态上恒成立 ⇒ CI 上空洞为真」的不变量，并造**合成反例树**补上；沙盒探针的 `gates/probe/gate-probes/gates/app.mjs` 与 `gates/fixtures.mjs` 在前提缺失时产出 `ok: false`（「前提缺失，门禁未被验证（**不等于通过**）」）⇒ 判红，而非跳过。

## 修法：夹具自造 homedir shim

把 `shape: 'real'` 改成 `shape: 'home-shim'`：

1. 仍**不设** `M2W_GLOBAL_CONFIG` —— 保留 `os.homedir()` 回退分支的覆盖。这是该分支的**唯一**覆盖：其余 9 条一律显式设了 `M2W_GLOBAL_CONFIG`，一旦那行回退被删改成硬依赖环境变量，全套夹具照样全绿。
2. 改为在子进程 env 里改写 `HOME` 与 `USERPROFILE`，指向夹具现造的合成 home，其下预置 `.config/opencode/tools/check-pointers.mjs`（复用既有替身载体生成逻辑，不复制门禁判定规则）。
3. 判别式收紧为 `require: /门禁结论:已判定/`，并加 `forbid: /跳过:未找到全局指针门禁/`。

**平台事实（已实测，非假设）**：Windows 上 `os.homedir()` 只认 `USERPROFILE`，**只设 `HOME` 会静默失效**并回落到真实用户目录 —— 夹具会变绿，但验证的根本不是这条分支。故必须同时设两个。（POSIX 上只认 `HOME`，多余的 `USERPROFILE` 无害 —— 属无害冗余，未实测。）

## 为什么这是净增益而不是等价替换

- 原夹具的**唯一独占覆盖面**（`os.homedir()` 回退分支）被保留并**确定化**；
- 消除环境分化：本机与 CI 验证同一件事；
- 消除误归因：不再受「项目当前有无断指针」影响；
- 真实配置仓的可达性**本来就该由 `check:docs` 手工步验证**（它不在链上、提交前手动跑），selftest 把它偷带进链上正是门禁本体拒绝的形态。

## 被明确否决的替代方案

| 方案 | 否决理由 |
|---|---|
| 改 `expectCode` | 无效 —— 两分支都是 `exit 0`，退出码区分不了 |
| 整个 selftest 移出 `verify:ci` | `registry.mjs` 显示 `docs` 门禁**无沙盒探针、无测试段**，selftest 是它唯一探针 ⇒ 会丢掉 9 条有效覆盖，且 R5b 的核对面不覆盖探针载体，**丢了不会判红**。为修 1 条退化牺牲 9 条健康覆盖，净亏 |
| 给 CI 装配置仓副本 | 配置仓是用户级仓，非为 CI 克隆设计；门禁本体 `:14-18` 已明确拒绝此路径 |
| 新增「跳过」三态语义 | YAGNI —— shim 已让降级分支在夹具里不再存在 |

## 验证

`node gates/repo/check-docs.selftest.mjs` → exit 0，10/10 全绿，输出中不再有「真实配置仓」字样。

**判定确定化自证**（本条是修复的核心验收点）：把宿主 `M2W_GLOBAL_CONFIG` 设成一个不存在的目录后重跑，10 条 `[ok]` 行与正常跑**逐字一致** —— 结论不随宿主环境分化。

临时目录无残留（`homeRoot` 的清理已并入既有 `finally`）。
