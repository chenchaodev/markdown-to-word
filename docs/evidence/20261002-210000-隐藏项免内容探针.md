# 隐藏项免内容探针：`.c8-tmp` 让门禁白付 4 秒

## 一、现象与定位

`verify:ci` 步连续三轮 232 / 233 / 237s，一致，非抖动。逐脚本按日志 Z 时间戳求差：

| 环节 | 耗时 | 占比 |
|---|---|---|
| `test:coverage` | 149.9s | 64% |
| 19 个静态门禁 + selftest | ~27s | 12% |
| `check:geometry` | 18.5s | 8% |
| `check:fixtures` | 11.7s | 5% |
| `check:coverage-zero` | 10.3s | 4% |
| `lint` | 9.5s | 4% |

对比 run 36840999312（148s 那轮），段数只从 125 涨到 128，但**段耗时 sum 从 372s 涨到 482s（+110s）**。涨幅集中在四处，其余段基本持平：

```
coverage-gate        2.2s → 17.3s  (+15.0)
gate-registry-gate   2.6s → 17.6s  (+15.0)
check:fixtures      1.0s → 11.7s  (+10.7)
check:coverage-zero  0.3s → 10.3s  (+9.9)
```

**干活量没涨**（探针恒为 31 项，`coverage-gate` case 12→18、`gate-registry-gate` 23→24），是每次干活变贵了。

## 二、机理

`gates/repo/repo-manifest.mjs` 的 `scanTopLevel` 对**每个**顶层目录调 `probeDirectChildren`，后者对直系每个 `.json` 做 `readFileSync` + `stripJsonComments` + `JSON.parse`（`:453-457` → `:215`）。

`.c8-tmp` 里是 c8 的 V8 dump，本轮 223 个文件 / 136MB，**全被逐个 parse**。`--cpu-prof` 佐证：`readJsonObject` 自耗 1623ms + `stripJsonComments` 736ms + GC 1608ms ≈ 4.0s / 4.56s 采样总量。

**而这���计算是纯白付**：`classifyProfile` 首行即 `if (p.hidden) return VCS`（`:114`），三项探针（`hasCode` / `docMajority` / `hasLockfileMarker`）的结果读出来也必被丢弃。实测把这三项全翻成相反值，`.c8-tmp` 分类仍是 `vcs`，一字不差。且 `TopEntry`（`:136-141`）只携带 `name/isDirectory/category/reason/configRole`，三个探针字段在 `:565` 构造条目时即被丢弃，**全模块无其他消费者**。

放大机制：dump 是每个子进程退出时**边跑边写**的，`check:coverage-zero` 与 `check:fixtures` 排在 `test:coverage` **之后**，此时 dump 已堆到峰值——两者正好是最慢的两个。

隔离实测（同一工作树，唯一差别是本函数）：

```
改前 topLevel() cold 5230ms  →  改后 101ms   (52x)
六条派生集逐字节相同（entries / mirrorPaths / protectedTreePaths /
                cleanProtectedSegments / buildOutputNames / packOutputNames）
```

## 三、写过的否决方案

| 方案 | 否决理由 |
|---|---|
| 按目录名黑名单排除 `.c8-tmp` | 违反 ADR-037 约束一（分类判据不含任何具体目录名）。它要消灭的正是这类手写清单，失效形态是恒绿：改名就不生效。**且会静默躲过所有现有锚点**（见第五节实测） |
| dump 移进 `output/` | ADR-048「关键约束二」已实测撞过：`output/` 是 gate-probes 段的「工作树零注入」指纹集，dump 边跑边写必与探针窗口重叠，报 `protected-tree-mutated`，**确定性假红，重跑不会好** |
| 排除出 `actions/cache` | `ci.yml:105` 的 cache path 是 `node_modules/.cache`，`.c8-tmp` 从来不在缓存里。没缓存的东西谈不上「排除」 |
| package.json 配 c8 `tempDirectory` | 绝对路径会让沙盒内那次 c8 与外层共用目录，子 c8 在 report 阶段清空它 ⇒ 外层覆盖数据整段丢失（ADR-048:52 实测）；`clean` 本就默认 `true`（`c8@12.0.0` `parse-args.js:131-134`），是空操作；`/tmp` 是 POSIX 路径而主 job 跑 `windows-latest` |
| CI 前后置 `rm -rf` | `.c8-tmp` **不被 git 跟踪**，runner 每轮是全新 VM ⇒ 跑前删的是空气；跑后删时门禁已在 `verify:ci` 内跑完 |

**关键认知**：这三个外部方案都在治「存量」，而 `.c8-tmp` 是**本轮跑出来的**（ADR-048:57 记着实测「全链跑完 214 个文件 / 约 134M」）。它们都只把存量挪走，本轮照样重新堆起来。

## 四、改法

在 `scanTopLevel` 里对隐藏项**不调探针**——让计算量对齐判据实际读什么，而不是加一个名字黑名单。判据一个字没改（`classifyProfile` 函数体、`probeDirectChildren`、`probeHasCodeDeep` 全部不动，它们对非隐藏项承重：`node_modules` 正是靠 `hasLockfileMarker` 归 `deps`）。

安全性是**结构性的**而非 empirical：`hidden` 的判据（`startsWith(".")`）与 `:552` 算的是同一个值，且早于任何探针字段被读取，故传 `false` 与传真值在数学上等价，不存在「碰巧当前成立」。

顺带把 `{ hasCode: false, ... }` 字面量提为 frozen 常量 `NO_PROFILE`（原先在 `:440` 与 `:548` 各写一遍）。冻结的理由：它会被直接交给 `classifyProfile`，一旦某调用点就地造字面量，「探针没跑」与「探针跑了但三项皆 false」就再也分不开——而那正是本条要保留的可区分性。

## 五、锚点有牙齿：三次注入实测

合成树加两个**对抗**隐藏目录（`.hidden-deps` 带 `lockfileVersion`、`.hidden-code` 带 `.ts`），期望均 `vcs`。

| 注入 | 结果 |
|---|---|
| 删 `classifyProfile` 的 `p.hidden` 早退 | **exit 1**，诊断点名 `.hidden-code=other,.hidden-deps=other` |
| hidden 早退挪到 `isBuildOutput` 之后 | **exit 1** |
| hidden 早退挪到函数最末尾（内容判据全在前） | **exit 1**，`.hidden-code=shared,.hidden-deps=deps` |

**新锚点是覆盖主力吗？实测：不是。** 三次注入中 `.gitignore` 每次都变 `other` 让 exit 1 成立——即便抽掉新锚点（注入 3）仍然 exit 1。故新锚点**不是唯一牙齿**，它守的是**可诊断性**：没有它时报错只显示 `.gitignore=other`，读者得自己反推是 `deps` 那条还是 `shared` 那条判据泄漏；有了它直接看到 `.hidden-deps=deps` / `.hidden-code=shared`。第三次注入正是这条价值的实证。

## 六、已知局限（如实记）

`check-ci-contract.selftest.mjs:761` 那条锚点自称能抓「判据里混进任何具体目录名」，但它**结构上抓不到 name-based skip**：合成树里没有 `.c8-tmp`，按名跳过不改变任何分类，锚点照样绿。这是该锚点既有的覆盖缺口，非本条引入。也正是本条选「谓词（`startsWith(".")`）」而非「黑名单」的理由之一——后者会静默躲过所有现有锚点。

## 七、交付时验证（同机同树 A/B，不跨机比较）

`npm run verify:ci` 全链 exit 0、128 段全绿。耗时对照**只用本机同一条命令**：

| 口径 | 改前 | 改后 |
|---|---|---|
| `topLevel()` cold | 5230ms | **101ms** |
| `coverage-gate` 段（`M2W_ONLY` 单段跑） | 7646ms | **629ms** |
| `gate-registry-gate` 段（同上） | 5841ms | **1356ms** |
| 六条派生集 | — | **逐字节相同** |

「改前」取自 `git stash` 切同一工作树（唯一差别是本函数），与「改后」是同一条命令的两次实跑。
