# 测试树按被测主体分四目录（REQ-142 方案原文）

## 起因

`test/segments/` 这个目录同时承担两种互不相干的被测主体，而它的名字只描述了其中一种。

DEV-GUIDE「测试体系」节定的口径是「test 树镜像 src 三层，按被测主体归属」——但 `segments` 是**执行单元**的名字（验收 runner 的一段），不是被测主体。段名里的 `segments` 在全仓只出现在「三段目录」这个执行概念上，从不指被测对象。

## 实测事实

### 一、75 段里 17 段的被测主体在 `gates/`，不在 core

逐文件实读 import 面（`grep -lE 'from "\.\./\.\./gates/'`）：

| 被测主体在 `gates/`（15 个） | 被测主体跨 `gates/`+`shared/`（2 个） |
| --- | --- |
| `coverage-gate` `dist-manifest-gate` `env-fingerprint` `fixture-contract` `gate-probes` `gate-registry-gate` `geometry-gate` `import-boundary` `install-smoke` `observability` `packaged-smoke` `pinned-actions` `release-artifact-gate` `signature-status` `supply-chain` | `contract-single-source`（测 `gates/` + `shared/` 的契约恒等）`entry-exit-guard`（测 `shared/entry-guard.mjs`） |

对照面：`test/main/` 34 段与 `test/renderer/` 17 段中，**只有 `test/renderer/settings-controls.test.js`** 一个文件 import `shared/`，其余零跨界。即 `main/` 与 `renderer/` 两层是干净的「测产品」，而 `segments/` 混了「测产品」与「测门禁」。

这 17 段与 `gates/` 是**同域**的：它们消费 `gates/smoke/smoke-proc.mjs`、`gates/artifacts/check-install-smoke.mjs`、`gates/smoke/smoke-report.mjs` 等门禁模块，断言门禁的判定面。

### 二、`test/tools/` 只剩一个死文件

ADR-038 的目标态原文（「`test/tools/` 整个取消，每个文件按 ADR-039 的跨树 import 事实归位」）**未达成**：该目录现存 1 个文件 `test/tools/smoke/smoke.mjs`，15 行，唯一代码是 `export { runSmoke } from "../../../dist/main/smoke.js";`。

死代码的证据链：

1. 唯一消费者是 `test/segments/packaged-smoke.test.js:42` 的 `import * as devSmokeEntry`——而该段 `:18` 的注释自己写着「主进程 `--smoke` 分支**不再经 `test/` 路径**」。
2. `package.json` 的 30 条 script 无一条指向它（全仓 grep 命中 4 处：3 处是注释、1 处是那条 import）。
3. `packaged-smoke.test.js:145-177` 正在断言它「必须是零实现薄转调」。即：**一个只为满足断言而存在的文件，其存在性被断言锁住**。该断言防的回归（marker 恒等 / 入口随包 / 打包面纪律）由同段其余断言（`:169-181` 主进程直连与单实例锁豁免、`:187-191` 实现唯一出处、`:195+` 打包面纪律）独立覆盖。

### 三、三目录口径被三处锁定，改第四个目录要动判据表述而非严格性

| 锁定点 | 形式 |
| --- | --- |
| `shared/test-common-surface.js:42` | `SEGMENT_DIRS = Object.freeze(["segments","main","renderer"])` |
| `test/acceptance.mjs` | 非递归发现 `SEGMENT_DIRS` |
| `gates/fixtures/gen-fixtures.mjs` | 同构 `scan` 同一数组对象（恒等由 `test/segments/fixture-contract.test.js` 断言） |

DEV-GUIDE 的口径原文是「段目录以三目录为全集，`test/` 下无第四个段目录（原 `test/pending/` 暂存区已删除……）新增段一律进三目录之一，**勿另开暂存区**」。

判据的**意图**是「不许开杂物抽屉」。`test/gates/` 镜像一棵真实存在的树（`gates/`），不是抽屉 ⇒ 意图被满足。要改的是判据的**字面表述**（「三目录为全集」→「段目录须镜像一棵被断言的树，判据为该树存在于顶层」），严格性不降。

## 方案

### 目标形态

```
test/
├── core/        ← 原 segments/ 中测 src/core 的 58 段
├── main/        ← 34 段（不动）
├── renderer/    ← 17 段（不动）
├── gates/       ← 原 segments/ 中测 gates/ 与 shared/ 的 17 段
├── common/      ← harness（不动）
├── fixtures/    ← 只读数据区（另见 REQ-143）
└── acceptance.mjs
```

全仓因此成为**四对镜像**，导航规则是「改哪棵树，去同名目录」：

| 被断言的树 | 断言 |
| --- | --- |
| `src/core/` | `test/core/` |
| `src/main/` | `test/main/` |
| `src/renderer/` | `test/renderer/` |
| `gates/**` | `test/gates/` |

现状下改一个冒烟门禁必须知道 `packaged-smoke.test.js` 在一个叫「core 渲染」的目录里——这个成本每次改门禁付一次。

### 步序（每步独立成提交，可独立回退）

1. **建 `test/gates/` 并迁 17 个段文件**（纯 `git mv`，不改内容）。
   - 连带：`shared/test-common-surface.js` 的 `SEGMENT_DIRS` 加 `"gates"`；`test/acceptance.mjs` 与 `gen-fixtures.mjs` 自动跟随（同一数组对象）。
   - 判据改法：`SEGMENT_DIRS` 的语义从「三段目录」改为「段目录」，并加一条自检——每个段目录的首段必须存在于顶层且不是 `common`/`fixtures`（否则又变回「枚举已知」，新目录漏登记即静默放行）。
   - 边界规则**不改**：`test-stay-in-test` 的 allow 面已含 `test`，新目录自动在允许面内；`gates-stay-in-gates` 的 allow 面是 `gates`/`shared`/`test/fixtures`，不含 `test/gates/` ⇒ 无需放宽。
2. **删 `test/tools/smoke/smoke.mjs` 与 `packaged-smoke.test.js` 中锁它的那组断言。**
   - 删：`:42` 的 import、`:51` 的 `DEV_ENTRY` 常量、`:145-177` 的 dev 入口 4 组断言（同一函数对象 / 单出口 / 无实现痕迹 / 单 specifier）。
   - **保留**：`:169-181`（主进程直连 `dist/main/smoke.js`、不得引 `test/tools/smoke`、单实例锁豁免、`app.exit(1)`）与 `:187-191`（`src/main/smoke.ts` 是实现唯一出处）——它们独立成立。`:192` 的 `[ok]` 文案要改（现宣称「dev 入口薄转调同一 runSmoke」）。
   - `shared/test-common-surface.js:56` 删 `test/tools` 那条 target ⇒ 声明面 5 目录 → 4 目录。
3. **改「三目录恒等」判据的表述并补负向锚点。**
   - `test/segments/contract-single-source.test.js` 的扫描面等式组（`:555-620`）：正向断言的声明面字符串（`:563`「5 个目录」）改为 4 个；负向 B（`:600-614`，用「磁盘上不存在的目录」验证 `missing` 侧）换替身——`test/pending`（它历史上真存在过，是被删的那个暂存区的名字）。
   - ⚠ **有陷阱**：`gates/repo/check-test-numbering.selftest.mjs:34-40` 的 `BASE_SHAPE` 五个目录计数 `16+11+11+6+6 = 50`，加上随门禁拷进去的 `shared/test-common-surface.js` 一个 = 51，恰好压 `shared/test-common-surface.js:66` 的 `MIN_SCAN_FILES = 50` 下限。删 `test/tools` 后 = 45 ⇒ **跌破下限判红**。必须把 6 个配额重分配到其余四个目录（`test/common` 是 `SCAN_TARGETS` 里唯一的非段目录，也是 `check-temp-cleanup` 的判定对象，不宜压太低）。
   - `gates/repo/check-temp-cleanup.selftest.mjs:41-46` 同一形状（`test/common` 为 7，共 51），同改。
   - 两个门禁的头注扫描面说明（`check-test-numbering.mjs:19` / `check-temp-cleanup.mjs:20` 各有一行 `test/tools/**/*.{js,mjs}`）删该段。
4. **ADR**：落 `docs/adr/ADR-0NN-段目录按被测主体镜像.md`，记三件事——① 段目录判据从「三目录枚举」改为「镜像一棵被断言的树」（含自检，防退化成枚举）② `test/tools/` 取消，ADR-038 的该条目标态就此达成 ③ 三段目录保持扁平不加子目录不变。

### 验证

- 开发回路：`typecheck` + `lint` + 受影响段（`M2W_ONLY='contract-single-source,fixture-contract,test-common-helpers,packaged-smoke,import-boundary'`）+ 纯文本门禁 `check:test-numbering` `check:test-numbering:selftest` `check:temp-cleanup` `check:temp-cleanup:selftest` `check:docs`。
- 提交前：`npm run test` 全量（改的是段目录发现机制本身，属 DEV-GUIDE「开发回路不得省全量的两种情形」第 ① 类：动了共享测试设施 `test/common/**` 与门禁脚本）。
- 完成判据：`checkSurfaceEquality` 的声明面 == 实测面，且段数与迁移前逐段对应（迁移是 `git mv`，不改段内容，故段数应完全相等——不等即有文件丢失或重复）。

### 不做的事

- **不改 `src/` 层的三段命名**（`core`/`main`/`renderer` 是既有的正确分层名，与测试树对齐即可）。
- **不并入 `test/gates/` 的 17 段里那 2 个跨 `shared/` 的**：`contract-single-source` 与 `entry-exit-guard` 测的是机制层与门禁契约，归 `gates/` 桶（它们断言的对象在 `gates/` 与 `shared/`），不按「跨了几层」分桶。
- **不改边界规则表**：allow-list 形态下新目录默认在允许面内，加规则反而是倒退。
