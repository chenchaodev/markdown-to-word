## 四、发布供应链 —— 压倒性大头，且会推翻 ADR-013

**这不是「给 `build` 加个 target」**：

- ADR-013 把「现阶段明确不签名」写成**现行决策**，其「三处同改」强制位含 `Get-AuthenticodeSignature`（Windows-only）与 SmartScreen 披露。
- **macOS 上未公证（notarized）的 app 打不开** —— Gatekeeper 直接拦。「不签名」在 macOS 上不是可接受的风险声明，是**不可用**。
- ⇒ 发 macOS = 推翻 ADR-013 + 采购 Apple Developer ID + notarization + hardened runtime + **改 `check:signature`**（它读 Authenticode，mac 上取不到事实；按 ADR-013 自己的规矩「取不到事实不得当作未签名放行」，门禁要么误报要么必须按平台分叉）。
- CI 还要加 macOS runner。`ci.yml` 三 job 全 `runs-on: windows-latest`、**无 `strategy.matrix`**。action 固定到 40 位 SHA（ADR-013 明确记录这是刻意代价），每加一个 job 会撞 `test/gates/pinned-actions.test.js:205` 的 `usages.length === 14`（`ci.yml:206-207` 已记为它绕路的先例）。
- `runs-on` **不被 `check-ci-contract.mjs` 校验**（零命中），所以不会直接判红 —— 撞门禁的是那条 `usages.length === 14`。

**性质：组织成本（要花钱、要证书、要推翻 ADR），不是工程成本。**

## 五、PDF 字体 —— 唯一贯穿的正确性缺口

| 路线 | 字体依赖落在 | mac/Linux 后果 |
|---|---|---|
| docx（`docx/render.ts:226`） | **消费机**（只把 `typography.fontEastAsia` 当名字写进 XML） | 静默替换，产物本身「正确」。软成本，**今天已如此**，非跨平台新增 |
| pdf（`pdf/template-css.ts:79`） | **生产机**的 Chromium | `font-family: "微软雅黑", …`，默认值 `"微软雅黑"`（`typography.ts:179`）、预设还有 `"宋体"`/`"仿宋_GB2312"`（`presets.ts:73,135`）—— **`仿宋_GB2312` 连 Windows 版 Office 以外都没有** |

⇒ pdf 落到 `sans-serif` → Helvetica → CJK 回退 PingFang。**不崩、不报错，但分页变、目录页码漂、版面与 Windows 不一致。**
`docs/DEV-GUIDE.md:98` 已记「pdf 侧走 Windows 系统字体零配置（Linux 部署需 CSS @font-face 内嵌 noto-cjk，后置）」。

**这是产品决策（随包分发字体？字体授权？），不是代码工作量。**

## 七、成本落点排序

1. **发布 / 签名 / 公证**（推翻 ADR-013 + 采购 + 门禁按平台分叉）—— 压倒性，组织成本
2. **PDF 字体可用性** —— 产品决策
3. **打包**（target + CI runner + icon：现只有 `icon.svg`/`icon.ico`，无 `.icns`、无多尺寸 `.png` 集）
4. **输出层深度耦合**（`resource-dirs.ts:49` 硬编码 `../../..`）—— 小，但**新增输出层时就付**，不是跨平台时才付
5. **`main/windows/`** —— 已有分叉，增量成本低
6. renderer / KaTeX / 临时文件 / persist —— **≈0**

第 1 项是「在没有第二个消费点时做，收益无法度量而成本照付」的那一项 ⇒ 跨平台推到「ADR-013 何时拍板」这个外部事件之后。
