# docx 产物标准符合性自查（样式表悬空引用）

> 结论去向：落 REQ.md 行 ｜ REQ-262 行「分析在哪」指向本文；修法供后续拍板，本文只给事实与可选修法清单
> 2026-10-21 实测。**取样方式**：解包本仓测试真跑产出的 `output/artifacts/*.docx`（5 个产物逐个查），**不读源码推导**。

> **为什么存**：用户 2026-10-21 提问「docx 输出到底是不是标准 docx 格式」。结论不能靠印象 —— 本仓的既有兼容结论（`docs/WPS-COMPAT.md`）是 2026-08-16 的**整体结论**（Word/WPS 能开），逐格状态至今全是 `⬜`（未逐项实测）。本文补的是「包级结构与样式表引用完整性」这一维的机器可判事实。
> **口径提醒**：本文结论基于 2026-10-21 的产物与当时的 `docx@9.7.1`；换库版本或改渲染层后须重新解包核对。

---

## 一、结论（一句话）

**包结构是标准 OOXML，Word/WPS 能打开；但 `styles.xml` 有 4 处「引用了不存在的样式」的不合规**（悬空引用），其中一处已造成**本仓自己的浅导入读不出正文字号**（见 §三）。

## 二、包级结构：**合规**（逐部件核对 5 个产物）

| 检查项 | 结果 |
|---|---|
| ZIP 必需部件（`[Content_Types].xml` · `_rels/.rels` · `word/document.xml`） | 齐备 |
| 每个部件都被 `[Content_Types].xml` 覆盖（Override 或 Default 扩展名） | **齐备**（Default 覆盖 png/jpeg/jpg/bmp/gif/svg/rels/xml/odttf；Override 覆盖 document/styles/numbering/footnotes/endnotes/settings/comments/fontTable/footer/header + docProps 三件） |
| `word/_rels/document.xml.rels` 存在 | 是 |
| `document.xml` 里每个 `r:id` / `r:embed` 都能在 rels 里找到 | **全部命中**（0 处悬空） |
| rels 里每个非外部 Target 在包内存在 | **全部命中**（0 处悬空） |
| 命名空间前缀都已声明 | 是（`w`/`r`/`mc`/`w14`/`w15`/`wp`/`a`/`m`/`w16`…） |
| `w:docDefaults` 存在 | 是（`w:rPrDefault` 有字体与字号，`w:pPrDefault` 为空） |
| OPC 关系类型（styles/numbering/footnotes/endnotes/settings/comments/fontTable/header/footer/image） | 标准 URI（`.../officeDocument/2006/relationships/...`） |
| 图片字节可达 | 是（`word/media/<sha1>.png`，由 `a:blip@r:embed` 经 rels 指向） |

> ⚠️ **一处自查假阳性（已排除，勿再当问题）**：首轮扫描脚本用「部件名是否出现在 Content_Types 的 Override 列表」判定部件声明，把 `.rels` 与 `.png` 报成未声明。实为 `Default Extension` 规则已覆盖（`rels`/`png` 在 Default 列表里），是我的正则只匹配了 `Default Extension=` 这一种属性顺序。**改正后：既无 Override 也无 Default 覆盖的部件 = 0**。

## 三、不合规项：样式表的 4 处悬空引用（真问题）

`styles.xml` 实际只定义了 15 个样式：`Title` · `Heading1`-`Heading6` · `Strong` · `ListParagraph` · `Hyperlink` · `FootnoteReference` · `FootnoteText` · `FootnoteTextChar` · `EndnoteReference` · `EndnoteText` · `EndnoteTextChar`。

但正文与样式表里引用了这些**不存在的** styleId：

| # | 悬空引用 | 出现在 | 后果 |
|---|---|---|---|
| **1** | `basedOn="Normal"` | `Heading1`-`Heading6` 等的 `w:basedOn` | 继承链指向空。Word 打开时按「无继承」渲染（观感正常），但**任何按 `styleId` 查样式的工具会查不到** |
| **2** | `basedOn="DefaultParagraphFont"` | `Hyperlink` / `FootnoteReference` 等字符样式的 `w:basedOn` | 同上 |
| **3** | `pStyle w:val="TOC1"` / `"TOC2"` | 目录段落的 `w:pPr`（`TableOfContents` 组件生成，`src/core/docx/chrome.ts:133`） | 目录条目段落指向不存在的段落样式；**`styles.xml` 里既没有 `TOC1`/`TOC2` 样式，也没有 `w:latentStyles` 块**（`w:latentStyles` 不存在）⇒ 目录层级样式实际不生效 |
| **4** | `rStyle w:val="IndexLink"` | 目录条目内 hyperlink 的 `w:rPr` | 指向不存在的字符样式 |

**另有一项规格层面的缺失**：`w:style` 标签上**没有任何 `w:default="1"`**（`Normal` 通常带 `w:default="1"` 标记段落默认样式），且**没有 `word/theme/theme1.xml`**（Word 自家文件通常带主题部件；本仓字体走 `docDefaults` 显式 `w:rFonts`，不依赖主题 ⇒ 缺主题不直接影响渲染，但少了主题色/主题字体这条常规路径）。

### 3.1 这不是「docx 库的问题」，是**本仓没定义这些样式**

`docx@9.7.1` 的 `IStylesOptions` 提供 `paragraphStyles` / `characterStyles` / `importedStyles` 三个入口（`node_modules/docx/dist/index.d.ts:1764-1770`），本仓**一个都没用** —— `src/core/docx/render.ts:244-259` 的 `styles` 只给了 `default.document`（即 `w:docDefaults`）。样式表里那 15 个样式全是 `docx` 库的**内置默认样式集**，其中 `Heading1` 的 `basedOn="Normal"` 是库自带的，而库**不提供 `Normal` 样式本体**（Word 侧由应用内部兜底，文件里不落）。

⇒ 修法是本仓自己补定义，不必改库。

### 3.2 已经造成的一个真实后果

**本仓的浅导入（`src/core/docx/template-import.ts`）对自家产出的 docx 取不到正文字号** —— 它取 `Normal` 样式块的 `w:rPr`，而 `Normal` 样式**在自家产物里根本不存在**；正文字体字号实际落在 `w:docDefaults/w:rPrDefault/w:rPr`。这条已写进 `docs/adr/ADR-086` 决定 4（深导入改从 `docDefaults` 取值），并由 [自家 docx 产物形态实测](20261021-220818-自家docx产物形态实测.md) 佐证。

**同源影响面**：任何第三方工具按 `styleId` 查样式（Pandoc 读 docx、python-docx 的 `document.styles['Normal']`、WPS/Word 的「修改样式」面板）在本仓产物上都会查不到 `Normal`；目录的 `TOC1`/`TOC2` 层级样式也不生效。

## 四、影响面与风险判断

- **能不能打开**：能。Word/WPS 对悬空 `basedOn` / `pStyle` / `rStyle` 的处理是「按无该样式渲染」，不报错、不弹修复提示。本仓 2026-08-16 的整体实测结论（`docs/WPS-COMPAT.md`「整体结论」）与产物结构事实一致 —— **不是「打不开」级别的问题**。
- **是不是「常见格式」**：**不是完全常见**。Word 自家产出的 docx 里 `Normal` 必然存在且带 `w:default="1"`，目录条目引用 `TOC1`/`TOC2` 时这些样式（或 `w:latentStyles` 里的潜在样式声明）也在。本仓产物缺这些 ⇒ 与「Word 写的文件」有可观察差异。
- **对谁有影响**：① 样式继承链（`basedOn` 落空 ⇒ 改 Word 端标题样式不会联动）；② 目录层级样式不生效（`TOC1`/`TOC2` 落空）；③ 第三方工具按样式 id 查询时查不到 `Normal`；④ 本仓自己的浅导入（已列 §3.2）。
- **对已有用户观感的影响**：**目前无可见变化**（悬空引用不改变渲染结果）—— 本条是「格式合规性/互操作性」问题，不是「用户能看到的问题」。**改它属用户不可感知变更 ⇒ 按 CHANGELOG 纪律不写用户文档**（ADR-047「有意义且别处查不到」两条之一不满足）。

## 五、可选修法（**本节已按 2026-10-21 三次探针实测订正，勿照旧配方实施**）

### 5.0 库机制（`node_modules/docx/dist/index.cjs:26835-26844`，File 构造）

```js
if (options.externalStyles !== undefined) {
  this.styles = new Styles({ ...externalStyles, importedStyles: [...defaultStyles.importedStyles, ...externalStyles.importedStyles] });
} else if (options.styles) {
  const defaultStyles = new DefaultStylesFactory().newInstance(options.styles.default);
  this.styles = new Styles({ ...defaultStyles, ...options.styles });   // ← 顶层键整体覆盖
} else { … }
```
`Styles` 构造（`:26432-26439`）按 `initialStyles → importedStyles → paragraphStyles → characterStyles` **逐个 push**。

### 5.1 三次探针的实测结果（`docx@9.7.1` 真跑）

| 探针 | 做法 | 结果 |
|---|---|---|
| **A** | 只给 `options.styles = { default:{…}, paragraphStyles:[TOC1,TOC2], characterStyles:[IndexLink] }` | ✅ 16 个内置样式**零丢失**、`docDefaults` 在位；❌ 无 `Normal`、无 `w:default="1"` |
| **B** | A 再加 `importedStyles:[ImportedXmlComponent.fromXmlString('<w:style w:type="paragraph" w:default="1" w:styleId="Normal">…')]` | ❌ **16 个内置样式全丢 + `docDefaults` 全丢**，只剩 `Normal`/`TOC1`；机理 = `{...defaultStyles, ...options.styles}` 顶层键整体覆盖，`defaultStyles.importedStyles` 正在被覆盖的位置 |
| **C** | 同 B 但 `options.styles` 里**不给** `importedStyles` | ✅ 内置样式零丢失、`docDefaults` 在位；`w:default="1"` 仍无处可加 |

**关键机制两条**：
1. `options.styles.paragraphStyles` / `characterStyles` 是**追加**语义（走 `StyleForParagraph`/`StyleForCharacter`）；`importedStyles` 是**替换**语义（顶层键覆盖）—— 用错一个就丢内置样式集。
2. `w:default="1"` **加不上**：`IParagraphStyleOptions` 无 `default` 字段（`IStyleAttributes.default` 只在未导出的 `Style` 基类构造里），`StyleForParagraph` 不接受该属性 ⇒ 走 `paragraphStyles` 拿不到 `w:default`。

### 5.2 订正后的修法清单

1. **补 `TOC1`/`TOC2` 段落样式 + `IndexLink` 字符样式**（探针 A 路径）—— 消掉 §三 的 #3/#4 两处悬空引用，让目录层级样式生效。**零后处理、零内置样式损失**，是本仓当前架构下的低风险高收益项。
2. **补 `Normal`（带 `w:default="1"`）** —— 三条候选路径各有代价：
   - 走 `externalStyles` 分支（库把 `defaultStyles.importedStyles` 与外部样式**合并**）：需实测该分支下 `options.styles.default` 注入的 `docDefaults` 是否仍在、`mc:Ignorable` 与命名空间是否完好（**待验证**）。
   - 打包后改写 `word/styles.xml`：产物字节不再由库单点决定，打包流水线多一道。
   - 放弃 `w:default="1"`、只补一个不带 `w:default` 的 `Normal`（走 `paragraphStyles`）：能消掉 `basedOn="Normal"` 的悬空，但「无默认段落样式标记」仍在。
3. **补 `w:latentStyles`** —— 让 Word 知道内置样式的默认形态（Word 自家文件都有）。是否必要见 §四 的判断。
4. **补 `word/theme/theme1.xml`** —— `docx@9.7.1` **无主题部件支持**（`index.d.ts` 里的 `themeColor`/`themeShade`/`themeTint` 只是 run 属性着色，不是主题部件）⇒ 只能走后处理补。本仓字体走 `docDefaults` 显式 `w:rFonts`，不依赖主题 ⇒ 补它的收益是「像 Word 的文件」，不是「修功能」。
5. **补一条产物级门禁**（解包产物 ⇒ 断言「`document.xml`/rels 引用到的每个 styleId 都在 `styles.xml` 有定义」「每个 `basedOn` 都有定义」「每个部件都被 `[Content_Types].xml` 覆盖」「每个 `r:id` 都能解析」）—— 这类问题**目前全靠人看**，没有任何机器判据守着。门禁的判据形态（哪些判红、哪些只告警）与落点见 ADR 讨论。

### 5.3 一条与本节无关但必须记住的事实

**补 `Normal` 时，`Normal` 里不要放 rPr**（字体/字号）—— 正文属性继续唯一来自 `w:docDefaults`（`theme.ts` 的集中配置），否则正文属性出现第二个真源，违反本仓「单一来源不复制」纪律，也与 `test/core/theme-fonts.test.js` 的「styles.xml 的 eastAsia/ascii 与集中配置一致」断言打架。
