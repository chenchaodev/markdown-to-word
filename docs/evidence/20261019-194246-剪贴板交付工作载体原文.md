## 一、第一轮保真 spike 结果(2026-10-19,用户实测)

方法:一份全内联 `style` 的 HTML,浏览器复制后分别粘进 Word 与 WPS。

| 形态 | Word | WPS |
|---|---|---|
| 标题层级 / 中文字体 / 粗斜体下划线删除线 / 超链接 / 列表 | 正常 | 正常 |
| 代码块(`<pre>` + 底色 + 左边框) | **底色与边框全丢**,只剩等宽字 | 底色与左侧竖线出现,但**每一行文字都带蓝框** |
| 引用块(`<blockquote>` + 左边框) | **格式全丢** | 有格式,但**每行文字都带蓝框** |
| 表格(`border-collapse` + `width:100%`) | **超出版心,显示不全** | **超出版心,显示不全** |

### 第二轮:表格承载 + 固定 pt 宽 —— 两端全部符合预期

用户实测回报:**Word 与 WPS 均满足预期**。验证形态与全部依据见 `docs/evidence/20261019-185151-剪贴板保真spike两轮结果.md`。

⇒ 四条硬约束,直接约束渲染器:

1. **段落级背景与边框不可移植**。代码块与引用块一律 **单格表格承载**(`td` 上色 / 上边框 / 上内边距);`pre`/`blockquote` 不再承担盒属性。
2. **`border-left` 会被 WPS 按行盒渲染**。禁止在任何块级元素上用 `border-left`;左边线只能由 `td` 的 `border-left` + `mso-border-left-alt` 表达。
3. **`width:100%` 在两端都会溢出**。表格宽度写**固定 pt**(版心宽),同时给 `table-layout:fixed`(WPS)与 `mso-table-layout-alt:fixed`(Word);列宽优先用 pt。
4. **`table` 带 `border="0" cellspacing="0" cellpadding="0"`**;`td` 补 `mso-padding-alt`;中文字体补 `mso-fareast-font-family`。全部样式内联。

### CF_HTML

由 Chromium/Electron 自动补头(`clipboard.write({ text, html })`),**禁止手写头再交给该 API**(双重包裹)。本项目 Electron 43,`writeHTML` 仍可用但不必用。

## 三、整体完成标准

1. 任一文件行点「复制为富文本」→ 剪贴板内含 `text/html` 与 `text/plain`,**不产生任何文件**
2. 粘进 **Word** 与 **WPS** 各一次:标题层级、中文字体、嵌套列表、粗斜体下划线删除线、超链接、代码块灰底、引用块、表格边框与底色全部保留;表格不超版心
3. 多文件队列(n≥2)逐项复制,顺序与队列一致
4. 图片 base64 内嵌;超预算按既有预算口径给出 warning,不静默丢图
5. pdf 与 docx 两条既有交付线零行为变化(既有测试段零改动)
6. ADR 落定「为何不复用 pdf 产物 / 为何表格承载 / 写入点为何收单文件 / 公式后置的理由」
