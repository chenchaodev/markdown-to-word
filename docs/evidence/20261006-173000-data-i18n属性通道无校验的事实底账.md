# 2026-10-06 data-i18n 属性通道无校验的事实底账

本文件为 REQ-235 的配套底账。**新会话做 REQ-235 之前先读本文件。**

## 一、问题

动态 key 通道有**两个**消费者，都走 `tByKey(key: string)`，都不经 `Dict` 校验：

| 消费者 | 载体 | 编译期校验 | 运行期兜底 |
|---|---|---|---|
| `KeyedWarning.key` | 经 IPC 传到 renderer | ❌ 无 → **已由 06b 修掉**（收窄为 `WarningKey`） | 有（`fallback` 字段） |
| `data-i18n*` 属性 | HTML 静态标注 | ❌ 无 | **无**（直接显示裸 key） |

**本文件只记第二个。** 第一个已修，此处仅作对照。

## 二、实测事实

### 2.1 规模与覆盖

- `src/renderer/*.html` 里 `data-i18n` / `data-i18n-placeholder` / `data-i18n-title` / `data-i18n-aria-label` 四种属性，去重后 **201 个属性值**。
- **201/201 全部在字典内**，零缺口（实测，非推断）。
- 消费者：`src/core/i18n/dom.ts:33-42`，四种属性统一走 `tByKey(el.dataset.i18n ?? "")`。

### 2.2 门禁

`gates/` 下对 `data-i18n` **零命中** —— 没有任何门禁管这些属性值。

### 2.3 失效模式

写一个字典没有的 key → `tByKey` 回退链（当前语言 → en → key）返回 key 本身 → 用户看到**原始属性值**，静默。

**这条通道的失效比警告通道更难看**：警告通道有 `fallback` 字段（至少显示中文原文），`data-i18n` 通道**连兜底都没有** —— 它把 `tByKey(...)` 的结果直接赋给 `textContent` / `setAttribute`。

## 三、与警告通道的对照（REQ-235 的核心论据）

| | 警告通道 | `data-i18n` 通道 |
|---|---|---|
| 载体 | IPC 传输的 `KeyedWarning` | HTML 静态属性 |
| 查表 | `tByKey(key: string)` | `tByKey(key: string)` |
| 编译期校验 | ❌ → 06b 已修 | ❌ 仍无 |
| 运行期兜底 | 有（`fallback`） | **无** |
| 已发生的真实事故 | `warn.precheckFailed` 孤儿（已修） | 暂无（但 201 个属性值零门禁） |

**同源但不同解法**：警告通道是 TS 类型问题（加类型即可），本条是 HTML 静态标注问题（要扫 HTML 文件，是门禁不是类型）。故不并入 06b。

## 四、做的时候需要知道的

1. **不能靠 TS 类型**。属性值写在 HTML 里，不在 TS 编译面内。
2. **现成的可抄模式**：`test/core/dual-pipeline-matrix.test.js` 的 `assertMatrixShape()` 用 `sourceLines(relPath)` 读源文件做存在性/非空校验 —— 那是「扫文件文本」的现成写法。
3. **字典侧已有单源**：`Dict = keyof typeof dict`（`zh.ts:550`），`en.ts`/`ja.ts` 以 `satisfies Record<Dict, string>` 锁全量。门禁只需把 HTML 属性值集合与 `Dict` 对读。
4. **注意 `data-i18n` 与 `data-i18n-placeholder` 等是四种不同属性**，但值都是字典 key，同一份对读逻辑。
5. **HTML 里可能有动态拼接的属性值**（如 `` `data-i18n="prefix.${x}"` ``）—— 若存在，静态扫不全，需先确认。**本文件未查这一项**，做之前先查。
