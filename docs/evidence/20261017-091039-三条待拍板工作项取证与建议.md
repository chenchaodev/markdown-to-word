### 1.4 选型前必须先查实的两条外部前提

**这是本项最关键的未知，且会直接决定路线。**

- Word 的 `TOC \c "图"` 域是**按 SEQ 域收集**的。本仓**全仓不产任何 SEQ 域** —— grep `SEQ` 于 `src/` 只命中 4 处**注释**（`captions.ts:27,54`、`prescan.ts:54`、`template-css.ts:198`，内容都是「与 Word SEQ \s 1 语义一致」）。**若该前提成立，`\c` 路线在当前「静态编号、免更新」的设计下会收集到 0 条。**
- `\t`（`stylesWithLevels`）是**按段落样式**收集、不依赖 SEQ 域，理论上更可能成立 —— 但本仓 `renderCaptionParagraph`（`captions.ts:136-140`）**当前不挂任何段落样式**（全仓 `paragraphStyles` / `characterStyles` 零命中）。

⇒ **裁决前请先让 librarian 查这两条外部文档**，否则路线可能在动手后才发现走不通。

### 1.5 要做什么（逐侧拆）

**渲染期要不要「先收集再插清单」？两侧答案都是「本来就是」。**

- docx：`prescan.ts:46` 在渲染前扫全文 → `render.ts:187` 拿到 `tocEntries` / `captions` → `:194-196` 插目录页。LoF 挂同一处即可，**零架构改动**
- pdf：`render.ts:311-312` 在渲染前建 `headings` 数组交给规则填 → `:332-333` 渲染完再拼目录（`cover + toc + body`）。LoF 沿用同一时序

⇒ **两侧都不需要重构管线**，只需新增一个收集数组 + 一个插入点。

**docx 侧两条路，成本差一个量级：**

| 路线 | 做法 | 代价 |
|---|---|---|
| **A（推荐）静态清单** | `buildCaptionContext` 已产出全部题注的 `{type,chapter,index,text}`，在 `prescanDocument` 里多返回一个**有序数组**（Map 的插入序即文档序，但 key 是节点需重排），再仿 `renderTocPage` 生成第二个 `TableOfContents` 实例 | ⚠ **已知限制**：书签只在**有 label 时**生成（`captions.ts:132-135`），无 label 的题注没有锚点；而库对无 `href` 的 `cachedEntries` 条目**退化为纯文本不超链接** ⇒ **静态 LoF 里未标 label 的条目不可点击**。要全可点就得给所有题注补书签（改 `:132` 的条件） |
| B Word 域 LoF | 走 `\t`（比 `\c` 更可能成立） | 需「先立样式 → 再插域」两步，且最终仍要用 `cachedEntries` 才能做到免更新打开即见 ⇒ **净成本高于 A** |

好处：A 完全贴合本项目「免更新路线」的既定立场（`chrome.ts:98-106` 的两种模式注释、`docs/WPS-COMPAT.md:45` 的口径）。

**pdf 侧同构照抄目录，成本低：**

- 收集：把 `rules/xref.ts:141-155` 的「有 label 才继续」早退改成「无论有无 label 都记一条 `{kind, seq, chapter, text}`」；**题注文本可能跨多个 inline child**（`rules/caption.ts:56` 只剥了首个 text token 的前缀），`heading-id.ts:65-77` 的延迟补写法是现成解法
- 渲染：仿 `buildTocHtml`（`postprocess.ts:57-71`）写 `buildCaptionListHtml`，插在 `render.ts:333` 的 toc 之后
- 页码：若要，复用 `injectTocPageNumbers`（已按 id 集合定位、class 无关）+ `electron-side.ts:99-104` 的两遍法。⚠ **但题注锚点目前只在有 label 时注入**（`xref.ts:155` 在 `:145` 早退之后）⇒ 要页码就得给所有题注注入 id

### 2.3 ⚠ 加键必带的两个隐性变更

**① 未认键有一条隐藏耦合**：块内**零个已知 key 就整块不剥除、当正文原样保留**（`:65-67`，防「以 `---` 开头的普通文档」被误吞，由 `test/core/frontmatter.test.js:80-88` 锁死）。

### 2.4 四个余量项逐项拆解

#### ① 单位（机构 / 院系）—— 真需求，成本最低

**要不要新增持久化键？—— 不要。**

### 3.6 四处潜在碰撞，逐条核

**① 几何门禁 — 会撞，但改法很轻**

- 登记点只有一个：`DRAWER_CONTROLS.preset = [{ id: "templatePreset" }]`（`geometry-spec.mjs:196`）。**它不在 `DRAWER_CONDITIONS`、不在 `DRAWER_DISABLED_TIERS`** ⇒ 卡片**不需要第三种可见性形态**（这是 ADR-077:40 明确的边界，正好适用）
- 选择器生成 `geometry-spec.mjs:402-404`：id 形态 → `#settingsDrawer [id="templatePreset"]`，页面探针取 `members[0]` 的 rect（`geometry-page.mjs:65-86`）。**给卡片容器保留 `id="templatePreset"` 即可零改 `geometry-spec.mjs`**；判据量的是容器盒，不判卡片数量
- **判序不变**：`geometry-core.mjs:391-433` 是「组内视觉序」判定，而 preset 组**只有 1 个控件** ⇒ 行聚簇只有一行，`drawer-order-mismatch` 结构上不可能触发
- ⚠ **真正会撞的是 `viewport-overflow`**：`geometry-core.mjs:362-366` 逐控件判 `rect.right ≤ vw + tolPx`。卡片网格容器宽度受 `panels` 约束，3 列放得下，但**这是新增的量**，必须真跑 `check:geometry` 验
- ⚠ **水平裁切判据帮不上忙**：只查 `panels` / `tabs` 两个容器的 `scrollWidth-clientWidth`（`geometry-core.mjs:436-452`）。卡片若用固定 `min-width` 导致内层溢出，**这条判据看不见**。`ui-guidelines.md:52` 抽屉 `overflow-x:hidden` 的存在说明这正是历史上出事的位置
- **段标签位**：`.sec-h + .sub-label` 去线规则（`settings.css:296-299`）当前对 01 组不生效（01 组无段标签）

**② 三语字典 — 卡片上的预设名是「数据」，不是新增文案**

- 预设名 `presetDisplayName()`（`settings-logic.ts:33-37`）走 `t(preset.i18nKey)`，6 条键 `preset.default/paper/business/officialCn/cnReader/cnMinimal` **已三语齐**（`zh.ts:351-356` / `en.ts:345-350` / `ja.ts:341-346`）

- 自定义预设无 i18nKey，直接用用户 `name`（`settings-logic.ts:34`）—— 卡片上就是用户输入，天然无需字典
- ⇒ **纯 UI-only 换形态不新增任何字典键**，`check:i18n-keys` 应保持绿
- ⚠ 派生提示行 `#templatePresetHint` 是动态节点，**不得挂 `data-i18n`**（`ui-interaction-guards.test.js:258-274` 逐个点名）

**③ 快速参数条镜像 — 三选一，必须显式裁决**

- 规范要求它**继续是 sel**：`ui-guidelines.md:61`
- 快速条是「舞台内底部常驻的一行四项高频参数」（`index.html:222-233`），横向预算极紧 —— 卡片网格塞不进去

### 3.7 与 REQ-247 的关系：三处真实交互，但不是「必须叠在其上」

**① 卡片要不要被跨组检索命中？**

- 检索读点 `searchableSettingsRows()`（`settings-panel.ts:617-626`）只取「`group !== "mirror"` 且 `labelKey !== null`」的声明表行，标签经 `t(row.labelKey)` 现算
- 现状：搜「模板预设」命中 **1 条**（01 组那条行标签）。卡片化后若只保留容器一条声明 ⇒ **命中数不变**（仍是 1），但落点是「跳到 01 组 + 滚到卡片容器」
- ⚠ **代价**：搜「学术论文」「宋体」这类**预设名/说明词现在检不到**（它们是数据不是 `labelKey`）。ADR-077:30 明确否决过「renderer 侧另抄一份控件→标签映射」（理由是那会躲过四项交叉校验）⇒ 想让 6 个预设名可检索，只能走**同型扩展**（给声明表加 `searchTerms` 一类字段，仍在同一条声明上），属独立设计决策，不是 UI-only

**② 段标签与卡片的层级关系**

- 现状段标签只有 7 枚，落在 02/03/05（`index.html:574,618,681,760,865,907,940`），**01 组无段标签**
- ADR-077:40 / `settings-ia.md:23` 口径：段标签「只做视觉分段与检索落点，**不是折叠层**，不引入第三种可见性形态」
- 卡片本身是**一整块可视化选择器**，不是长列 —— 01 组只有 1 个「项」，加段标签没有收益 ⇒ **建议 01 组不加段标签**，与 REQ-077 的段标签层无冲突

**③ 键盘方向键**

- `onSettingsTabKeydown`（`settings-panel.ts:571-599`）的 `↑/↓/Home/End` 绑在 **`.settings-tab` 的 keydown** 上，是竖向 tablist 的 ARIA 必备键位，焦点在 tab 按钮上时才生效
- 卡片拿到焦点后：若卡片容器是 `role="radiogroup"` + `role="radio"`，方向键按 ARIA 应在**组内移动选项**（`aria-activedescendant` 或 roving tabindex），与 tablist 的换组键**不冲突**（不同元素、不同 handler）—— 但**必须实测确认 keydown 不冒泡到 tab handler**

**判定**：这是一条「**独立但必须排在 REQ-247 收尾之后**」的工作项。理由：① 它要动 `index.html` / `settings-panel.ts`，正是 REQ-247 P2 的可写清单，**并发会撞**；② REQ-247 的 `verify:ci` 当时未跑，几何门禁的「重排类改动必须单独成提交」也有要求。但**不是「必须叠在 REQ-247 之上做」** —— REQ-019 的裁据（八组制 / 折叠层）都不涉及预设组，改它不推翻 ADR-077 任何一条；唯一沾边的是 `searchableSettingsRows` 的标签单源，而卡片化在保留 `id` + `labelKey` 的前提下对该判据零影响。

> **本文落盘时的状态**：REQ-247 已于 2026-10-17 划完全部完成标准并随 4.2.0 发版，上述约束已解除。

### 3.9 判断：2026-08-26 的「暂不执行」今天是否仍成立

| 当时的理由 | 今天的证据 | 判定 |
|---|---|---|

**新增的、当年没有的反对理由：**

1. ⚠ **规范互斥**：`ui-guidelines.md:71` 明写「新配置项 → 控件映射（**强制，禁止发明新控件形态**）」，映射表里**没有「卡片」这一行**。⇒ 卡片化**第一步不是写代码**，是得先拍板要不要给映射表加这一行（`:84` 原文：「确需新模式：先改本文档并说明理由，确认后再实现」）—— 这是**产品/视觉决策，须用户拍板**
2. ⚠ **文档债已成事实**：`settings-ia.md:46` / `:112` 已写「预设卡」，实现是 select，`ui-guidelines.md:61` 写「预设 sel」—— **三份设计文档对同一控件三种口径**，无论做不做都该先裁决
3. REQ-247 落地后 **01 组成为抽屉里唯一「没有段标签、没有 seg 化、没有检索扩展」的组**，卡片化会让它成为异类

**支持现在做的理由：**

1. 2026-08-26 的「暂不执行」是**排期判断**（「待后续提出」），不是否决，且被原样登记为「开放但不排期」
2. 6 条 `preset.hint*` 三语说明文案**已写好但当前完全未使用**（select 形态下说明藏在选中项里）。卡片网格能让**预设名 + 说明**同时露出，等于让已有数据有落点
3. 改造成本已从「重构整条预设链路」收缩为「renderer 6 文件 + 1 样式表 + 1 测试段」，core 与持久化零改动

### 3.10 三档建议

| 档 | 内容 | 代价 |
|---|---|---|
| **A. 继续搁置** | 台账状态与「重看条件」不动 | 零成本。但 `settings-ia.md:46`「预设卡」与实现 select 的口径不一致**会继续留着** |
