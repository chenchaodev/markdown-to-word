# 顶层目录结构与项目根来源改造调研

> 调研快照：2026-10-03。**两轮**：① 目录结构 + 根来源改造面（§一~§四 · §六~§九）；② 沙盒副本机制怎么修（§五之二，2026-10-03 追加）。全程只读（read / grep / glob + 单命令级离线诊断），未跑构建、测试、聚合门禁链，无 git 写操作。

> 体量类数字（文件数 / 行数 / import 处数 / 占比）除**净减收益**外一律给取数命令，不抄数值 —— 改一次代码就会漂。

## 一、结论速览

| 问题 | 结论 |
|---|---|
| 顶层四棵树（`shared` `test` `tools` `gates`）是不是太多 | **不是**。依赖图实测单向无环、无冗余边，四条树边界规则里三条真行使 |
| `shared/` 少值不值得占一个顶层目录 | **值得**，但 ADR-038 给的理由站不住（见 §三） |
| `test/` 体量超 `src/` 是不是测试策略问题 | **不是**。分解后产品测试对源码是正常比值，超出部分全在测门禁的那一段（见 §四） |
| 「沙盒复制机制是最大负债」 | **成立**。根因是 `ROOT` 按文件位置派生；实测阻塞点唯一，REQ-164 落地后 **25 个副本里 23 个可删**、机制整段可退役（见 §五之二） |
| REQ-164 改造后能删多少代码 | **只改 2 行，但连带 9 处入口守卫**（不是 1 处，见 §六） |
| 沙盒机制怎么修 | **不用单独修** —— 它是 REQ-164 落地后的可删产物。净减约 905 行且失效方向由 fail-open 翻成 fail-closed；立项 **REQ-165**（见 §五之二） |

## 二、依赖形状（实测，非推断）

跨树 import 逐条解析（遍历 + `posixpath.normpath`，非文本 grep）：

| 边 | 取数命令 |
|---|---|
| `src → shared` | **0 条**（`grep -rn "shared/" src/` 的命中全是 `src/core/pdf/rules/shared.ts` 同目录文件，与仓根 `shared/` 无关） |
| 各树内部边 + 跨树边 | `gates/repo/check-import-boundary.mjs` 的 `LAYER_RULES` / `TREE_RULES` 判定；自行复核用遍历脚本按 `posixpath.normpath` 解相对说明符后按首段归类 |
| 环 | **0** |

⇒ 方向单向、无环、`src/` 零引用仓根 `shared/`。**这一层没有可合并的冗余边。**

`src/` 内共用代码一律走 `src/` 内部相对路径；把「机制层」放在 `src/` 外正是为了不进运行时依赖图。

## 三、`shared/` 该不该占顶层目录

**值得，但 ADR-038 给的理由（`:41`「给跨树 import 一个合法名字，否则边界规则第 2 条写不出来」）是错的理由、对的结论。** 正确理由两条：

1. **它是三棵互不依赖的树的唯一汇点。** `gates` / `test` / `tools` 三棵树彼此无依赖却都指向它 —— 任何单独一棵树都当不了它的家。「≥2 个独立消费方」是教科书判据。
2. **它是全仓唯一被允许自算项目根的位置。** 见 `check-import-boundary.mjs` 的 `ROOT_SOURCE_FILE` 与 `no-self-computed-root` 规则。放在顶层 depth=1 才使 `shared/paths.js` 里那一处 `resolve(dirname, "..")` 成立 —— 该文件 `:14-15` 自陈这一点。

**折进 `gates/` 的具体后果**（不是风格问题）：`tools → shared` 的边会变成 `tools → gates/shared/…`，而 `tools-stay-in-tools` 的 allow 面不含 `gates` ⇒ 要么放行（**废掉 ADR-050 一条 commit 前刚建立的隔离**），要么保留字面 `shared` 前缀（树边界规则退化成 ADR-043 已否掉的「字面量当树名、拼错即恒绿」）。两条都是倒退。

**`tools/` + `gates/` + `shared/` 合成一棵**：删掉 `tools-stay-in-tools` 与「哪棵树断言什么」这个轴，ADR-050 的收益当场回退。且 `tools/` 是最便宜的一棵，保留它的边际税最低。

**一条不必修但值得登记的观察**：`shared/test-common-surface.js` 的内容全是 `test/` 段目录的扫描面（`SEGMENT_DIRS`），却因「`gates/` 不许引 `test/common`」而被迫住在 `shared/`，并因此成为必须逐字节复制进沙盒的文件之一。这是 `shared/` 已退化成「跨树需要往里放的东西的容身处」的一个证据 —— 但移动它会立刻违反 `gates-stay-in-gates`，**不要动**。

## 四、`test/` 与 `src/` 的体量对比（推翻「测试策略有问题」）

按**代码行**（剔除注释与空行）分解，比值取数：逐文件剔除 `//` / `/* */` 注释行与空行后按树汇总再相除。

- `test/` 超过 `src/` **完全由「测门禁的那一段」造成**（`test/gates/`，对应主体 `gates/`）。产品测试段（`test/core` + `test/main` + `test/renderer`）对 `src/` 是**正常量级的比值**。
- 真正的异常是另一条：**`gates/` 的代码行与 `src/` 同一量级** —— 验证装置与产品等体量。这是 60 份 ADR 一贯的刻意选择，**合并目录不会让它小一分**。要缩小只能砍门禁**数量**，那是另一个决策。

**元测试该不该独立成第 5 棵树？不该**，三条理由：

1. 它已在正确位置上 —— ADR-051 的镜像判据（`shared/test-common-surface.js` 的 `checkSegmentMirrors`）要求**每个段目录镜像一棵顶层被断言的树**，`gates` 命中顶层 `gates/`。提升为顶层树会**破坏镜像不变式**，还要在 `checkSegmentMirrors` 开特例。
2. 提升无边界收益 —— 导航规则「改哪棵树去同名目录」已经成立。
3. ADR-051 备选方案已用实测否决过 colocated 与顶层化。

**该不该砍元测试？证据说不该** —— ADR-039 实测：探针证明「会红」，测试段证明「语义对」，职责不同；全砍会丢装包冒烟、几何门禁、副本闭包守护这类**没有第二条守护路径**的段。

## 五、沙盒复制机制：根因定位与一条被推翻的结论

### 根因

门禁 selftest 之所以必须把门禁脚本**逐字节复制**进夹具才能改根，唯一原因是 `ROOT` 取自 `shared/paths.js` 的**按文件位置**派生：复制本体 ⇒ 副本的 `dirname` 变了 ⇒ 位置派生的值落到夹具根。这是位置耦合的副作用，不是沙盒的需要。

### 仓内已有反例证明不需要复制

- `gates/repo/check-pointers.mjs` 与 `gates/repo/check-docs.mjs`：扫描根恒为 `process.cwd()`，刻意不接收 `--root`。
- `gates/repo/check-docs.selftest.mjs` 文件头自陈「**本体不复制、不改写、不换根：跑的就是 `gates/repo/check-pointers.mjs` 本身**」，只设 `cwd`；实测该文件 `copyFileSync` 零行。
- `gates/repo/check-transform-dispatch.selftest.mjs` 同样零复制。

⇒ 改造方向确立：**`cwd` 作为唯一根来源，无 fallback、无 `--root`、无环境变量。** 与 ADR-040 否掉的 `--root` 不冲突 —— 否的是「可关掉的判据 = 橡皮章后门」，而 `cwd` 单一来源**没有第二条分支**，同样没有后门。

### ⚠️ 曾被推翻的一条（后续又推翻了，见 §五之二）

**一度判「可删 `shared/copy-closure.js` 与 `test/common/copy-closure-audit.js`」是错的**，理由是：改 `cwd` 后被复制的门禁**仍然** `import { ROOT } from '../../shared/paths.js'`，而 **ESM 静态 import 按文件位置解析、与 cwd 无关** ⇒ 沙盒里没有这份文件就是 `ERR_MODULE_NOT_FOUND`。

⇒ 当时的结论是「复制机制与根来源无关，REQ-164 不动它」。**§五之二 实测推翻了这一条**：该论证只成立于「复制点还在」的前提，而 REQ-164 的意义正是**不再复制**。

### 两条也一并被推翻的初判

- **9 个 copy 沙盒已经**把 `cwd` 指向夹具根，改后 `ROOT` 值完全不变 ⇒ **零改动**。
- `check-import-boundary.mjs` 两处刻意锚 `projectRoot` 的扫描**不是风险** —— `import-boundary.test.js` 的调用是**进程内直调，不 chdir**，`cwd` 恒为仓根；该文件的树边界调用已按 ADR-043:37 传显式沙盒入参，**一行都不用改**。

### 仍真实存在的四类静默失效（属复制机制，不属根来源）

| 失效 | 位置 |
|---|---|
| 闭包门禁是**所有复制点的并集** ⇒ 「某个沙盒漏复制」结构上不可发现 | ADR-040 背景一自陈 |
| `writeFileSync` 造的副本扫描器看不见 | `contract-single-source.test.js` 文件头自陈 |
| tree-mirror（`cpSync`）**永不判红**，只登记 | `copy-closure-audit.js` 的 `COPY_MECHANISMS` |
| **`auditViaCoverage` 只检查 `shared/paths.js` 一个文件**（`ROOT_SOURCE_RELATIVE` 硬编码）⇒ 除它之外的任何依赖，per-`via` 断言**完全不覆盖** | `copy-closure-audit.js` 的 `ROOT_SOURCE_RELATIVE` + `auditViaCoverage` |

第五类的实测复现（模拟某 via 漏带 `shared/test-common-surface.js`）：`violations = 0`（并集 fail-open）且 `gaps = 0`（per-`via` 同样看不见）⇒ **双绿**。ADR-040 背景一只记了并集 fail-open，per-`via` 是按 `paths.js` 写死的补丁，**不是通用 per-`via`**。

### 四类里的第四类不是缺陷（后续修正）

`inString` 掩码是 ADR-041 fail-closed 取舍的**产物**，用来把「文档串里的 `require("x")`」排除掉。**不修，无动作** —— 不应与前三类并列记为静默失效。

### 前三类在 REQ-164 之后怎么处理

⇒ 前三类随 REQ-165（沙盒副本机制退役）一并消失；改动面见 §五之二。

## 五之二、沙盒副本机制怎么修（第二轮补充，实测）

**结论：不用单独修 —— 它是 REQ-164 落地后的可删产物。立项 REQ-165。**

### 阻塞点实测（唯一）

造一个假仓（含一份 11 行、内含「门禁」词的 CHANGELOG），`cwd` 指过去跑**真仓**的 `check-changelog.mjs`：

```
[ok] CHANGELOG 口径扫描通过:条目区自第 5 行起(非空 202 行 / 版本标题 38 个),6 类判据零命中
EXIT=0
```

扫的是**真仓的 202 行**，不是夹具的 11 行。⇒ 阻塞点唯一且确认：`ROOT` 按 `import.meta.dirname` 派生。真脚本 + 假 cwd 之所以跑不通，**只**因为这一处。

### 复制点分三类（扫描面 `test/ gates/ tools/ shared/`，跑 `scanCopySites`；数量取数同该函数）

| 类 | 处置 | 硬理由 |
|---|---|---|
| **A1 · 只造假数据**（`check-changelog` / `gen-archive-index` / `check-test-numbering` / `check-ci-contract` / `dist-manifest` 五个 via） | **可删** —— 只注入数据，从不改写门禁源码，复制纯粹为让 `ROOT` 落到夹具 | `check-ci-contract.mjs` 已是 `ctx.root ?? ROOT`；`dist-manifest.mjs` 入口守卫**已经是** `isMainModule(import.meta.url)`，REQ-164 天然兼容 |
| **A2 · 必须改写门禁源码**（`check-temp-cleanup.selftest.mjs` 把探针 `before/after` 互换；`clean-artifacts-gate.test.js` 逐字节改写 `TARGET_DIRS`） | **不可删** | 必须有一份**可写**的门禁源码副本；14 条用例里只有这 1 条需要，但夹具形态是文件级共用的 |
| **B · 打包/构建产物环境**（tree-mirror `sandbox.mjs` 的 `cpSync`） | **删不得，且不加门禁** | 见下 |

**tree-mirror 不加判红的理由**（上一轮把「永不判红」列为缺陷是过度归因）：清单从顶层实际内容派生（新增树自动在内）；node_modules 是目录联接、裸包名天然可解析；探针会在沙盒里**真跑门禁**，运行时缺文件当场红。要加闭包判据得为「整树集合」重设闭包模型，且会误判四类树之间合法的跨树 import。

**install-smoke 的 8 份副本可删**：它们不是打进安装包的产物，是 npm script 驱动的 `gates/artifacts/*.mjs`；沙盒要的只是「合成 `release/` 树 + 假 exe + 桩 launcher」。**连带白掉一条约束** —— `shared/userdata.js` 因被逐字节复制而被迫零内部依赖，删复制后自动消失。`:719` 的「副本应与生产脚本逐字节一致」断言是**自指的**（复制是为了断言复制品等于原件），一并删。不改成「从 npm 装真包」：装包冒烟要 electron-builder + 网络 + 数分钟且非确定性，换来的字节同一性在跑真脚本时**恒真**。

### 净减与失效方向翻转（核心收益）

| 文件 / 段 | 现状 | 改后 |
|---|---|---|
| `test/common/copy-closure-audit.js` | 493 | **0（整删）** |
| `shared/copy-closure.js` | 393 | ~180 —— **不能整删**，`lexSource` / `skipQuoted` 被 `check-import-boundary.mjs` 与 `check-temp-cleanup.mjs` 用 |
| `contract-single-source.test.js` 的 (e) 节 + 文件头说明 | 239 | **0（删）** |
| 白名单式复制点门禁（替代） | 0 | **~40** |
| **净** | | **≈ −905** |

**关键差别不是行数，是失效方向**：现状对「新增复制点」是 **fail-open**（扫不出来就只登记，还要求人工同步 `SANDBOX_ENTRY_EVIDENCE`）；白名单门禁是 **fail-closed**（`copyFileSync(` 出现在两个已知沙盒文件之外即判红）。

T1 落地后副本只剩 A2 的 **7 个文件 / 2 个沙盒**，复制清单就写在 `copyFileSync` 调用点旁边三行内 —— 用 945 行守 7 个文件，收益为负。

### 被否决的替代方案

| 方案 | 否决理由 |
|---|---|
| env `M2W_ROOT` | ① 就是 REQ-164 已否决的 fallback 双分支；② **把响亮的 `ERR_MODULE_NOT_FOUND` 换成静默错根**（env 拼错或 `spawnSync` 没透传时，门禁默默扫真仓并 exit 0 —— 本仓最恨的「以为被查过」形态）；③ ADR-054 明写「不给门禁加任何模式开关、环境变量或逃生阀」。**注意「内部参数 vs 公开 flag」的差别在此不成立** —— 反对的不是 flag 表面，是分支本身 |
| CLI `--root` | 已否（ADR-040 备选表 + ADR-054 实施约束 5） |
| 拆 `paths.js`（根来源单独成模块） | **不解决任何问题** —— 沙盒仍需在沙盒位置提供那个模块，仍是一次复制，只是复制的东西更小。代价 45 处机械改动，收益为负 |
| `node --import` / 自定义 loader / `module.register()` | 技术可行（可拦截 `shared/paths.js` 合成 `ROOT`），但：① 进程级全局解析改写，无静态产物可评审，出错形态是 `ERR_MODULE_NOT_FOUND` 或更糟的错模块；② 门禁的「判据可读」属性归零；③ **入口守卫一个都跑不掉**，故省不下那 9 处改动。为省 25 行 `copyFileSync` 引入进程级魔法，收益/成本倒挂 |

### 载体建议（已按此执行）

- 新开 **`docs/adr/ADR-0NN-沙盒副本机制退役.md`**（命中总纲五的「移除模块」+「改对外接口」）。须点名：`ADR-040` 被取代的前提（它建立在「复制是根注入的必要手段」上，但其「豁免表归零」净收益仍成立）；`ADR-041` 的 `inString` 取舍**不被取代**，但 `collectSpecifiers` 若随审计层删除则该 ADR 需标部分退役 —— **不点名会让两份说法漂移**。
- **不并进 REQ-164**，新开 **REQ-165**。判据：规模与风险不同（2 行 vs 删 905 行 + 重写 6 个夹具构造，混号会把 REQ-164 的验收标准「代码只 2 行」逼成假话）；**有硬顺序依赖**（复制点是 cwd 派生根的前提，先删会红），两个有互斥前提的事项不合号；本仓先例是 REQ-006 拆为 REQ-162/163，判据见 `docs/REQ.md` 该墓碑行。
- 连带项（REQ-165 开工时）：`docs/DEV-GUIDE.md:137-138`「沙箱副本闭包」两段整段重写；`check-import-boundary.mjs:241-247` 那段「若某脚本需要自算根，正确做法是给它所在的沙盒补复制点」的指令改写；核对 ADR-039（列举 `copy-closure.js` 为真跨树）与 ADR-043（把 `shared/` 判为机制层）是否仍成立。

## 六、改造面（连带面比初判大）

### 代码只 2 行

| 位置 | 现状 | 改成 |
|---|---|---|
| `shared/paths.js:20` | `path.resolve(import.meta.dirname, "..")` | `process.cwd()` |
| `gates/repo/check-pointers.mjs:1991` | `resolve(argv[1]) === join(ROOT,'gates','repo','check-pointers.mjs')` | `fileURLToPath(import.meta.url)` |

**但入口守卫是 9 处，不是 1 处。** 形态实测分两类：

| 形态 | 处数 | REQ-164 后 |
|---|---|---|
| `import.meta.url` / `isMainModule(import.meta.url)` 自比 | 多数门禁（含 `check-unpacked-smoke` `check-install-smoke` `check-release-artifacts` `check-dist-manifest` `clean-artifacts`） | **天然兼容** |
| `path.join(ROOT\|projectRoot, 'gates/…')` 与 `argv[1]` 比对 | **9 处**：`check-pointers` `check-docs` `gen-archive-index` `check-temp-cleanup` `check-test-numbering` `check-ci-contract` `check-changelog` `registry` `coverage-gate` | **全部失配** |

⚠️ **初判「其余 8 处安全，理由是被 copy 进沙盒时 cwd 与位置同值」是错的** —— 那 9 处今天安全**正因为**它们被 copy 进沙盒；REQ-164 让沙盒不再复制 ⇒ 该理由消失，它们全部变成「守卫永不成立 ⇒ 无输出、退出码 0」。

失效形态极难排查：`ROOT` = 夹具根（`cwd` 指合成仓）而 `argv[1]` 仍是真实仓路径 ⇒ 不相等 ⇒ `main()` 不跑 ⇒ 无输出退 0。靠「输出里有 `门禁结论:…`」断言的自检段会**真红**，但红的是「门禁没跑」而非「夹具没生效」。

**仓内既有正解先例**（照此形态，零豁免）：`print-env-fingerprint.mjs:461`、`check-gate-probes.mjs:193`、`gen-fixtures.mjs:597` 三处已用 `import.meta.url` / `fileURLToPath(import.meta.url)` 自比。

## 七、已坐实的两条风险（均已排除）

## 八、验收判据（含一条反直觉点）

新增负向夹具落 `test/gates/check-pointers-e2e.test.js`（该段已有「现造合成仓 + `cwd` 指向它 + 断言输出行」的完整骨架，直接接）：

- **夹具 A · 入口守卫负向锚点**：`cwd` 指向合成仓、`argv[1]` 指向真实仓（即现状）⇒ 期望退出码 1 且输出命中「门禁结论」。若守卫被改坏成 `join(cwd, …)`，本条因「无输出 + 退出码 0」而红 —— 这正是要钉的失效形态。
- **夹具 B · 沙盒根恒等锚点**：`os.tmpdir()` 造 `<sandbox>/gates/repo/<某门禁>.mjs` + `<sandbox>/shared/paths.js` + `<sandbox>/package.json`，以 `cwd: <sandbox>` 跑 ⇒ 期望根相关诊断指向 `<sandbox>` 而非真实仓路径。

**反直觉点**：把 `paths.js:20` 临时改回 `import.meta.dirname`，新夹具**必须仍然绿** —— 夹具只能钉行为，不能依赖被测实现的方式；把 `check-pointers.mjs:1991` 改成 `join(process.cwd(), …)`，**必须红**。

正向恒等断言：仓根跑时 `process.cwd()` 与原位置派生值必须相等。
