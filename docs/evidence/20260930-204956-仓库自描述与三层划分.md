# 仓库自描述与门禁三层划分（REQ-110 分析档案）

## 起因

主观反馈是「`test/` 与 `scripts/` 组织有点混乱」。经 `lib-1` 核对社区惯例，结论是**目录划分本身不违反任何惯例** —— `src/` 有无、`scripts/` 还是 `tools/`、测试 colocated 还是集中，全是风格偏好，零硬约束。真正的硬约束只有四条相关：electron-builder 的 `files` 默认会把根目录的 `src/` `test/` `scripts/` 打进 asar；`node --test` 默认发现模式含 `**/test/**/*`；ESLint v9 flat config 必须在项目根；TS 6.0 起 `rootDir` 默认改为 tsconfig 所在目录。本仓四条都已正确处理。

所以「乱」的来源不是命名，而是**同一份知识在多处各自枚举**。

## 现状事实（逐条实测）

- 依赖方向：`core` 出边 **0** 条，`main→core` 77 条，`renderer→core` 43 条，无反向依赖，由 `scripts/check-import-boundary.mjs` 的 8 条规则机械断言。
- `scripts/` 34 个顶层 `.mjs` + 5 个岛目录（`gate-probes/` `geometry/` `pack-size/` `smoke-report/` `supply/`），**不在任何 tsconfig 的 `include` 内**，仅 eslint 覆盖。
- `test/` 210 文件，入口 `test/acceptance.mjs` 读目录零注册发现；**测试全部 import `../../dist/**` 编译产物而非 `src/`**（`tsconfig.test.json` 理由：dist 无类型标注，`checkJs` 会炸出约 1050 条噪声）。
- **6 处顶层目录各自枚举**：`check-test-numbering.mjs:72` `check-temp-cleanup.mjs:83` `gate-probes/contract.mjs:27,38` `clean-artifacts.mjs:46` `check-ci-contract.selftest.mjs:59`（14 条）`package.json:90`（`build.files`）。
- **26 处各自计算项目根**，3 种语法：`new URL('..')` ×20 / `new URL('../..')` ×5 / `import.meta.dirname` + `resolve('..')` ×2。
- **测试目录清单 4 处**：其中 2 处**逐字相同**（`SCAN_TARGETS` / `EXCLUDED_DIRS` / `isExcluded()` / `listScannableFiles()`，经 diff 验证），只有 `gen-fixtures.mjs` ↔ `acceptance.mjs` 这一对被 `test/segments/fixture-contract.test.js:67` 断言恒等，另两处无守护。
- **9 条 `scripts/ → test/` 跨树 import**（原设计说 7 条，漏了 `test/tools/geometry/` 那 4 条），全部指向纯机制，没有一条指向测试。
- `GATE_IDS`（`gate-probes/contract.mjs:49-56`）**只有 6 项**，而 `package.json` 有 20+ 门禁脚本。

## 四条核实与对原设计的修正

设计文档由 `ora-1` 产出，其四条未核实项经定向核实后如下。**四条里有四条推翻了原说法。**

### 一、`clean-artifacts` 的删除风险 —— 不成立

原称 `PROTECTED_SEGMENTS` 是 fail-open、「新增目录若被当 target 传入会被删」。实读不成立：`clean-artifacts.mjs:245` 有 `['dist','release','all']` 硬白名单，拒绝后直接返回不删除；`:252` 路径取自**冻结的** `TARGET_DIRS`，不来自用户输入；`:105-123` `assertMatchesBuildConfig` 把 `TARGET_DIRS` 钉死在 `package.json` 的 `build.files` 与 `build.directories.output`；`resolveTarget:126-144` 再拒绝对路径 / `..` / 越出项目根，`inspectTarget:150-154` 再拒符号链接与非目录。**组合起来是 fail-closed。**

### 二、门禁「没人跑」—— 要拆成两类

原称 5 个门禁「跑得动但没人跑」，这是把「不在 `verify:ci` 字符串上」等同于「没人跑」，漏掉了测试段 import 这一层：

| 门禁 | 真相 |
|---|---|
| `check:temp-cleanup` | 真·无人跑（链上无、无 workflow、无间接调用） |
| `check:docs` | 真·无人跑，但**是 2026-09-27 刻意裁决**，有双处注释备案（`check-ci-contract.mjs:253-258` + `check-docs.mjs:14-18`）：载体在配置仓、CI 恒不可达 ⇒ 恒 `exit 0`，留在链上是「给文档正在被 CI 检查的假象」 |
| `check:pack-size` | 被 `test:coverage` 间接调用（`test/segments/observability.test.js:49-63`） |
| `check:smoke-report` | 被 `test:coverage` 间接调用（同上 `:40-48`） |
| `check:install-smoke` | 逻辑被间接调用（`install-smoke.test.js:48`），CLI 入口需 `--execute` 才真安装 |

另有一处原设计漏掉的：门禁有**两条调用路径**，除 npm script 链外，`ci.yml:55` 与 `release.yml:59` 在 `npm ci` **之前**裸调 `node scripts/check-ci-contract.mjs` 做 fail-fast，`check:pinned-actions` 同理（`ci.yml:65` / `release.yml:67`）。机制 A 的门禁注册表若只登记 npm script，会漏掉这条路径。

### 三、探针「重叠」—— 方向反了

原称 `coverage` 与 `dist-manifest` 两套都有且重叠，可收敛为单探针。实测：

- **`coverage` 不重叠**，连被测模块都不同。探针真起 c8 进程验 `package.json` 真实参数向量（`gates/coverage.mjs:147-160`）；测试段只做静态审计（`coverage-gate.test.js:58-59` 调 `loadBaseline` + `auditStatic`），**一次都不执行 c8**。探针文件头 `:11-13` 自述「两层职责不同，缺一不可」。删探针会让「`--check-coverage` 被删」这类漂移失去守护 —— 静态审计只能发现「阈值与基线不一致」（有人同时改了两处）。
- **`dist-manifest` 才真重叠**，且探针是测试段的真子集（测试段多测 6 类负向），残留差异仅「默认参数路径 + 沙盒副本」。
- **缺口远大于重叠**。7 项既无探针也无测试段：`transform-dispatch` / `test-numbering` / `temp-cleanup` / `docs` / `archive-index` / `contract`(`:selftest`) / `coverage-zero`。其中 `coverage-zero` 被两处文件头显式「互让」掉（`gates/coverage.mjs:241` 与 `coverage-gate.test.js:24`），它**在** `verify:ci` 链上（第 12 步）但**不在** `REQUIRED_CI_STEPS` 的 11 条里 —— 从链上删掉它契约也不会报红。
- 另有 3 处「探针独有、测试段无兜底」的负向，是真单源收不了：`fixtures` 的 content-drift/missing（`fixtures.mjs:77-109`）、`dual-matrix` 的两条 covers 负向（`dual-matrix.mjs:124-175`）、`smoke` 的「转换核心被桩掉后冒烟必须非 0 退出」（`app.mjs:169-182`）。

### 四、判据 4 不能当支点 —— 核心修正

原设计以「**能否自己让 CI 变红**」为整套划分的支点，声称可无主观取舍地拆 `test/common/` 与 `test/tools/`。实测它在 `test/common/` 上**退化为平凡判据**：

- 19 个文件**无一**自己 `exit`；**无一**被 `package.json` 直接调用（`package.json` 对 `test/` 的引用只在 `:41 :42 :44 :46`，指向 `test/tools/*` 与 `acceptance.mjs`）。
- 判据两条正面判据全不满足、反面全满足 ⇒ 19/19 落在同一侧，等价于「整个目录该搬走」，**无法支撑 8/11 的内部切分**。而 8/11 只能来自读文件头注释语义，正是原设计自己承认没有反向证据的路径。
- 这是循环论证：判据的立论基础是「9 条跨树 import 全指向纯机制」，而那 9 条实际只落在 `test/common/` 的 3 个文件上（另 6 条在 `test/tools/geometry/`）。
- 唯一真边界：`segment-host.mjs` —— 全目录唯一自己会 `exit` 的模块，但不由 `package.json` 调用，只由 `runner.js:402` 派生。判据的「自己会 exit」这一支没有约束「exit 的码被谁消费」。

**替换判据**：`test/common/` 里真正跨树的只有 3 个（`entry-guard.mjs` ← `check-geometry.mjs:96`、`copy-closure.js` ← `check-temp-cleanup.mjs:77`、`userdata.js` ← `smoke-proc.mjs:25`，另 `entry-guard.mjs` 还被 `test/tools/visual-check.mjs:39` 复用），其余 16 个零跨界证据。按「**是否存在来自 `test/` 目录树之外的 import**」这条单一可 grep 的事实重判 → **3 进 `shared/`，16 留测试树**。

这个替换的额外好处：新判据与边界规则（机制 C）是**同一条事实** —— 判定与执行合一，不再是两套东西。

顺带修正 `test/tools/` 的去向：`visual-preload.cjs` 被 `scripts/geometry/driver.mjs:39` import，按新判据它也是跨树的，不能只当「人工工具」。

### 五、`check-docs.mjs` 不构成第 7 处枚举

原设计担心它是第 7 处顶层枚举点。实读不成立：全文件 73 行、**零硬编码清单**，纯委托执行全局配置仓的 `tools/check-pointers.mjs`。它报告的「23 份 / 50 份」扫描面在**配置仓**，属于配置仓的枚举面，与本仓「顶层自描述」不是同一个清单。**6 处这个计数在本仓范围内站得住。**

## 修正后的目标态

划分判据从「退出码消费」换成「跨树 import 事实」；结构其余部分不变：

```
src/       产品代码（8 条机械规则不变，不在本需求范围）
test/      断言产品行为。segments/ main/ renderer/ 保持扁平（是被守卫的属性）
gates/     断言仓库/产物/流程状态 —— 今天的 scripts/ 主体，按域分子目录
           repo/ artifacts/ coverage/ fixtures/ geometry/ supply/ smoke/ probe/
shared/    纯机制，零出边。paths · userdata · temp-resource · copy-closure ·
           entry-guard · geometry/{core,spec,page}
```

`shared/` 不是凭空造的层 —— **现状已隐含存在它，只是没名字**，证据就是那 9 条跨树 import 全部指向纯机制。补上名字，双向依赖一次归零。

三个机制：

- **A 顶层自描述**：单源从 `readdir` 派生顶层类型分类 / 测试扫描面 / 门禁注册表；6 处枚举改派生；`MIN_SCAN_FILES=50` 的**下限**语义换成**声明数 == 实测数**的等式（下限永远抓不到「漏扫一个子目录」）；`PROTECTED_SEGMENTS` 转 fail-closed。门禁注册表须覆盖**两条调用路径**（npm script + workflow 裸调）。
- **B 门禁统一协议**：门禁导出 `check(ctx): Problem[]`（零 IO、ctx 注入），三种驱动器（CLI / 沙盒探针 / 验收段）消费同一份逻辑。差异是**驱动器**不是**机制**。探针从 opt-in 变必填属性 —— 先补 7 项缺口，再谈必填化。
- **C 边界规则升 5 条**：`gates/**` 只能 import `gates/` `shared/` `test/fixtures/`（只读）；`test/**` 可 import `dist/` `shared/` `gates/`；`shared/**` 零出边；禁自算根路径。判红机制零新建 —— `test/segments/import-boundary.test.js:560` 已在造假源码喂给 boundary 判红。

**依赖拓扑**：`#03`→`#04` 消费 `#01` 建立的路径单源；`#05`→`#06`→`#07` 串行。步序与泳道见 `docs/PLAN.md`。

## 一处尚未闭合的缺口

现状只断言 asar **产出后**的顶层三项（`check-asar-manifest.mjs:45`），**没有断言 `build.files` 白名单里的项与实际目录一致**。目标态应补这一条 —— 「显式白名单」这个正确选择只做了一半。

注：`check-asar-manifest.mjs` 曾有一处只改门禁未改配置的半成品（把 `.map` 排除从 dist 侧扩到全包，但 `package.json` 的 `build.files` 仍只有一条 `!dist/**/*.map`）。已由 `7eae894 (REQ-108)` 补完 —— `build.files` 现为两条负向 glob（`!dist/**/*.map` 与 `!node_modules/**/*.map`），与门禁口径一致。本需求开工时该处不再是缺口。
