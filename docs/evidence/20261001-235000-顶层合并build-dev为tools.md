# 顶层合并：build/ + dev/ → tools/，工具函数下沉 shared/（REQ-144 方案原文）

## 起因

顶层六棵树里，`build/` 与 `dev/` 是**唯二不建边界规则**的两棵，也是唯二「有跨树出边却无判据守护」的两棵。合并它们不是为了少一棵树，而是为了让这两棵树从「规则豁免的例外」变成「正常受管的一棵树」。

ADR-038 给这两棵树的定位是「**不产生断言**的产物生产与人工目检」。该定位对 `dev/` 成立，对 `build/` **不成立**——`build/clean-artifacts.mjs` 确实在断言仓库状态。

## 实测事实

### 一、`build/clean-artifacts.mjs` 是门禁，住在 `build/`

它的实际行为：

- 「生成目录清理（`clean:dist` / `clean:release`），**校验通过才删除**，exit 0/1」（文件头 `:3`）
- `assertMatchesBuildConfig` 把删除目标钉死在 `package.json` 的 `build.files` / `build.directories.output` 上，**配置迁移后不一致即拒绝执行**（`:14-15`）
- 保护区从实际顶层派生（`topLevel().cleanProtectedSegments`），并有两道**封闭**闸门：`--target` 只接受 `dist`/`release`/`all` 三个关键字，目标取自冻结的 `TARGET_DIRS`（`:44`），不来自调用方
- 有专属守护段 `test/segments/clean-artifacts-gate.test.js`（19 条断言，覆盖预演零删除、真实删除、幂等、参数面负例、打包配置不一致拒绝、保护区/上跳段/绝对路径守卫、删除失败退出码）
- 在 `verify:release` 链内（`dist` script 的首步）

即：它是仓库里**唯一会 `rmSync` 的脚本**，判定面二元，且判据完备。ADR-038 那句「不产生断言」在这一处与实现不符。

### 二、三条跨树出边，零判据

```
build/clean-artifacts.mjs:35        → gates/repo/repo-manifest.mjs        （topLevel，保护区派生单源）
build/copy-renderer.mjs:16          → gates/artifacts/check-dist-manifest.mjs  （借 parseArgs + isMainModule）
dev/renderer-coverage-report.mjs:30 → gates/artifacts/check-dist-manifest.mjs  （同一处借用）
```

这三条边**没有任何判据守**。ADR-038 的推理链是「不 assert ⇒ 无需约束」，而实际有边。

`gates/repo/check-import-boundary.mjs:876` 把 `build` / `dev` 与 `dist` 同组登记为 `TREE_BOUNDARY_LITERAL_PREFIXES`，注释原文：

> `dist` 是编译产物目录；`build` / `dev` 是门禁树按断言域分列出去的两棵产物生产树（不 assert 任何东西，故不建边界规则）—— 它们与 `dist` 同形：**被引用，不治理**。

`dist` 确实与它们同形（是输出，不是代码，可被引但自身无出边）。`build` / `dev` 不同形——它们是**有出边的代码树**。

### 三、`check-dist-manifest.mjs` 是伪装成门禁的工具库（本条的根本成因）

它导出 13 个符号，**25 个仓内文件从外部 import 它**，其中大半与 dist 清单无关：

| 外部 import 者 | 实际只要 |
| --- | --- |
| `build/copy-renderer.mjs` | `parseArgs` + `isMainModule` |
| `dev/renderer-coverage-report.mjs` | `parseArgs` + `isMainModule` |
| `gates/repo/check-import-boundary.mjs` | `parseArgs` + `isMainModule` |
| `gates/repo/check-pinned-actions.mjs` | `parseArgs` + `isMainModule` |
| `gates/repo/check-transform-dispatch.mjs` | `parseArgs` + `isMainModule` |
| `gates/smoke/check-build-fresh.mjs` | `parseArgs` + `isMainModule` |
| `gates/smoke/smoke-report.mjs` | `isMainModule` |
| `gates/artifacts/check-{asar,install-smoke,release,signature-status,unpacked-smoke}.mjs` | `parseArgs` / `isMainModule` / `toPosix` |

一个叫「检查 dist 清单」的文件被当成 CLI 工具库与路径工具用——这是三条出边中两条的**唯一成因**。

### 四、`test/` 确实消费 `build/`（合并时的连带面）

`test/segments/dist-manifest-gate.test.js:25` 直接 `import { copyRenderer } from "../../build/copy-renderer.mjs"`。这是 `test-stay-in-test` 的 allow 面里 `build` 与 `dev` 两个元素的**唯一实际使用者**（`dev/` 在 `test/` 侧零 import）。

## 方案

三步，顺序有依赖：③ 依赖 ①② 的产物，① 依赖 ②。

### ① 工具函数下沉 `shared/`

```
shared/cli.mjs    parseArgs · isMainModule
shared/fsx.mjs    toPosix · writeFileAtomic · hashBuffer · hashFile
```

`gates/artifacts/check-dist-manifest.mjs` 保留它真正的职责：`MANIFEST_SCHEMA` · `DEFAULT_DIST_DIR` · `DEFAULT_MANIFEST_PATH` · `collectFiles` · `buildManifest` · `serializeManifest` · `parseManifest` · `diffManifests` · `describeRoot` · `main`。

`shared/` 是机制层、零跨树出边（ADR-038/043 的 `shared-no-out-edge`），CLI 参数解析与文件哈希正是机制而非断言。**这一步独立成立**，且是 ②③ 的前提。

连带：13 个外部 import 改成引 `shared/cli.mjs` 或 `shared/fsx.mjs`。

### ② `clean-artifacts.mjs` → `gates/artifacts/`

它断言仓库状态、有守护段、在 `verify:release` 链内——按 ADR-038 的划分标准（层按**断言对象**分）它属于 `gates/`。

连带面（约 10 处）：

| 位置 | 改什么 |
| --- | --- |
| `package.json:87-88` | `clean:dist` / `clean:release` 两条 script 的路径 |
| `test/segments/clean-artifacts-gate.test.js:55,116,358` | 沙盒按 `build/clean-artifacts.mjs` 路径写副本（3 处） |
| 同上 `:60` | `USAGE_HINT` 的字面量 |
| 同上 `:642-643` | 断言 `pkg.scripts["clean:dist"]` 逐字等于 `node build/clean-artifacts.mjs ...` |
| `test/segments/contract-single-source.test.js:329-331` | 相对解析锚点注释与夹具（取 `build/clean-artifacts.mjs → ../shared/paths.js` 这条真实 import 作样本） |
| `test/common/temp-resource.js:14` / `test/renderer/version-chip.test.js:25` | 注释里的段名引用 |
| ADR-038 | 「`build/` 不 assert 任何东西」一句改为「产物生产与人工目检;`clean-artifacts` 是例外(断言打包配置)，已归 `gates/artifacts/`」——**部分取代** |

> 改法上，搬文件比留在原处好：搬完 `build/` 只剩两个纯产物脚本（`copy-renderer` · `svg-to-ico`），ADR-038 的分列意图恢复成立（无需为它开口子）。

### ③ `build/` + `dev/` → `tools/`

① 完成后 `copy-renderer` 与 `renderer-coverage-report` 的出边指向 `shared/`；② 完成后 `clean-artifacts` 的出边也指向 `shared/`（它本来就在 `gates/` 内）。**合并后 `tools/` 的跨树出边为零**，因此：

```
gates/repo/check-import-boundary.mjs
├── TREE_DIRS                          加 tools
├── TREE_BOUNDARY_LITERAL_PREFIXES     ['dist','build','dev'] → ['dist']
└── TREE_RULES                         加两条 allow-list：
      { id:'tools-stay-in-tools', scope:'tools', allow:['tools','shared'] }
```

`dist` 留在字面前缀组是对的——它是编译输出，可被引、自身无出边，**真同形**。

目标形态：

```
tools/
├── copy-renderer.mjs              拷 renderer 静态资源到 dist/renderer
├── svg-to-ico.mjs                 SVG → ICO
├── visual-check.mjs               视觉自查（ui:shots，644 行）
├── visual-preload.cjs             上面那个工具的主窗桩
├── visual-about-preload.cjs       关于窗桩
├── renderer-coverage-report.mjs   被 c8 排除层的只读覆盖率报告
└── setup-env.ps1                  一次性写 Electron 镜像环境变量
```

七个文件，无子目录——每个文件名自解释，且 `visual-*` 三个共享前缀表达了「必须深度相邻」这一 import 图看不出来的耦合（`dev/visual-preload.cjs:124` 已登记过这件事：从 `test/tools/` 深 2 层搬到深 1 层时才被发现）。

**「哪些脚本进 CI/release 链」这个信号不由目录名承载**，它住在 `package.json` scripts 与 DEV-GUIDE「门禁接入点」表两处。现状 `build/` 已经是混的（`icons` 纯本地、`clean-*` 在链内、`copy-renderer` 在 `verify:ci` 链内），目录名从未准确表达过它。

## 验证

- 开发回路：`typecheck` + `lint` + 纯文本门禁 `check:boundary` + `check:temp-cleanup` + 受影响段（`M2W_ONLY='import-boundary,dist-manifest-gate,clean-artifacts-gate,contract-single-source'`）。
- 提交前：`npm run test` 全量（动了 `eslint.config.js` 的 lint 面与门禁脚本扫描面，属 DEV-GUIDE「开发回路不得省全量」第 ① 类）。
- 完成判据：
  1. `grep` 证实 `tools/**` 对 `gates/**` 的 import 为零条；
  2. `check:boundary` 实跑绿，且**两条新增负向锚点**证明 `tools` 的 allow-list 会真判红（不是恒绿断言）；
  3. `check:temp-cleanup` 绿（`ROOT_COMPUTE_SCAN_DIRS` 改名后仍覆盖全部五棵树）。

## 不做的事

- **不改 `shared/` 的零出边定位**。ADR-043 已把「零出边」精确为「零跨树出边」（树内互依与 `node:` 内建放行）。① 新增的两个模块都只 import `node:` 内建，符合现状，无需修订 ADR-043。
- **不给 `tools/` 建子目录**。七个文件、名字自解释、无共同子域；造子目录是为不存在的分组服务。
- **不把 `svg-to-ico.mjs` 归到 `tools/` 之外**。它 24 行、两个专用依赖（`sharp` + `png-to-ico`）、纯本地、只服务一条 `npm run icons`——单文件职责留在平铺目录里最清楚。
- **不改 `src/` 与 `test/` 的任何东西**。本条只动顶层两棵树的归属与其边界规则；测试树内部的改造见 REQ-142 / REQ-143。
