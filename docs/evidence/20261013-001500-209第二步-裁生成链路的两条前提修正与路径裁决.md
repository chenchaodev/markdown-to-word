## 两条原意图被重验推翻

### 一、123 处 `fixtures = null` 不是死代码

原记录（ADR-062:309、台账标题）把 121/123 处空声明列为「无人读的死声明」。**实测不成立**：

- `check-image-digests.mjs:206-223` 的 `classifyFixturesDeclaration` 三档判定**已解耦**到新模块，但
- 对**真实 123 处**跑这条规则的**唯一执行点**是 `gen-fixtures.mjs:169`（`validateSegmentContract` 内）；自测里的调用全是 `{fixtures:null}` 这类**字面合成对象**，不读真实段
- `check-test-layout.mjs` 全文不读 `fixtures` 导出 ⇒ 无第二个门禁读它

⇒ 这些字面量是**每个测试段「本段无验收样例」的契约声明**（`validateSegmentContract` 的 `absent` 档：键缺失即判红）。删掉它们等于丢失该声明，且 `absent` 档会当场判红。**原记录建立在「没人读」的错误前提上**，本条不删。

### 二、它与生成器不可分离（拆进程不可行）

曾以为「删生成器」与「删 123 处」是两件独立的事。**实测耦合**：

- `gen-fixtures.mjs:380` `validateSegmentContract(seg.name, mod)` 的返回值直接决定 `:381-384` 是否 `continue`（跳过该段 ⇒ 不产出任何产物）——契约判红 = 该段产物面被跳过，二者是**前后置**而非并列
- `:385` `if (mod.fixtures === null) continue;` —— 产物面必须先读契约才知道产出什么
- 段 import（`:363`）与 electron mock 注册（`:262-268`）是两者共同前置 ⇒ 拆成两个进程会重复付出 import 全部 146 段的成本

⇒ 可行的最小粒度是「**拆文件不拆进程**」：搬函数，生成器 import 它。
