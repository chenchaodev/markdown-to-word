# 2026-10-13 data-i18n 属性通道校验门禁落地

REQ-235 的落地记录。**新会话改动本门禁前先读本文件与上引事实底账。**

## 一、做了什么

新建门禁 `gates/repo/check-i18n-keys.mjs`(判据面 `src/renderer/*.html`)，三件套
(本体 + `.selftest.mjs` + `.case-roster.json`)形态照刚落地的 `check-segment-contracts` /
`check-output-unwritable-registry`。判**每个 `data-i18n*="值"` 的值必须是 Dict 键**。

### 判据 A(主判据)

单个属性值依次过两关，任一不过即逐条点名 `文件:行号: 属性名=值 → <原因>`：

- **值域** `^[A-Za-z0-9_]+(\.[A-Za-z0-9_]+)+$`(`segment.leaf` 形态，至少一个点)。
  含空格 / 首尾空白 / 前导或尾随点 / 单段无点 / **空值**都判红。**空值不豁免**：
  `tByKey("")` 返回 `""`，`dom.ts` 把它直接赋给 `textContent` / `setAttribute` ⇒ 文案被静默清空。
- **字典成员**：值必须是 `Dict` 键集合的一员。字典外值运行期经回退链返回裸 key 本身。

### 判据 B(防空门禁：扫描面塌缩)

纯文本门禁最坏的失效形态是**恒绿**。故两条，均从**文件清单派生**、无写死数字下限：

- 扫到的 HTML 份数为 0 ⇒ 判红(树被搬空 / `SCAN_ROOT` 写坏)；
- **每个 HTML 文件至少一处 `data-i18n*`** ⇒ 某文件零命中即判红点名(新 HTML 忘了接入，或该文件扫描静默失效)。

另在 CLI 层加一道：字典键数切出 0 条 ⇒ 判红(`extractDictKeys` 的切片锚失配 ⇒ 空字典会把
**所有**属性误判红，与「真有字典外 key」混在一起；单独拦归因更干净)。

## 二、底账「未核实项」已闭合(本文件新增的唯一实测)

事实底账 §四.5 留了一问：「HTML 里是否有动态拼接的 `data-i18n` 值？」—— 那是底账**唯一**
的未核实项，若存在则静态扫不全。本门禁落地时**实扫闭合**：245 处属性值里 `${` 出现 **0 次**、
非字面量 **0 条** ⇒ **静态扫可全覆盖，不必为动态值设计豁免**。

实测规模(跑 `node gates/repo/check-i18n-keys.mjs`，绿)：

- `dict` 键数 = `Dict = keyof typeof dict`(`src/core/i18n/zh.ts`)，从源码切片枚举;
- `src/renderer/` 两个 HTML;属性出现总数与去重值数见该命令结论行(数字不在此复述，随日常增删变)。

## 三、设计取舍(为什么这么做)

1. **读源码切片，不 `import` dict**。`import src/core/i18n/zh.ts` 需先 build，会给门禁加一道
   构建前置;切片(`const dict = {` … `} as const;` + 行首 `^\s*"<键>":`)零前置 ⇒ 可排在 `build`
   之前的静态门禁组内。`en.ts`/`ja.ts` 各自 `satisfies Record<Dict,string>` 锁全量，故只枚举 zh 键集。
2. **先剥 HTML 注释再扫**。`index.html` 有若干注释文本提到「不带 `data-i18n`」(说明性，非属性)；
   更重要的是防御未来的 `<!-- 例:data-i18n="x.y" -->` 文档示例——注释不是渲染属性。
   剥注释**保留换行**，故行号不错位(行号是「点名第 N 行」的前提)。
3. **不用 `shared/copy-closure.js` 的 `lexSource`**：它抹的是 JS 行注释与块注释，
   **不认 HTML 的 `<!-- -->`**；且它把属性值标进 `inString` 掩码，那对「抽 JS import specifier」是
   对的，对「读 HTML 属性值」反而把目标遮住。HTML 注释用本门禁内的 `blankHtmlComments` 抹。
4. **不反向判「死键」**:静态 key 大量由 `settings-panel.ts` / `dialogs.ts` / `book-wizard.ts` 经
   `t()` 用,死键判据面横跨 TS 与 HTML,属另一条工作线,不在本门禁。
5. **上链**：`check:i18n-keys` + `check:i18n-keys:selftest` 进 `verify:ci`(插在
   `check:html-const-mirror` 之后,与它同为「读 renderer HTML 文本」的静态门禁组,均在 `build` 之前)。

## 四、与警告通道的对照(为何不并入 06b)

同源但不同解法:警告通道(`KeyedWarning.key`)是 TS 类型问题,已收窄为 `WarningKey`;
`data-i18n` 通道的属性值写死在 HTML 里,不在任何 tsconfig 编译面内 ⇒ `Dict` 类型约束不到它,
只能做「扫 HTML 文本」的门禁。故独立成一道,不并进类型修复。
