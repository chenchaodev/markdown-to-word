# `wc -m` 字节陷阱与规则文件瘦身、台账归位

## 一、`wc -m` 在本机返回字节数，把「余量」误读成「超限」

上一轮改完指针后报出「`AGENTS.md` 2958 字符，超其自订的 ≤2500 上限 458，建议提请扩容」。**该结论是错的。**

本机 locale 未设（`LANG` / `LC_ALL` 均空），此时 `wc -m` 退化为返回**字节数**：

```
wc -c  = 2978   (字节)
wc -m  = 2978   (locale 未设 → 同字节数,不是字符数)
wc -L  = 425    (最长行字节)
```

按 UTF-8 解码后实际字符数远小于字节数 —— 中文一字三字节，2978 字节对应的字符数不足其半。照 `wc -m` 的读数判断，会把「余量」报成「超限」。

**已在载体里补上这一条**：`AGENTS.md` 的容量条目现在自带「本机 `wc -m` 在 locale 未设时返回的是字节数」的提醒，并写明正确量法。理由是这条规则**自带一个会骗过执行者的测量陷阱**，而执行者正是唯一会去量这个文件的人 —— 属于该留在载体里的异常处理，不该只躺在证据里。

## 二、规则文件瘦身：可删的历史极少

按「不保留历史，只保留规则 / 为什么 / 异常如何处理」逐行核过，结论是这份文件**本来就没有多少历史可删**。逐条判定：

| 内容 | 判定 |
|---|---|
| `(勿回退 md-to-pdf)`、`(勿用 27 alpha)` | **勿回退标注** —— 全局三.2 明令不得擅动 |
| `(勿升 15,tasklist peer 冲突)` | 这是**为什么**，属要保留项 |
| ②「旧日志载体 LOG.md 与 `docs/large/` 已取消」+ ADR 指针 | 「已取消」是规则（别重建），ADR 指针是**为什么** |
| `(CI 不需要)`、`(npm 警告 + electron-builder 读不到)` | **异常处理**与**为什么** |
| `(原独立状态文件已撤销)` | 唯一名副其实的历史残留 —— 既非规则也非为什么 |

实际只删了 11 字（`AGENTS.md:12`「原独立状态文件已撤销」→「勿再新建独立状态文件」，规则一字未损），版本随之推到 v2.3。

**若当初按误报的「超 458」去大砍，被削掉的会是上面那些规则与「为什么」** —— 那才是真损失。误报比超限更危险。
