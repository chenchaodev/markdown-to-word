## 一、这条为什么不是「补一个判据」

ADR-062 上表 L1 的字面口径是「每个镜像源模块有 `test/**/<m>.test.js`，或在 `gates/repo/test-exemptions.json` 登记」。开工前重验的实测把这条口径的性质改了：

| 口径 | 定义 | 实测 |
|---|---|---|
| A（路径镜像） | `shared/mirror-path.mjs` 的 `mirroredSourceOf()`：段路径镜像真实源 | `src/**` 模块样文件 **163** 个 · 有镜像段的 **4** 个 · 无段无豁免 **159** 个 |
| B（实际被测） | 某段 import 到的 `dist/**` 产物反推回源 | 无任何测试到达的模块 **84** 个 |

**146 段里只有 4 段按路径镜像真实源。** 所以字面口径做成 fail-closed，等价于先做一次 159 段的测试补齐工程（或写 159 条豁免理由）—— 这不是一条门禁工作项的量级。而 ADR-062 第 1 条（6 拆 3 合）那条主线正是被 L1 当前置押后的：**前置若要求 159 段，主线永久死锁**。

⇒ **2026-10-14 用户裁决**：改弱形态「**源模块须有交代**」—— 被测试实际到达 **或** 在豁免表登记，两向对读。

## 三、本次真正的裁决：「什么算到达」必须与 C1 同口径

判据落地时出现一个分叉。门禁侧初版按「扫全部 `test/**` 且**含 type-only 引用**」判定到达，好处是基线更小；**否决**，改为直接复用 `check-test-layout.mjs` 的 `isSubjectImport`（解析后落在 `dist/**` 的**值**引用）。

否决理由三条：

1. **诊断输出会因此失真。** ⑰ 族的结论行字面写「已被 test/ **实际到达** N 个」。只靠 `import type` 才被提及的模块，**任何测试从未加载过它**，计进去那句话就是假的。**一个把未加载模块报成「实际到达」的门禁是假绿** —— ADR-062 判 L11 的 basename 口径为假绿，用的是同一个理由。
2. **可见性反了。** 那批模块在 B 口径下被判为「已到达」⇒ **不入表** ⇒ 在表里完全不可见；A 口径下它们进表、带 `category` 与理由，才是可见的。而这道门存在的理由恰恰是体量可见。
3. `isSubjectImport` 排除 type-only 的**理由不因族而异**（type-only 是编译期擦除的类型标注、不是取得被测对象的手段）。它虽标着「C1 的单一定义」，但理由是通用的；两族各持一份定义，那条理由迟早在某一族上被重新解释一遍。

**留下的最大收益**：本文件里「什么算被测 import」只有一处定义（`isSubjectImport`），⑰ 族通过调用它使用。`grep` 可验：`startsWith(DIST_TREE)` + `!typeOnly` 这一对只出现在 `isSubjectImport` 本体一处。

**两个维度是正交的，只对齐了后者**：① **扫哪些文件** —— `test/**` 的**全部**文件，不只 `.test.js` 段（段经 `test/harness/**` 等非段支持文件间接到达被测对象是既有形态，只扫段会把「经助手到达」误判成「没有交代」）；② **什么算到达** —— 值引用。

## 四、基线 84 条的构成（其中一个数字不能照抄）

| 类别 | 条数 | 含义 |
|---|---|---|
| `no-test-yet` | 75 | **无任何引用** —— 测试面上完全没人提到它 |
| `type-only-module` | 4 | 全部引用都是 `/** @typedef {import(…)} */` 之类，运行期从未加载 |
| `indirect-load-not-visible` | 5 | **运行期确实加载过**，但走 `await load(…)` / `await import(distUrl(…))` 这类间接动态 import，静态抽取器看不见 |

`indirect-load-not-visible` 是这次新增的分类值，**它与 `type-only-module` 必须分清**：那个说「没有任何测试在运行期加载过它」，这个说「**加载过**，但那条路径对静态抽取器不可见」。两者处置也不同（前者补测试；后者把间接动态 import 改成静态可见形态）。把两者并成一个值，等于让表里出现「说测试没加载过它、而它其实被加载过」的条目 —— 与本门禁「体量可见**且**陈述为真」的存在理由相反。

⚠ 实施泳道最初把 9 条差额全按 `type-only-module` 归类，**拒绝照单全收**并逐条核了全部引用形态，发现其中 5 条是间接动态 import 加载的。**这是「表里的陈述必须为真」这条判据的实际兑现** —— 若按原计划贴分类，豁免表自己就带进了 5 条假陈述。

⚠ 上表三个数字是 2026-10-14 的取值，**不是当前值**。实时构成取 `node gates/repo/check-test-layout.mjs` 的结论行。

## 五、本次暴露的既有缺口（已另立号跟踪）

`extractImports` 的动态 import 正则是 `/\bimport\(\s*['"]([^'"]+)['"]\s*\)/g` —— **只认字面量参数**。`await import(distUrl("…"))` 的参数是调用表达式、`await load("../../dist/…")` 是自定义包装，两种都看不见。

⚠ 这是**既有**缺口，不是 REQ-196 引入的，**且同样落在 C1 的分母上**。本次只是第一次把它暴露出来。处置两条待拍板：① 教抽取器穿透包装形式 —— 但 `extractImports` 是 C1 / L4 / C3 / L6 / L8 共用的共享原语，改它会同时移动若干既有分母，必须单独一批并做前后分母对拍；② 或把测试侧的间接动态 import 收敛成静态可见形态（不动门禁）。见 `docs/REQ.md` 对应号。

## 六、主会话收尾时拆掉的一颗埋雷

## 九、REQ-242 的处置裁决（2026-10-14）

第五节那个抽取器缺口已拍板：**走路线②（收敛测试侧写法），否路线①（教抽取器穿透）**。

### 裁决推翻了主会话提的一个假设

主会话在派侦察前的原话是：「`session-persist-feedback.test.js` 里的 `await load(…)` 很可能是为了**绕过 ESM 模块缓存**，把那种形态改成字面量 `import(…)` 会命中缓存、直接把测试语义改坏 —— 那就不是零风险的第一刀。」

**这个判断是错的。** 实测：三个包装函数（`distUrl` · `load` · `path.join(ROOT,…)`）**全都没有缓存语义**，是纯路径拼装器，把仓内相对路径变成 `file://` URL 字符串。全仓 `test/**` 里不存在任何 `delete require.cache` / `?v=` / `Date.now()` 拼 URL 的击穿。真击穿只有两处，形态完全不同且都不在本题 5 个模块之列：`test/harness/settings.js:48-56` 与 `test/main/ui-state.test.js:65`（`?tag=` / `?case=` 拼 query）。

**推翻它的证据方向反而对路线②有利**：`focus-return-guards.test.js:127-130` 与 `session-persist-feedback.test.js:242-245,419` 两段各自写了「排空焦点栈」与「存快照复位」代码，段头注释明写它们依赖**模块实例被复用**（`dist` 模块在一个进程内只 import 一次，焦点来源栈是模块级单例，不排空就会取到别人的条目）。**若真改成每次全新实例，这些复位代码反而失效** —— 复位的是旧实例，新实例带着初始态。⇒ 现在就没有隔离可破坏。

### 真正的约束是加载时机，不是缓存

`session-persist-feedback.test.js:381-382` 的自陈注释：「状态元素取自 refs 模块自身：同进程内前序段可能已加载过该模块（元素绑定在当时的 document stub 上），读自己的 stub 会与被测模块脱节」。`src/renderer/dom/refs.ts` 在**模块初始化期**抓 `document`，而 `installDomStub` / `setGlobalSlot("document")` 都在其之前执行。

⇒ **改法与「改成静态 import」恰好相反**：静态 `import` 会把加载提到 stub 安装之前、直接跑不通；正确改法是**保持 `import()`、只把说明符换成字面量**（`await import(distUrl("x"))` → `await import("../../dist/x")`）。字面量与包装式解析到同一绝对 URL ⇒ 同一模块实例 ⇒ 零语义差。

### 为什么否掉路线①

1. 它要求抽取器开始**求值**：跨过程常量折叠（两个 `distUrl` 基址派 —— `dist/` 与 `dist/renderer/` —— `settings-controls.test.js:304` 还有 `const dist = (rel) => distUrl(rel)` 二级别名），以及 `session-persist-feedback` 里与 `distUrl` 基准不同的第二个基准（段文件自身目录）。本文件 `:1746-1749` 对 `covers` 明写既定取舍：**「刻意不解析变量引用……判据看不懂的写法按未声明处理，不在这里猜」** —— 路线①必须在头注显式推翻这条取舍。
2. **它永远解不出形参**：`test/renderer/wizard-deps.js:28-35` 与 `convert-flow-deps.js:26` 是 `${prefix}` 前缀参数化，任何窄模式都解不出前缀的两个实参值 ⇒ 即便做完美，`settings-save.ts` 与 `settings-bindings-preset.ts` 仍不可见（实测无其他加载点）。
3. 侦察实测：窄模式可覆盖到 **17/19** 个模块，但这 17 条经 `fileExists` 过滤后**全是真边、无一条假命中** —— 也就是说误报风险低**只依赖「当前用法单一」这一偶然事实**，而门禁是 fail-closed 的，这个偶然性没有机器守护。

### 范围取最小切口，不做全量清扫

侦察普查的规模：可字面化 **61 处**（`import(distUrl(字面量))` 43 + `path.join(ROOT,…)` 7 + `load(相对字面量)` 11）· 参数化 **9 处**（改结构才能解）· 真缓存击穿 **2 处**（**必须保留 query，改了就失去存在理由**）· 字符串内与段装载 **13 处**（不在范围）。

最小切口 = 改 **4 处**即可摘掉那 5 条 `indirect-load-not-visible` 表项（⑰ 族已到达数 79 → 84，表 84 → 79）。全量清扫则 79 → 96、表 84 → 67，且**不新增任何债**（那 12 条转 stale 的表项删掉即 ratchet 正常收益，`_baseline` 冻结清单按设计不动）。

**本次取最小切口**：REQ-242 登记的文本就是那 5 个模块；61 处全量清扫 + 8 条 L5 豁免补录是另一件事的量级，不塞进这一条。

### 两条路共有、必须一并处理的隐藏成本

这些 import 一旦变可见，**L5 会新增跨层边且不在豁免表里**（L5 已转 fail-closed ⇒ 不补 ≥20 字理由的表项就是红）。侦察列出 8 条，跨 4 个段（`session-persist-feedback` · `settings-controls` · `ui-interaction-guards` · `wizard-open-sync`），目标都是 `dist/core/i18n/index.js` 与 `dist/core/settings/settings-defaults.js` 这类 core 资产。

⚠ **实施时不要照抄「8 条」这个数**：侦察的最小切口段落自述「C 组 11 处里有 3 处是 `dist/core/**`，所以 L5 补录不可省」，但它同时列的 8 条边横跨 4 个文件，而最小切口只改 `session-persist-feedback` 的调用点。**到底补 2 条还是 8 条，必须实测差集，不得照抄**。

#### 实施结果（2026-10-14，最小切口实测）

改 **4 个模块点 / 2 个文件**（`session-persist-feedback.test.js` 里 `file-list` · `convert-flow` · `recent-files` · `first-run-guide` 共 5 处，`wizard-open-sync.test.js` 里 `book-wizard` 1 处）。同段里的 `state` / `settings-panel` / `settings-drawer` 与两处 `dist/core/**`（`i18n/index` · `settings/settings-defaults`）**一律未动** —— 它们不是本条目标，且动了会把 core 资产变成跨层边。

| 读数 | 改前 | 改后 |
|---|---|---|
| ⑰ 已被 test/ 实际到达 | 79 | **84** |
| 豁免表条数 | 84 | **79**（删掉 5 条 `indirect-load-not-visible`，残留 0） |
| 表分类构成 | 75 baseline + 4 type-only + 5 indirect | **75 baseline + 4 type-only** |
| `_baseline` 冻结清单 | 75 条 / 2026-10-14 | **75 条 / 2026-10-14（未动）** |
| L5 跨层命中 / 豁免 / 未登记判红 | 28 / 27 / 0 | **28 / 27 / 0（实测零新增）** |

**L5 实测差集为零 ⇒ 侦察那句「L5 补录不可省」在最小切口下不成立。** 机制清楚：那 8 条边要变可见，前提是加载 `dist/core/**` 的调用点本身被字面量化，而最小切口刻意不碰它们。**这是「先实测差集再决定」的实际兑现** —— 若照抄 8 条补豁免，会造出 8 条指向并不存在的跨层边的假表项。

三条自证（各贴输出）：

- **ratchet 自证**：把 `recent-files` 那一处改回 `await load(…)` ⇒ 门禁立刻判红 `recent-files.ts → src-module-unaccounted: … 它在测试面上**没有任何交代**`（exit=1），逐字引用了本族自己的处置口径。⇒ **删表项正是让门禁反过来强制新写法的机制**；那 5 条若留着，改不改都绿，这条 ratchet 就白做了。
- **同实例自证**：5 处逐一比对「旧 wrapper 解析出的绝对路径」与「新字面量解析出的绝对路径」⇒ 全部同一文件 ⇒ 同一模块实例（缓存键不变）。`focus-return-guards` 的排空焦点栈与 `session-persist-feedback` 的快照复位这两个依赖实例复用的金丝雀随之全绿。
- **五段实跑**：`M2W_ONLY=session-persist-feedback,focus-return-guards,ui-interaction-guards,wizard-open-sync,convert-command-lock npm test` → **110 case 全绿**。`lint` / `typecheck` exit 0。

⚠ **过程中一个自己的错，值得留档**：做同实例校验时，我把 `load` 的基准误当成 `ROOT + dist`，脚本于是报「URL 不一致」五条全红，差点得出「改写有问题」的错误结论。实际 `load` 的定义是 `path.resolve(here, rel)`（基准 = 段文件目录），与新字面量说明符**同一基准**。⇒ **wrapper 的基准必须从它自己的定义读，不能从名字推断** —— `distUrl` 用 `ROOT/dist`，`load` 用段目录，同一个文件里两种基准并存。
