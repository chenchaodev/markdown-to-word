# 门禁扫描面把 `test/common/*.mjs` 漏在盲区（REQ-146 取证）

## 现象

两道文本门禁 —— `check-test-numbering`（测试树规划编号）与 `check-temp-cleanup`（临时目录删除收口）—— 声明自己只扫 `test/common/**/*.js`。而该目录下确实有 `.mjs` 文件，落在扫描面之外。

取当前文件名：

```
grep -lE '\.mjs$' test/common/*.mjs
```

## 为什么早该被发现：声明面与实测面本就矛盾

`shared/test-common-surface.js` 里有两个判据同时存在：

- **声明面** `SCAN_TARGETS`（`:65-68`）：逐目录手写「文件判定」谓词。它是两道门禁真正消费的清单。
- **实测面** `SOURCE_FILE_RE = /\.(?:js|mjs|cjs)$/`（`:80`）：回答「磁盘上哪些算测试源文件」，用于派生面与等式判据。**它含 `.mjs`**。

同文件、同一个「什么算测试源文件」的知识，一处认 `.mjs`、一处不认。注释只解释了「谓词按目录手写」的来由（`:27-30`），**从未论证过 common 为什么排除 `.mjs`**。

## 判定为遗漏而非设计的证据链

1. **同期存在过一条明确接受 `.mjs` 的兄弟谓词。** 扫描面单源化那次（`git show 1a0a069`）两条并列：`{dir:"test/common", accept: endsWith(".js")}` 与 `{dir:"test/tools", accept: /\.(js|mjs)$/}`。后一条被 `ADR-051:57` 当「代价」记录后删除（目录本身已不存在）。⇒「门禁扫描面接受 `.mjs`」在本仓是**已知且认可**的形态。
2. **谓词从未随目录内容变化更新。** `.js` 那行自单源化起未动，而那些 `.mjs` 是之后才加入的。
3. **全仓无一处记载。** `ADR-037`（单源化）、`ADR-051`（删 `test/tools` 谓词）、`docs/DEV-GUIDE.md`、`docs/REQ.md`、evidence 全部无命中。本仓对这类差异的记载密度极高（ADR-051 即为一例）；若是有意，必留痕。

## 先被证伪的一个怀疑

怀疑方向原是「这三个文件漏标 `// @ts-check`，覆盖声明与门禁扫描面脱节」。**不成立**：

- `test/core/tscheck-coverage.test.js` **不使用 `SCAN_TARGETS`**，自建 walker 走 `test/` 全树，扩展名判据 `/\.(js|mjs|cjs)$/`（`:37`、`:65-77`），无目录排除。
- 那三个 `.mjs:1` 均已带 `// @ts-check`，且已在 `tsconfig.test.json` 的 program 内、也被 eslint 覆盖。

⇒ 类型与 lint 两面**无缺口**，缺口只在两道文本门禁的扫描面。顺带排除一个连带猜测：段发现面（`runner.js:187` 只认 `*.test.js`）本就不该收这些文件，不是缺口。

## 实际漏检后果

| 门禁 | 漏掉什么 | 后果 |
|---|---|---|
| `check-test-numbering` | 上述文件里写进字符串字面量的规划编号（`B1–B13` / `F1–F9` / `C1–C4` / `D-\d{2}` / `OPT-\d+` 等） | 门禁不判红。且这些是跨段复用的 harness 与桩件 —— 规划编号一旦泄漏，每个 import 它的段都读到，扩散面比单个段内泄漏更广 |
| `check-temp-cleanup` | 同文件里裸写的 `fs.rmSync(dir, {recursive:true})`，以及 `removeTree` / `removeFile` 第二实参的写法错误 | 门禁不判红。即「绕过收口助手直接递归删除」在 harness 层是检测不到的 |

## 修复

- `shared/test-common-surface.js:67` 谓词由 `endsWith(".js")` 改为 `/\.(?:js|mjs)$/`（与历史 `test/tools` 那条同形，便于对照）。
- 同文件 `:28` 文件头的复述字面量（`common 收 *.js` → `common 收 *.js 与 *.mjs`）同步 —— 留着旧说法会让同一文件自相矛盾。
- 两道门禁头的扫描面字面量同步：`gates/repo/check-test-numbering.mjs:19`、`gates/repo/check-temp-cleanup.mjs:20` 的 `test/common/**/*.js` → `test/common/**/*.{js,mjs}`。这两处是**复述**单源，必须跟着走。
- 谓词上方补「为什么」的注释，点明须与三处口径对齐：本文件 `SOURCE_FILE_RE`、`test/core/tscheck-coverage.test.js` 的 `SOURCE_EXT_RE`、`eslint.config.js` 的 `NON_PROGRAM_EXTS`。

未动：`EXCLUDED_DIRS`、`MIN_SCAN_FILES`、`SEGMENT_DIRS`、`isSegmentFile`、等式与镜像判据、两道门禁的 ALLOWLIST。

## 验证

四条单命令全绿：

```
node gates/repo/check-test-numbering.mjs
node gates/repo/check-test-numbering.selftest.mjs
node gates/repo/check-temp-cleanup.mjs
node gates/repo/check-temp-cleanup.selftest.mjs
```

谓词放宽的实际效果由前两条的输出自证 —— 扫描文件数增加，增量恰为那三个 `.mjs`（数值为可变数字，不在此抄落，取法见各门禁输出末行的「扫描 N 个文件」）。

ALLOWLIST 未因此变 stale：白名单条目按「文件 × 内容」匹配，放宽扫描面只新增命中面，不会让已命中条目变成零命中。输出里的「白名单条目本次零命中」提示属既有状态，未处理。

`npx tsc -p tsconfig.test.json` 通过。
