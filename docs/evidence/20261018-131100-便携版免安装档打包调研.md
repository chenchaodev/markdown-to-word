# 便携版免安装档 · 打包调研(issue #1 诉求 1)

> 来源:GitHub issue [#1 便携版及转换markdown代码为word内容到剪贴板需求](https://github.com/chenchaodev/markdown-to-word/issues/1),2026-10-16 提出。
> 取证方式:`explorer` 一条只读泳道 + `librarian` 一条(electron-builder 26.15.3 钉版源码);**承重结论由主会话在本地复核**(实读 `package.json` · 门禁 · workflow · `release/` 实盘 · `.gitignore`)。**未跑任何门禁链与构建**(门禁链由主会话收尾时统一跑)。

## 一、issue 里用户自问的问题(「WinRAR 解压安装包能否当便携版」)

**基本不能。** `release/MarkdownToWord-Setup-4.2.0.exe`(113.5 MB)是 NSIS 单文件,内部是压缩数据块,不是可运行目录树。真正「解压即用」的形态**在本机已存在**:`release/win-unpacked/`(含 `MarkdownToWord.exe` · `resources/app.asar` · `m2w.cmd`,实读确认)—— 但它**不在发布资产内**。

⚠ **未实测**:未实际用解压工具打开安装包核对内部结构(上述判断来自 NSIS 打包形态与 `package.json` 的 `nsis` 段配置,非解压实测)。

## 二、打包现状

- `package.json:128-172` 是 `build` 段**唯一配置源**(仓根无 `electron-builder.yml`/`.json`)。
- `win.target`(`:151-158`)**只有 `nsis` + `x64`**;无 `portable`、无 `zip`、无 `dir`。
- `artifactName` 只存在于 `nsis.artifactName`(`:169` = `${productName}-Setup-${version}.${ext}`)⇒ **新增 target 无命名模板**。
- `directories.output` = `release`(`:131-133`);`files`(`:134-142`)只收 `dist/**` + `package.json`;`asar` 键**不存在**(用默认 `true`);无 `extraResources`,只有 `extraFiles`(`:143-148`)把 `build-assets/m2w.cmd` 放安装根。
- **打包命令在 CLI 上又硬写 target**:`package.json:114` 的 `dist` = `… electron-builder --win nsis --x64 --publish never …` ⇒ 只改 `build.win.target` 会被这行盖掉,**必须同批改**。

## 三、发布链的「三处硬点名」(漏一处即红或缺件)

1. `gates/artifacts/check-release-artifacts.mjs:174-175` 期望集 = `installer + .blockmap + latest.yml` **恰好三件**;`:109-125` 的 `findForeignArtifacts` 对 **release 顶层任何带版本号且不在期望集内的文件直接判红**;`:189-196` 要求 installer 与 blockmap 存在且非空;`:245-256` 的 SHA-256 报告**对期望集循环生成**(故把 zip 加进期望集会自动进报告)。
2. `.github/workflows/release.yml:189-196` 的 `ASSETS` 同样硬点三件,缺一即 `exit 1`。
3. `package.json:114` 链内其余 `check:*`(`check:dist-manifest` / `check:asar` / `check:signature` / `check:unpacked-smoke`)**经逐条核对后确认与形态无关**(`check-install-smoke.mjs:255` 只读 `build.nsis.artifactName`;`check-unpacked-smoke.mjs` 只读 `release/win-unpacked`,zip 不会移除它;`check-signature-status.mjs` 只声明「不签名」)⇒ **这三处无需改动**。

**两条正面证据**:
- 体积门禁**已容忍无安装包形态**:`gates/artifacts/pack-size/contract.mjs:51-62` 的 `installer` 条目 `required:false`,注释原话「缺则告警不判红:**便携/dir 形态本来就没有安装包**」。
- 该门禁**不需要为 zip 新增条目**:`installer` 条目测的是「发布目录内体积最大的 `*Setup*.exe`」,且不枚举未知产物;zip 的内容即已被 `unpackedTotal` 跟踪的解包目录 ⇒ 不为 zip 新开条目(避免范围膨胀)。

## 五、语义分叉与选型(用户 2026-10-18 拍板)

| 档 | 手段 | 代码改动 | 设置落点 | 启动代价 |
|---|---|---|---|---|
| **(a) 免安装解压即用** ✅ 选定 | `dir` + `zip` | **零** | 仍写 `%APPDATA%`(与另两档无差别,见下) | 一次性解压 |

### ⚠ 一条被纠正的判断(留痕,防止后人重犯)

初版本文件写作「`portable` 仍写 `%APPDATA%`,所以不取」—— **`librarian` 查实这条理由并不成立**:`dir`+`zip`、`portable`、NSIS 安装版三者**都不改变 Electron 的 `userData` 位置**(默认 `%APPDATA%`),这是 Electron 应用层的行为,与 electron-builder 的 target 无关。⇒ **真正的区分理由是启动代价**:`portable` 的 `unpackDirName` 默认是构建期生成的 ksuid(或 `false` → 每次启动落 `$PLUGINSDIR`),**每次启动都重新解压**;zip 只在用户解压时付一次。**选型不变,理由换成这条。**

### electron-builder 26.15.3 的 zip target 事实(`librarian` 从钉版源码查实)

- `zip` 是合法 win target(`scheme.json` 的 `WinBuildOptions.target` 枚举明列),落 `ArchiveTarget`;`dir` 是 `NoOpTarget`,产物只有解包目录。
- **二者不互斥**:解包目录由 `pack()` 无条件建立,再分发到各 target ⇒ `--win zip` 会**同时产出** `win-unpacked/` 与 zip。
- x64 下 zip **默认名** = `${productName}-${version}-win.zip`。
- **`win.target` 数组项里不能写 `artifactName`** —— `TargetConfiguration` 的 schema 为 `additionalProperties: false`(仅 `target` / `arch`),且 26.15.3 **不存在 `build.zip` 配置段**;覆盖链是 `config[<target>].artifactName` → `build.win.artifactName` → `build.artifactName`。
- 加 `build.win.artifactName` **不影响 nsis**:nsis 有自己显式的 `build.nsis.artifactName`,在覆盖链上优先级更高。
- CLI 多 target 合法(`--win nsis zip --x64`);`--publish never` 保留无害。
- Windows 的 zip 内部**不带外层目录**(`withoutDir = !isMac`),「解压即用」语义成立;`process.resourcesPath` 与 `asar` 均与 target 无关。
- 门禁侧的 `expandArtifactName` **只支持 `productName` / `version` / `ext` 三个占位符** ⇒ 命名模板不得引入新占位符。

⇒ **本步的命名决定(主会话拍板)**:新增 `build.win.artifactName` = `${productName}-Portable-${version}.${ext}`,产物名形如 `MarkdownToWord-Portable-4.2.0.zip`。理由:门禁与 workflow 都能用**同一个**模板展开(不复制 electron-builder 的默认公式),且名字自解释「便携版」。`artifactName` 不含 `%APPDATA%` 之类的路径语义,它只是文件名模板。
