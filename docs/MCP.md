# MCP 接入

本程序提供一个 [MCP](https://modelcontextprotocol.io) 服务端，让支持 MCP 的 AI 助手（如 Claude Code、Cursor、Cline 等）直接把 Markdown 转成 Word，而不必把文件内容粘贴进对话。

> **前提**：服务端需从源码检出运行，需要 Node.js >= 22.13 与已装齐的依赖，使用前先完成构建（见 [开发者手册](DEV-GUIDE.md) 的「命令」节）。Windows 安装版程序不含该服务端。

## 快速开始

在助手的 MCP 配置里加一段，然后重启助手：

```json
{
  "mcpServers": {
    "markdown-to-word": {
      "command": "node",
      "args": ["<项目路径>/dist/mcp/index.js"]
    }
  }
}
```

`<项目路径>` 填本程序在磁盘上的位置（含 `dist` 那一级的上一层）。配置完成后，助手的工具列表里会出现 `convert_markdown`。

启动后服务端会往标准错误写一行启动提示，这是正常的；协议本身走标准输入输出。

## 能力

服务端只提供**一个**工具：

### `convert_markdown`

把 Markdown 转成 `.docx`。

| 参数 | 必填 | 说明 |
|---|---|---|
| `input` | 是 | Markdown 文件的**绝对路径**，或包含 `.md` / `.markdown` 的目录绝对路径。目录会被递归收集 |
| `outputPath` | 否 | 产物的完整绝对路径。只能配单个输入文件。路径已存在时本次调用失败，不会改名 |
| `template` | 否 | 内置排版预设 id，取值见 [命令行用法 · 内置排版预设](CLI.md#内置排版预设)。省略则使用默认排版 |

`outputPath` 的限制与命令行入口的 `-o` 相同，理由也一样：调用方点名要的就是这个路径，改名会让按固定名取产物的脚本取不到。

## 返回值

每次调用返回一个结果对象：

```json
{
  "artifacts": [
    {
      "input": "/abs/path/笔记.md",
      "outputPath": "/abs/path/笔记.docx",
      "warnings": [],
      "degraded": ["mermaid"],
      "elapsedMs": 118
    }
  ],
  "degraded": ["mermaid"],
  "elapsedMs": 118
}
```

| 字段 | 说明 |
|---|---|
| `artifacts` | 每个产物的明细 |
| `artifacts[].input` | 输入文件的绝对路径 |
| `artifacts[].outputPath` | 产物的绝对路径 |
| `artifacts[].warnings` | 警告标识列表 |
| `artifacts[].degraded` | 本项发生的降级，没有则为空数组 |
| `degraded` | 全部产物的降级并集，供助手一眼判断 |
| `elapsedMs` | 本次调用总耗时（毫秒） |

目录输入时，`artifacts` 每项对应一个产物文件。

## 降级：Mermaid 图表

**服务端没有图表渲染宿主，` ```mermaid ` 围栏会按等宽代码块写入 Word。** 这属于功能降级，因此会被**明确写在返回值里**——`degraded` 字段出现 `"mermaid"` 就表示这份产物里的 Mermaid 图是代码块而非图形，`artifacts[].degraded` 逐项标出，`degraded` 是全部产物的并集。

这样设计是刻意的：如果助手拿到一份「有图无图全看运气」的产物，同样的输入可能产出不同结果，助手就无法据此判断自己的回答是否可信。降级可见，助手才能决定是否提示需要人工补图，或改用图形界面转换。

不含 Mermaid 的文档不会出现在 `degraded` 里。

## 失败与重试

| 情况 | 助手看到什么 |
|---|---|
| 参数有问题（缺 `input`、路径不是绝对路径、路径不存在、目录里没有 Markdown、`template` 不存在） | 工具返回失败，附带可读的说明 |
| 转换失败（源文件过大、渲染出错等） | 工具返回失败，附带错误原因 |
| `outputPath` 已被占用 | 工具返回失败，说明该路径已存在 |

**参数类错误都在返回值里，不中断会话。** 助手可以据此改参数重试，例如把相对路径换成绝对路径，或换一个产物路径。只有协议层面的问题（比如调用了不存在的工具）才会中断。

「未知预设」的报错会列出全部可用预设 id，助手据此即可自行纠正。

## 行为说明

**只产出 Word。** PDF 打印依赖桌面宿主，服务端运行在纯命令行环境下，因此不提供 PDF。

**不渲染 Mermaid 图表。** 见上一节。

**单次调用有 120 秒的上限。** 超时按取消处理并返回失败。命令行入口不设这个上限（等多久由人决定），但 AI 助手不会主动中止一个卡住的调用，若不设上限，一次卡死会拖住后续所有调用。

**不读界面里的设置。** 助手调用的排版完全由本次参数决定，跨会话可复现。

**产物同名时自动改名。** 未指定 `outputPath` 时，若目标位置已有同名产物，会写成 `笔记 (2).docx`，不覆盖既有文件——这与图形界面一致。
