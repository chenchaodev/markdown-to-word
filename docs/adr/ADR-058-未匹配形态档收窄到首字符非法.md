# ADR-058 · 未匹配形态那一档收窄到「首字符非法」

| 项 | 值 |
|---|---|
| 状态 | 现行 |
| 日期 | 2026-10-02 |
| 取代 | [ADR-057](ADR-057-未匹配形态的指针自报一档.md) **决定一的分类口径**（该条「不扩 `REF_FORMS` 首字符集」与「只出声不判红」「零覆盖必须出声」仍成立） |

## 决定

**一、分类口径收窄为：剥掉开头的 `./` 或 `../` 前缀之后，首字符落在 `REF_FORMS` 首字符集 `[A-Za-z0-9_一-龥]` 之外、且整体形如「名字.扩展名」的反引号 / markdown 链接内容。**

**二、扩展名不再取「仓内实测枚举的那一族」—— 任何扩展名都算**（仍要求形如「名字.扩展名」，以免把纯符号数进来）。那张枚举表连同其取数命令一并删除。

**三、其余三条不变**：只出声不判红 · 零覆盖必须出声 · 措辞骨架与另两族平行。

## 背景

[ADR-057](ADR-057-未匹配形态的指针自报一档.md) 落地后，那一档在全仓分类出 **113 处**。实现方在交付时提出两条异议（其报告 ⑤1 / ⑤2），经**全量复核**后成立 —— 它当时只做了抽样。

**复核方法**：不经门禁内部实现，直接在仓内抽取全部「纯路径形态」的反引号 / 链接内容，按判定档同一套基准（引用方目录优先 → 仓根次之 → 无兜底）逐条解析。

| 量 | 值 |
|---|---|
纯路径形态候选 | 737 |
其中解析不到 | 347 |
其中 `.md` 且**判定档看不见**的 | **51** |

**那 51 条逐条看过，没有一条是本仓坏指针。** 它们分两类：

- **跨仓引用**：全局配置目录下的 WORKFLOW / REQ-RULES / DOC-SYSTEM / ENV-GUIDE / PUBLISH-GUIDE / CODE-GUIDE / tools/AGENTS 七份指南，以及本仓台账自身 —— 按 ADR-054 决定四与 ADR-053，这些在本仓本就不可达、不该改字面
- **记号与示例**：形如 sourcemap / tools / bar / PLAN 的派生名与示例文件名 —— 通配、派生名、以及文档里为了讲清问题而写的**示例文件名**

⚠️ 上面第一类那七个**故意不加反引号**：写成反引号形态时存在性档会当真指针去判，而它们在本仓不可达 —— 那正是本 ADR 要记的那类噪声，**记它的时候不能自己制造它**。

**首字符分布给出了收窄的依据**：那 347 条里绝大多数首字符**都在允许集内**（`c` 99 · `s` 49 · `t` 30 · `d` 20 · `p` 19 · `m` 14 …）。真正非法的只有 `-` 开头的 3 条（`.` / `/` 开头的那 20 条剥掉相对前缀后即合法）。

⇒ **113 处的噪声不是来自「首字符非法」，而是来自「扩展名不在册」** —— 而后者这一族并不独享：ADR-055 决定一已经单立了「代码扩展名引用」那一族管 `.mjs` / `.ts` / `.js` / `.cjs`，实现侧也已做逐字去重。本族多出来的是图片、配置、脚本一类，而这些在本仓大量以**记号**而非指针形态出现。

⇒ **本族真正在守护的洞只剩「首字符非法」一条。**

## 备选方案

| 方案 | 为何不选 |
|---|---|
| 撤掉这一档 | 成本归零，但 ADR-057 备选方案表最后一行「什么都不做」正是这个 —— 它已被否决。且 REQ-159 记的那个洞会重新变成隐形 |
| 保持 113 处的宽口径 | 实测 0 真阳性。成本是常驻的噪声 + 一张需人工同步的扩展名枚举表（第五处无机器对读的差异），换来的只是「这个洞存在」的记账 |
| 只扩 `REF_FORMS` 首字符集 | 那是改判定覆盖面；ADR-057 决定一已否决，且对扩展名那一维不适用 |
| 按扩展名逐个加进 `REF_FORMS` | 同上，且会让 `.json` `.png` 这类非指针对象进入判定面 |

## 后果

**得到的**

1. **噪声大降**：分类对象从「形如路径的一切」缩到「首字符非法的那几个」，枚举表与它的维护义务一并消失（第五处需人工同步的差异没了）。
2. **守护的洞变得精确**：ADR-057 与 REQ-159 记录的那个洞是「首字符非法的引用完全隐形」；收窄后这一档数的就是它，一一对应。
3. ADR-057 决定一里「宁可偏宽」的措辞歧义随之消失 —— 收窄后「偏宽」只体现在**名字侧不设字符白名单**（含空格等仍会被数进来），与实现一致。

**付出的（逐条）**

1. **首字符合法但路径已失效的引用仍然不可见** —— 那是 ADR-055 那族与人工裁决的事，不是本族。收窄等于明确承认：本族不为那类负责。
2. 本仓那一族将长期处在**个位数**的量级。**这意味着它极易被当成噪音删掉** —— 而 ADR-057 备选方案表最后一行挡的就是这个。删它要改 ADR-058，不是清理代码。

## 收窄的代价：一条新的隐形洞（本条必须与决定一同读）

**收窄把「首字符非法」当成了本族与「普通写坏的引用」之间的全部区别，但实测表明「中段字符非法」同样能让 `REF_FORMS` 匹配失败。**

具体：`REF_FORMS` 的中段字符集是 `[\w.\/一-龥-]`，**不含空格**。所以形如 `` `foo bar.md` ``（名字含空格）、`` `中·x.md` ``（名字含间隔号）的引用**匹配不上判定档** —— 而它们首字符合法，本族按决定一**不收**；扩展名若不是代码四类，ADR-055 那一族也不收。

⇒ **三族全不数 ⇒ 重新变成隐形。** 实测量级：仓内「名字.扩展名」形状且三族全不数的反引号内容 **248 处**。

⚠️ **`foo bar.md` 正是 [ADR-057](ADR-057-未匹配形态的指针自报一档.md) 背景里的实测表点名的三条之一** —— 收窄把 ADR-057 自己举的那个例子排除在外了。写下这一条，是为了让下一个写出「名字里带空格」的路径的人知道：**这一族不管它**。

**这 248 处里绝大多数也不是坏指针**（`settings.json` · `package.json` · `src/core/i18n/{zh,en,ja}.ts` 这类首字符合法的普通引用），但**真坏指针混在里面无法被看见** —— 与 ADR-055/056/057 记的那几族同一性质：**不是「判错」，是「没判」**。

⇒ **取舍的成立条件写明在这里**：本 ADR 的目标是「别让这一族变成噪声源」，代价是「中段非法那一支现在无人看守」。若目标应是「别让写坏的指针隐形」，则收窄是错的，应回到 ADR-057 的宽口径。**两者不可兼得**，这个取舍由本条显式承担，不留给下一个人猜。

## 不做

- 不撤掉这一族
- 不动 ADR-055 的「代码扩展名引用」那一族
- 不改 ADR-057 的「只出声」「零覆盖必须出声」「措辞骨架平行」三条
- **不把「中段字符非法」那一支纳回来**（那是上面的取舍，不是遗漏）
