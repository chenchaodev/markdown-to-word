# ADR-041 · specifier 抽取排除字符串字面量

| 项 | 值 |
|---|---|
| 状态 | 现行 |
| 日期 | 2026-09-30 |
| 取代 | 无 |
| 关联 | [ADR-040](ADR-040-沙盒复制集纳入shared并删除根路径豁免表.md) · [REQ-110](../REQ.md) |

## 决定

副本闭包门禁的 specifier 抽取，先接受一份**词法掩码**（逐下标标记该字符是否处于字符串字面量内部），**只在掩码判 false 的位置**抽 specifier。

掩码由 `blankComments` 的既有状态机顺带产出（等长布尔数组，行列坐标不变）。`collectSpecifiers` 的掩码参数**必填，不给默认值**。

## 背景

`test/segments/contract-single-source.test.js` 的副本闭包门禁，其 specifier 抽取跑在「**抹注释、留字符串**」的文本上。`scripts/check-temp-cleanup.mjs:215` 的白名单条目里，`why` 字段用**文档字符串**记录历史写法 `require("fs").rmSync(…)`，于是被抽成裸包名 specifier，该段判红。该文件此前不是沙盒副本，`check-temp-cleanup.selftest.mjs` 落地后成为副本，问题才暴露 —— 这条断言进 `test:coverage`，所以 CI 变红。

实跑 11 个副本共抽出 **38** 个 specifier，其中**恰好 1 个**是假阳性。其余 8 个是真实相对边。也就是说**单点发生、整类敞开**：今后任何 `why` 里写 `from "…"` 或 `require("…")` 都会复现。

**关键约束决定了实现形态**：`blankComments` 是状态机，遇引号即 `skipQuoted` 跳过、但**原样保留内容** —— 这是刻意设计，因为真实 import 的 specifier 本身就是字符串。所以「无脑剥掉字符串」不是不建议，而是**不可能**。

**判据**：真 import 的 specifier 引号是**词法记号**（不在任何字符串内）；文档串里的 `require("fs")` 那对引号**在字符串内部**。状态机本来就知道每个下标是否在字符串内，只是没把这份知识输出。

### 这个不对称是设计意图还是遗漏

**方向是设计意图，覆盖是遗漏。** 复制点扫描侧的容忍是写明理由的（`contract-single-source.test.js:288-289`：后果只是多一条「未静态解析」登记，**不判红**）；specifier 侧的 fail-closed 也是写明理由的（`copy-closure-audit.js:264-268` + 段头 `:15-19`：副本解析失败发生在沙盒子进程内，极难定位，故意偏保守）。遗漏在于**没有词汇手段区分「文档串里的 import 形状」与「真 import」**，于是唯一出口变成改措辞或开豁免类别 —— 而这两条都把门禁往弱的方向推。

## 备选方案

| 方案 | 不选的理由 |
|---|---|
| 无脑剥掉字符串字面量 | 不可能。specifier 本身就在字符串内，剥掉等于把所有 import 都抹成「无 specifier」 |
| 在「行首 / 语句位置」用正则匹配 | 正则无法可靠判定语句位置：import 可缩进、在块内、前面有 label；同一行还可能是 `const doc = "…"; import x from "y"`；`require(` 的合法形态（`await import(`、赋值右侧）也无法用行首覆盖。掩码才是精确判据 |
| (c) 改 `why` 措辞，不写 `require("…")` 字面形状 | 把一条**语义**规则（散文记历史写法）绑在一条**词汇**规则上，且**反复发生**：每个新 `why` 写自然散文就红一次，红的信息（某个不存在的裸包名）还会把人引向错误方向。可作止血，不能作方案 |
| (d) 给「文档串命中」单开不判红的登记类别 | 判定「是否在字符串内」和掩码是同一份词法工作；能分类就能不抽。且它把免罪项放进闭包判定路径，而本仓库对闭包路径的态度恰恰相反 —— `SANDBOX_ENTRY_EVIDENCE`（`copy-closure-audit.js:50-66`）之所以要配机械抽查（`auditEntryEvidence` 三条件），就是因为「登记能把死副本洗白」是它要防的头号事。再加一个无法抽查的登记类别，与既定立场正面冲突 |

## 后果

- **掩码方案最大的失败模式是掩码恒为 true**（什么都抹 ⇒ 闭包门禁恒绿），这正是 `check-import-boundary.mjs:533-535` 点名的恒绿失效。因此验收必须是**双向锚点，缺一不可**：① 正向锚点（文档串返回 0 个 specifier）；② **同区域共存负向锚点**（同一段文本里放诱饵 + 真 `import x from "./real.mjs"`，断言恰好抽到 1 个且是 `./real.mjs`，证明掩码没把整块抹掉）；③ 既有负向锚点一条都不许动（`relative-outside-copy-set` / `bare-specifier` / 死副本 / 登记失效各条），它们是「掩码恒 true」的探针；④ 覆盖面不得缩小（`:284-287` 的反退化断言、`:370-374` 指向 `test/` 的边都不要删）。
- **回归判据**：specifier 总数只许少 1（38 → 37）。少 2 个以上说明掩码误伤真 import，属失败。
- 掩码参数必填是刻意选择：「忘了传掩码就退回旧行为」的默认值就是恒绿退化的入口。
- **已知边界（登记，不隐藏）**：正则字面量里若含 `import "x"` 形状，掩码判 false（`skipRegex` 不当字符串）⇒ 假阳性仍在。极罕见。写进 `contract-single-source.test.js` 的「已知覆盖边界」节（该处是边界的唯一权威处，**不在 `copy-closure.js` 里复制一份** —— 该文件 `:17-18` 已写了这条纪律）。
- 掩码是等长布尔数组，行列坐标不变 ⇒ `copy-closure.js` 的坐标契约不破。
