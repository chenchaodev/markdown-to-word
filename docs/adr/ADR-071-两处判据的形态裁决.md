# ADR-071 · 两处判据的形态裁决（#08 断言收敛 · #10 反向注册）

## 决定

**一、#08 的新判据不设豁免，措辞改为「零本地顶层断言实现」。**

判据要禁的不是「段内出现 `assert` 这个名字」，而是「段内自己实现一遍断言逻辑」。二者形态如下，机器判前者：

- **违规（要清零）**：本地 `function assert(cond, msg) { if (!cond) throw ... }` —— 函数体自带 `throw`，即断言逻辑的第二份实现。
- **合规（保留）**：委派型窄化壳 `@returns {asserts cond}` 的本地函数，函数体只调用 harness 断言、不含自己的 `throw`。

那 8 个段目前**全部属于违规**。以 `test/gates/supply/supply/supply-common.test.js:100-102` 为样板：

```js
function assert(cond, msg) {
  if (!cond) throw new Error(`supply-common 断言失败:${msg}`);
}
```

逐字复制 `assert.js` 的实现，只多两行 JSDoc 注解。`assert.js:199-201` 的原话是「在段内包一层带 `@returns {asserts cond}` 的本地函数**调用本 helper** 即可」—— 那 8 个段照做了字面（声明成断言函数），没照做意图（真的去调 helper）。**它们不是正当豁免，是没迁完的迁移。** 修法就是把函数体改成委派，不是给它们开豁免。

**二、#10 的判据按「跨 feature 的槽」数，不按「点位」数，且 `recentRefreshHandler` 明确豁免。**

- 槽存在的目的是回避一条 import，所以删槽+删注册+删读者是**一个工作单元**，跨几个文件都算一处。按点位算会把一个机制数成两处。
- `recentRefreshHandler` 由 `renderer/renderer.ts:142` 在**组合根**注册 —— 这已是 ADR-065 承诺的目标形态，**删掉它等于把正确形态退回 feature 自注册**。ADR-065 §二把它算进「四处」是错的。
- `commandBusyProbe`（槽 `convert/file-list.ts:204` · 注册 `convert/convert-flow.ts:69`）与 `settings-save.hooks`（`settings/settings-save.ts:54`）**两端都在同一 feature 内**，不跨 feature，因此不构成本步退出条件的阻塞项；它们可以在对应 feature 的提交里顺手清理，但**不得计入判据**。
- 真正必须清零的跨 feature 反向注册是 **`stageChangedHandler`**（槽 `renderer/state/state.ts:69`，由 `ui/recent-files.ts:200` 写、`convert/file-list.ts:42` 读 —— ui 写、convert 读，确属跨 feature）。

## 背景

两处判据在开工前都读不出该按什么形态执行，且按字面执行会做错事。

第一条来自只读测绘（结论底账见 `docs/evidence/20261006-141113-三份只读测绘事实地图与接手须知.md` §三）：#08 的判据②「段内零本地顶层 `assert`」会命中 8 个段，其中 `test/gates/supply/supply/` 那 6 个恰是全仓 case 化最彻底的样板。若按「正当豁免」处理，等于让样板自身带一个判据会红的例外，后续 125 段的推广反复撞同一堵墙。

决定「它们不是豁免」的依据是直接读码，不是转述：`supply-common.test.js:94-102` 的注释自称「局部版」且只声明为断言函数，而函数体是断言逻辑的第二份实现。`assert.js:343-349` 的重复面盘点已经把这类逐字副本记为「逐字相同，仅前缀段名不同」—— 它没把带注解的这 8 份单独列为一类，说明在盘点者眼里它们就是那批副本的一部分。

第二条同源（§五）：ADR-065 §二称「四处反向注册 handler」但**从未逐个点名**，于是无法判定它所指具体四项。实测三点：`recentRefreshHandler` 由组合根注册（已是目标形态）；`commandBusyProbe` 的槽与注册是同一机制两端；`settings-save.hooks` 是真实反向注册但 ADR 未计。ADR 未点名，故不擅改其正文，改为在此裁决判据的计数口径。

## 备选方案

**否决 · 给那 8 个段开豁免机制。** 豁免表是门禁里已有的成熟形态（`check-test-layout.mjs` 三张豁免表），加一张并不难。但豁免的是**断言逻辑的第二份实现** —— 而 #08 要消除的正是它。给样板开后门，等于把「这段没迁」固化成「这段不用迁」，判据从此只能被绕过不能被满足。

**否决 · 给 `assert.js` 加一个带 `asserts` 的变体，让段直接引它。** `assert.js:197-199` 已经写明为什么不把窄化塞进公共件：`assert` 刻意不声明为 `asserts cond`，因为 TS2775 要求调用目标有显式类型标注，而段内惯用法是解构取用 —— 那条约束对公共件的导出形态同样成立，加变体会把同一个 TS 限制推到更难的地方。

**否决 · #10 按点位算，凑成「四处」。** 点位数会随代码移动而变（同一机制今天在两个文件、明天合并成一个文件，点位数就变了），判据不稳定。且按点位算必然把已是目标形态的 `recentRefreshHandler` 一起算进去，导致「删四处」的执行动作删掉组合根注入。

**否决 · 改 ADR-065 正文把「四处」订正为数字。** `adr/` 装会被取代的决定，旧条不改动、只在新条状态行标取代（见载体表分界线）。本 ADR 即那一份新条。

## 后果

- #08 的新判据措辞随之改写，机器判「函数体是否自带 `throw`」而非「有没有叫 `assert` 的顶层函数」。**判据实现时须复核那 8 个段逐个确属违规** —— 本决定只直读确认了 `supply-common` 一个样板，其余 7 个在 #08 施工时逐个分类。
- 判据转正前先按 `pending: true` 上链（机制见 `check-test-layout.mjs:1439` 的 `report(id, line)` 唯一漏斗，样板在 `:508-517`），符合步序表「新判据先报告后转正」。
- #10 的退出条件从「四处反向注册 handler 删除」改为「**跨 feature 的反向注册槽清零（当前 1 处：`stageChangedHandler`）**，组合根注册的槽不算」。ADR-065 与 `docs/PLAN.md` 的对应表述按此更新。
- 组合根注入这条正面判据**新增为独立判据**（scope 命中 `renderer/renderer.ts`，禁其 import 子模块私有符号），否则「保留 `recentRefreshHandler`」只是本次口头约定，无机器看守、下一轮重构会再次被当成待清的债。
- 那 8 个段的注解依赖 `@returns {asserts cond}` 收窄类型。ADR-069 起产物带 `.d.ts` 后该必要性可能下降，届时可进一步简化；但**不是本决定的前置**，不得据此跳过委派改造。
