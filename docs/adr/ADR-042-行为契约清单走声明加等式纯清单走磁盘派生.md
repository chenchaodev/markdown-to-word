# ADR-042 · 行为契约清单走声明 + 等式，纯清单走磁盘派生

| 项 | 值 |
|---|---|
| 状态 | 现行 |
| 日期 | 2026-09-30 |
| 取代 | **部分取代 [ADR-037](ADR-037-顶层与扫描面一律派生.md)** —— 只取代其中「测试扫描面从磁盘派生」一句；顶层派生、根路径单源、禁自算三条继续现行 |
| 关联 | [ADR-037](ADR-037-顶层与扫描面一律派生.md) · [REQ-110](../REQ.md) |

## 决定

**判据：新增一个目录时，加错了会不会静默改变行为？**

- **会** → 清单是**行为契约**（测试面、门禁面这类定义了「什么被验收」「什么被门禁扫」的地方）。走**显式声明 + 等式强制**：漂移必须判红，并点名差异的目录名。
- **不会** → 清单是**纯清单**（顶层目录这类只决定保护/镜像/排除范围的）。走**从磁盘派生**，新增目录零改动。

两者的共同内核是「实测成员集 + 显式判定函数」，差别只在**成员集从哪来**：纯清单的成员集来自 `readdir`，行为契约的成员集来自声明（判定函数决定每个成员的文件接受谓词与排除理由）。

本条是 [ADR-037](ADR-037-顶层与扫描面一律派生.md) 把两类清单用同一条规则处理之后的精确化 —— 实测发现它们的失败模式相反，故精确化而非推翻。

## 背景

[ADR-037](ADR-037-顶层与扫描面一律派生.md) 决定「顶层目录、测试目录、项目根三者一律从实际内容派生」。执行时发现两类清单的失败模式相反：

**顶层是惰性的。** 新增一个顶层目录 `foo/`，它应当只进保护集 / 镜像集 / 白名单一致性检查，不改变任何行为。派生即可达成：成员集来自 `readdir`，分类函数判定 `source` / `verify` / `shared` / `doc` / `output` / `config` / `vcs`。

**测试面不是惰性的。** 新增一个测试子目录 `test/perf/`，若被当作段目录就**立刻改变行为**：验收会多跑它、`gen-fixtures` 会往它生成样例。派生在这里是危险的 —— 一个随手新建的目录会静默变成验收对象。所以段目录成员必须**显式声明**。

更进一步：扫描面本质是**判断**而非**事实** —— `test/fixtures` 就在磁盘上但必须排除，排除理由是「它不是测试代码」这个意图决策，磁盘告诉不了你。这一点对顶层同样成立：`readdir` 能告诉你有什么，**告诉不了你 `dist` 是产物、`src` 是源码**。所以两处都不是「纯派生」，而是「实测成员集 + 判定函数」，区别只在成员集的来源。

测试面的漂移控制用**等式**（声明数 == 实测数）而非下限。下限（`MIN_SCAN_FILES`）只回答「walker 是不是整体坏了」，不回答「是不是少扫了一个子目录」—— 新增子目录而某处漏改时，walker 照样扫到上百个文件、下限照样满足、门禁**静默恒绿**。等式是唯一能抓「漏」的判据，判红时点名 `extra`（磁盘有未登记）与 `missing`（已登记磁盘已无）。下限保留，但两条各管一件事。

## 备选方案

| 方案 | 不选的理由 |
|---|---|
| 两者统一为「全部从磁盘派生」 | 测试面的段目录成员会被静默改变 —— 随手建一个 `test/perf/` 就会让它变成验收对象。这是行为变更且无人察觉，正是本仓反复在治的「静默降级」 |
| 两者统一为「全部显式声明 + 等式」 | 顶层退化回 6 处各自枚举 —— [ADR-037](ADR-037-顶层与扫描面一律派生.md) 要治的正是这个。顶层新增目录本可以零改动，没必要强制手改 |
| 保持 ADR-037 原样不动 | 两套哲学并存却不写明区分依据，下一个会话会以为其中一条是疏漏并"修正"它。实测已证明二者不能互换，必须留下判据 |
| 用「派生 + 等式」双保险（两者都做） | 顶层做等式是空转 —— 派生出来的成员集与磁盘必然相等，等式恒绿，判据不产生任何结论。多加一个恒绿判据只是噪音 |

## 后果

- [ADR-037](ADR-037-顶层与扫描面一律派生.md) 标为部分被取代：顶层派生与根路径单源继续有效，被取代的只有「测试扫描面从磁盘派生」那半句。
- 本条给出的是**判据**而非清单本身。遇到新的清单类需求时，先问「加错了会不会静默改变行为」，据此选模式 —— 不需要为每个新目录重新讨论。
- 顶层派生的**类别词表实际是 10 项**（`vcs` `build` `artifact` `deps` `source` `verify` `shared` `config` `doc` `other`），比 [ADR-037](ADR-037-顶层与扫描面一律派生.md) 写作时列的 7 项多 `build` / `deps` / `other`。多出这三项是执行期的实测结果：`build`（编译配置声明的输出树）与 `deps`（安装树）必须与 `artifact`（打包输出）分开，否则「产物」一类会把源码输出树也划成可删；`other` 是兜底档，保证任何未识别条目都有确定归属而不是掉出全部集合。分类函数 `classifyProfile(profile)` 的**签名里没有条目名参数** —— 名字只在「读声明时按名匹配」与「报告显示」两处出现，所以「改名不改类别」是结构性保证而非纪律要求。
- `build.files` 白名单的取反模式**不要求目标存在** —— 因为 `check:contract` 在 CI 里跑在 `npm ci` 之前，那时安装树尚不存在，无法被分类成 `deps`；若要求取反目标可判定，这条判据就是恒红的不可达判据。
- 行为契约清单的维护成本明确存在：新增段目录要改一处声明 + 跑一次等式。这个成本是**有意的** —— 它把「加一个目录会不会悄悄改变验收语义」从「没人知道」变成「必须在代码里写出来」。
- 后续泳道（跨树边界、门禁统一协议、目录重组）凡涉及清单，按本条判据选模式，不再逐处讨论。
