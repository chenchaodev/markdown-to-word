# ADR-080 · 预设目录去重与提示态口径

| 状态 | 现行 |
| 日期 | 2026-10-19 |

## 决定

内置预设目录按「同一套设置只能有一条内置预设」去重,并因此把「提示态」的口径钉死:

1. **删掉与 `business` 逐字段重合的那条内置预设**(`cn-minimal`),保留 `business`。判据是 **`matchesPreset` 为真**,不是文案相近:`typography` / `pageSetup` / `headerFooter` / `watermark` / `equationNumbering` / `breakBeforeH1` 全同。
2. **选中项继续是派生的**,不新增「用户上次选了哪条预设」的持久化状态。选择身份 = 当前设置反查出的第一条匹配,回落值 `default`。
3. **「已微调」提示态不存在**。选中项恒对应一条真实预设 ⇒ 该态不可达,随第 2 条一并删除:分支、`.template-hint--custom` 重音样式、三语 `preset.modifiedHint`、以及无消费方的孤儿键 `preset.hintTitle` 全部移除。`resolvePresetHint` 对未知 / 已删 id 只作防御性兜底,回落 `default` 说明。

## 背景

`business` 与 `cn-minimal` 除 `id` / `i18nKey` / `name` / `hint` 外逐字段相同。选中项在启动时由设置反查(`resolvePresetSelection`),按数组序取第一条匹配 ⇒ 两条同时命中时永远是靠前的 `business`。后果是用户选「中文极简」后重启,下拉显示成「商务简报」、说明行随之改口 —— **不是显示层 bug,是目录里存在两条同一套设置的预设**。

同时暴露:既然选中项恒由设置派生,`resolvePresetHint` 的「选中项不存在 → 已微调」分支在正常链路里取不到值,其配套的样式与三语文案是死代码;而 `preset.hintTitle` 在上一次展示升级后已无任何消费方。

## 备选方案

1. **选择身份另存**(记住用户显式选中的 id)—— 否决。它只掩盖症状:下拉里仍是两条等价选项,用户仍在两个等价项之间做无意义选择;且要新增持久化键,触发 ADR-024 / ADR-028 的分组与兜底面,成本远高于收益。
2. **把两条预设改成数据不同** —— 否决。预设值已定稿,为「让两条看起来不一样」而造差异是没有用户诉求的产品变更;真要区分,应作为新的产品决定并同时给出各自的说明文案。
3. **在 renderer 侧另存「最后一次选择」**(localStorage 一类)—— 否决。设置状态的单一来源会被劈成两份,导入 / 重置 / 多窗口任一路径都可能与设置本身不一致。

## 后果

- **对外可见**:内置预设少一条(图形界面下拉、向导、命令行 `--template` 清单同源)。`--template cn-minimal` 由「可接受」变为「未知预设」并报用法错误(退出码 1)。
- **用户设置不变**:原先选「中文极简」的用户,设置值与 `business` 完全一致 ⇒ 升级后照常匹配 `business`,产物不变,只是下拉里少一个等价选项。
- **口径**:「已微调」态不再是可实现的 UI 状态。若将来改回「记住用户显式选择」的选择模型,必须**另起 ADR**并把该提示态作为新决定重新引入 —— 不要以「代码里曾经有」为由恢复,那是本次明确删掉的。
- **文档侧**:预设条数不再抄进设计文档,以 `TEMPLATE_PRESETS` 为准(本次已把 [`docs/design/settings-ia.md`](../design/settings-ia.md) 01 组那处的硬编码条数换成指针)。
- **未覆盖**:`docs/evidence/` 下的历史取证保留当时的「6 条」快照,不回改。
