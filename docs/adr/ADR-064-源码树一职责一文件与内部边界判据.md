## 背景

`src/` 162 个代码文件 / 34,142 行。事实底稿与架构评审全文见 [evidence 底稿](../evidence/20261004-103703-src结构诊断与目标结构评判.md)。此处只列直接构成决策依据的五条。

**一、顶层分层是本仓最成功的治理，一个字都不该动。** 实测层向零违规：无一条反向边；`electron` 20 处 import 全在 `main/**`（17 文件）＋ `renderer/about-preload.cjs`（1），`core`/`convert`/`cli`/`mcp` 为 0。15 条 `LAYER_RULES` ＋ `SRC_TOP_LAYERS` allow-list 经实测是本仓资产。

**二、真自伤集中在「四个文件承担多份职责而名字只说了其中一份」。** `core/i18n.ts`（201 行、60 个消费文件、入度全仓第一）同时是注册表再导出面 ＋ 10 个与 i18n 无关的警告构造器 ＋ 语言全局状态 ＋ **core 内唯一碰 DOM 的文件**；`core/cancel.ts`（296 行）后 42% 是图片请求守卫；`ConvertContext` 在 `core/convert.ts:86` 与 `convert/context.ts:50` 各有一份**同名不同形**的 interface；`settings-schema.ts` 与 `settings-defaults.ts` 职责纠缠且靠头注而非文件名区分。

**三、`core/` 内部零约束是「没人管」，不是「管不了」。** 实测 `core/` 9 个子目录的运行期依赖图几乎是一片 DAG：`docx` 与 `pdf` 之间唯一一条边是 type-only（`HeaderLogoData`），`image`/`util`/`style`/`settings` 是叶子。**唯一的运行期环是 `markdown ⇄ pipeline`**（`markdown/ai-cleanup.ts` → `pipeline/{frontmatter,parse}.js` 2 条反向边），成因是**一个文件放错了目录**：`ai-cleanup` 是「解析之后的变换」，它需要 `parseMarkdown`，于是「markdown 目录」反向依赖了「解析器目录」。对比 `renderer/`：实测 5 对双向、47 条 feature 间运行期边，正因为如此才**只能**约束基础层 —— `core/` 没有那个前提。

**四、19 条取证里 6 条不动、6 条提法有误或部分动，只有 7 条要动。** 评审纠正了事实底稿四处误读，其中「`settings-save.ts:6` 写法不一致」**已被证伪**（那行在 `/** */` 块内，是散文；全仓运行期 import 环实测为 0）—— 按原事实去修会去改一段散文。

**五、唯一不可替代的能力与唯一会失去的保护都已定位。** 沙盒探针层（≈2.25k 行）能发现「门禁在真实工作树上失效但夹具仓里绿」，不可替代；`protocol.mjs`（366 行）的「三种驱动器共用同一份判定」承诺，实际驱动器只有 2 个，34 道门禁里 28 道从未使用 —— 但它们都不在本条的范围内，本条只动 `src/` 与 `LAYER_RULES` 的实现形态。

## 决定

### 一、不变式

> **`src/` 下每个文件的名字，是它唯一职责的名字。** 目录名 = 一层职责类别；文件名 = 该类别下的一个具体主体；**同名概念在 `src/` 内只允许存在一份**（唯一例外：`docx` / `pdf` 两条渲染管线的对位实现，白名单逐条登记）。

**不给 `src/` 建「模块 → 文件」映射表** —— `core/i18n.ts` 有 60 个消费方、`core/convert.ts` 有 43 个，任何以枢纽为键的映射都会退化成「枢纽的清单」，而枢纽不该有清单。替代物是**反向索引** `npm run owners -- <模块路径>`：打印「谁 import 了它 ＋ 它属于哪棵树 ＋ 它的镜像测试段路径」。约 40 行，与 ADR-062 的 `npm run where` 共用同一个 import 图扫描器。

### 五、测试侧的连带改动（不可拆开）

`src/` 每动一次都在打断测试：**134 段里 99 段（74%）import `dist/**`**。因此**每个 src 移动必须与它的镜像测试移动在同一个 commit 内完成** —— 「搬 src」与「修测试 import」绑成不可分割的一步。

拆 `i18n` 的触点是 **29 处**：24 段运行期 import ＋ 5 处 JSDoc 类型标注。已逐处核实那 5 处是 `/** @typedef {import("../../src/core/i18n.js").X} */` 形态，**只对 `typecheck` 负责、运行期不受影响**，故 `tsc -p tsconfig.test.json` 会点名，**不会静默**。它们指 `src/` 而非 `dist/` 是**不得已**：`dist` 不产 `.d.ts`（REQ-163），类型引用指 `dist/` 会全变 `any`（REQ-089 同因）。

### 六、六阶段推进方案

**阶段之间有硬序，不可并行。** 全程唯一允许并行的写入是 `gates/` 下两个不同文件。



**T0 的第 0 步（并入本方案）· REQ-170「gates/ 零静态类型兜底」，实测后改判。**

原方案是「给 `gates/` 单开 `tsconfig.gates.json` 并开 `checkJs: true`，先清零既有类型错误」。**实测把这个方案否决了**：

| 配置 | 存量错误 | 性质 |
|---|---|---|
| `checkJs: true` | **1,028 条** | 544 条参数/绑定/索引隐式 any（纯缺 JSDoc 标注，`.mjs` 无标注时永远满足不了 `strict`）· 106 条继承的 `noUncheckedIndexedAccess`（对无标注 JS 无意义）· 18 条 TS2304 **全是跨模块 JSDoc typedef 引用未导入**（`GateProbeResult` 声明在 `contract.mjs`，`app.mjs` 的 `@returns` 直接引用；JSDoc 类型是模块作用域的）· **真拼错 0 条** |
| `no-undef` ＋ node globals（eslint） | **1 条** | 仅 `setImmediate` 未声明为 global，非代码错 |

清零那 1,028 条等于给 3 万行 JS 逐个补类型注解，与本条诉求（抓「一个字符的错」）相差三个数量级。

**实际采用**：`eslint.config.js` 末块对 `gates/**/*.mjs` / `shared/**/*.mjs` / `shared/**/*.js` / `tools/**/*.mjs` 开 `no-undef` 并集中声明 node globals。成因：`no-undef` 默认不在 `tseslint.configs.recommended` 里（typescript-eslint 刻意关它，因为 TS 自己查），而这几棵树不在任何 tsconfig 的 `include` 内 ⇒ 标识符拼错两道静态检查都不报，只有 `npm run acceptance` 真跑到才炸。

**验证**：① 三棵树存量零错误；② 反证——向 `check-import-boundary.mjs` 注入 `notDefinedAnywhere.x`，`no-undef` 判红并点名行号，还原后绿；③ `npm run lint` 退出码 0，既有配置未被打破。

**未做**：不开 `tsconfig.gates.json`、不开 `checkJs`、不补 JSDoc 标注。若将来某道门禁开始 `import dist/**`（`checkJs` 会把整个 dist 拉进检查范围，复制 `tsconfig.test.json` 已踩过的那 1,050 条噪声坑），再重新评估。

**T2 的 5 步与排序理由**

| 步 | 内容 | 触点 | 为什么是这个顺序 |
|---|---|---|---|
| 1 | `util/`→`text/` ＋ `settings-*` 改名 | 3 段 | 纯改名零逻辑，先跑通「搬 ＋ 修测试 ＋ 验」这套动作 |

**T0 与 T1 分开的理由**：落两个不同门禁文件，分开则回滚粒度细 —— T1 若有设计错误（判据设计比 src 改动更容易推翻）可以单独退，不牵动已立的 `src` 判据。

**T1 判据设计的两个要点**：① L4 不能只写「必须 import 解析到 `<R>` 内的主体」—— `test/core/runner-report.test.js` 根本不 import 任何 src 模块，L4 无从检查，须补「**必须 import 至少一个本层被测主体**」，否则框架自测段会漏网；② **L5（跨层禁止）必须 report 模式起步**，因为 `test/core/heading-scale.test.js` import `dist/renderer/*` 做 token 对照这类合理跨层会被误伤，诊断必须直接给出「搬去 `test/behavior/` 并写 `covers`」的指引。

**一个刻意排开的冲突**：ADR-062 的 P2（harness 归位，**86 处 import 重写**）与 T2（每步都在重写 import）**都改 `test/`**。两者交错会在同一批文件里互相掩盖。故 **86 处重写全部推到 T3**，即所有 src 移动做完之后。代价是 T2 期间 `test/common/paths.js` 仍在（它本就不该在 src 搬运期间消失）；收益是两个改写集永不重叠。

### 八、与 ADR-062 的次序（关键）

**本条必须先行，且必须在 ADR-062 的 P1 之前完成。**

ADR-062 的不变式是 `test/<R>/<rest>.test.js ⟺ <R>/<rest>.<ext>`，`R` 从磁盘派生。本条的全部改动发生在 `src/` **内部路径**上，**六个顶层子目录一个都不增不减** ⇒ 派生源集合不变 ⇒ **不推翻那套镜像**，只是模块搬家后镜像段路径跟着变（位置即身份的定义本身）。

但 ADR-062 的 L1 是 **ratchet**（豁免表只许减不许增），且以模块路径为键。反序的代价具体是：81 项豁免表的键是**当前**的 src 路径，src 一搬就产生一类**语义模糊的红**（「模块已不存在」是删豁免还是路径变了？L3 措辞只覆盖「已有测试文件」），且每次搬文件都要手改豁免表 —— **在一个仍在结构性变动的时期制造大量无信息量的 diff**。

正序的代价是 ADR-062 的 T1 拿到的 src 已是终态，基线一次生成即准确。

## 备选方案

**A · 给 `core/` 加 9 条方向层向规则（对齐 `renderer/` 的做法）。** 否决 —— `renderer/` 之所以只约束基础层，是因为实测 5 对双向、47 条 feature 间边；`core/` 实测内部几乎是一片 DAG（唯一环是一个文件放错目录）。把 `renderer/` 的答案套到 `core/` 上，会为它并不存在的病开药。

**B · 在 `src/` 建「模块 → 文件」映射表（对齐 ADR-062 的位置即身份）。** 否决 —— `src/` 没有 1:1 的天然对应，而枢纽有 60 / 43 个消费方，任何以枢纽为键的映射都会退化成枢纽清单。改用反向索引 `npm run owners`。

**C · 与 ADR-062 合并成一条工作项、一个 ADR。** 否决 —— 两者是不同决定（「一职责一文件」vs「位置即身份」），且次序必须显式。分开立才有「本条是 ADR-062 的前置」这句话可写。

**D · 先做 ADR-062 的 P1 建判据，再改 src。** 否决 —— 见「七」的 ratchet 论证。

**E · 顺手把 `WATERMARK_GRAY` 与 `RULE_GRAY` 的同值合并掉（DRY）。** 否决 —— 改了分隔线灰不该改水印灰。合并是拿语义独立性换 DRY，`colors.ts:11` 的注释判断正确。

**F · 把 `renderer/style/` 也并入某个 TS 命名空间。** 否决 —— 4 个 CSS 3,546 行没有任何 `.ts` import，只由 HTML `<link>` 消费，消费机制与 TS 模块完全不同。

### 最容易静默出错的三处

1. **🔴 `i18n` 拆分（201 → 4 文件，29 个触点）**
失效形态：回退链的 `current` 是模块级 `let`（`core/i18n.ts:146`）。若它落到 `dom.ts`，`setLanguage` 与 `applyStaticTexts` 会读不同状态 —— **且现有测试全绿**（`test/core/i18n-registry.test.js` 测的是注册表形状，不是跨模块状态一致性）。
**对策**：① `current` 必须留在 `t.ts`，`dom.ts` **只 import 不导出**它（判据 `i18n-dom-no-export-let`）；② `core-i18n-dom-only` 把 DOM 的使用面锁死；③ 搬完立刻跑 `test/core/i18n*.test.js` ＋ `test/renderer/settings-logic.test.js` ＋ `test/renderer/session-persist-feedback.test.js`（它 import `core/i18n`）。

2. **🔴 删两条 type re-export（`main/ipc/types.ts` ＋ `renderer/state/state.ts` 的 3 条）**
失效形态：漏改 import 路径 tsc 立即红（**安全**）。更隐蔽的是：若有人把某条 `import type` 改成**值** import（例如为了拿 `t()` 而 import 整个 i18n 模块），会把 43 个消费方的依赖面静默扩大 —— **不会红**，因为方向合法。
**对策**：`core-no-duplicate-export` —— core 契约的 type 不得被第二个文件 `export type` 转出（白名单在 `main/ipc/types.ts` 删除后为空）。

3. **🟠 `main/converter/index.ts` 删 7 个跨层转出**
失效形态：漏改一个消费方 ⇒ 段崩（安全）。更糟的是反向 —— 某个消费方为了「少改一处」改成从 `../converter/index.js` 取装配层符号，**桶又长回来且没人发现**。头注已自述过这个诱惑。
**对策**：`main-ipc-no-assembly` 覆盖不到 `main/windows/preview.ts`（它 import `../converter/index.js` 而非 `../../convert/`）。正确的判据是跨文件符号来源追踪，**超出本仓门禁架构能力** —— **显式登记为已知边界**：桶瘦身后在 `main/converter/index.ts` 头注写明「本桶只转出本目录 5 个实现」，不为它建机制。
