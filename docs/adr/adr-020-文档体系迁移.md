# adr-020 · 文档体系迁移至全局 v8.1 规则集

| 项 | 值 |
|---|---|
| 状态 | 现行 |
| 日期 | 2026-09-27 |

## 决定

1. **目标体系**采用全局 v8.1：`docs/REQ.md`（号台账 · 永久）· `docs/LOG.md`（想做但没做 · 只追加）· `docs/PLAN.md`（单任务临时）· `docs/large/NN-短标题.md`（大型需求台账）· `docs/adr/adr-0NN-短标题.md`（一决策一文件）· `docs/archive/`（长分析原文）· `docs/CHANGELOG.md` / `docs/USER-GUIDE.md` / `docs/DEV-GUIDE.md`。
2. **编号统一为单序列 `REQ-0NN`，合并规则是「原 `REQ` 号不变 → `REF` 按原号顺延接在其后 → 本次取最后一个号」**：原 `REQ-001`–`REQ-022` **号不变**；原 `REF-001`–`REF-029` 按原号先后顺延接到 `REQ-023`–`REQ-051`；本次文档体系迁移 = `REQ-052`；下一个可用号 = `REQ-053`。旧号全部保留在台账「原号」列，**一律不复用**，合并后不再使用 `REF-` 前缀。
3. **台账状态词表在模板三值上追加 `未开工`**：33 条从未开工的项在「在办 / 已完成 / 已作废」里没有对应值，写成「已作废」会把仍活的待拍板项误标成已否决；它们的事实体（待拍板 / 暂缓 / 不做 + 原因 + 重新评估触发条件）在 `docs/LOG.md` 三张表，号与事项分工不重叠。取值共四个：`在办` / `已完成` / `已作废` / `未开工`。
4. **落地 `docs/REQ.md` 等于翻开指针门禁的项目模式开关**：全局 `tools/check-pointers.mjs` 的项目探针是 `docs/REQ.md`，命中后扫描范围从「根 6 份 md」扩到「根 md + 整个 `docs/`（`docs/archive/` 除外）」。迁移期间门禁会红，属已知状态，**第 01 步先取存量快照并逐条登记**，不带着未登记的红往下走。
5. **已闭环的验收明细层（12 份功能域文件，原 `acceptance/` 目录）与技术事实层（9 份域文件，原 `research/` 目录）整层移入 `docs/archive/`**，按只读历史对待；两层的入口指针改指归档路径，并在此条与 `docs/LOG.md` 各留一行指针，避免下个会话找不到事实库。
6. **`docs/adr/` 19 份决策文件改名对齐模板**（`ADR-0NN-短标题.md` → `adr-0NN-短标题.md`），字段保留项目版（决策 / 理由 / 备选 / 代价 / **验证 / 来源 / 关联**）并补模板要求的 `状态` / `日期`；原单文件 ADR 索引的编号台账退役，取号改为 `ls docs/adr/` 取最大号 +1。
7. **A-059 的三条人工验收判据随载体退役**：两条引用已 tombstone 的容量契约门禁与原路线图文件的容量豁免，判据不可判定故作废；第三条「条目级外迁零改写」改写为对本迁移产物自身的逐字核对。`REQ-039`（原 REF-028）说明列的失真（`check:docs` 已移出 `verify:ci`）在 `docs/REQ.md` 下方注明。

## 背景

全局规则与模板在 2026-09-27 从 v7.8 切到 v8.1，文档体系换了骨架（`WORKFLOW-PLAN` / `WORKFLOW-DELIVER` / `CAMPAIGN-GUIDE` 退役，容量契约与台账一致性两项门禁随之退役）。本仓仍在旧体系上：常驻 12 份根 md + 5 个子目录层，其中原文档索引的「容量契约」表、原路线图的双序列编号台账、原单文件 ADR 索引的编号台账三处**当前已无任何机器校验**（全局门禁的 `RETIRED` tombstone + 实跑输出可证），属于「规则与实际不符」——按全局规则「规则与实际不符时改规则」，迁移是让本仓重新落回可校验状态。

原路线图文件里的 51 条需求已逐条对代码 / 测试 / CHANGELOG 复核（结论见本条「后果」段与 `docs/LOG.md`），其中 5 处说明列失真属实、另发现 1 处未登记的失真，因此**不照搬旧表**，按实际状态重新分流。

## 备选方案

| 方案 | 不选的理由 |
|---|---|
| 新序列从 `REQ-023` 起、原 `REF-*` 号留在台账里不重编号 | 台账会同时存在两个前缀，违反「单序列、不按类型另起序列」；且 `REF-029` 与将来的 `REQ-029` 同数字不同义 |
| 历史项**不进**台账，只留 git + `docs/archive/` | 台账失去「这个号做过什么」的查表能力；用户裁决「统一编号、统一存盘」，51 条全部进台账 |
| 33 条未开工项一律写成 `已作废` + `~~` 划掉 | 把仍活的待拍板 / 暂缓项误标成已否决，且 33 行划掉后表格几乎不可读；改用追加的 `未开工` 值（见决定 3） |
| 本次迁移取 `REQ-030`（历史项之前留号） | 会插在历史中间，不便一眼看出「本次是最后一个」；用户裁决取最后一个号 `REQ-052` |
| 技术事实层保留为项目常驻层并在 `AGENTS.md` 登记 | 用户裁决归入 `docs/archive/`。取舍知悉：归档层定位是「不读 / 不登记 / 不入索引」，故本条在决定 5 里留了指针行作为找回路径 |
| 两层历史材料直接删除、交给 git | 同上裁决归入 `docs/archive/`：这些是实测结论与门禁陷阱（如 NTSTATUS 判读、覆盖率陷阱），删掉只能翻 git 历史重建 |
| `docs/adr/` 保留 `ADR-0NN-` 大写文件名 | 目录自带的 `docs/adr/README.md` 会与实际命名矛盾，且取号说明要改写；改名成本低（入站链接集中在 `docs/` 内，`src/` / `test/` 仅 2 处注释 + 1 处测试字面量） |
| 保留原文档索引（`docs/` 内那份）作 `docs/` 索引 | 它的两项职责（容量契约 / 索引）分别退役与上移到根 `README.md`，留着只剩一个空壳索引层 |

## 后果

- **好处**：`docs/` 从「12 份根 md + 5 层」收敛为「7 份根 md + 4 个有明确职责的层」；指针门禁的项目模式首次真正覆盖本仓 `docs/`（此前零覆盖），悬空指针与失效小节名重新可判；51 条历史需求第一次在一处可查（号、原号、标题、状态、日期齐全）。
- **代价 1（门禁红窗）**：`docs/REQ.md` 落地后到第 05 步之间 `npm run check:docs` 会报出存量违规（容量契约表、旧文档名与死链接），随迁移逐步清零。
- **代价 2（机器硬依赖）**：`test/segments/signature-status.test.js` 读 `docs/SIGNATURE-STATUS.md` 并断言含 `ADR-013`；`test/segments/env-fingerprint.test.js` 读 `docs/index.html`；`scripts/gen-archive-index.mjs` 硬编码 `HOST_EXCLUDE_DIRS = {archive, campaigns}` 且被 `verify:ci` 与 `check-ci-contract.mjs` 的 `REQUIRED_CI_STEPS` 强制；`.gitattributes` 钉 `docs/archive/INDEX.md` 的 EOL。这四处必须随迁移同批改，否则门禁或测试红。
- **代价 3（号 ↔ commit 的连接要翻译）**：18 条历史项的 commit message 尾部带的是**原号**（如 `(REF-018)`），台账里是新号；反查提交须经「原号」列，否则查不到。
- **代价 4（知识可达性）**：技术事实库进了只增不改的归档层，日后查「某库行为 / 某踩坑」需按文件名检索，不能指望索引；缓解手段是本条决定 5 与 `docs/LOG.md` 的指针行。
- **`docs/adr/` 取号规则变化**：不再有中央台账，靠 `ls docs/adr/` 取最大号 +1，取代原「编号台账」。
