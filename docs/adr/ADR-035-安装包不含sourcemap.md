# ADR-035 · 安装包不含 sourcemap

| 项 | 值 |
|---|---|
| 状态 | 部分被 [ADR-036](ADR-036-安装包排除范围扩到依赖侧sourcemap.md) 取代 —— 被取代的只有「排除范围」一处：ADR-035 定的是仅 `dist/**/*.js.map`，现扩为全包（含 `node_modules/**/*.map`）。**其余裁决全部继续现行**，尤其「不改 `tsconfig` 的 `sourceMap`」与「`dist/` 目录本身仍留 `.map`」两条 —— 前者是覆盖率门禁的测量依据，后者决定排除只发生在打包层 |
| 日期 | 2026-09-30 |
| 取代 | 无 |
| 关联 | [ADR-036](ADR-036-安装包排除范围扩到依赖侧sourcemap.md) |

## 决定

安装包（electron-builder 的 `build.files`）不再收录 `dist/**/*.js.map`；`tsconfig.json` 的 `sourceMap: true` **保持开启**，`dist/` 目录本身仍产出 `.js.map`。改动只发生在打包的收录层，不在编译层。

## 背景

`tsconfig.json` 开启 `sourceMap` 的原因是覆盖率门禁：`npm run test:coverage` 用 `c8 --include="dist/**"` 采集 Electron 产物，`.js.map` 是把覆盖率映射回 `.ts` 的唯一依据，链路经实测可用（两份相关历史快照头部均自述「结论去向：未升 · 无对应 ADR」，故此处不作回指，避免把只读快照的结论去向改写成指向本条）。

而 `package.json` 的 `build.files` 原本是 `"dist/**"` 无任何排除，于是这项编译期必需品被一并打进了对外交付物。实测 `.js.map` 的键为 `version` / `file` / `sourceRoot` / `sources` / `names` / `mappings`，**不含 `sourcesContent`**（TypeScript 默认不内联源码正文）—— 故暴露面是内部文件路径、原始标识符名与行列映射，不是源码正文。体积上 `.js.map` 占 `dist/` 文件数近一半，在安装包里是纯冗余。

该问题 2026-08 的审计已记为「真实卫生问题」并写下了排除写法 `!dist/**/*.map`，但未落地；此后 `.js.map` 数量只增不减。

## 备选方案

| 方案 | 不选的理由 |
|---|---|
| 关掉 `tsconfig` 的 `sourceMap` | 直接切断覆盖率门禁的测量链路。阈值向量一旦失去基准，`verify:ci` 的阻断判定即空转 —— 拿一个打包卫生问题换一个正确性门禁失效 |
| 从 `dist/` 里删除 `.js.map` 文件 | 同上，且会波及本地调试与覆盖率采集。收录层排除是唯一只影响交付物的位置 |
| 继续随包分发 | 体积换不到用户可感知的收益：安装包内没有符号消费者，也无人做线上崩溃栈还原 |

## 后果

- 安装包体积下降，且不再对外暴露内部源码结构。
- 用户报障时的堆栈不再能自动映射回 `.ts`，定位需在开发侧复现 —— 明确接受的代价。
- 加一条门禁断言守护该排除规则，防止 `build.files` 被后续改动无意放宽。
- 若将来要做线上崩溃栈还原，正确路径是**另立**一条受控的 sourcemap 上传流程（带 `sourcesContent`、只上传不随包分发），而不是把 `.js.map` 放回安装包。
