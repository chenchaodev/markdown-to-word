## 决定

1. **`test/segments/` 拆为 `test/core/` 与 `test/gates/`**，按**被测主体**归属，不按执行单元归属：

   | 段目录 | 镜像的被断言的树 | 段数 |
   |---|---|---|
   | `test/core/` | `src/core/` | 58 |
   | `test/main/` | `src/main/` | 34 |
   | `test/renderer/` | `src/renderer/` | 17 |
   | `test/gates/` | `gates/**` 与 `shared/**` | 17 |

   迁移是 `git mv`，不改段文件的断言。`test/gates/` 里的 17 段是被测主体在门禁树或机制层的段（含 2 段断言对象跨 `gates/` 与 `shared/` 的：`contract-single-source` 守扫描面与副本闭包契约、`entry-exit-guard` 测 `shared/entry-guard.mjs`）—— 归 `gates/` 桶的依据是「它们断言的对象在 `gates/` 与 `shared/`」，不是「跨了几层」。

2. **段目录的判据从「三目录枚举」改为「镜像一棵被断言的树」**，并补一条机械自检：

   - 判据实现：`shared/test-common-surface.js` 的 `checkSegmentMirrors(root, segmentDirs = SEGMENT_DIRS)`；
   - 判定口径：段目录名必须是**顶层某棵树的目录名**（顶层目录自身或其直接子目录 —— `core`/`main`/`renderer` 命中 `src/` 的三个子目录，`gates` 命中顶层 `gates/`）；`common` `fixtures` `acceptance` 三个 harness / 数据区 / 入口名被显式排除在镜像面外；
   - fail closed 点：`gates/repo/check-test-numbering.mjs` 与 `gates/repo/check-temp-cleanup.mjs` 各判一次，判红文案与判定同在单源。

   **判据的严格性不降，反倒多了一条可机械拦截的形态**：早先「三目录为全集」是**文档口径**，机械面只有「扫描面等式」（声明 == 磁盘）—— 新增第四个段目录并登记进 `SEGMENT_DIRS` 时，等式照样绿，而「不许开杂物抽屉」这条意图无人判定。现在枚举里混进一个不镜像任何树的目录（`test/pending/` 这类暂存区）会**判红并点名**，由两个自检夹具 + `contract-single-source` 段内两条负向锚点双向证明（不是恒绿断言）。

3. **`test/tools/` 取消，ADR-038 该条目标态就此达成**。该目录最后一个文件是 15 行的薄转调（`export { runSmoke } from "../../../dist/main/smoke.js";`），唯一消费者是 `packaged-smoke` 段里锁它的那组断言 —— 即「一个只为满足断言而存在的文件，其存在性被断言锁住」。随目录一并撤销的断言有：dev 入口与实现是同一函数对象、dev 入口单出口、dev 入口无实现痕迹、dev 入口单 specifier。**保留**的是同段内独立成立的那几条：主进程 `--smoke` 分支直连 `dist/main/smoke.js`、不引任何 `test/` 路径、单实例锁豁免、`app.exit(1)`，以及 `src/main/smoke.ts` 是实现唯一出处。

4. **四个段目录保持扁平，不加子目录**（沿用 ADR-038 的结论，只是目录名集合变了）。

## 背景

**一、`segments` 是执行单元的名字，不是被测主体的名字。** DEV-GUIDE「测试体系」节定的口径是「test 树镜像 src 三层，按被测主体归属」，而段名里的 `segments`（验收 runner 的一段）在全仓只出现在「段目录」这个执行概念上，从不指被测对象。75 段里 **17 段的被测主体在 `gates/` 或 `shared/`**（逐文件实读 import 面得出，见 evidence 的实测事实表）：`packaged-smoke` 消费 `gates/smoke/smoke-proc.mjs`、`install-smoke` 消费 `gates/artifacts/check-install-smoke.mjs`、`observability` 消费 `gates/smoke/smoke-report.mjs`……它们与 `gates/` 是**同域**的：断言门禁的判定面。对照面是干净的 —— `test/main/` 34 段与 `test/renderer/` 17 段中只有 `test/renderer/settings-controls.test.js` 一个 import `shared/`，其余零跨界。即 `main/` 与 `renderer/` 两层是纯粹的「测产品」，`segments/` 混了「测产品」与「测门禁」。

**后果是可计量的导航成本**：改一个冒烟门禁要去一个叫「core 渲染」的目录里找段文件（`packaged-smoke.test.js`），这个成本每次改门禁付一次，且新人按目录名判断段归属必然错判 17 次。

**二、「三目录恒等」这条口径的机械面有一个洞。** 判据被三处锁定（`shared/test-common-surface.js` 的 `SEGMENT_DIRS` · `test/acceptance.mjs` 的非递归发现 · `gates/fixtures/gen-fixtures.mjs` 的同构 `scan`，后两者引同一数组对象故恒等由「同一对象」保证）。但那三处锁的是**发现面**，锁不住「意图」：新增第四个段目录并登记进 `SEGMENT_DIRS` 时，发现面、扫描面、等式判据全部照常满足，唯一会说「这不对」的是文档里那句「三目录恒等」—— 而文档不是判据。这正是这棵树反复在治的失效形态（ADR-037 记录过同一形状：`MIN_SCAN_FILES` 的下限语义挡不住「少扫一个子目录」，实际扫描 142 个文件，下限只挡 walker 整体失效）。

**三、`test/tools/` 的取消在 ADR-038 写下时是目标态，落地时没达成。** ADR-039 用实测数据（19 个 `test/common/` 文件全部落在「自己 exit / 被 `package.json` 直接调用」两条判据的同一侧，判据退化为平凡判据）否掉了「按自检能力切分 `test/`」这条路，于是 `test/tools/` 剩下的 3 个真跨树文件（`entry-guard.mjs` `copy-closure.js` `userdata.js`）在 ADR-040/043 里下沉进了 `shared/`，`geometry` 三个模块在 ADR-049 归了位。抽屉清空后没人删目录本身，只剩那一个 15 行死文件 —— 而它还被断言锁着。

## 备选方案

1. **否决一：不开第四个目录，把 `segments/` 直接改名成 `core/`（即 17 段门禁段留在 `core/` 里）。** **不选**，理由：改名不解决「一个目录同时装两种被测主体」这件事本身，只是换了个更误导的名字 —— 目录名开始**承诺**「这里测 core」而实际有 23% 的段不测 core，比改名前更坏。DEV-GUIDE 的归属判例（跨层段看被测主体）会第一次被目录名本身违反。

2. **否决二：段与夹具 colocated（把段下沉到被断言的树旁边，如 `gates/repo/*.test.js`）。** **不选**，理由：**ADR-038 已有实测结论，本条直接引用**。三目录恒等已被三处锁定（`acceptance.mjs:43` 非递归发现、`gen-fixtures.mjs:5` 同构 scan、`fixture-contract.test.js` 断言恒等），89 段扁平是**被守卫的属性**而不是待清理的杂乱；且 colocated 会让门禁脚本与其段混在同一目录，门禁树的边界规则（`gates-stay-in-gates` 的 allow 面是 `gates`/`shared`/`test/fixtures`）要么放宽要么把段排除出扫描面，两条都是倒退。本条只**加**一个镜像对象（`gates/**`），不加**深度**（不分子目录），正是为了绕开这个已论证过的代价。

3. **否决三：保留 `test/tools/`，只把它从扫描面摘掉。** **不选**，理由：那 15 行文件的唯一价值是满足一条断言；摘掉扫描面等于承认「门禁不扫这个目录里的东西」，为一个死文件开一个规则豁免例外，与 ADR-050 刚消掉的「规则豁免的例外」直接冲突。

## 后果

- **收益：四对镜像，导航规则是「改哪棵树，去同名目录」。** 改一个冒烟门禁 → `test/gates/`；改 core 渲染 → `test/core/`。目录名从「执行单元」变成「被测主体」，与 DEV-GUIDE 的归属判例首次一致。
- **收益二：段目录判据第一次有了机械面。** 「不许开杂物抽屉」从文档口径变成 `checkSegmentMirrors` 的 fail closed 判定，且由三个负向夹具（两个门禁 selftest 各一条 + `contract-single-source` 段内两条）证明会判红。判据不再需要随段目录增减改文字。
- **代价一：`SEGMENT_DIRS` 从「三段目录」变成「段目录」，`test/tools` 的判定谓词（`*.js|.mjs`）随之删除。** 声明面从 5 个目录变 4 个，`SCAN_TARGETS` 的第三条消失。`contract-single-source` 段里那条「声明面恰好是这 5 个目录」的字符串断言与负向 B 的替身必须同步改（负向 B 的替身改用 `test/pending` —— 它历史上真存在过，是被删掉的暂存区，与「登记过后来整目录取消」是同一失效形态；原替身已随 `test/tools/` 一起不存在了）。
- **代价二：两个门禁 selftest 的 `BASE_SHAPE` 配额必须重分配。** 原 `16+11+11+6+6 = 50`（五目录）删掉第五个目录后塌到 44，**跌破 `MIN_SCAN_FILES = 50` 下限判红**。配额按实测段数比（58 : 17）重分配到 `core` 与 `gates`，`main`/`renderer`/`common` 保持原值 —— `common` 是等式之外唯一的非段目录、也是 `check-temp-cleanup` 的判定对象，压太低会让「walker 整体失效」那条负向夹具的前提不可靠。夹具还须为每个段目录**额外造出顶层的同名空树**，否则新增的镜像判据在夹具里恒红。
- **代价三：路径字面量在本条中被改动 60 余处**，其中三处是**运行时路径**而非注释，改错只在实跑时红：`gates/probe/gate-probes/registry.mjs` 的 20 余条段探针 `ref`（`gate-probes` 阴性探针实跑时会校验 ref 指向的段存在）、`gates/probe/gate-probes/gates/dual-matrix.mjs` 的 `SEGMENT_RELATIVE`（把差异矩阵段复制进沙盒改）、`gates/probe/gate-probes/coverage-baseline.json` 的单源指针文案。`test/fixtures/docs/README.md` 是 `gen:fixtures` 的生成产物，其段路径列随之重生成（`check:fixtures` 逐字节比对，不重生成即判红）。
- **代价四：本条**不改**树边界规则。** `test-stay-in-test` 的 allow 面是 allow-list 形态（`test`/`dist`/`tools`/`shared`/`gates`），新目录默认在允许面内；`gates-stay-in-gates` 的 allow 面是 `gates`/`shared`/`test/fixtures`，不含 `test/gates/` —— 故 `test/gates/` 里的段不得被 `gates/` import（方向是 `test/gates/` → `gates/`，不违反）。加规则反而是把「新目标默认非法」退回成「枚举已知」。
- **已知残留**：`src/**/*.ts` 与 `tools/visual-preload.cjs` 的注释里仍有 5 处指向旧段路径的历史指针（它们是产品代码与工具树，不在本条的写集内），照「旧条不改动」的同款理由留给下一轮；它们不影响任何判据（纯注释，无运行时路径）。
