## 决定

门禁自检缺不缺，用**两条可 grep 的事实**判，不用主观归属、不用文件头注释语义：

1. **归属判据**：一个文件归 `shared/` 还是归 `test/`，只看**是否存在来自 `test/` 目录树之外的 `import`**。这条事实同时就是 [ADR-038](ADR-038-gates-test-shared三层与跨树边界.md) 边界规则的执行者 —— 判定与执行合一。
2. **覆盖判据**：每个门禁**必须**有至少一条能证明它会红的探针，缺探针即判红。属性从 opt-in 变必填。落地分两步：先补齐现存 7 项缺口，再把必填化变成门禁本身。

自检载体保持**一套机制三种驱动器**（CLI / 沙盒探针 / 验收段），差异只在能否在 `build` 前运行，不在机制。

## 背景

设计上曾以「**能否自己让 CI 变红**」作为整套划分的支点，声称可无主观取舍地拆 `test/common/` 与 `test/tools/`。实测该判据在 `test/common/` 19 个文件上**退化为平凡判据**：19 个文件无一自己 `exit`、无一被 `package.json` 直接调用（`package.json` 对 `test/` 的引用只在 `:41 :42 :44 :46`，指向 `test/tools/*` 与 `acceptance.mjs`），判据两条正面判据全不满足、反面全满足 ⇒ 19/19 落在同一侧，无法支撑任何内部切分。且这是循环论证：判据的立论基础是「9 条跨树 import 全指向纯机制」，而那 9 条实际只落在 3 个文件上。

真跨树的只有 3 个：`entry-guard.mjs`（被 `check-geometry.mjs:96` 与 `test/tools/visual-check.mjs:39` 复用，4 处，最硬的候选）、`copy-closure.js`（`check-temp-cleanup.mjs:77`）、`userdata.js`（`smoke-proc.mjs:25`）。其余 16 个零跨界证据。

覆盖侧：`gate-probes/contract.mjs:49-56` 的 `GATE_IDS` **只有 6 项**，而 `package.json` 有 20+ 门禁脚本。**7 项既无探针也无测试段**：`transform-dispatch` / `test-numbering` / `temp-cleanup` / `docs` / `archive-index` / `contract`(`:selftest`) / `coverage-zero`。

其中 `coverage-zero` 值得单记：它被两处文件头显式「互让」掉 —— `gates/coverage.mjs:241` 写「npm run build 前半段不在本探针判定面」，`coverage-gate.test.js:24` 写「`--zero` 承担…故不放本段」。互让的结果是没人守。它**在** `verify:ci` 链上（第 12 步）但**不在** `REQUIRED_CI_STEPS` 的 11 条里（`check-ci-contract.mjs:261-273`），所以从链上删掉它契约也不会报红。

「重叠」的说法也被推翻一半：`coverage` 的探针与测试段**根本不重叠** —— 探针真起 c8 进程验 `package.json` 真实参数向量（`gates/coverage.mjs:147-160`），测试段只做静态审计（`coverage-gate.test.js:58-59` 调 `loadBaseline` + `auditStatic`），一次都不执行 c8；探针文件头 `:11-13` 自述「两层职责不同，缺一不可」。只有 `dist-manifest` 真重叠，且探针是测试段的真子集。

## 备选方案

| 方案 | 不选的理由 |
|---|---|
| 继续用「能否让 CI 变红」作归属判据 | 实测退化为平凡判据，见背景。且唯一真边界 `segment-host.mjs`（全目录唯一自己 `exit` 的模块，却只由 `runner.js:402` 派生、不被 `package.json` 调用）说明「自己会 exit」这一支没有约束「exit 的码被谁消费」 |
| 按文件头注释语义判归属 | 无反向证据。设计给出的「8 归 `shared/` / 11 留测试树」只能这么得出，而按跨树 import 重判是 3 / 16 —— 差异 5 个，且多算的那 5 个（`temp-resource` 路径耦合、`paths` `assert` `case`）零跨界证据 |
| 把 `coverage` 与 `dist-manifest` 的双探针收敛为单探针 | `coverage` 会丢能力：删探针后「`--check-coverage` 被删」这类漂移失去守护，静态审计只能发现「阈值与基线不一致」（即有人同时改了两处），发现不了「c8 实际不再检查覆盖率」。另会丢掉 `--exclude` 生效性断言（`gates/coverage.mjs:176`）。`dist-manifest` 才可收敛，且仅丢「默认参数路径 + 沙盒副本」这一窄面 |
| 探针保持 opt-in，不改 | 「要有才加」意味着新增门禁可以不带自检，而这正是 7 项缺口的成因。缺口本身说明 opt-in 已被事实否决 |
| 只补探针、不补验收段 | 探针证明「会红」，不证明「判据语义对」。二者缺一不可 —— `coverage` 的两层正好演示了这一点 |
| 把 7 项缺口一律补成探针 | `check:contract` 类门禁必须在 `build` 之前、`dist` 不存在、验收 harness 坏掉时仍能运行，它是 `verify:ci` 的第 1–2 步，只能用 CLI 驱动器。约束的是驱动器不是机制 |

## 后果

- `coverage` 的两层自检必须**都保留**，不得收敛。这是本条最容易违反的一条。
- 探针必填化之后，新增门禁若不带探针，`check:gates` 自身即判红。落地顺序是「先补 7 项缺口 → 再开必填化」，否则必填化会立刻把现存缺口变成一片红。
- 3 处「探针独有、测试段无兜底」的负向是真单源，任何收敛方案都不得动：`fixtures` 的 content-drift / missing（`fixtures.mjs:77-109`）、`dual-matrix` 的两条 covers 负向（`dual-matrix.mjs:124-175`）、`smoke` 的「转换核心被桩掉后冒烟必须非 0 退出」（`app.mjs:169-182`）。
- 归属判据与边界规则同源，意味着「判定用哪条事实」和「门禁查哪条事实」不会再各说各话 —— 这是相对原设计最主要的改进。
- `test/common/` 16 个零跨界文件留测试树是**默认结果而非刻意选择**。将来若有第 4 条跨树 import 出现，归属会机械地跟着变，不依赖人记得改。
