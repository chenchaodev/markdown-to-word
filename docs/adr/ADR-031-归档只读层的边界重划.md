# ADR-031 · 归档只读层的边界重划：约束分析正文，不约束目录维护类指针

| 项 | 值 |
|---|---|
| 状态 | 现行 |
| 日期 | 2026-09-29 |
| 关系 | **部分取代 [adr-020](adr-020-文档体系迁移.md) 决定 5 的「按只读历史对待」一句** —— 那一整层仍归 `docs/archive/`，但「只读」的约束对象由「整份文件」收窄为「分析正文」。adr-020 的决定 1/2/3/4/6/7 与其门禁接线均不受本条影响。 |

## 决定

「只读历史层」约束的**对象是分析正文**，不是整份文件。据此把 `docs/archive/` 内的改动分成两类：

| 类别 | 定义 | 可否改 |
|---|---|---|
| **分析正文** | 结论、数值、判断、方案取舍、步序记录、否决理由 —— 即「当时说了什么、怎么推出来的」 | **不可覆写**。哪怕今天看���该更新：那是**另开一次分析**并另立载体，不是修指针 |
| **目录维护类指针** | 相对路径、载体改名 / 移层后的指向、跨文件链接 | **可修**。前提是改动**只落在「指向哪个文件」上**，一个字都不触及分析正文的语义 |

**判据一句话**：看这次改动改的是「指向哪个文件」还是「说了什么」——前者可改，后者不可。

**本条不动的两件事**：

1. **`docs/archive/` 仍在指针门禁扫描面外**（`PROJECT_EXCLUDE_DIRS`）。边界重划解决的是「能不能改」，**不是**「改完会不会自动变红」。死链在本层仍不会自动报红，这是已知且接受的代价 —— 自动化覆盖与历史保真之间的取舍本轮不重开。
2. **裸文件名的历史引用不因本条而变成可改对象**。它们不断言位置（见下条备选方案），属分析正文的一部分。

## 背景

adr-020 决定 5 把已闭环的验收明细层与技术事实层整层移入 `docs/archive/`，「按只读历史对待」。这句话写得太宽，宽到**把两类性质完全不同的东西一并冻住**：

- 迁移把文件换了目录，于是文件内**按旧位置写的相对路径**集体失效 —— 归档件里有三处链接指向仓根的 README，相对前缀却只退了一级，从归档目录解析过去落在 `docs/` 下，而那里从来没有这份 README。
- 而这些失效路径**恰好落在这批文件里**，因为只有被移层的那批文件才会写错相对路径。

结果是：越是一次大迁移，冻结层里的死链越多；而门禁整棵排除该层，**这些死链永远不会自动变红**，只能靠人偶然读到。2026-09-27 的迁移台账里就有 4 处这样的死链（3 处指向不存在的 README + 1 处指向迁移后已删除的载体），同批实读还查出同类若干处。

**为什么这构成「反转决定」而不是「澄清后果」**：被收窄的那句约束（`按只读历史对待`）位于 adr-020 的**决定 5**，不在其后果节。后果节记的是这条决定的代价，不是这条决定本身。改动它等于改动 adr-020 决定了什么 —— 故按 [adr/README.md](../adr/README.md)「取代写法」，**不改 adr-020 的决定正文**，另立本条并把它的状态标为部分被取代。

原先迟迟不修的理由是「改它等于改只读材料」—— 这条理由在**原宽度下成立**：那时没有区分「改指向」与「改说法」，两者都被算作改材料。区分之后，这个阻塞不再成立。

## 备选方案

| 方案 | 不选的理由 |
|---|---|
| **就地追加到 adr-020 后果节，不动决定**（原派工写法） | 约束句本身在决定 5。写进后果节会造成「决定说只读、后果说可改」两处并存 —— 正是全局规则禁止的「两处互相矛盾的写法」，且后来者不知以哪处为准 |
| **把 `docs/archive/` 纳入门禁扫描面**，靠机器守住 | 门禁对历史语境的裸文件名（迁移前那批已删的路线图类文档、设计规范的两份文档等）**必然误报**，而「修」这些误报就等于篡改历史。门禁自己的注释也把这条列为当初整棵排除的理由。这属另一条决策（门禁能力），不在本轮 |
| **顺手把裸文件名的历史引用也改成现行路径** | 裸名不断言位置（读者从上下文能懂指的是哪个文件），改它不增加可达性，只增加「历史文本被现代化」的改动面。**明确划在只读侧之外** |
| **只修本次这 9 处，不写边界** | 下次迁移还会再造一批，而没人知道能不能改 —— 边界不落纸，「能不能改」就每轮重新吵一遍。这正是本条存在的理由 |
| **解冻整层（恢复可改）** | 越界成本太高：分析正文被覆写后，归档层就失去「这是当时的原话」这一唯一属性，而这是它区别于 git 历史的全部价值 |

## 后果

- **本条约束的**：任何想把「只读」扩回「整份文件不可动」的改动，或想连裸名引用一起改的改动，都必须先推翻本条。
- **可预期的副作用**：归档层内**允许出现「分析正文未被改动、但路径被更新过」的文件**。日后核对归档件与历史原文时，须比对**分析正文**，不能整文件做逐字比对 —— 否则会把这条例外误判成篡改。这是本条明确接受的代价。
- **不做门禁接线**：本条不新增任何机器校验。改完的指针靠本轮实跑核对，不靠常驻门禁。
- **本轮实际改动**（分析正文零改动，只动指向）：台账 4 处（3 处根 README 链接各补一级 `../` 改为从仓根解析，1 处指向已删载体者脱链并注明载体已删）+ 同类 5 处（设计规范两份文档各补 `../` 前缀、迁移决策 ADR 补 `../adr/` 前缀、两处同目录引用去掉多余的 `archive/` 前缀）。
