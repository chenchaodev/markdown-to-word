# ADR-081 · 页眉 default 档承载单位

| 项 | 值 |
|---|---|
| 状态 | 现行 |
| 日期 | 2026-10-19 |
| 关联 | [ADR-030](ADR-030-水印与页眉裁决及矩阵补行.md) 6-B3（页眉的定位是承载身份信息，双管线取 docx 侧为准）｜ 身份行单源 [`src/core/pipeline/header-identity.ts`](../../src/core/pipeline/header-identity.ts) ｜ 两侧消费 [`src/core/docx/headers.ts`](../../src/core/docx/headers.ts) 与 [`src/core/pdf/template.ts`](../../src/core/pdf/template.ts) ｜ 单位字段来源 [ADR-078](ADR-078-frontmatter元数据契约与产物属性落点.md) ｜ **不触发** [ADR-024](ADR-024-设置分组与渲染前变换层下沉.md) / [ADR-028](ADR-028-持久化schema表与上下文契约.md)（零新增设置键） |

## 决定

页眉 `headerMode: "default"` 的内容由「文档标题」扩为**身份行 = 标题 · 单位**：

1. **取值**：标题沿用既有优先级（frontmatter `title` 优先，其次文件名派生标题）；单位取 frontmatter `organization`（封面已消费的同一字段）。两者各自 trim、丢弃空项，以 `" · "` 连接。
2. **装配条件**：身份行非空才装配页眉。只有单位、没有标题时**也出页眉**（单位单独成行）；两者都空时不装配 —— 与既有「无标题不出页眉」同向，只是判据从「标题」换成「身份行」。
3. **单一来源**：拼接只在 `headerIdentityText` 一处，docx 与 pdf 各自调用它取串，**不得在任一渲染器侧自行拼**。`custom` / `none` 两档与水印合并逻辑不变。
4. **不新增档位、不引入 `headerText` 占位符**，也不把单位变成可单独开关的设置项。

## 背景

页眉在 2026-08 的裁决里定位为**承载身份信息**（ADR-030 6-B3），当时只有标题可承载；单位自 4.3.0 起已进 frontmatter 与封面（ADR-078），页眉却仍只显示标题 —— 同一份身份信息在封面有、在每页页眉没有。产品侧在「扩 default 档」与「新增档位 / 占位符」之间选了前者。

## 备选方案

1. **新增第 4 档或给 `headerText` 加 `{title}` / `{org}` 占位符** —— 否决。要加枚举档位、白名单、几何规格、声明表与向导步 ⇒ 触发 ADR-024 / ADR-028 的持久化面，并把一个「默认就该显示什么」的问题变成用户必须先学会配置的问题。占位符还会引入第二套插值语法与转义责任。
2. **只在封面显示单位，页眉保持纯标题** —— 否决。页眉存在的意义就是每页复述身份；封面只在第一页。
3. **单位在页眉另起一行** —— 否决。页眉高度与字号口径（7pt / 灰色）是为单行设计的，第二行会挤压正文版心且与「标题居中」的既有观感冲突；`·` 分隔与 pdf 封面 metaLine 的写法一致，不新增样式。

## 后果

- **可见行为变更（仅限带单位的文档）**：default 档页眉由「标题」变为「标题 · 单位」；只有 `organization` 的文档从「无页眉」变为「有单位页眉」。**没有单位的文档输出一字不变** —— 这是 A 案与 B 案的关键差别，也是选 A 的原因之一。
- **双管线一致**：docx 与 pdf 的 default 页眉文案由同一个纯函数给出，测试在两侧产物上各自断言整串。若日后新增身份字段（如院系、日期），只改 `headerIdentityText` 并同步两侧断言，不要在渲染器里加分支。
- **文档面**：页眉模式的用户说明与设计 IA 同步为「标题 · 单位居中，缺项跳过」。
- **未实测**：WPS 对页眉文本的读取属既有能力，本次只是内容变长，未新增实测项。
