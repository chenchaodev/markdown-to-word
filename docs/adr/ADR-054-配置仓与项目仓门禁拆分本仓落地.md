## 背景

**触发事实。** 本仓 `gates/repo/check-docs.mjs` 是薄包装，`exec` 仓外 `~/.config/opencode/tools/check-pointers.mjs` 做判定；载体不可达时打印「未判定」并 `exit 0`；该检查在门禁注册表登记为 `access: "local"`，**刻意不在 `verify:ci` 链上**。本仓公开（`CONTRIBUTING.md` 明确邀请 Fork），而 `docs/DEV-GUIDE.md` 的开发回路要求改文档后跑 `check:docs` ⇒ **任何 Fork 出去的 PR，文档指针零覆盖而门禁报成功**。

这违反全局 `tools/AGENTS.md` 点名的形态：「触发 0 处 = 零覆盖，不是『查过没问题』」「『载体不可达就 exit 0』的静默跳过是『以为被查过』的形态」。而本仓单方面修不了 —— 判据本体在仓外。

**上游已把方向与边界裁定完。** 配置仓 `ADR-016` 决定三给出「按对象在哪，不按代码在哪」的归属表，并明写「**不执行拆分，拆分方案由项目仓出**」。本条即那份方案。上游基线 `72f072a`，工作树干净，拆分未执行。

**落地前存量实测**（cwd = 本仓跑上游门禁，`EXIT=0`）：项目模式扫描 67 份、0 错误；载体形态 C1/C2/C4/C5/C6 量过 305 处、判红 0 条；台账 R1–R7 判定 7/7 共 0 错误；跨仓路径触发 23 处。⇒ **本条落地当天不会假红。**

**工作量实测**（口径同 `ADR-016` 背景 3：按顶层定义切段、含文档注释块）：配置仓独占 1294 行 · 下游独占 803 行 · **共享基础设施 1502 行** · `main` 344 行（下游单模式重写约 140 行）⇒ 落地实测**本仓文件 1637 行**（含文档注释）：比毛估少，因 `main` 按单模式重写、配置侧自报段落整体删除。行数为「该版本的发布事实」，照写；后续重构会让它变，届时随提交更新。`ADR-016` 背景 3 说「只盯那 16% 会低估工作量一个量级」—— 本条确认，并补一句：那 16% 是**净减法**，真正的工作量是那 1502 行必须**复制**，而 `ADR-016` 备选方案 3 已否决「留配置仓共用」。

## 决定

**一、完全拆分，本仓自持门禁脚本，落在 `gates/repo/check-pointers.mjs`，只含项目模式。**
配置仓独占的 1294 行不移植。门禁根一律取 `shared/paths.js` 的 `ROOT`，本文件内不得再出现第二处仓根字面量。

**二、`ADR-016` 决定三第 1 行的读法在此落边界。**
该行「指针存在性 · 小节名 · 无引号序数小节 → 配置仓」的依据列描述的是**各判据在配置仓那次运行里的对象**；归属规则首句是「按对象在哪」，故**同一判据在下游对象上的实例归下游**。本仓据此持有：指针存在性（第 1/3/5 档）· 台账 R1–R7 · 载体形态 C1/C2/C4/C5/C6 · 跨仓路径。

**若按字面读成「下游不检查自己的指针」，`check:docs` 在本仓将只剩 R1–R7 与 C 组，拆分目的落空** —— 该读法与同一张表第 3 行的分列方式自相矛盾（第 3 行说「配置仓恒无对象」的归下游，反过来第 1 行对象在本仓的自然也归本仓）。

**三、台账形态上限的三个常量在本仓门禁文件内各留一份；T2 不搬，门禁文件内留 tombstone。**
`ADR-016` 决定三把 T2 划给配置仓（对象是全局配置目录 `DOC-SYSTEM.md` 那一行）—— **但它没有裁定本仓的常量住在哪**，而 C1/C2 归本仓且必须有一个数字。故拆分后世上存在三份 20/200/100：配置仓常量、T2 守着的全局配置目录 `DOC-SYSTEM.md`、**本仓常量（无判据守着）**。本仓**不造第二份人读源**（撞 `AGENTS.md`「各列上限只在全局配置目录维护、禁回抄」的勿回退条款），改为把 `AGENTS.md` 那一行改成指本仓门禁为**强制点**。tombstone 须写明**理由**（归属已裁定 + 两份拷贝的前提在本仓不成立），不是只写「已退役」。

**四、跨仓路径只保留分类，不保留判定；盲区必须出声且进结论行 `gaps`。**
该判据的判红基准是全局配置目录的 `exists`/`read`，而其消歧判据是「项目里解析不到」—— 拆分后两者在本仓指向同一目录，**照搬得到的是确定性假红**（当前 23 处触发全红），不是精度下降。三条分类口径是纯本仓判据，原样保留；判定一步替换为不可判自报，写明「**分类 N 处 · 判定 0 处 · 未判，非『查过没问题』**」并推进 `覆盖:不全(...)`。

⚠️ **拆分后没有任何机器会判这一族**：配置仓那份脚本按决定三不含本判据，而它在配置仓 `PROJECT_ROOT` 恒 null ⇒ 双侧皆无执行体。这不是「本地能跑 CI 不能」，是**彻底无人判**。缓解只有一条且不引入任何代码路径、环境变量或开关：**`docs/DEV-GUIDE.md` 记一条维护者手动跑上游全量门禁的命令**。

**五、单元测试随判据一起搬进本仓，且先于判据搬。**
上游 `tools/ledger.test.mjs` 覆盖的正是本仓要复制的那些纯函数。逐块清点（74 块）的结果是：**直接可搬 36 块 · 搬移需改写 15 块 · 不搬 23 块 · 已裁定 9 块**。不搬的后果是：**单仓持有约 2445 行判据（其中 1502 行为复制品）而零单元测试**，只剩端到端夹具兜底 —— 比不拆分更危险（今天上游那 1574 行测试仍在跑）。

三处形态转换必须做到，缺一则测试等于没写：
1. 上游是 `.mjs` + `node:test` 的 `test(...)`，而本仓段机制只收 `test/<段目录>/*.test.js` 且要求导出 `async function run()` ⇒ **原样落进去不会被收集执行**。须逐块改写为 `createCaseSuite()` 的 `suite.case(...)`（`test/common/case.js`）。
2. 8 处夹具依赖 `templates/docs-init/`，本仓无 `templates/` ⇒ 夹具改为**内联构造**，不再 vendor 一份模板（那会再多一个会漂的副本）。
3. 已裁定块：`GLOBAL_GUIDE_NAMES` 随判据搬（跨仓判据的数据）；「两模式候选顺序相反」改写为**单模式下顺序不得依赖默认值**（`ADR-014` 决定二的原意在单模式下的存活形态）；「项目模式同样豁免」改写为单模式断言；「退出码按侧别」两块**不搬**（`ADR-016` 决定四已判该机制作废，其结论改由「各持脚本」这个结构性事实满足）。

**六、`check:docs` 挂进 `verify:ci`，`access` 同步改 `chain`；两者必须同一次提交改完。**
拆分后本仓 `main()` 没有侧别（`ADR-016` 决定四），故不需要 `configErrorCount` / `exitSideIsProject` / `失败侧:` / `退出码依据:` 四段。`check:docs` 排在 `check:docs:selftest` 之前。

**七、三处改动必须原子：`check-docs.mjs` / `check-pointers.mjs` / `check-docs.selftest.mjs` 同批。**
`check:docs:selftest` **已在 `verify:ci` 链上**并被注册表载体表登记、由「载体必须在链上」那条判据强制；旧自检十条夹具全部围绕仓外载体变量，拆分后全部判失败 ⇒ 分两步落地会让 `verify:ci` 中间态直接判红。

## 备选方案

| 方案 | 为何不选 |
|---|---|
| 引入 npm 依赖分发门禁 | 用户已裁决否决。补技术理由：判据要在本仓 `docs/evidence/` 留取证快照、判据文案要与本仓文档逐字对读，依赖升级会在无人裁决时改动判定语义 |
| 共享基础设施留配置仓共用 | **配置仓 `ADR-016` 备选方案 3 已否决** —— 那不是拆分，是把耦合从数据挪到代码 |
| 本仓造人读源 + 搬 T2 换对象 | 与决定三冲突；且会守「本仓门禁 ↔ 本仓那份没人读的文档」，而每会话自动投递的是全局链 ⇒ 全局改数值时形成静默分叉 |
| 跨仓路径保留仓外目录为可选 | 依赖回流，零配置目标被自己推翻；且 CI/Fork 上零覆盖而绿灯比现状更可信 |
| 跨仓路径整条不搬，只留豁免分支 | 那 23 处永久不可查**且自报区一字不提**；豁免表措辞读起来像「已处理」，是比「出声不判红」更纯的「以为被查过」 |
| 把「全局指南存在性」改成本仓声明式清单 | 那是**第三份「全局有哪些指南」的真源**，判的仍是「本仓清单 == 本仓清单」。与 `ADR-016` 重看条件「要把判据写法标准化，而不只是搬位置」反向 |
| 合并成一个文件（删 `check-docs.mjs`） | 两条以 `check-docs.mjs` 为合成主体的负向夹具（沙盒探针与验收段各一条）会命中一条已不在判定链上的文件，测试对象与被测对象脱钩 |
| 不搬单元测试，只靠端到端夹具 | 见决定五 |

## 后果

**得到的**

1. 任何 clone / Fork 零配置即可跑真实的文档指针判定；CI 与外部贡献者第一次真正被检查。链上成本实测 0.23–0.25s。
2. 本仓门禁判定面从「本地手动、常跳过」变成「链上必跑」，且判据与本仓文档同仓演进。
3. 配置仓那份脚本不再兼做下游判据的执行体。

**付出的（逐条）**

1. **判据从此两份**，规则演进要改两个仓 —— `ADR-016` 后果 1 已认领。
2. **两套可能漂移的豁免表与解析基准**（`ADR-016` 后果 2）。本仓具体清单：`skipReason` · `resolveRef` + `refDirOf` + 两个 order 常量 · `CONDITIONAL_CARRIERS` · `GLOBAL_GUIDE_NAMES` · `EXCLUDE_DIRS` · `REF_ALLOW` / `NOT_IN_SKELETON` / `NON_HEADING_QUOTES` · 解析计数三件套。**本仓不设机器对读**（那需要跨仓可达性，`ADR-016` 备选方案 3 已否决该形态）⇒ 唯一对冲是门禁文件头记录上游基线 commit 与本次搬移的差异清单，供人工重核。
3. **跨仓死指针在本仓彻底无人判**（决定四）。
4. **本仓常量与全局文档的三个数字之间无机器保证**（决定三）。
5. **`ADR-014` 决定二在本仓退化为单模式** —— `resolveRef` 的「方向相反 + 必须显式传参」不再需要。**须在门禁文件内写明这是 `ADR-014` 决定二在单模式下的退化，不是违反它**。同理 `EXCLUDE_DIRS` 在本仓**只排除 `docs/evidence`、不排除 `docs/adr`** —— 后者是被 `ADR-014` 备选方案 3 否决的**配置侧**口径，被对齐到本仓就是覆盖收缩，本仓 17 份 ADR 会静默移出扫描面。
6. **指针门禁对 `.mjs` 指针结构性失明**：上游 `REF_FORMS` 三条形态都以 `\.md` 收尾 ⇒ 门禁扫描面内的反引号 `.mjs` 引用**一条都判不到**。解析不到的引用分两类，**处置方式不同，不要混记成一个数**：多数是**路径前缀腐坏**（文件搬了家、引用没跟，basename 在仓内他处仍活着 ⇒ 可批量重写），少数是**真无同名文件**（需逐条查证）。

   **本条不写数量** —— 数量随文档增删而变，且本条先前记的两个数字按任何「扫描面 × 解析序」组合都复现不出来（试过 15 种组合，无一命中），照抄会让下一个核的人以为能核出来。

   **量法**：扫描面 = 仓根 `*.md` + 整个 `docs/` 递归，**`docs/evidence/` 整棵除外、`docs/adr/` 在面内**；抽取按 `REF_FORMS` 的形态；解析用判据本体导出的 `resolveRef` / `checkExistence`（引用方目录优先、仓根次之、无兜底）。⚠️ **没有一条与门禁完全等价的单行命令** —— 本体的 `collectProjectScope` 与 `REF_FORMS` 未导出，所以任何外部量法都要自己复刻扫描面与抽取形态；复刻版在当前文档树上计数与本体一致，但那不是恒等关系（文档里出现 `-foo.mjs` 这类首字符即分叉）。

   **拆分前既有的盲区、不由本条引入**，但挂链后「门禁绿」会被误读为「文档路径都对」。处置已另立条目，且**判据覆盖面与坏引用分开记** —— 判据扩了形态，那些坏引用仍要逐条修。
7. **并非每道搬来的判据都有单测**：清点显示指针存在性 / 小节名 / 无引号序数三档的单测（6 块）在上游被归配置仓、不搬。它们**有端到端夹具兜底**，但弱于单测一档。后果清单里「哪些判据有单测、哪些只有夹具」须分开记，不得混成一句「有测试覆盖」。

**不做**

- 不给门禁加任何模式开关、环境变量或「载体不可达即自动降级」的逃生阀（`ADR-015` 决定三 3 的论证在此同样适用；且已搬的「退出码单值 + 无降级开关」单测要求 vendor 文件里 `process.argv` 恰好 1 处、`process.env` 0 处）。
- 不改台账形状规则的来源：台账纪律仍在全局配置目录 `REQ-RULES.md`，载体表那一行在全局配置目录 `DOC-SYSTEM.md`。
- 不扩 `REF_FORMS` 到 `.mjs`。

**清上游欠条**

配置仓 `ADR-015` 已知缺口 1（下游包装脚本的退出码口径须注明按侧别）在本仓仍未清；拆分后本仓单模式 ⇒ 以「单模式取代按侧别计」清掉并在本条留记录。

## 实施约束

1. **入口守卫必须与本体同批落地**，且 `process.exitCode = main()` 那行**保持缩进**（自执行探测是行首锚定正则）。
2. **仓根只能取 `shared/paths.js` 的 `ROOT`**，本文件内不得再出现第二处仓根字面量。
3. **物理删除 `atConfigRepo` 与 `PROJECT_ROOT` 的三元判定** —— `cwd == ROOT` 时前者恒真 ⇒ `PROJECT_ROOT` 恒 null ⇒ 项目模式永不进入、退出码回落 ⇒ **零项目覆盖 + `exit 0``**。清点的实测表明这会造成**双向失真**（判红侧夹具恒红、豁免侧夹具恒绿，而恒绿那侧会把真洞永久放过）。
4. **禁止把「站在配置仓旁边」那套基准带进来**（判红基准与消歧判据必须指向不同目录）。
5. **自检不得复制门禁本体**：夹具在系统临时目录现造合成项目仓、靠 `cwd` 指向它跑仓内真门禁。这条依赖「`PROJECT_ROOT` 恒等于 `process.cwd()`」，因此**本门禁不新增 `--root` 参数**。
6. **零覆盖必须出声**：跨仓路径「判定 0 处」与载体形态零覆盖一律进结论行 `覆盖:不全(...)`。
7. 改动既有文档前先读其头部；`ADR-034` 只改状态格，正文一字不动。
8. 判定本体变更必须同批更新注册表的 `access` / `judgmentNote` / `probes[].why` 与 `package.json` 链编排。
9. **注册表的 `judgment.module` 必须指向本体 `gates/repo/check-pointers.mjs`，不能指向转发层 `check-docs.mjs`。** 转发层只做「转出 `main` + 入口守卫」，而 R4b 只读 `judgment.module`、遇 `export function main` 的本地声明即返回、不追转发链 ⇒ 指向转发层时**本体去掉入口守卫不会被任何判据抓到**（已实测：指向转发层 exit 0，指向本体 exit 1 + `judgment-load-mismatch`）。`check-docs.mjs` 仍是 npm script 的执行入口，两者并存不冲突。
12. **负向夹具的故障注入载体不得选「决定六会改成链上」的门禁。** 决定六把 `check:docs` 挂上链后，以它为载体的两条夹具（沙盒探针的 `fault-access-declared-unreachable` 与验收段的「声明可达但实际没人调」）其注入（把 `access` 改成 `chain` 且 script 不在链上）**变成空操作 ⇒ 夹具恒绿**，即「断言恒真」那一族。
    修法两条同时要：**① 换载体**到一条 `access: "local"` 且其 script 确定不在任何链上的门禁（候选 `install-smoke` / `pack-size`，已实测可用）；**② 在夹具内先断言载体此刻确为 `local`**，不成立即判红 —— 否则将来有人把那条也挂上链，夹具会**静默退化成恒绿**，而门禁全绿里看不出差别。
    本条是实施约束 8 的连带项：**挂链类改动必须同时核对以被改门禁为载体的负向夹具**。
10. **`REQ-0NN` 红线在本仓有一处结构性例外并在此登记**：判定本体含两条校验台账号形态的正则（`LEDGER_ID_RE = /^REQ-\d{3}$/`、`LEDGER_NUM_RE = /^REQ-(\d{3})/`），**去掉它们判据就无法识别台账号形态，C1/C2 与 R3 全部失效** ⇒ 保留。随之而来的形态示例注释（`REQ-000` 零值占位、四位数 `REQ-0030` 拒绝位、墓碑 `~~REQ-004~~`）也保留，且注释已明写「`REQ-000` 是号段的零值占位，**不是工作项号**」。这是「登记例外」而非「默认放行」—— 全局规则的可豁免形态是「写明依据」，不是沉默。自检夹具里的合成台账号同理（它必须用真形态才能验出真判红）。
11. **搬入本仓的测试代码须按本仓门禁改写，不得进 ALLOWLIST**：测试段里的 `C1`/`C2`/`C5` 字面量会触发 `check-test-numbering`（规划编号登记制），临时目录删除须走 `test/common/temp-resource.js` 的 `removeTree`。两处都**改代码**而不是登记豁免 —— 全局规则明写「能修引用就不登记例外，豁免表会腐烂」。
