## 决定

设置抽屉的**六组边界不动**，改在组内加段标签层、组间加跨组检索，并把水印总闸落成三档（无 / 文字 / 图片，第三档标「规划中」并灰禁）：

1. **六组边界不动**。用户反馈的「找不到」诊断为**组内平铺无层级 + 组间无检索**，不是分组边界错；本轮只补这两层。
2. **组内加段标签**：02 排版拆「页面 / 文字 / 段落」，03 页眉页脚与水印加「水印」段标签，05 转换拆「清理 / 产物 / PDF 样式」。
3. **`tocMode` 由原生 `<select>` 改两档 seg**。现 `<select id="tocMode" class="toc-mode-select">`（`src/renderer/index.html:761`）的 `toc-mode-select` 类在 `style/` 与 `src/` 内**零命中**，是死类；seg 化后该类不再存在。
4. **抽屉内加跨组搜索**，控件标签经**声明表新增 `labelKey` 字段**做真单源；水印总闸取三档，第三档「图片水印」标「规划中」并**灰禁 + 配一行可见说明**（照 AI 清理分档的既有做法）。

## 背景

抽屉当前形态是「六组 Tab 平铺，每组一长列控件」。两类症状：① 组内长列没有中间锚点，控件一多就只能顺着找；② 组间没有检索入口，想找「导出后行为」要先知道它在 05 组；窄窗（≤1080px）下 05 组那一行甚至点不到。

先验过的分组假设是「六组边界划错了，应改八组」或「应在常用 / 进阶两级折叠」，下面记录它们被否掉的事实依据，以及被选方案要连带动到的文件清单。

## 备选方案

1. **八组制**（在六组基础上再拆两组）—— 否决。成本不在「拆得多好看」，而在几何判定层与声明表是**多处同改、且有几处是硬编码计数**：须同改 `shared/geometry/geometry-spec.mjs` 的 `DRAWER_GROUPS` / `DRAWER_CONTROLS` / `DRAWER_GROUP_BY_KEY` / `DRAWER_CONDITIONS` 四表 + 声明表 `ControlGroup` 联合（`src/renderer/settings/settings-controls-table.ts:29`）+ 逐控件 `group:` 字面量（该文件 42 处，其中 40 处落在抽屉六组、2 处 `mirror`）+ `DRAWER_CONTROLS` 的逐控件基线表 + 两处 `=== 6` 计数断言（`test/renderer/ui-contract-guards.test.js:577` tab 数、`:599` `role="tabpanel"` 数）。收益却只解决「组内长」这一个症状 —— 而组内长正是段标签层直接治的。
2. **「常用 / 进阶」两级折叠**（组之上再套一层折叠）—— 否决，理由是硬的：`shared/geometry/geometry-core.mjs:342` 的可见性判定是 `const expectVisible = inActive && (condOn ?? true)`，这个表达式**只承认两种从属关系** —— `DRAWER_CONDITIONS`（条件从属项，未启用整块移除）与 `DRAWER_DISABLED_TIERS`（分档类从属项，灰禁不移除）。第三种形态（折叠层：未展开时其下控件既非「可见」也非「被主控收起」，而是「不在当前可见集内」）在几何判定层**无处安放**：塞进 `condOn` 会与 `DRAWER_CONDITIONS` 的语义混同、塞进 `DRAWER_DISABLED_TIERS` 会把「收起」误报成「灰禁」。按 [ADR-071](ADR-071-两处判据的形态裁决.md)，给判据加第三种形态要先挂 `pending` 再转正 —— 那是独立一条工作线，不该混进这次抽屉重构。
3. **renderer 侧另抄一份「控件 → 标签」映射**供搜索用** —— 否决。声明表的扁平视图 `controlTable()`（`settings-controls-table.ts:873`）是测试侧四项交叉校验（逐控件 ⇄ 声明表、声明表 ⇄ `index.html`、声明表 ⇄ 几何规格、复位块覆盖）的**唯一读入口**，其文件头注释明写「一律经它读，**不各自重述键与 id**」。另抄一份映射就是重述一份，既躲过这四项校验、也会与标签文案分叉。故走**声明表新增 `labelKey` 字段**：标签 key 与控件 key 落在同一条声明上，搜索经它取，renderer 侧不存在第二份清单。

## 后果

- **水印总闸第三档不是新增能力**：图片水印这一档本期只落「档位 + 规划中标 + 灰禁 + 可见说明行」，不落渲染实现。灰禁按 `docs/design/settings-ia.md` §3 规则 1 的唯一例外处理 —— 不靠裸 `disabled`，必须配一行可见文字（AI 清理两个分档的既有做法：`settings.aiCleanupTiersLocked`）。
- **若第三档日后要真接上**，`AppSettings` 会新增持久化键，触发 [ADR-024](ADR-024-设置分组与渲染前变换层下沉.md) §一（新键同时补整文件形状校验与字段级兜底，不得只补其一）与 §四（迁移让存量用户产物逐字节一致）。本条**不预先批准**该持久化。
- **段标签不是折叠层**：段标签只做视觉分段与搜索落点定位，不引入第三种可见性形态，因此**不触碰**几何判定层（`expectVisible` 表达式不变）。
- **字典侧连带**（与本条同批落地）：两代组名键收敛为一代；组名统一取「应用」；zh 组名的字间硬空格删净、字距效果改由 CSS `letter-spacing` 出（同批的 P1 视觉步负责落 token）。
- **已知缺口（三条，均已 grep 取证，本步不删）**：
  - `settings.groupHeaderFooter` / `settings.groupWatermark` **不是组名键** —— 它们是 `presetCoveredGroupLabels()`（`src/renderer/settings/settings-bindings-preset.ts:58,61`）为预设切换 toast 拼的「被覆盖项」标签，与新组「页眉页脚与水印」不是同一语义。该文件不在本工作线任何一步的可写清单内，故本步不删；要收敛须先扩可写清单或另起工作线。
  - `settings.groupAppearance` **不是组名** —— 它是 `index.html:887-888` 复用的主题行 aria-label，保留。
  - `settings.cssTooLarge` 经 grep 确认**已在用**（`src/main/ipc/register.ts:649` 经 `t()` 接入 CSS 体积上限分支，`src/main` 侧**无**硬编码中文字面量），故不在孤儿键之列、不删。
