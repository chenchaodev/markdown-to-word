# ADR-033 · 差异矩阵的键覆盖状态改为机器可读，并接进阴性自检门禁

| 项 | 值 |
|---|---|
| 状态 | 现行 |
| 日期 | 2026-09-30 |
| 关联 | [REQ-084](../REQ.md) · 波次 5 · 排期载体 `docs/large/01-非功能需求排期.md`（收尾时入档） |
| 命名 | 与既有 32 条一致用 `adr-0NN-` 前缀（`ADR-0NN-` 大写形态属 REQ-101 迁移范围） |

## 决定

给双管线差异矩阵的**键覆盖状态**一个机器可读的登记，并把它接进阴性自检门禁。

1. **登记形状 = 段级键集合 + 逐行 `covers` 标注**（两个数据源、一个判定函数）：
   - `DUAL_PIPELINE_KEYS`（台账段，8 键 + `semantic` + `note`）= 段自己声明「应覆盖哪些键」，取代原先**只存在于矩阵段头注释里**的名单。
   - `covers: string[]`（矩阵行，26 行全有，20 行为 `[]`）= 每行声明自己覆盖哪些键。
   - `assertKeyCoverageRegistered()` 断三个方向：键集合自身合法（id 唯一 / `semantic` 非空）· **每个声明的键至少被一行 `covers` 命中** · **`covers` 里的键都在声明集合内**；另在矩阵行内断第四条：**`covers` 字段必须显式存在**（`[]` 合法，省字段判红）。
2. 登记落在**测试段内**，不下沉 core —— 沿用 [adr-030](adr-030-水印与页眉裁决及矩阵补行.md) 与该段既有的「矩阵是测试契约」理由。
3. 阴性自检接进 `check:gates`：新增 `GATE_IDS` 一项 `dual-matrix` + `scripts/gate-probes/gates/dual-matrix.mjs`，判定命令 `M2W_ONLY=dual-pipeline-matrix electron test/acceptance.mjs`，判据面是矩阵段内既有的 `assertMatrixShape`（**判定口径单源，探针不复制判定逻辑**）。
4. **不改** `verify:ci` 链、不新增 npm 脚本、不改 `check-ci-contract.mjs` 的 `REQUIRED_CI_STEPS`。

## 背景

8 个双管线键的覆盖状态此前**只存在于 `dual-pipeline-matrix.test.js:9-12` 的注释里**，矩阵行无任何可判字段。

后果有实证：补行之前 `typography` / `breakBeforeH1` / `headerFooter` / `watermark` 四个键**零覆盖**，而两处**已确认的「设置项在一侧静默失效」**（水印不透明度在 docx 侧零消费、页眉 default 模式在 pdf 侧整体静默）恰好落在这片零覆盖区。它们能静默那么久，直接原因就是**「有没有被覆盖」不可判** —— 改注释不会让任何东西变红。

台账侧已有的 `MATRIX_ROW_IDS` / `MATRIX_ROW_TO_LEDGER` 登记只管「新增矩阵行」，**管不到「新增双管线键」**。REQ-084 的真实目的不是「跑矩阵」，是**防将来忘写**。

## 备选方案

1. ❌ **只在段头注释里补一份键清单** —— 与现状同构，注释不可判，零新增约束。
2. ❌ **只加逐行 `covers`，不要段级键集合** —— 只答得了「这行覆盖了啥」，答不了「有没有键没人管」：新加一个键而不补行时，旧行一句不多一句不少，**全绿** —— 正是本条要防的那一种忘写。
3. ❌ **只加段级「键 → 行 id」映射表，不要逐行标注** —— 答得了「有没有键没人管」，答不了「这行声称覆盖的是不是真覆盖」：映射里写一个早已不存在的行 id 无人察觉；且该形态的故障注入点与真实维护动作（改矩阵行）不同源。
4. ✅ **段级声明 + 逐行标注的组合（本决定）** —— 代价是多一处要同步的字段，换来两个方向各自可判，且与台账既有的「双侧互为漏登记探测器」形态同构。
5. ❌ **从 core 反向枚举共有字段求差集，判键集合的完备性** —— 那是从「发现工具」，与本段「台账是登记工具、不是发现工具」的口径冲突（45 项决策条目同理：来自一次人工枚举，不是从代码推导的完备集）。**列为不做项。**
6. ❌ **为形状守护另写 `scripts/check-*.mjs` 静态门禁（约 50ms、不必拉 Electron）** —— 它要复制一遍段内的判定逻辑（MATRIX 在段内、段内 import `dist/`），判定口径一旦两份就会漂移；本仓对「同一语义两处各写一份」一贯判红。**代价是每次门禁多花约 5.8s 的 Electron 启动。**
7. ❌ **把 `headingNumbering` / `captionNumbering` 也收进键集合** —— `captionNumbering` 已被 `caption-label-strip` 行实跑锁住（按「顺带锁住」处理）；`headingNumbering` 矩阵里确无对应行，收进来会让「每键至少一行覆盖」当场判红，而**补那行是新增矩阵行的活、不属本条（登记字段化）范围**。改为在登记表头注里**显式登记为已知缺口**，而不是让它看起来「表已完备」。

## 后果

- **跟改面**：26 个矩阵行各增一个 `covers` 字段（20 行为 `[]`）；台账段新增 `DUAL_PIPELINE_KEYS` / `assertKeyCoverageRegistered` / `keyCoverageCounts`；矩阵段 `assertMatrixShape` 与 `MatrixRow` typedef 增判据；`contract.mjs` 增 1 个 `GATE_IDS` 项与 `GATE_META` 项；新增 1 个探针文件；`report.mjs` 增 3 处接线；`gate-probes.test.js` 增 1 条 case 名标签；矩阵段 `meta.description` 变更导致 `samples/docs/README.md` 需重生成。**无生产代码改动，无用户可观察的行为变化。**
- **常驻成本（实测）**：单次门禁 2.7s；探针跑 3 遍 = **5.8s**；`check:gates` 全量 **17.3s**，且**未增加沙盒成本**（复用同一份 tree sandbox）。
- **⚠️ 链内净增成本 = 0**：键覆盖断言在矩阵段的 `assertMatrixShape` 里，而**该段已随 `test:coverage` 跑全部 123 段而在 `verify:ci` 链内执行**。故**不需要**再往链里插一个 npm 脚本 —— 那会是重复跑同一批段，与 [adr-016](adr-016-门禁链内全量验收只跑一遍.md) 冲突；且 Windows 下 `M2W_ONLY=x cmd` 的 POSIX 前缀语法在 `cmd.exe` 里不成立，非新增包装文件不可。**这是本条相对原计划的一个改进：原计划预设要改链，实测不必。**
- **⚠️ 已知限制（明确不解决，不假装解决）**：`GATE_IDS` 是**有意精选的子集**（`check:temp-cleanup` / `check:test-numbering` 同样不在其中），`check-ci-contract.mjs` 的 `REQUIRED_CI_STEPS` 也是精选子集且只断言「必备项在链内」、**不断言「链内无多余项」**。因此**接线后门禁仍可能被静默移出链**而不判红：把 `dual-matrix` 从 `GATE_IDS` 删掉，或把本条依赖的 `test:coverage` 从 `verify:ci` 移走，现有断言都不会拦。这是该清单的**既有形状**，不是本条引入的；补「链组成 = 显式登记表」那道守卫已按用户 2026-09-30 裁决排除在本条之外。
- **「抓到忘写」栏**（三条已有实跑负向证据：两次工作树负向 + 一次元负向，均 exit 1 且关键字精确命中）：① 段声明的某个键**没有任何矩阵行覆盖**（新键没补行 / 覆盖标记被误删 / 行被删）② 某行 `covers` 声明了**台账未登记的键**（登记漂移、拼错、行凭空声明）③ 某行**漏写 `covers` 字段**本身 ④ 键集合自身畸形（id 重复 / `semantic` 为空）。**元负向**（旁路 `assertKeyCoverageRegistered` 调用 → 门禁判红）证明探针本身不是空过。
- **「抓不到什么」栏**：① **完备性** —— 键集合**手工登记**，往 `SharedRenderOptions` / `ResolvedRenderSwitches` 加字段而不登记 ⇒ 全绿。**这是最深的一条：门守的是「已登记的键不被遗忘」，不是「键集无遗漏」。** ② **覆盖深度** —— `covers: ["watermark"]` 只表示「该键有可执行断言入口」，不表示断言触及每个子项。③ **断言有效性** —— 一行可声明覆盖某键而 `verify` 恒真。④ **刻意排除的键** —— `headingNumbering`（矩阵无对应行）与 `captionNumbering`（由现有行顺带锁住）。⑤ **矩阵之外的双管线行为** —— 本机制不新增任何差异维度的发现能力。

## 不做项

1. 不判键集合的**完备性**（需从 core 反向枚举，属「发现工具」）。
2. 不为 `headingNumbering` 补矩阵行（新增矩阵行不属本条范围）。
3. 不补「链组成 = 显式登记表」守卫（用户 2026-09-30 裁决）。
4. 不把新探针或任何 npm 脚本加进 `verify:ci`（重复跑同一批段，与 adr-016 冲突）。
5. 不把判定逻辑复制到 `scripts/` 下的独立静态门禁（两份口径必然漂移）。
6. 不改动 `src/**` 任何生产代码。
7. 不触碰 `dual-pipeline-matrix.test.js` 里既有的 `6-Cx` 注释编号（`check:test-numbering` 只扫字符串字面量，注释不在判定面内，清理属另一件事）。
