## 背景

诊断的完整数字见 [evidence 底稿](../evidence/20261004-095219-测试与门禁组织诊断事实底稿.md)。此处只列直接构成决策依据的六条。

**一、测试与门禁已构成一套 2.5 倍于应用的平行应用。** `src/` 34,130 行，`test/` ＋ `gates/` ＋ `shared/` ＋ `tools/` 合计 85,905 行。

**二、目录数量不是问题，放置不可判定才是。** 顶层 8 个目录对 34k 行 `src` 不算多。真病在同一层里混着三种不同性质的测试（模块单测 / 跨模块行为 / 测试框架自测），而名字看不出区别。实测：`test/core/runner-report.test.js`（797 行）测的是 `test/common/runner.js`；`test/gates/entry-exit-guard.test.js`（556 行）测的是 `shared/entry-guard.mjs`；`test/gates/contract-single-source.test.js`（347 行）零 `gates/` import 而主被测是 `dist/core/*`。`test/main/` 20 个段里约一半主被测是 `dist/convert/*`。

**三、命名的偏差是系统性的，且没有任何门禁看守。** 146 个测试文件核对结果是 127 相符 / 15 偏窄 / 4 偏宽。134 个段里只有 **29 个**能被「文件名与被测模块同名 ⟹ 测它」这条唯一可能的机械映射命中（**命中率 22%**）。最典型：`test/main/about-update.test.js` 全文 42 行只测 `compareVersions` 一个纯函数，承诺的「关于」窗口与更新检查根本没测。

**四、更严重的是规则层已经腐坏。** ① `docs/DEV-GUIDE.md` 四处仍写「四个段目录」，而代码里是 7 个—— 目录规则的唯一权威本身与代码矛盾；② `gates/repo/check-test-numbering.mjs` **根本不判命名**（它扫规划编号字面量泄漏），这个名字会让 AI 相信命名被守着；③ 现行唯一的命名类机器判据 `checkSegmentMirrors` 只验「顶层或顶层下一层存在同名目录」，实测 `test/docs/` `test/tools/` `test/shared/` `test/build-assets/` **全部 PASS**。另有 13 个 `test/gates/` 文件的文件头自述「位于 `test/core/`」—— 规则改过、文件头没同步。

**五、`test/fixtures` 不是测试夹具。** 它 35 个 `docs/` 文件全部是 `gates/fixtures/gen-fixtures.mjs` 的生成产物，其中 **33 个零运行时消费者**；另有一个 170KB 的生成 PDF 零引用躺在里面；两对图片逐字节重复；而真正的输入桩只有 `input/` 的 4 个文件（全部有消费者）。它实际是「给人在 GUI 里拖入的样例文档」，owner 是生成器，却被当发布物逐字节校验。附带代价：**134 个段被强制 100% 显式声明 `export const fixtures`，其中 111 个写的是 `= null`**。

**六、复杂度的真实所在。** 测试树本身不复杂（readdir ＋ glob ＋ 一个 929 行 runner，零注册表）。复杂在两处：门禁元框架（`registry.mjs` 1141 行 ＋ `protocol.mjs` 366 ＋ 沙盒探针层 ≈2.25k 行，其中 `check:gates` **不在 `verify:ci` 链里**，只在本地手动跑），以及 5 条段目录元规则里 4 条是散文。

**为什么值得做**：命名的 22% 命中率与零门禁看守，直接后果是**每一个新写的测试段都在赌「自己放对了地方」**，而 AI 不会读完 200 行散文再落笔。这条约束下的失败形态是静默的 —— 段跑绿了，但它守着的是错的东西。

## 决定

### 一、目标结构

```
m2w/
├── src/                    应用代码 —— 本次不动（165 个模块）
│   ├── core/ (78) · renderer/ (44) · main/ (29) · convert/ (8) · cli/ (3) · mcp/ (3)
├── gates/                  门禁脚本（判据本体）+ 与被守门禁同居的 selftest
│   ├── repo/ · probe/ · geometry/ · artifacts/ · smoke/ · supply/
│   └── gate-index.mjs      ← registry.mjs 1141 行重写为 ~140
├── shared/                 机制层（10 文件）—— 内容不动，删 test-common-surface.js
├── tools/                  构建与开发脚本（9 → 6 文件）
├── samples/                ★ 从 test/fixtures 迁出（顶层 +1）
│   ├── gen.mjs             ← gates/fixtures/gen-fixtures.mjs（610 行）
│   ├── manifest.json       生成时的段名集合 ＋ 输出清单（漂移比对基准）
│   ├── EXEMPT.json         生成物之外的例外，须登记 why
│   ├── docs/ (37 生成物) · input/ (4 手工输入桩) · manual/ (15 人工目检)
├── build-assets/ · docs/ · .github/
└── test/                   镜像源 = src 的 6 个子目录 ＋ gates ＋ shared ＋ tools
    ├── acceptance.mjs      唯一入口（保持）
    ├── core/ ⟷ src/core/ · main/ ⟷ src/main/ · renderer/ ⟷ src/renderer/
    ├── convert/ ⟷ src/convert/ · cli/ ⟷ src/cli/ · mcp/ ⟷ src/mcp/
    ├── gates/ ⟷ gates/（按 repo|probe|geometry|artifacts|smoke|supply 分层）
    ├── shared/ ⟷ shared/（含 geometry/） · tools/ ⟷ tools/
    ├── behavior/           跨层行为段（必须 export const covers）
    └── harness/            非段支持代码（原 test/common/ 17 个 ＋ dom-stub.js）
```

**`test/fixtures/` 整个消失。**

### 二、唯一不变式

> `test/` 下每个段文件的路径，是它的**被测源文件路径的机械变换**：
> `test/<R>/<rest>.test.js` ⟺ 被测主体 `<R>/<rest>.<ext>`，`R` 从磁盘派生（`src/` 的六个子目录 ∪ 顶层树 `gates`/`shared`/`tools`）。**位置即身份。**

判据落在新门禁 `gates/repo/check-test-layout.mjs`（L1–L12），逐条为：

| 编号 | 判据 | 判红条件 |
|---|---|---|
| L1 | 镜像完整性 | 每个镜像源模块有 `test/**/<m>.test.js`，或在 `gates/repo/test-exemptions.json` 登记 |
| L2 | 豁免表完整性 | 每条豁免须有 `reason`（≥20 字）与 `coveredBy`（非空，每项须真实存在） |
| L3 | 豁免表无陈旧 | 豁免的模块已有测试文件 → 判红并点名删哪条 |
| L4 | 位置正确 | `test/<R>/**/<m>.test.js` 必须 import 解析到 `<R>` 内的主体 |
| L5 | 同层自由、跨层禁止 | `test/<L>/**` 只许 import `dist/<L>/**`、`<L>/**`、`test/harness/**`、`node:*`；跨层 import → 判红并提示「搬去 `test/behavior/`」。**先跑一个阶段的只报告模式**（见「落地」P1/P4） |
| L6 | 行为段声明 | `covers` 缺失 / 空 / 指向不存在的模块 → 判红 |
| L7 | 无多余顶层目录 | `test/` 顶层集合 == 镜像源派生集 ∪ {`behavior`,`harness`} |
| L8 | harness 自测 1:1 | `test/harness/*.test.js` 必须与同目录 `*.js`/`.mjs` 同名 |
| L9 | 发现面下限 | 段文件数 < 100 → 判红（walker 失效兜底） |
| L10 | import 收口 | `test/**` 不得经 `test/common/paths.js` 门面，必须直引 `shared/paths.js` |
| L11 | 门禁必有载体 | 每道门禁入口必须有 `gates/<dir>/<name>.selftest.mjs` 或 `test/gates/<path>.test.js` 之一 |
| L12 | 链归属 | `access: "chain"` 的 script 真在 `verify:ci`/`verify:release`/`dist` 链上；`access: "local"` 的不得在链上 |

**L1 的豁免表基线自动生成**：门禁提供 `--write-baseline` 一次落盘，之后只许减不许增（ratchet）；人工只填新增项。

### 三、AI 落笔判据

一个 agent 接到「给 X 加测试」时，**不读任何文档**即可 O(1) 定位：

```
输入：src/core/markdown/slug.ts
 1. P 以 src/ 开头        ⇒ M = test/<P 去 src/ 前缀，.ts→.test.js>
 2. P 以 gates|shared|tools/ 开头 ⇒ M = test/<P 换 .test.js>
 3. M 已存在 ⇒ 追加到末尾（唯一动作，零决策）
 4. M 不存在 ⇒ 新建
 5. import 目标：src 树换成 dist/ 前缀 + .js，其余树用原路径
 6. 断言需跨层 ⇒ 写 test/behavior/<主题>.test.js 并 export const covers
 7. 只有「样例要给人拖进 GUI」时才 export const fixtures；不写 = 无样例
 8. 不需要决定：目录名、文件名、要不要写 meta、要不要登记
```

**设计核心：路径是算出来的，不是选出来的** —— 所以「追加进已有文件」是阻力最小的路径。当前体系里追加反而需要决策（先判断断言属于哪个「内容主题」，而主题划分是散文规则）。

支撑：`npm run where -- <模块路径>`（约 30 行，静态 import 图反查）打印镜像段路径 ＋ 所有 `covers` 里提到它的 behavior 段，防重复写。

### 四、规则清单的处置

| 现行元规则 | 处置 |
|---|---|
| 段目录镜像一棵被断言的树（含 `common`/`fixtures`/`acceptance` 三名显式排除） | **保留但彻底重写** → L1 ＋ L7（判据从「同名目录存在」改为「精确等于派生集」） |
| 归属判例（跨层段归属看被测主体） | **删除** → L4 ＋ L5。归属 = 被测主体路径 = 段路径；跨层断言去 `test/behavior/` 并声明 `covers` |
| 同模块多段口径（同一模块可拆多段、文件名带主题后缀） | **删除** —— 它直接生产了 15 个「偏窄」；改为「一个主体一个文件」，需要第二份断言就追加 |
| 扫描面等式 ＋ 下限 | **合并**为 L7 ＋ L9；手写枚举可派生后「声明 vs 实测」不再可能不等 |
| fixtures 契约「每段显式声明」 | **删除** → 改为「导出即有样例，不导出即无样例」；只保留 ①导出 `fixtures` 的键集与类型校验 ② `samples/docs/` 与 `manifest.json` 的逐字节漂移比对 |
| 规划编号不进测试树 | **保留，原样**。它与命名无关，是真判据。只改文件名：`check-test-numbering` → `check-planning-tokens` |
| fixtures 三子目录按内容命名 | **删除**（随 `samples/` 落地），改为目录准入判据（生成物 vs 手工物） |
| 「断言写可验证事实，不写无断言日志」 | **保留散文形态**，但移进最小段模板的头注 —— 这条无法机器判，而它对 AI 是有效的 |
| 注册表的 `why` 散文（约 120 行） | **删除**，搬进各 `.selftest.mjs` 头注（就地可搜、随代码走，比集中一处更不易腐坏） |

`docs/DEV-GUIDE.md`「测试体系」节从 16 行压到 **3 行**：一段命令表 ＋ 一句「位置即身份，判据在 `gates/repo/check-test-layout.mjs`」＋ 指向本 ADR。**规则本体在门禁里，DEV-GUIDE 只留命令。**

### 五、`gates` 与 `test` 的目标形态

**保留进程边界 / 函数边界这条分界，换承载方式**（这条分界本身干净且有解释力，问题只在于它没被写成人一眼能看到的规则）：

| | 守什么 | 放哪 | 命名 |
|---|---|---|---|
| 门禁自测 | **进程边界**：真跑 CLI、`cwd` 语义、退出码、入口守卫 | **与被守门禁同居** `gates/<dir>/<name>.selftest.mjs` | 派生 |
| 门禁函数级测试 | **函数边界**：`analyze(ctx)` / `judgeXxx()` 的判定口径 | **镜像** `test/gates/<dir>/<name>.test.js` | 派生 |

7/20 未登记的问题随注册表概念删除而消失 —— 新判据 L11 是**路径存在性**，不可能漏登记。

**门禁元框架：保留索引，删掉机制。**
- `registry.mjs` 1141 → `gates/repo/gate-index.mjs` ≈140 行，每条门禁只留 3 个字段（`script` / `access` / `judgment`），`probes[].ref` 与载体存在性派生、`why` 与 `judgmentNote` 删除。判据从 R1–R5c 五条缩成 L11 ＋ L12 两条。
- **`protocol.mjs`（366 行）删除** —— 「三种驱动器共用同一份判定」的承诺，实际驱动器是 CLI ＋ 一个验收段共 2 个；34 道门禁里只有约 6 道真有可注入 judgment，其余 28 道为符合协议要把 IO 塞进 ctx 包装。门禁就写成两段：`export function analyze(ctx = {}) → Problem[]`（纯）＋ `async function main()`（打印 ＋ 出码）—— 这个形态已在 6+ 道门禁里自发长出来。
- **沙盒探针层（≈2.25k 行）删除**，但**保留它唯一不可替代的能力**并压成 L11 的一条负向夹具：门禁自测必须被判红要求在**真实工作树**上跑一次绿。这是本条唯一「失去保护」的补偿设计。

### 六、顶层四棵树的处置

| 树 | 处置 | 理由 |
|---|---|---|
| `shared/` | **保留独立** | 唯一的零依赖层；并进 `gates/` 会让 `test/` 为「知道仓根在哪」而依赖被测对象（依赖倒置）。准入判据即「零依赖」：新增文件不得 import `src/`/`gates/`/`tools/` 任何东西 |
| `gates/` | **保留独立，禁止进 `src/`** | 判据层 vs 执行层必须分开，否则「红/绿」失去含义。进 `src/` 会同时踩三个雷：`tsconfig`/`c8 --include` 把 30k 行判据算进应用面；`check-import-boundary` 的层向规则让它们合法 import Electron/main；「应用代码」与「对应用代码的检查」再也分不开 |
| `tools/` | **保留但瘦身到 6 文件** | 71% 的行数（`visual-*` 1010 行）是 geometry 门禁的页面探针，因共用 preload 路径前缀而放错位置；迁入 `gates/geometry/` 后只剩「构建与开发脚本」一桶。零测试的 3 个走豁免表，`setup-env.ps1` 按「无被测导出」按类别豁免 |

| `gates/repo/check-docs.mjs` | **不动** —— 65 行薄包装这个形态本身是对的，是本仓该有的样子 |

## 备选方案

**A · 只镜像 `src/` 六个子目录，`gates`/`shared`/`tools` 合并进一个 `test/infra/`**（文件名带路径）。省 2 个目录，代价是 97 个模块（`gates` 78 ＋ `shared` 10 ＋ `tools` 9）的命名从「算出来」退回「想出来」，而它们是全仓改动最频繁的非应用代码。**否决** —— 用小的视觉收益换一个大的复发风险，且本次的病根正是命名需要判断。

**B · 6 个镜像 ＋ 把 `gates`/`shared`/`tools` 的测试塞进 `test/behavior/`。** 否决 —— `behavior/` 现有语义是「跨层行为段」，塞进去等于给它加第二层含义，日后没人说得清一个段为什么在那里。

**C · 压到 `test/` ≤10 个目录（不强制镜像 `shared/` 与 `tools/`）。** 比 A 好（不引入新目录），**否决** —— 那 19 个模块重新变成「测试是可选的」。

**D · 继续在现体系上打补丁（改文件名、修 13 个文件头、删 `pending` 断言）。** 否决 —— 22% 的映射命中率与零门禁看守是结构问题，逐个改名不动结构，下一个 agent 写的段还是会赌「自己放对了地方」。

**E · 直接上 `node --test` 替代自研 runner。** 否决 —— runner 本身不是问题源（实测 5 段全跑 2.9s，其中段本身 1.4s，隔离收益是实的）；换掉它属独立议题，与本条的目标不变式无关。

**F · 只建 `check-test-layout` 判据、不搬文件。** 否决作为终态（判红无法消化）—— 但**采纳为第一步**：先让门禁把全量违规摊开，输出权威计数，这份计数要写进本 ADR 与台账。

| 注册表的 `why` 散文作为集中审计轨迹 | 中 | 搬进各 `.selftest.mjs` 头注 —— 就地可搜、随代码走 |

### 最容易出错的地方（按出错概率 × 静默性排序）

1. **🔴 6 个大文件拆分**（`supply-chain` 1677 行守 4 道门禁 · `install-smoke` 1380 · `observability` 1348 · `dist-manifest-gate` · `release-artifact-gate` · `geometry-gate` 1213）。失效形态：**漏搬一组断言，测试仍全绿**（被漏的那组本来就是重复断言或已被别的段覆盖）。**对策**：拆分前后断言调用数（`assert(`/`assertEqual`/`assertIncludes`/裸 `throw`）逐份对账，总和不得减少；再叠加 `test:coverage` 的 0% 文件集合逐文件比对。两道独立客观证据。
2. **🔴 `test/gates/` 三份合并为一份**（`check-pointers-*`）。反向失效：合并时同名 case 撞车被静默覆盖。**对策**：合并前后 `createCaseSuite` 登记的 case 名集合逐条 diff。
3. **🟠 删 `test/common/paths.js` 的 86 处 import 改写。** 机械但量大。漏改一处 → 该段拿不到 `ROOT`，症状是该段崩在最前面。**这条其实是安全的**：`test:coverage` 立即暴露（该段整段不执行但 runner 判段失败）。
4. **🟠 L5 跨层禁止的判红面。** 预判会误伤一批「合理」的跨层段（如 `test/core/heading-scale.test.js` import `dist/renderer/*` 做 token 对照）。**对策**：先跑只报告模式，拿到完整误伤清单再转判红；诊断里必须直接给出「搬去 `test/behavior/` 并写 `covers`」的完整指引。
5. **🟡 `M2W_ONLY` 段名改为完整相对路径。** 这是**行为变更**不是重构 —— 现存依赖 basename 匹配的用法（含 `EXCLUSIVE_SEGMENTS = ["gate-probes"]` 的子串语义）要一并复核；该串会从匹配 `gates/gate-probes.test.js` 变成匹配 `gates/probe/gate-probes.test.js`，**P6 删掉 `gate-probes.test.js` 时这条正好一起消失**（顺序必须 P6 在后）。
6. **🟡 镜像源的「`src` 子目录派生」。** `src/` 新增一个子目录时 `test/<新层>/` 不会自动出现 → L1 判红。这是**期望行为**（强制同步），但诊断里要写清「新增 `src` 层 ⇒ 新增 `test` 层，两者同 PR」。

### 明确不建议动

| 项 | 判断 |
|---|---|
| `src/` 的分层与 `LAYER_RULES` | **本次完全不动**。`convert-no-outside-src` 用 `prefix:` 而 `faces-no-outside-src` 用 `layer:` 的不一致是真实的债，但那是 `src` 树的债，另立工作项 |

| `gates/repo/check-docs.mjs`（65 行薄包装） | 不动。见「决定·七」 |

2. `test/main/` 下 20 个主被测在 `dist/convert`/`dist/core` 的段，**只能从测试侧修**（搬 `test/behavior/` 或改挂 `test/convert/`），不能靠动 `src` 分层让归属自然变顺。

### 修复项复测

首判常常是错的。这张表记的是「首判可能是什么」与「怎么复测」，避免下一次在同一个坑里绕第二遍。

| 现象 | 首判（可能错） | 复测动作 |
|---|---|---|
| `check:test-layout` 四段计数与本 ADR 记录不一致 | P1 门禁的 walker 或豁免表基线有误 | 删 `test-exemptions.json` 重跑 `--write-baseline`，比对两次数值；连跑三次确认输出一致 |
| P4 后 `npm test` 全绿但段数减少 | 拆分漏搬（**最危险的静默失效**） | 比对拆分前后断言调用数总和 ＋ `test:coverage` 的 0% 文件集合，两者任一变化即定位到漏搬的那一份 |
| L5 转判红后大量误伤 | 预判的合理跨层段未列入 `behavior/` | 退回只报告模式，取完整误伤清单逐条处置后再转判红 |
| `verify:ci` 在 P6 后链长变长 | 新增门禁被误挂进链 | 查 `gate-index.mjs` 的 `access` 字段；`access:"local"` 出现在链上即判红（L12） |
| `M2W_ONLY` 段筛选命中数异常 | 段名改为完整相对路径后 basename 匹配失效 | 复核 `runner.js` 的 `EXCLUSIVE_SEGMENTS` 子串语义；`gate-probes` 那条应随 P6 一并消失 |

### 怎么回滚

每个阶段是独立可回退的 commit，**回滚顺序与实施顺序相反**：

- P6 的对账表是沙盒层退役的唯一保险 —— **回滚 P6 前先确认对账表仍在且全绿**。
- P4 的断言调用数对账表与 `test:coverage` 的 0% 文件集合是「没漏搬」的客观证据，回滚 P4 前先核对这两份记录。
- P3 的「迁移前后 `samples/docs/` 逐字节相同」是纯搬家的证据 —— 任何一项不同就不是纯搬家，须先查清再继续。
- P1 的四段计数是后续所有阶段的工作量基线，回滚 P1 之前不要回滚 P2 及以后。
- P2/P3/P4 全部是机械改写（路径变更、文件搬动、import 改写），`git revert` 即可，不需要数据迁移。**唯一不可 `git revert` 的是删除动作** —— 沙盒层与 `protocol.mjs` 的删除内容在 git 历史里可取回，但**判据的退役（注册表 `probes[]` 概念消失）不可回退**，回退后必须重跑 P1 才能重建一致性。
