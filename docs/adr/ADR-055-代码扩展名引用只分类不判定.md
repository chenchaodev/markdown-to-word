# ADR-055 · 代码扩展名引用只分类不判定

| 项 | 值 |
|---|---|
| 状态 | 现行 |
| 日期 | 2026-10-02 |

## 决定

**一、指针门禁不扩 `REF_FORMS` 到代码扩展名；改给 `.mjs` / `.ts` / `.js` / `.cjs` 四类单立一档「只分类、不判定」，且该档必须自报。**

现有三条 `REF_FORMS` 形态全部以 `.md` 收尾。四类代码扩展名的引用**不在判定面内** —— 不是判它们通过，是压根不判。新增的一档对它们做存在性分类并把计数推进结论行的 `覆盖:不全(...)`，措辞与既有的跨仓路径档一致：「分类 N 处 · 判定 0 处 · 未判，非『查过没问题』」。

**二、本档完全不解析，只数形态。** 实现上本档**不调 `resolveRef` / `checkExistence`**，而是拥有一条**独立的抽取正则**（不复用、也不从 `REF_FORMS` 派生）。因此**不引入第二个解析基准** —— 这比「与判定档一致」更强。

为什么不解析：分类的对象是**形态**，不是有效性。若调 `resolveRef`，那几百次解析会灌进 `main` 里已有的「引用解析 … 判定 N 处」自报计数，把一个口径为「判定档解析量」的数字撑成四位数 —— 那是污染一个已判定的自报数字。以后若要「本仓解析得到 X / 不到 Y」这类分项（对人工裁决更有用），正确做法是往本档**注入一个解析回调**并在调用前后快照 / 还原 `refStats`，而不是直接调 `resolveRef`

**三、零覆盖必须出声。** 扫描面内一条这类引用都没有时，结论行仍须出现该族（哪怕计数为 0），不许整段静默消失。

**四、`docs/adr/` 下的这类引用照常分类，但不动其正文。** ADR 是不可回改的决策史，正文里的旧路径记的是「当时如此」；按字面改成现存路径等于篡改历史。

**五、活文档里的失效引用逐条处置**，按「路径前缀腐坏」与「真消失」分两类：前者改成仓库内真实路径（真身须实测定位、不得凭猜），后者写成历史称谓 + 现名/现状的说明并保留旧路径痕迹。**绝不把死路径悄悄替换成一个恰好同名的活文件** —— 那是把「记错了」改成「指错对象」，比留着更坏。

**六、本仓台账的三个列上限例外已登记在 `AGENTS.md`，本条不碰它。**

## 背景

[ADR-054](ADR-054-配置仓与项目仓门禁拆分本仓落地.md) 后果 6 记了这个盲区，并把它留作「另立条目」。本条是那个条目的落地。

实测（按门禁扫描面复刻：仓根 `*.md` + 整个 `docs/`，`docs/evidence/` 整棵除外、`docs/adr/` 在面内）四类代码扩展名引用共 235 处解析不到，分布：

| 位置 | 数量 |
|---|---|
`docs/adr/` 正文 | 182 |
活文档（`docs/DEV-GUIDE.md` · `docs/design/*` · `README.md` 等） | 53 |

全部是「路径形态但仓内无此文件」。⚠️ **这个数与门禁自报的数不是同一个东西**：门禁报的是**形态分类数**（这类引用总数，分式与有效性无关），而本条背景写的是其中**解析不到**的那一部分。两者不矛盾，但看到结论行里的数字时要先分清自己在看哪个。，**没有一处是标识符误判**。其中 `.mjs` 那 94 处里 **91 处是路径前缀腐坏** —— 文件搬了家、引用没跟（`scripts/check-ci-contract.mjs` 的真身已是 `gates/repo/check-ci-contract.mjs`），真消失只有 3 处。

触发点是 [ADR-054](ADR-054-配置仓与项目仓门禁拆分本仓落地.md) 决定六把 `check:docs` 挂上 CI 之后，「门禁绿」会被读成「文档路径都对」—— 而实际上有 235 处从来没被查过。**这正是该 ADR 决定四已经处理过的结构同类问题的翻版**：判红基准不可达 ⇒ 照搬得到的是确定性假红，不是精度下降。

⚠️ **裁决前提已实测验证**：把 `REF_FORMS` 的扩展名临时扩进去，真实仓立刻判红大量引用 —— 即「那是墙不是精度」这一前提成立。同一次运行里自检失败两条夹具，证明失效形态被钉住。

⚠️ **量法不是判据的恒等式**：`collectProjectScope` 与 `REF_FORMS` 均未导出，所以上述统计由外部脚本复刻扫描面与抽取形态得到，与门禁本体在当前文档树上计数一致但**不是恒等关系**（文档里出现 `-foo.mjs` 这类首字符即分叉）。

## 备选方案

| 方案 | 为何不选 |
|---|---|
| **直接扩 `REF_FORMS` 到代码扩展名** | 立刻红 91 处以上 —— 91 处是路径前缀腐坏而非指针断裂。那是一堵需要先修 91 处才可能绿的墙，而其中大部分位于 ADR 决策史里（决定四不改它们），改不动 ⇒ 结果是「判据面扩大但恒红」，比不判更糟 |
| 逐条修完 235 处再扩判定面 | ADR 里那 182 处按决定四**不得**改字面 ⇒ 永远修不完 ⇒ 判定面永远开不了 |
| 单开一条门禁专判代码路径 | 第三份「哪些路径该被查」的真源，与判据本体的单源冲突；且它同样解决不了「ADR 正文该不该改」这个人的判断问题 |
| 把 ADR 从扫描面排除 | ADR-054 后果 5 已明确否决：`docs/adr/` 排除会让本仓 17 份 ADR 静默移出扫描面，那是覆盖收缩 |
| 保持现状不吭声 | 就是本条要解决的那件事：绿被误读为「都查过了」 |

## 后果

**得到的**

1. 「门禁绿 = 文档路径都对」这句话不再成立，且**门禁自己会说出它不成立** —— 235 处分类数进结论行，零覆盖也出声。
2. 活文档里 53 处失效引用被真正修掉，其中 91 处前缀腐坏里落在活文档的那部分一并归位。
3. ADR 决策史完整：182 处旧路径作为历史痕迹保留，同时不再隐形。

**付出的（逐条）**

1. **本仓判据面**新增一档分类逻辑，与上游那份产生**第三处需要同步的差异**（前两处是豁免表与解析基准，见 ADR-054 后果 2）。本仓仍不设机器对读（跨仓可达性被 ADR-054 备选方案 3 否决），唯一对冲仍是门禁文件头记录的上游基线 commit。
2. **四类代码扩展名引用永远不会被判红**，直到有人裁决「ADR 正文怎么处理」。这是显式的已知缺口，不是待办 —— 记在这里就是让它可见。
3. 「代码扩展名」这个集合是**手写枚举**（本条只列四个）。新增语言/扩展名时**必须同步改这一档**，否则新扩展名静默退回零覆盖。故零覆盖自报是这一档的必要配套，不是可选项。

   ⚠️ **它守护的是「本档自身的抽取正则被改窄或删掉」**，不是「`REF_FORMS` 被扩了扩展名」。后者的真实失效形态是**两档重叠** —— 同一批引用既被分类又被判定，两个计数互相矛盾。因本档抽取正则与 `REF_FORMS` 无关，`REF_FORMS` 被扩时本档**不会**归零。
4. 活文档的 53 处修完之后，将来再有人重构文件路径，这批引用又会失效 —— 这次是被分类数暴露出来，不是被门禁拦下。

**不做**

- 不扩 `REF_FORMS`（决定一）
- 不改 `EXCLUDE_DIRS`（`docs/adr/` 仍在扫描面内）
- 不加环境变量、不加模式开关、不加 `--root`
- 不改 ADR 正文里的历史路径（决定四）
