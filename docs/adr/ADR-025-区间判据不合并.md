# ADR-025 · 区间判据不合并,只归位真正相同的两处

| 项 | 值 |
|---|---|
| 状态 | 现行 |
| 日期 | 2026-09-28 |

## 决定

**不合并**渲染前变换侧与预检侧的两套保护区判据。只把真正逐字相同的两处（`SourceRange` 类型定义与区间合并循环）归位到 `core/markdown/source-ranges.ts`；节点集合收集、两套 masking 策略、两处切行口径一律保持各自独立。

## 背景

规格（`docs/large/01-设置契约与主管线收敛.md` 步 02 的 2-3）要求「把两份 `SourceRange`、两套 masking、两套切行口径合一，2 个消费点共用」，理由是节点类型集合已经分叉（渲染前变换侧只认代码 / 行内代码 / HTML，预检侧多认公式 / 行内公式 / 表格），所以集合必须参数化传入而不能硬合并。

2026-09-28 开工前的实测复核发现，**这条规格的前提大半不成立**，且分叉比「节点集合不同」深得多：

1. **`precheck.ts` 早已写明不复用的理由，且是语义层面的**（原文在 `src/core/pipeline/precheck.ts` 的 `buildMaskedRanges` 上方）：AI 清理侧把「反斜杠 + 下一字符」整段当**不可改写**（转义是保护对象），而预检侧的 `\( … \)` 检测**恰恰要看转义形态** —— 共用一份会把要检的信号一起掩掉。这不是重复，是两侧对同一段源码的**角色相反**。
2. **预检侧是两个节点集合常量，不是一个**：`MASKED_SOURCE_NODES`（6 类）与 `RAW_TEXT_SOURCE_NODES`（3 类）。第二个集合有刻意的**反向**理由 —— 它刻意**不含** `code` / `inlineCode`，因为 remark 给未闭合围栏建的 `code` 节点恰好从围栏行开始，拿它当掩码会把要检的那一行自己挡掉。
3. **AI 清理侧实为两套并行 masking 策略**（token 替换式 + 段替换式），共用区间收集但返回形态不同。
4. **两处切行口径的差异不是「切 vs 不切」**：预检侧产带偏移的 `SourceLine[]`（换行正则认 `\r\n` / `\n` / `\r` 三种），AI 清理侧不产偏移，且 `fixHeadingLevels` 在 CRLF 归一**之前**跑、归一时机与 `cleanupBody` 内部那一处不同。

真正逐字相同的只有两处：两份 `SourceRange` 都是 `{ start: number; end: number }` 半开区间、区模块私有、零字段差异；两处区间合并循环的 filter、排序比较器、合并逻辑完全一致，只有返回形态不同（数组 vs 包在 `contains` 查询器里）。

## 决定要点

### 一、只归位相同物，不归位相似物

`core/markdown/source-ranges.ts` 只承载 `SourceRange` 类型与区间合并（并提供合并后数组的查询能力，让预检侧不必再另写一次合并）。两套节点集合收集、两套 masking、两个切行函数留在各自模块。

### 二、新模块不得携带宿主能力

`precheck.ts` 之所以在边界门禁的 node: 内建白名单里，是因为它本身有 `existsSync` / `realpathSync`。**新文件不在该名单内，因此不得 import 任何 `node:*`** —— 归位时若发现合并逻辑需要 IO，说明抽错了边界，退回。

### 三、把「为什么不合一」从代码注释升级为本 ADR

原理由写在 `precheck.ts` 的函数注释里，读者必须翻到那个文件才知道为什么有两份。保留该注释（它是代码旁的就近指引），但以本条为准。

## 备选方案

- **照规格原样合一，把节点集合参数化传入** —— 不选。集合参数化只解决表面差异，解不了第 1 条的语义冲突：预检侧一旦复用 AI 清理的保护区收集，`\(` 检测会失效，而那正是预检要抓的静默丢内容场景（有测试段守护）。这是拿一个已修的用户可见缺陷换一个整洁的目录结构。
- **把两侧的节点集合也归位到同一模块，用参数区分** —— 不选。第二个集合「刻意不含 code/inlineCode」的理由只对预检成立，参数化后这个反向理由会退化成调用方的一条注释，约束力消失。留在各自模块里，它就写在那个理由旁边。
- **连切行口径一起归位** —— 不选。两侧产物形态不同（带偏移 vs 不带），且 `fixHeadingLevels` 与 `cleanupBody` 的 CRLF 归一时机本就不同，抽「一个切行函数」要加两个开关参数，等于把差异藏进参数里而不是暴露出来。
- **完全不归位，两处重复留着** —— 不选。约 15 行的 `SourceRange` + 合并循环是真重复，且是「契约单源」原则（`CODE-GUIDE.md`）直接覆盖的形态。

## 后果

- 净收益比规格预期小得多：省下的是真重复，不是规格设想的那一整层。**这一点必须写明**，否则下一个会话会按规格的措辞重新提「把两套判据合一」并以为那是未完成的欠账。
- 代价：多了一个只放两样东西的小模块。接受 —— 它承载的是契约（区间类型）而非工具函数集合，与 `core/markdown/` 下其余按「一个概念」命名的文件同形。
