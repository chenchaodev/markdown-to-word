# adr-030 · 水印与页眉的三处产物裁决，及差异矩阵补行

| 项 | 值 |
|---|---|
| 状态 | 现行 |
| 日期 | 2026-09-29 |
| 关系 | 承接 [adr-014](adr-014-双管线保持独立.md)（双管线保持独立、差异用矩阵锁）。本条在**不改双管线结构**的前提下关闭三处「设置项在一侧静默失效」。 |

## 决定

关闭三处**已确认**的产物缺陷，并把 4 个零覆盖的双管线键补进差异矩阵。**不接矩阵门禁**（用户 2026-09-29 裁决，另立 REQ-084）。

| # | 缺陷 | 决定 |
|---|---|---|
| **6-B1** | 水印角度两侧符号约定相反（docx 侧注释写「正值 = 逆时针」用 DML 单位，pdf 侧用 CSS `rotate()` 即正值顺时针），全链路无补偿性取负 | **调成中文出版惯例的「左下 → 右上」**（用户 2026-09-29 裁决）。**先渲染验证再定具体角度**：docx 侧倾向待人工确认（见「未决」），两侧默认角度调到一致且都读作左下→右上。同时**改掉 `chrome.ts` 那句写反的注释** —— 无论方向结论如何，注释与代码不符是确定的缺陷 |
| **6-B2** | 水印不透明度在 docx 侧**零消费**（`chrome.ts` 注释自认「由浅灰配色近似，Run 无 opacity 字段」），选 docx 时该设置静默失效；pdf 侧真消费 | **在 docx 侧真实现**（用户 2026-09-29 裁决）。可行性先验：docx 侧水印是 DML 形状（`<a:xfrm>` 的 `wps`），**不是文字 run** —— 注释里那句「Run 无 opacity 字段」把形状当成了 run，形状的填充透明度是有等价字段的（`solidFill` 下的 alpha 或 VML 的 fill opacity）。**若实测不可行**，退到「界面按所选格式条件禁用并标『仅 PDF 可调』」，并在 LOG 记明退档原因 |
| **6-B3** | 页眉页脚「默认」模式两侧产物不同：docx 走「文档标题居中页眉」，pdf 走**空页眉**（标题只进页面 title） | **统一到 docx 侧**（用户 2026-09-29 裁决）：两侧的「默认」模式都出「文档标题居中页眉」。**这改 pdf 产物**，须同步更新差异矩阵里对应的行 |

## 决定要点

### 一、6-C1 矩阵接门禁本轮不做

矩阵目前不在任何门禁里，只挂在验收测试的一个段上；8 个双管线键只覆盖 4 个，而 6-B2 与 6-B3 两处**已确认的失效恰好就在零覆盖区**。

**只补行、不接门禁**（用户 2026-09-29 裁决，另立 REQ-084 记录）。**先补行是有意排序**：补行本身就是堵当前那个洞（那两处失效就在零覆盖区），而门禁接线防的是「将来忘写」，性质不同；且接线会让 `verify:ci` 多一道**每次提交都要付**的常驻门禁。等矩阵在链外稳了再谈。

### 二、6-C3 的 66 条源码锚点：改成校验存在性，不删字段

矩阵有 66 条源码锚点，实测 **25.8% 指向空行或纯注释**、1 条行号越界（指向一个只有 364 行的文件的第 399 行）。而这些锚点只校验格式、不校验存在性 —— **有字段但零约束，比没有字段更误导**。

**决定：改成打开文件校验行号存在，并顺带修掉那 17 条指错位置的锚点。** 不删字段的理由：它们是矩阵的**导航价值**（「这条 mustMatch 的实现源头在哪」），删掉等于把差异矩阵降级成纯断言清单。代价是每次跑矩阵多开几十个文件（纯读，无 Electron，可接受）。

### 三、6-D2 必须与 6-D1 配套，不单独做

两侧渲染选项各有 30+ 字段，**15 个共有字段在两边各声明一遍**。交叉继承（抽基类型 + 两侧各加独有条目）严格是行为等价，但它**只让 JSDoc 单源，不解决漏传** —— 类型系统对可选字段没有默认值检查，漏传不报错、只静默用默认值。而「漏传不报错只静默用默认值」正是那两处失效的同类。

**决定：6-D1（12 个默认值字面量收成 1 个来源 + 把 docx 侧「构造时统一解析、故全字段必填」的形态推广到 pdf 侧）与 6-D2 配套落地**，逐键断言默认值。单独做 6-D2 价值不足。

### 四、台账的价值是「让下一次有人加键时有地方登记」

45 项决策条目（默认值字面量 15 · 推导逻辑 20 · 排序编号规则 10）逐条归四档：载体所迫（登记，不动）· 实质漂移（修或登记为已知差异并进矩阵）· 设置项失效（必修）· 已被矩阵锁住（不动）。

**代码本身没有「该重构」的地方** —— 重复都是局部的、成对的、有注释标注的。缺的是一张表，和一个保证新键会进表的机制。台账不是发现工具，是**登记工具**。

## 未决（需人工一次渲染）

6-B1 的 docx 侧方向**无法从代码断定**：`docx` 库只把 `rotation` 原样写进 DML 的 `rot` 属性（`ST_Angle`，60000 度分之一，**不取负**），方向取决于 DML 对 `rot` 的约定。pdf 侧可确定（CSS `rotate()` 正值恒为顺时针）。

故 6-B1 的实现分两步：**先渲染验证 docx 侧实际倾向，再定默认角度取值**。人工判据已缩到最小：45° 导一份 docx，看文字往哪边倾。

## 备选方案

- **水印不透明度改「界面条件禁用 + 标仅 PDF 可调」** —— 否决（用户裁决），但保留为 6-B2 的**退路**（若 DML 形状透明度实测不可行）。
- **页眉统一到 pdf 侧（两侧都出空页眉）** —— 否决。页眉的定位是承载身份信息，两侧都空等于这个功能整体失效。
- **删掉矩阵的 66 条源码锚点字段** —— 否决。它们是导航价值；问题在「零约束」而非「存在」，修法是让它有约束。
- **把矩阵接进门禁** —— 否决（用户 2026-09-29 裁决，REQ-084）。**先补行再谈接线**，理由见要点一。
- **单独做 6-D2 交叉继承** —— 否决，理由见要点三。

## 后果

- **本步改产物**：水印不透明度（docx 侧新消费）、页眉默认模式（pdf 侧改）、水印默认角度（两侧）。三者都是用户可观察的变化，回收尾时按写入判据 ② 写 `CHANGELOG` 的 `[待发版]`。
- 差异矩阵从 4 个键覆盖扩到 8 个，「只被枚举 2 处」等不变量获得更硬的守护 —— 但**仍无门禁**（要点一），矩阵回归要靠 `M2W_ONLY=dual-pipeline-matrix` 手动跑或全量测试带。
- **受本条约束的**：任何想改回「统一到 pdf 侧」「删掉源码锚点」「先接门禁后补行」的改动，都必须先推翻本条。
