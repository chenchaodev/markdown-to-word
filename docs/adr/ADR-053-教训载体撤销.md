# ADR-053 · 教训载体撤销,教训按「读者本来就会打开的那份文件」分流

| 项 | 值 |
|---|---|
| 状态 | 现行 |
| 日期 | 2026-10-02 |
| 取代 | [ADR-034](ADR-034-文档载体结构定稿.md) 的**决定 4**(新建 LESSONS.md 载体)。ADR-034 的其余决定仍现行 |
| 关联 | [ADR-034](ADR-034-文档载体结构定稿.md)(载体结构定稿,本条撤销其决定 4)· 配置仓 ADR-007(规则的载体位置由「触发那一刻在不在上下文里」决定,本条是那条判据在教训载体上的应用) |

## 决定

**撤销 docs/LESSONS.md 这个载体**,不新开任何替代的汇总载体。教训按「**读者本来就会打开的那份文件**」分流:

| 教训类型 | 落点 | 什么时候会被读到 |
|---|---|---|
| 测试与断言 | 全局配置目录 `CODE-GUIDE.md` | 写代码或写测试前 |
| 门禁判据 | 全局配置目录 `tools/AGENTS.md` | 改门禁 / 写判据之前 |
| 编排与并行 | 全局配置目录 `WORKFLOW.md` 四 / 八 / 九 | 开工 / 收尾 / 派工时 |
| 台账纪律 | 全局配置目录 `REQ-RULES.md` | 登记新号 / 改状态 / 搬行时 |
| **载体设计层面的判断** | `docs/adr/`(是决定)/ `docs/evidence/`(是事实) | 改那个载体时 / 下一个会话接手时 |

**判据是「找出会读它的人,写进他本来就会打开的那份文件」**,不是「找一份适合放教训的文件」—— 后者会造出一份没人读的新载体。

配套:载体形态判据的 **C3(教训三条)随载体一并撤销**,C 组由 6 条变 5 条。**C# 编号不重排**(保留 C3 空号,C4/C5/C6 不前挪),因为这些编号已被 ADR、evidence 快照与本仓 `docs/DEV-GUIDE.md` 引用,重排会让历史引用全部错位。evidence 头部「结论去向」的取值域由四选一收为**三选一**(升 adr/ADR-0NN · 落 REQ.md 行 · 未升)。

## 背景

三条实测,不是推理。

**一、它的触发从未执行过。** 整个会话几十次开工,零次读它。触发写法是「开工前扫**同主题**那几节」,三个问题叠加:条件循环(要读了才知道该看哪节)、没有频率(不是「每次开工」)、且与写的触发(「提炼出教训时」)用 `·` 粘在同一格,读的触发被写的触发稀释。对照本仓 `docs/DEV-GUIDE.md` 的触发写着「**每次开工**」—— 一次没漏。**一个从不执行的触发,和一个没有触发,效果相同。**

**二、没有内容可留。** 原 30 条逐条核实,只有体例行是本仓专属(绑本仓 evidence 批量迁移 + 指针门禁那条约束链),而那条体例要求的源锚已随内容上收作废;其余全部跨项目可复用,已上收进上表的全局载体。载体里唯一属于它自己的内容,是关于它自己的写作规范,而那条规范刚好也作废了。

**三、上限把知识库变成有损的。** C3 总条数上限 30/30 已饱和,今天为记 5 条新教训必须删 4 条旧教训 —— 其中至少 1–2 条我认为仍然成立,只是「顶不掉新的」。**这个取舍被甩给了人,而它是系统设计问题,不该由人替系统做决定。**

## 备选方案

| 方案 | 结论 |
|---|---|
| **保留载体,收窄为「只收本仓专属教训」** | **否决。** 清空后实测「载体盲区提示:docs/LESSONS.md 不存在或无主题节 ⇒ C3 零覆盖」—— 变成「载体在、无门禁守护、没人写没人读」的中间态,是三种状态里最坏的一种。而且它唯一的内容就是描述它自己的格式规范。 |
| **保留载体 + 把上限改成「溢出即拆载体」+ 单条上限放宽** | **否决(方向对,顺序错)。** 这两条治的是「将来记不进」,而主因是「今天这个载体从不被读」。载体位置错配不动,先调上限等于治标。 |
| **给门禁注册一条 LESSONS.md 豁免**(仿门禁里的 `CONDITIONAL_CARRIERS`),让 ADR 里的历史引用不判红 | **否决。** 门禁自身的注释已警告:「登记具体名字会像已删文件那样腐烂(本仓已因僵尸豁免条目删过一次)」。而且它会给未来写错的引用开绿灯。 |
| **只把源锚删掉、内容留在项目** | **已否决(本轮实际先做了这一步,做完后才看清载体位置本身错配)。** 教训上收是对的,但上收之后剩下的空载体才是问题本体。 |

## 后果

**正面。** 载体集从 5 个降到 4 个;「人只需看四个地方」降为三个;跨项目教训第一次进入**自动注入**或**写测试前必读**的上下文,而不是躺在一个开工不读的文件里。

**需要盯的代价。** 收录判据从「挂不上号」变成「读者本来就会打开那份文件」—— **这条判据不可机械核验,靠人判**。若将来又有人开一份「教训汇总」,会重演今天。同理,ADR-034 状态标为「部分被取代」只解决了「谁来记这次撤销」,没解决「下一次谁来发现载体错配」—— 那件事的答案仍是 ADR-007 的判据:**载体位置由触发那一刻在不在上下文里决定**,而它只能靠人读那条判据时自觉应用。

**ADR-034 正文的处置。** 决定 4 已撤销,但 ADR 是旧条不改动、只标取代。因此只做两件事:状态行标「部分被取代」并指向本条;正文中两处载体名去掉反引号、不带 `docs/` 前缀 —— 这与**同一份文件里 LOG.md 的既成写法一致**(那个载体同样被删,而它在正文里不带反引号,门禁便不判死链)。改的是路径形态,不是决定的内容。
