# ADR-079 · 剪贴板富文本交付面走独立渲染路径与表格承载

| 项 | 值 |
|---|---|
| 状态 | 现行 |
| 日期 | 2026-10-19 |

## 决定

「转换结果复制到剪贴板」是**第三条独立输出路径**,不复用 pdf 的 HTML 产物:

1. 渲染入口收在 `src/core/clipboard/render-fragment.ts`,只依赖 core 共享模块,**不 import `core/pdf/**`**;
2. 代码块与引用块一律用**单格表格承载**(底色、边框、内边距只写在 `td` 上),`pre`/`blockquote` 不再承担盒属性;
3. 所有表格宽度写**固定 pt**(版心宽),不使用 `width:100%`;
4. 系统剪贴板的写入点收在 `src/main/services/clipboard-write.ts` 单文件,CF_HTML 头交给 Electron/Chromium 自动生成,**不手写头**;
5. 公式、Mermaid、内部锚点按已登记降级处理(TeX 源码 / 普通代码块 / 纯文本),不静默丢内容。

## 背景

用户要求「转换结果直接进剪贴板、不生成文件」,目标编辑器是 Microsoft Word 与 WPS 文字,粘贴格式为 CF_HTML。

pdf 产物不能直接复用,原因有四条,任一条都足以判死:

- **编号在 CSS 里**:pdf 模板用 `::before` + `counter()` 输出标题/题注编号,而剪贴板片段在 Word 里没有对应的 CSS 计数器,编号必须物化为文本;
- **完整文档外壳**:pdf 产物带 CSP、`@page`、`mm` 边距与 `body` 级规则,粘贴片段里这些都不成立;
- **资源形态**:pdf 用 `file://` 引用本地图片,粘贴后对方机器读不到,必须转 `data:` URI;
- **内部锚点**:pdf 的 `#id` 跳转在粘贴后必然失效。

Word 的粘贴路径也不是浏览器排版:它把 HTML 转成 Word 段落/表格模型。两轮实测(Word + WPS)确认:

- `pre` / `blockquote` 的底色与边框在 Word 中被丢弃;WPS 保留但按行盒逐行画框;
- `width:100%` 的表格在两端都超出版心;
- 单格 `td` 承载底色/边框/内边距在两端稳定,固定 pt 宽 + `mso-table-layout-alt:fixed` 后不再溢出。

## 备选方案

- **复用 `PdfArtifact.html` 再做后处理**:编号在 `::before` 里无法内联物化,类名样式(含 KaTeX 的 class 树)需要完整 CSS 内联器才能还原;不选。
- **引入 `juice` 做 CSS 内联**:新增依赖,且 KaTeX 的 class 树在 Word 中仍然失真;不选。
- **把剪贴板做成第三个 `ConvertFormat`**:产物路径与扩展名派生(`paths.ts`)会被这个不落盘的模式污染;不选。
- **走 RTF / COM 插入 Word**:跨编辑器不可用,且引入平台专用接口;不选。
- **手写 CF_HTML 头**:Chromium 已自动补 `Version:0.9` 与偏移,手写会双重包裹;不选。

## 后果

- 三条渲染路径(pdf / docx / 剪贴板)的编号口径必须一致:标题与题注计数已抽成 `core/markdown/heading-numbering.ts` 与 `core/markdown/caption-numbering.ts` 两个纯函数,三处共用;新增编号规则时改这一处。
- 剪贴板的视觉形态由内联 `style` 单点决定,**不能再靠 CSS 文件调样式**:改观感要改 `core/clipboard/styles.ts`,并重跑 Word/WPS 实测。
- 公式暂为 TeX 源码文本;升级到 OMML 或 KaTeX 时只改剪贴板渲染规则,不动 pdf/docx。
- 图片预算、取消守卫、警告去重与 pdf 侧同源(复用 `resource-limits` / `request-guard` / `i18n/warning`),新增图片来源时不要另起一套。
- 新增一条交付面后,renderer 侧的入口是文件队列的**行级按钮**(每行一个,批量即逐项),不为它新增转换模式。
