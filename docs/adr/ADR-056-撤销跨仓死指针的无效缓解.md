# ADR-056 · 撤销跨仓死指针那条无效缓解

| 项 | 值 |
|---|---|
| 状态 | 现行 |
| 日期 | 2026-10-02 |
| 取代 | [ADR-054](ADR-054-配置仓与项目仓门禁拆分本仓落地.md) 决定四里的**缓解那一句**（「缓解只有一条……`docs/DEV-GUIDE.md` 记一条维护者手动跑上游全量门禁的命令」）。**该条其余决定与后果仍成立** —— 决定四本身（「跨仓路径只保留分类，不保留判定」）不在取代范围内 |

## 决定

**一、撤销 ADR-054 决定四那条缓解，`docs/DEV-GUIDE.md` 里对应的命令一并删除。**

理由：**那条命令永远 `exit 0`，从未进入跨仓档的判红分支。** 它不是误报（它没声称自己查了跨仓档），但它被放在那个位置、带着那个用途，就是**无效缓解** —— 比没有更坏，因为它给出一次假的完成感。

**二、承认「跨仓死指针这一族机器判不了」，并把它登记为显式已知缺口，不补执行体。**

**三、这一族与「ADR 决策史内的旧路径」并成同一族记录**（见下），两者的共同点是**都需要人工裁决**，且都不是漏洞。

## 背景

本条撤销的东西是 ADR-054 决定四自己写的，缓解那一句原文是：

> 缓解只有一条且不引入任何代码路径、环境变量或开关：**`docs/DEV-GUIDE.md` 记一条维护者手动跑上游全量门禁的命令**。

那条命令落在 `docs/DEV-GUIDE.md` 里，位置在「门禁详解」的 `check:docs` 条目下，写着「改完跨仓引用后到全局配置目录跑 `node tools/check-pointers.mjs` 全量一遍，**退出码 0 才算过**」。

**实测证明它进不了判红分支。** 两种跑法都试过：

| 跑法 | 实测输出 |
|---|---|
按 `DEV-GUIDE` 写的跑法（工作目录 = 全局配置目录） | `门禁结论:已判定 \| 通过 \| 范围:26`，**范围 26 是配置仓自己那 26 份** |
同一脚本，工作目录 = 本仓根 | 同样 `范围:26` |

也就是说这条命令**判的是配置仓自己的文档**，与本仓的跨仓引用无关。跑多少次都是 `范围:26 · 0 错误`。

**为什么会这样**：判据本体的仓根与扫描面取自**脚本自身位置**，不是工作目录。所以无论从哪里跑，它都在判配置仓。而跨仓档要求「对象在配置仓、文件在下游」这个组合 —— 全局配置目录那份按 ADR-016 决定三本就不含该判据，且它自己也报「无对象……本仓不知道下游项目的根在哪」；本仓那份按 ADR-054 决定四**主动**只保留分类。⇒ **两个仓都没有可达的判红执行体，且这不是疏漏，是两条决定各自的必然结果。**

⚠️ **本仓那份不是「丢了实现」而是「主动摘掉了判红」** —— 跨仓分类的三条口径与 `classifyCrossRepoRefs` 都在本仓判据里。所以准确表述是：配置仓那份**无对象**，本仓那份**有意不判**。

**代价必须承认**：撤掉之后，跨仓死指针从「有假绿」变成「连假绿都没有」。

## 备选方案

| 方案 | 为何不选 |
|---|---|
| 保留命令但加一句「它进不了判红分支」 | 加了也没人看 —— 而一个不敢删的错命令会一直留在验证基线的唯一载体里，下一个人还会照它跑 |
| 把命令改成能进判红分支的跑法 | 实测两种跑法都不行（见背景表）；要能判，得让配置仓那份知道下游根在哪 |
| 补一个跨仓可达的执行体 | 要跨仓可达性，而配置仓 `ADR-016` 备选方案 3 恰好否决过这个形态。且要推翻 ADR-054 决定四的核心理由「照搬得到的是确定性假红」，**得先证伪那个理由** —— 而这个理由现在仍成立 |
| 撤掉并顺带修 ADR-054 正文 | ADR-054 已推送。`docs/adr/README.md` 定的规矩是「旧条不改动正文，只改状态格」，所以走本条新文件 + 状态格标注 |

## 后果

**得到的**

1. 验证基线里不再有一条**永远绿灯**的命令占着「防跨仓死指针」的位置。
2. 「跨仓死指针机器判不了」从一句藏在 ADR 后果里的说明，变成 `DEV-GUIDE` 里承认证据缺失的一句话。
3. 本仓输出里那句自报（`覆盖:不全(… 跨仓路径未判(分类 N 处 · 判定 0 处) …)`）不再与文档里的说法矛盾 —— **文档不再说有一套跑法，输出说没判，两边一致**。

**付出的（逐条）**

1. **改跨仓引用后没有任何机器兜底**，必须人工到全局配置目录核对那一族的引用是否指向真实文件。这是显式的已知缺口，不是待办。
2. 本仓判据面**少一条**看似存在的防线 —— 它本来就不存在，只是被文档伪装成存在。

## 与另一族的关系

**需要人工裁决、机器判不了的两族**（同族记录，便于将来一并裁决）：

| 族 | 为什么机器判不了 | 现在的自报 |
|---|---|---|
**跨仓路径**（本条） | 判红基准在仓外。配置仓那份无对象，本仓那份按 ADR-054 决定四有意不判 | `覆盖:不全(… 跨仓路径未判(分类 N 处 · 判定 0 处,判红基准在仓外不可达) …)` |
**ADR 决策史内的旧路径**（ADR-055 决定四） | 按字面改等于篡改决策史；不改则指针早已失效 | `覆盖:不全(… 代码扩展名引用未判(分类 N 处 · 判定 0 处,判红基准需人工裁决「文件真的搬走了」与「文档记的是决策史」)` |

两族的差别在于**人工裁决时能不能改**：跨仓路径**可以**改（文档记的是「该指向哪个文件」，随时会更）；ADR 决策史**不能**按字面改。所以将来若有裁决，跨仓这一族先动。

## 不做

- 不补跨仓可达的执行体（备选方案两条已否）
- 不改 ADR-054 正文（已推送，走本条 + 状态格标注）
- 不动判据本体的跨仓档实现（分类在、判红按决定四不在，都维持现状）
