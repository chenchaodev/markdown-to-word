## 决定

仓库里**没有任何一处允许枚举顶层目录、测试目录或项目根**。三者一律从实际内容派生：单源模块用 `readdir` 读出顶层并对每个条目分类（`source` / `verify` / `shared` / `doc` / `output` / `config` / `vcs`），测试扫描面按「能否被门禁链消费」派生，项目根路径收敛到一个常量模块。

派生结果替换现有的 6 处顶层枚举、4 处测试目录清单与 26 处自算项目根。门禁同时新增一条规则：代码里出现自算项目根（`new URL('..')` 或 `import.meta.dirname` + `resolve('..')`）即判红。

扫描面完整性判据从**下限**（`MIN_SCAN_FILES = 50`）改为**等式**（声明数 == 实测数）。

## 背景

`lib-1` 核对社区惯例后确认：目录叫什么、放几层，全是风格偏好，零硬约束。本仓真正有后果的硬约束只有四条，都已正确处理。所以「组织乱」的来源不是命名，而是**同一份知识在多处各自枚举**。

实测出的重复是逐字级的：`scripts/check-test-numbering.mjs:72` 与 `scripts/check-temp-cleanup.mjs:83` 各持一份完全相同的 `SCAN_TARGETS` / `EXCLUDED_DIRS` / `isExcluded()` / `listScannableFiles()`，70 行 diff 唯一差异是两个 `SNIPPET_MAX` 常量值。同理，项目根有 26 处各自计算（3 种语法、2 种深度）。

代价是**静默降级**：新增一个测试子目录，要改 4 处；漏改的那份门禁不会报错，只是扫不到，恒绿。4 处里只有 1 对被 `test/segments/fixture-contract.test.js:67` 断言恒等。`MIN_SCAN_FILES = 50` 的下限语义也挡不住「少扫一个子目录」——实际扫描 142 个文件，下限只挡 walker 整体失效。

根路径自算更隐蔽：目录深度一变，26 处一起错，而**深度依赖是改布局时唯一无法被门禁发现的一类错**。

## 备选方案

| 方案 | 不选的理由 |
|---|---|
| 维持现状，只在两份重复文件各加一条「本清单与另一份同步」的注释 | 注释不产生约束，已经有一份 `fixture-contract` 断言证明「登记过的重复」和「没登记的重复」差别巨大 |
| 把清单集中到某个共享文件，但内容仍是手写枚举 | 只把 6 处枚举变成 1 处枚举。仍是「枚举已知」，新增目录照样要改那一处，且没有任何机制发现漏改 |
| 给 `scripts/` 补 `// @ts-check` 补类型安全 | 与本决定正交，且实测不可行：`spawnSync(process.execPath, [...])` 动态参数 + `readFileSync` 后文本判定会炸出上百条噪声，与 `tsconfig.test.json` 记录的 1050 条同类。`eslint.config.js:44` 的 `projectService.allowDefaultProject` 类型感知 lint 已是本仓对非 TS 文件的合理上限 |
| 保留 `MIN_SCAN_FILES` 下限作为兜底 | 下限只回答「walker 是不是整体坏了」，不回答「是不是少扫了一个子目录」。两个问题需要两个判据 |
| 引入现成的目录清单库或插件扫描 | 需求是「派生实际内容」，≤30 行 `readdir` 即可；引入依赖换不来「从实际派生」这个语义，且仓库已有同形范式（`eslint.config.js:15-29 defaultProjectGlobs` 运行时扫描） |

## 后果

- 新增任意顶层或测试目录，**零处需要手改**，漏改不再可能静默发生。
- `clean-artifacts.mjs` 的 `PROTECTED_SEGMENTS` 从白名单枚举改派生后转 fail-closed（新增顶层目录不会被误判为可删）。该脚本现状**本已是 fail-closed**（`clean-artifacts.mjs:245` 有 `['dist','release','all']` 硬白名单，路径取自冻结的 `TARGET_DIRS`，另有 `assertMatchesBuildConfig` 钉死 `package.json`），本决定去掉的是「以后新增顶层目录时保护集不会自动跟进」这一隐患，不是修一个现存的删除风险。
- 门禁注册表必须覆盖**两条调用路径**：除 npm script 链外，`ci.yml:55` 与 `release.yml:59` 在 `npm ci` 之前裸调 `node scripts/check-ci-contract.mjs` 做 fail-fast。只登记 npm script 会漏掉这条。
- 派生逻辑本身成为新的单点。`readdir` 分类规则写错会让所有下游一起错，因此这层必须有自检。
