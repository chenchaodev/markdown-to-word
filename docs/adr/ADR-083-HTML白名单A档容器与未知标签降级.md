# ADR-083 · HTML 白名单 A 档容器与未知标签降级

| 项 | 值 |
|---|---|
| 状态 | 现行 |
| 日期 | 2026-10-20 |

## 决定

HTML 白名单只扩「对齐容器」这一档,并把白名单外标签的降级行为从「丢弃 / 转义」统一为「剥壳留文本」:

1. 块级只放行 `div` / `p`,唯一属性 `align`,取值限 `left` / `center` / `right`(大小写不敏感,其余值按非法属性忽略并告警);
2. 容器内容限「文本 + 现有 14 个行内标签」,**不支持容器内嵌 Markdown**、不支持跨多个 Markdown 节点配对开闭标签;带空行的容器写法按未配对标签处理(只留文本);
3. 行内标签仍不允许任何属性,`style` / `class` / `id` / `on*` / `data-*` 一律不开口子;
4. 白名单外标签统一「剥壳留文本」:删除标签本身、保留其内部文本;`script` / `style` / `iframe` / `object` / `embed` / `template` 整段丢弃;HTML 注释丢弃(分页注释 `<!-- page-break -->` 除外);
5. 判定、解析、序列化、剥壳、标签/属性枚举收敛到 `src/core/markdown/html-whitelist.ts` 单模块,docx 与 pdf 只做渲染映射,不再各持一套扫描算法;
6. 预检从「只判标签名」升级为「标签 + 属性」两级:白名单外标签报原告警,白名单内标签带非法属性报新告警。

## 背景

现状只支持 14 个无属性行内标签,判定单源在 `src/core/markdown/html-whitelist.ts`,但表达式扫描在两处各写一份(`docx/handlers/inline-html.ts` 的节点流合并与 `pdf/rules/html.ts` 的源码栈扫描)。用户实际遇到的 HTML 只有两类:用 `<div align="center">` / `<p align="center">` 做居中,以及导出工具塞进来的带属性/未知标签。

现状对这两类的处理都不好:带属性的白名单标签在预检里**不报**,却被 docx 整段丢弃、被 pdf 转义成源码文本;块级容器同样如此。用户看到的是「内容没了」或「标签满地」。

A 档按真实需求取最小集合,避免把「HTML 子集」做成一个需要长期维护的 HTML→docx 转换器。台账的重看条件因此收窄为「出现 HTML 表格或 `style` 类真实需求」,不是「有块级需求就做全量」。

## 备选方案

- **一次做满 HTML 子集**(table / figure / details / 受控 style):docx 侧等于新写一个小型 HTML→docx 映射器,表格合并、嵌套、间距都是长期负担;且 `details` 在打印产物里没有交互语义。不选。
- **引入 `parse5` 做容错解析**:浏览器级容错对手写 Markdown 里的片段用不上,还新增一条依赖与一层需要裁剪的白名单。不选。
- **保留两套扫描各自扩展**:行内阶段尚可维护,块级与属性一上来,两侧漂移面成倍扩大;两处注释已互为「须同步」的软约束,不构成护栏。不选。
- **只扩白名单、不改未知标签降级**:`<div class="x">正文</div>` 仍然丢整段,预检的「带属性不报」缺陷继续存在。不选。

## 后果

- docx 与 pdf 的 HTML 能力此后由同一份标签/属性表驱动;新增标签必须同时给出 docx 映射,否则渲染色会掉回降级路径。
- PDF 侧输出由本仓重新序列化,不直接透传用户原文:属性值重新转义,`style` 由本仓按 `align` 生成。安全边界从「整串白名单判定」变成「属性表 + 序列化」,新增属性时必须同时给出取值校验。
- 未知标签从「pdf 显示源码 / docx 丢弃」变成「两侧都只留文本」,`warn.htmlTagNotAllowed` 的语义随之改变,三语文案须同批更新。
- 「容器内不解析 Markdown」是刻意的能力边界;用户需要在容器内使用粗体/斜体时,只能用行内 HTML 标签,不能用 `**`。若后续要支持,须先做两侧的跨节点配对,不在本档内顺手加。
