## 决定

`build/`（产物生产）与 `dev/`（人工目检/诊断）**不纳入**树边界 import 规则的治理面。这是**显式决策**，不是默认遗留的空白状态。

改用**路径常量存活性断言**看守这类依赖：`gates/geometry/geometry/driver.mjs` 导出的具名路径常量里，凡「断言时点必然已存在」的（`root` / `entryScriptPath` / `preload` / `styleDir`）逐个做存在性校验，悬空即判红并指名常量名与绝对路径。产出目录（`distIndex` / `outDir` / `reportPath`）刻意**不**断言 —— 它们在写之前合法地不存在。

## 背景

REQ-110 目录重组拆出这两棵工具树时，它们被登记为 `TREE_BOUNDARY_LITERAL_PREFIXES` 里「被引用、不治理」的**字面前缀**，并在注释里写「与 `dist` 同形」。那是描述现状，不是论证过该不该治理。REQ-116 要求把这件事定下来。

评审（`ora-4`）按 [ADR-042](ADR-042-行为契约清单走声明加等式纯清单走磁盘派生.md) 的判据 —— **「新增目录加错了会不会静默改变行为」** —— 逐条实测了三条候选规则，结论全部是否决：

| 候选规则 | 实测结果 |
|---|---|
| ① `src/**` 不得 import `dev/**` · `build/**` | `src` 树 603 条相对 import，**0 违规**；纯前瞻 |
| ② 工具树不得 import `test/{segments,main,renderer,common}/` | 两树共 10 条相对 import，**0 违规**；纯前瞻 |
| ③ 登记「运行时路径拼接」这条跨树依赖 | **结构上不可表达**（见下） |

三条之所以都不值得立，按 ADR-042 的分类：这两棵树是**纯清单** —— 加错目录**不改变行为**（它们不 assert 任何东西）。给 5 个文件、10 条边、零违规的树立 allow-list 规则，是 ADR-042 备选表里「两者统一为全部显式声明+等式」的原样重演，强行制造维护成本换零收益。

## 备选方案

**否决一：给 `build/` `dev/` 立 import allow-list 规则。**

除 0 违规之外还有两个更硬的理由：

1. **①会写成 98.6% 恒绿的规则。** `TREE_SCAN_EXTENSIONS` 只有 `.js` / `.mjs` / `.cjs`，而 `src/` 的 148 个代码文件里**只有 2 个**是这三种扩展名（145 个 `.ts`、1 个 `.cts`）。规则扫到 1.4%，其余 `.ts` 全部隐形。而 `selfCheckTreeLayout` 只验「scope 目录存在」、**不验扫到了几个文件**，自检会绿着放行这条失效规则 —— 这正是 [ADR-043](ADR-043-树边界规则allowlist与shared零跨树出边.md) 点名的「扫不到就等于没规则」恒绿失效。
2. **③会开 ADR-043 自己警惕的口子。** 树边界规则的输入是 import 说明符（`collectRelativeImportsWithLine` 的三条正则），`path.join(root, "dev", …)` 是普通函数调用的字符串实参，**整条管线没有一步看它**。而全仓 77 处根锚定路径拼接里**只有 20 处是纯字面量**（26%），其余 57 处首参或后续是变量。任何基于字面量的规则只能覆盖四分之一的面，明天有人写 `path.join(root, ...parts)` 就绕过 —— 与 ADR-043 的立场正面冲突。

**否决二：登记已知的反向跨树依赖**（`gates/geometry/driver.mjs` 把 `dev/visual-preload.cjs` 当 preload 消费）。理由同上：它是运行时路径拼接，静态登记等于给一条只能看见 26% 面的规则开口子。

**否决三：把 preload 的根改由 `driver.mjs` 注入（REQ-126 原方案）。** 派工前提错误 —— `driver.mjs` 只导出路径字符串常量，不 spawn、不建窗口；真正的注入点是 `worker.mjs`（`new BrowserWindow`）与 `orchestrator.mjs`（`spawn`）。实际实施时按此修正，且 `dev/visual-preload.cjs` 有**第二个消费方** `dev/visual-check.mjs`（`npm run ui:shots`），两处都必须注入，否则「缺失即判红」会直接弄挂该命令。

## 后果

- **工具树没有 import 层面的治理**，这是本决策显式承担的成本。它们能引什么无约束 —— 但它们也不 assert 任何东西，被引时不改变行为，风险低于 `test/` 与 `gates/`。
- **跨树的运行时路径依赖改由「锚在常量上」的存在性校验看守**，不可绕过：重写 `path.join(root, ...parts)` 躲不掉，因为检查锚在常量声明上。失败形态是**恒红**（路径不在就红），与 ADR-041 / ADR-043 警惕的「恒绿」方向相反。
- **本决策不覆盖自算项目根**。`dev/visual-preload.cjs` 曾是全仓唯一自陈深度耦合却仍自算根的文件；`ROOT_COMPUTE_PATTERNS` 四条正则对它的命中数是 **0**（它用 CJS 的 `__dirname`，不带 `import.meta`）—— 即 ADR-040 的「零豁免」在那个文件上是**正则盲区，不是有意豁免**。该文件的根已改为由注入传入（REQ-126），但**盲区本身未被本决策覆盖**，登记在 REQ-124。
- 若将来 `build/` / `dev/` 长出新的职责（例如开始 assert 什么、或新增跨树 import），本决策须重看 —— 那时它们就不再是 ADR-042 意义上的「纯清单」了。
