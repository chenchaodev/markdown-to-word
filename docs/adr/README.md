# 架构决策记录

**本目录装会被取代的决定。** 分界线是**可变性**，不是「有没有决定」：决定被推翻时另起一份新文件、旧条只在状态行标取代 —— 这才进 `adr/`。**不会变的事实快照**（查到的库行为、实测数据、走过的错路）进 [`docs/evidence/`](../evidence/)，只增不改。两者同源于「不改历史」，差别在**有没有后继**。

## 一决策一文件

一个决定一个文件，文件名 `docs/adr/ADR-0NN-短标题.md`，`0NN` 固定三位零填充（`ADR-001` / `ADR-012`，与工作项号 `REQ-003` 同约定；大写是为了与工作项号一眼区分）。决定被推翻时**不改正文，另起一个新文件**（见下「取代写法」）。

## 序号分配

**这是唯一的分配方式，没有中央台账。**

- `0NN` = 本目录现有文件的最大号 + 1；`adr/` 为空时从 `ADR-001` 起。
- 新建前先 `ls docs/adr/` 确认最大号，并确认没有重号（两个文件同号即为错）。
- 号不复用：文件被取代后旧号仍占位，新决定继续往后取号。

```bash
ls docs/adr/
```

## 字段骨架

新建一个 `docs/adr/ADR-0NN-短标题.md`，逐字段填：

```markdown
# ADR-0NN · <决策标题>

| 项 | 值 |
|---|---|
| 状态 | 现行 / 已被 ADR-0NN 取代 / 部分被取代 |
| 日期 | YYYY-MM-DD |

## 决定

<一句话说清决定了什么。>

## 背景

<为什么需要做这个决定：当时的约束、痛点、触发事件。>

## 备选方案

<考虑过但没选的方案，一条一行 + 不选的理由。>

## 后果

<这个决定带来的好处与代价；有什么以后会受它的约束。>
```

## 取代写法

旧条目**不改动正文**，只把它的「状态」改成「已被 ADR-0NN 取代」（`部分被取代` 同理，并写清被取代的是哪几段）；新文件在「背景」里写清它与旧条目的关系：

```markdown
## 背景

本条取代 [ADR-002](ADR-002-短标题.md)。旧条目的「决定」仍然成立，本条只把 `<具体哪一点>` 改为 `<新做法>`，其余部分沿用。
```

被取代不等于作废：旧条目留在目录里，`ls` 一眼能看出演进链条。
