# 研究结论

### 2026-08-02 G4 实测事实(printToPDF 管线,已验证)
- 结论:
  - `@mdit/plugin-tasklist@1.0.2` peer 要求 markdown-it ^14.2.0,与 15.0.0(2026-07-30 发布)冲突 → 项目固定 markdown-it **14.3.0**(同样原生 ESM),插件生态按 14 系演进
  - `printToPDF({ pageSize:'A4', margins:0, printBackground:true, preferCSSPageSize:true, displayHeaderFooter:true, footerTemplate })` 在 Electron 43 实测成功;margins 设 0、边距交给 `@page { size:A4; margin:18mm 16mm 22mm }`(preferCSSPageSize 生效)
  - 任务列表 checkbox 打印 bug 规避方案实测有效:渲染后把 `<input class="task-list-item-checkbox" type="checkbox" disabled[ checked]>` 替换为 ☐/☑ 字符 + `li.task-list-item { list-style:none }`,PDF 输出为 Unicode 符号(observer 实测截图确认,非原生控件)
  - 图片统一转 `pathToFileURL` 绝对路径(override image rule)实测可用:相对路径图片正确嵌入 PDF
  - `footerTemplate` 必须内联样式(9px 灰字),页码「第 X 页 / 共 X 页」正常
  - 代码高亮:`import hljs from 'highlight.js/lib/common'` + highlight 回调 + `ignoreIllegals:true` 实测可用;PDF 需 printBackground 才有底色(已开)
  - smoke 已扩展 pdf 链路(中文/表格/代码块/任务列表/删除线/图片/页码,魔数 %PDF- 校验)
- 理由:全部经本项目实际运行验证(smoke + PDF 产物 + observer 视觉确认)
- 来源: 自查 + @librarian(lib-1 调研)+ @observer(obs-1 视觉验收)

### 2026-08-02 G4 调研:markdown-it → HTML → printToPDF 管线(带来源,待 G4 实测)
- 结论:
  - markdown-it 15.x 原生 ESM(内置 TS 声明,无需 @types);**表格/删除线核心内置默认开启,零插件**;任务列表唯一需插件:`@mdit/plugin-tasklist`(mdit-plugins 官方 TS 集合,活跃维护);`markdown-it-gfm` 包不存在(npm 404)
  - highlight.js:`import hljs from 'highlight.js/lib/common'`(ESM exports 映射 `./es/common.js`),highlight 回调 + `ignoreIllegals: true`;CSS 主题经模板 `<link>` 引入;**printToPDF 必须 `printBackground: true` 才带代码块底色**
  - printToPDF 固定参数:`pageSize: 'A4'`(默认 Letter!)+ `printBackground: true` + `preferCSSPageSize: true`(否则 `@page` size/margin 被忽略,issue #38674);@page 存在时 `landscape` 选项失效(issue #8365),方向写 CSS;页码走 `footerTemplate` 的 `pageNumber`/`totalPages` 类,`@page` margin box 页码不可靠
  - 图片:HTML **落盘临时文件 + `webContents.loadFile()`**,file:// 下相对 src 自动解析;data URL 加载才需要 `baseURLForDataURL`
  - 分页:`break-before: page`(别名 `page-break-before: always`)在 Chromium 打印可靠;`break-inside: avoid` 有兼容缺口,强制分页最稳
  - **已知坑(待实测)**:Chromium 打印原生 checkbox 有 bug(勾选态不显示/全黑,issues 40627907/40350661)→ 任务列表用 CSS `appearance: none` 自定义外观
- 理由:@librarian 调研,官方文档/Chromium issue/2026 实测来源
- 来源: @librarian(lib-1)
- 关联: 里程碑 G4,src/core/pdf/render.ts

### 2026-08-02 md→pdf 路线修订:弃 md-to-pdf,改 Electron printToPDF
- 结论:pdf 路线由 `md-to-pdf`(5.2.5)改为「markdown-it → HTML 模板 → `webContents.printToPDF()`」(Electron 43 内置,与 puppeteer `page.pdf()` 同源)
- 理由:Electron 自带 Chromium,保留 md-to-pdf 会重复下载 ~300MB 第二个 Chromium,且其 9 个月无更新;自研 HTML 模板将来可复用做预览
- 来源: @librarian + @oracle
- 关联: docs/架构决策.md ADR-002
- 取代:下方「md→pdf 库调研」条目中 pdf 部分

### 2026-08-02 Windows GUI 方案调研
- 结论:选 **Electron**(43.2.0,2026-07);Tauri 体积小但 Node 代码需 sidecar 改造;本地服务+浏览器体验差;neutralino 社区小
- 理由:主进程即 Node,现有 TS 管线直接 import;一份 Chromium 两用(GUI + PDF 打印)
- 镜像(勿回退):安装设 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`;electron-builder 另需 `ELECTRON_BUILDER_BINARIES_MIRROR`(winCodeSign/nsis)
- 来源: @librarian
- 关联: docs/架构决策.md ADR-002

### 2026-08-02 md→docx / md→pdf 库调研(规划选型用)
- 结论:docx 路线选 `docx`(9.7.1,2026-05-27)+ remark 自研渲染;**pdf 部分已被 2026-08-02「md→pdf 路线修订」条目取代**
- 理由:
  - docx:中文 eastAsia 一等支持(`font: { ascii, eastAsia, hAnsi }`),原生 ESM+TS,600 万下载/周,维护稳定;`@mohtasham/md-to-docx`(3.0.1,2026-07-31)仅暴露 fontFamily 无独立 eastAsia,留作回退;`markdown-docx`(vace)无字体入口,排除
  - pdf(原结论):md-to-pdf 一行 API 内置 markdown-it+语法高亮+分页;中文靠系统字体(Linux 缺 noto-cjk 会出方块)或 CSS `@font-face` 内嵌;`pdfmake` 需手动注册 TTF 字体,最不省事
- 来源: @librarian
- 关联: docs/路线图与迭代规划.md

### 2026-08-02 G1 实测事实(docx 9.x + remark 管线,已验证)
- 结论:
  - `docx` 9.x 的 `Document` 直接收 `numbering: INumberingOptions` 对象,不需要 `new Numbering()` 实例
  - `TextRun` 无公开可变 `options` 字段,行内样式用构造参数累积传递(不可事后改)
  - mdast 中 `image` 是 **PhrasingContent 行内节点**(嵌在 paragraph 内),不是块级节点;行内渲染需支持 `ImageRun`
  - `ImageRun` 的 type 枚举是 `png/jpg/gif`,魔数判断要返回 `"jpg"` 而非 `"jpeg"`
  - Windows 下生成 docx:设置 `font: { ascii, eastAsia, hAnsi }` 后 document.xml 正确写入 eastAsia,中文字体生效
- 理由:全部经本项目实际运行验证(typecheck + 生成 docx + 解包检查 XML)
- 来源: 自查
- 关联: src/core/docx/render.ts,里程碑 G1
