# 用户手册

## 简介

Markdown 转换工具是一款 Windows 桌面应用，把 Markdown 文件转换成 **Word (.docx)** 或 **PDF** 文档。转换在本地完成，文件不上传，无隐私风险。

输出的是真正的 Word 文档（不是改后缀的网页），中文排版可控：字体、字号、行距、缩进、纸张、边距、分页、章节编号都可设置。

## 安装与卸载

- **安装**：双击 `MarkdownToWord-Setup-<版本>.exe`，按向导下一步即可（可选择安装目录）
- **卸载**：Windows「设置 → 应用」中找到 `MarkdownToWord` 卸载即可（列表里显示的是安装包产品名，「Markdown 转换工具」只是窗口标题）

## 快速上手

### 基本转换

1. **选择文件**：点击「选择文件」或直接把 Markdown 文件（支持多个）/文件夹拖入窗口
2. **选格式**：底部选择「Word (.docx)」或「PDF (.pdf)」
3. **点转换**：单文件点「开始转换」；多文件可选「批量转换」（每个文件一个文档）或「合并转换」（合成一个文档）

转换完成后会显示输出路径，可一键打开文件或所在文件夹。

### 剪贴板直转

主界面空态/拖放区显示「粘贴 Markdown 转换」按钮：

- **粘贴文本**：点击按钮后读取剪贴板 Markdown 文本直接转换
- **粘贴路径**：剪贴板为文件路径时，复用拖入队列逻辑
- **空/非文本**：给出提示，不执行转换

适合从 AI 工具（ChatGPT、Claude 等）复制 Markdown 输出后直接转换。

### 成书向导

点击「成书向导」按钮，七步引导式串联所有功能：

| 步骤 | 内容 | 说明 |
| ---- | ---- | ---- |
| ① 模板/预设 | 选择内置预设或导入 Word 模板 | 覆盖字体、字号、页面设置 |
| ② 封面页 | 输入标题/作者，生成独立封面 | docx 封面节 / PDF HTML 封面 |
| ③ 页眉页脚 | 默认/自定义/无三种模式 | 支持 logo 和左右分栏 |
| ④ 水印 | 文字/角度/不透明度/浅灰 | Word 旋转置底，PDF 固定覆盖层 |
| ⑤ 合并源 | 多选 Markdown + 排序 | 以 page-break 拼接 |
| ⑥ 目录/页码 | 开 TOC + 选择模式 | 静态或 Word 域目录 |
| ⑦ 输出 | 付印格式三选一 | Word / PDF / 双格式；含封面页和完整目录 |

全程无需打开设置面板即可产出复杂成书。

### 首次启动引导

首次启动时会出现「选预设 → 向导 → 转换」引导路径，帮助快速上手。可跳过，不强制打开设置面板；非首次启动不再出现。

## 命令行与 AI 助手

图形界面之外，本程序还提供命令行入口与供 AI 助手调用的 MCP 服务端，两者调用同一套转换能力。装好本程序后即可使用，不需要另装 Node.js。

### 何时用得上

- **命令行**：把转换写进脚本、批处理或自动化流程，一次处理一批文件，并按退出码判断成败
- **AI 助手**：让支持 MCP 的助手（如 Claude Code、Cursor、Cline 等）直接把 Markdown 转成 Word，不必把文件内容粘贴进对话

### 入口在哪

| 形态 | 命令行入口 | MCP 服务端 |
| ---- | ---- | ---- |
| 装好本程序后（无需 Node.js） | `%LOCALAPPDATA%\Programs\MarkdownToWord\m2w.cmd` | 同一个转发器，另设环境变量 `M2W_ENTRY=dist\mcp\index.js` |
| 从源码检出 | `node dist/cli/index.js` | `node dist/mcp/index.js` |

安装版把命令行入口装成一个转发器 `m2w.cmd`，落在安装根目录、与程序可执行文件并列，写出完整路径即可调用：

```bash
"%LOCALAPPDATA%\Programs\MarkdownToWord\m2w.cmd" 笔记.md
```

它调用的是安装包内那份转换代码，与图形界面是同一份实现，因此行为和版本都一致。

**该用哪一种：** 只装了安装包就用安装版入口，无需准备任何环境；要改代码、在开发环境里跑，或需要在多份检出之间切换时，才用源码检出的两条命令，那条路径需要 Node.js >= 22.13 与已装齐的依赖，并先完成构建。

### 安装版入口的三点限制

1. **不在 PATH，也没有开始菜单快捷方式。** 命令行里要写上面那个完整路径，或先把安装根目录加进 PATH。
2. **不能被直接拉起。** Windows 上不能用 `spawn` 直接启动 `.cmd`，须经 `cmd.exe /d /s /c` 转发一道；而 `cmd /s /c` 会剥掉最外层一对引号，路径含空格时要写成 `""完整路径""`。这是调用方（脚本或客户端）要负责的事，不是转发器的缺陷。
3. **MCP 只产出 Word。** 经安装版入口调起 MCP 服务端时不提供 PDF；Mermaid 图表不渲染，会在返回值的 `degraded` 字段里报出。配置写法与协议细节见 [MCP 接入](MCP.md)。

### 命令行入口

两种形态的输入路径与选项完全一致，下面以源码检出形态为例：

```bash
node dist/cli/index.js <输入路径...> [选项]
```

三行即可跑通：

```bash
# 单个文件 → 同目录同名 .docx
node dist/cli/index.js 笔记.md

# 一条命令出两个格式
node dist/cli/index.js 笔记.md --format both

# 整个目录（递归收集 .md / .markdown）
node dist/cli/index.js ./文章目录
```

常用选项：

| 选项 | 说明 |
| ---- | ---- |
| `--format` | 输出格式：`docx`（默认）/ `pdf` / `both` |
| `-o`, `--output` | 指定产物的完整路径；只能配单个输入，且不能与 `--format both` 同时使用 |
| `--template` | 套用一个内置排版预设，省略则使用默认排版 |
| `--json` | 标准输出改为结构化结果数组，便于脚本解析 |
| `--help` | 显示用法说明 |

输入可以是文件，也可以是目录。退出码：`0` 成功、`1` 命令行写法有误、`2` 输入读不到、`3` 转换失败、`4` 产物写不出去。完整的语法、内置预设清单、JSON 字段与退出码表见 [命令行用法](CLI.md)。

### AI 助手调用（MCP）

源码检出形态在助手的 MCP 配置里加一段，然后重启助手，助手的工具列表里会出现 `convert_markdown`：

```json
{
  "mcpServers": {
    "markdown-to-word": {
      "command": "node",
      "args": ["<项目路径>/dist/mcp/index.js"]
    }
  }
}
```

该工具把 Markdown 转成 `.docx`。装好安装包后的配置形态见 [MCP 接入 · 安装版形态](MCP.md#安装版形态)，参数与返回值的字段表也在该页。

### 与界面行为的三处差异

- **不自动打开产物**：命令行入口转换完成后不打开文件夹或文档
- **同名改名的规则分两路**：未指定产物路径时自动写成「名 (2).docx」，既有文件保持原样；用 `-o`（AI 助手侧为 `outputPath`）点名路径时不自动改名，该路径已被占用则本次失败
- **不渲染 Mermaid 图表**：两种用法都没有图表渲染宿主，` ```mermaid ` 围栏按等宽代码块写入产物；AI 助手侧还会把这一降级写进返回值的 `degraded` 字段，供助手判断产物是否可靠。需要出图请用图形界面转换

两种用法都不读取界面里保存的设置，排版完全由本次命令的选项或参数决定，因此结果跨会话可复现。

## 界面说明

### 主界面布局

- **标题栏**：品牌区 + 格式切换（Word/PDF）+ 设置按钮 + 关于按钮
- **文件区**：拖入文件/文件夹，或点「选择文件」
- **快速参数条**：模板预设 + 纸张 + 方向 + 输出目录，四项高频参数即时调整（与设置抽屉同源双向同步）
- **转换按钮**：开始转换（底部常驻）
- **最近转换**：转换后显示最近记录

### 文件操作

- **单文件态**：显示「追加文件」按钮，点击追加更多文件
- **多文件态**：可追加、移除、拖拽调整顺序，列表按顺序转换
- **点击行为**：单文件=更换文件，多文件=追加文件；拖入新文件始终=追加
- **快捷键**：`Ctrl+O` 添加文件、`Ctrl+Enter` 开始转换

### 最近转换

最近转换是窗口下方常驻的折叠条，转换成功后才出现（无记录时整条不显示）：

- **单击条目**：仅加载到文件列表、不转换，可先改设置再转
- **行内圆形箭头图标**（悬停或键盘聚焦时浮现）：重新转换，按该条目记录的格式直接重转
- **行内文件夹图标**：打开该源文件所在文件夹
- **「清空记录」**：清空全部最近记录
- 记录条数有上限，同一路径只保留最近一条，列表按时间由新到旧排列

### 设置面板

「设置」抽屉内含 6 组标签页导航：

| 标签 | 内容 |
| ---- | ---- |
| 01 预设 | 模板预设选择与说明，另存为、删除、导入/导出、导入 Word 模板 |
| 02 排版 | 纸张、方向、四边边距、中文字体、西文字体、正文字号、行距倍数、标题字号档位、标题间距档位、首行缩进、对齐方式 |
| 03 页眉页脚与水印 | 页眉模式、页眉文字、页眉图片、页眉布局、自定义页脚；下半部分为水印文字 / 旋转角度 / 不透明度 / 浅灰经典观感 |
| 04 编号与目录 | 章节编号、题注编号、公式编号、自动目录（其下挂目录模式）、H1 前分页 |
| 05 转换 | AI 清理（含保守规整 / 结构改写两个分档）、Obsidian 兼容、Obsidian 附件子文件夹、输出目录、导出后行为、PDF 自定义 CSS |

05 / 06 两组组头带「不入预设」标记（这两组的内容不随模板预设变动）。改动即时生效并自动保存。

## 转换模式

| 模式 | 触发 | 输出 |
| ---- | ---- | ---- |
| 单文件 | 选择 1 个文件 → 开始转换 | 源文件同名换扩展名 |
| 批量 | 选择多个文件 → 批量转换 | 每个文件单独生成一个文档 |
| 合并 | 选择多个文件 → 合并转换 | 所有文件按顺序合成一个文档，文件名含「-合并」；合并产物含单一总目录，覆盖全部源文件标题（可点击跳转） |

**重名保护**：输出文件已存在时自动加序号（如 `文档 (2).docx`），绝不覆盖原有文件。

**完成弹窗**：转换结果始终显示在常驻的结果汇总条（路径 + 打开所在文件夹 / 打开文件 + 可折叠的警告列表）。要不要额外弹「转换完成」弹窗，由弹窗内的「不再提示」复选框控制——它默认已勾选（即默认不弹）；取消勾选后每次转换完成都会弹窗，并提供复制路径、打开所在文件夹、打开文件。

## 转换预检报告

开始转换前（**所有**转换入口都触发：单文件、批量、合并、成书向导付印、剪贴板直转、最近记录行内重转），程序会先做一次预检，扫描常见问题：

- 缺失的本地图片（相对路径找不到文件；含被安全边界拒绝的绝对路径 / UNC / `file://` / 越界 `..`，见「图片增强」）
- 悬空的交叉引用（如 `[章节](#sec:x)` 但文中无对应 `{#sec:x}`）
- 未标注语言的代码块（`` ``` `` 后无语言标识）
- 不被支持的公式定界符（写成 `\(x\)` / `\[x]`——本工具只认 `$…$` 与 `$$…$$`，前一种会按普通文字印出而不渲染公式）
- 白名单外的块级 HTML（该块内容会被整块丢弃）
- 未闭合的代码围栏（它之后的内容会被整段当作一个代码块）
- 未配对的 `$`（按普通文字印出）
- 形似表格却没排成表格的行（缺首行下的分隔行）

若发现问题，会弹出带「校」印章的预检报告，逐条列出警告；点「继续转换」正常出文件，点「取消」中止。干净文档（无上述问题）则不弹报告，静默直接转换。

批量/合并转换时，所有文件的警告会聚合成**一次**报告，并**按文件分组**列出（每组标明是哪个文件），不再混成一份看不出来源的清单。

**合并转换的硬阻断**：若任一源文件有未闭合的代码围栏，合并会被**直接阻止**（没有「继续」可点），并告诉你哪个文件第几行。因为合并是把多份拼成一份文档，一个未闭合的围栏会跨过文件边界，把它之后的内容——包括**后续所有文件**——整段变成一个代码块，等于凭空少掉几份稿子。单文件与批量转换不受此限，仍是「警告 + 可继续」。

## 设置项详解

### 模板预设

| 功能 | 说明 |
| ---- | ---- |
| 内置预设 | 默认 / 学术论文 / 商务简报 / 公文 / 长文阅读 / 极简 |
| 另存为预设 | 保存当前设置为自定义预设（有数量上限，超出后保留先保存的条目；上限见 `src/core/settings/settings-defaults.ts`） |
| 内置预设覆盖范围 | 完整交付链：排版、编号与目录、页眉页脚、文字水印、公式编号、H1 前分页（选预设即得成品观感）；自动目录开关与目录模式两种预设都不含 |
| 自定义预设存储范围 | 仅排版 + 页面设置（其中排版含章节编号与题注编号）；不含自动目录开关与目录模式、页眉页脚、水印、公式编号、H1 前分页与输出设置 |
| 导入/导出 | JSON 格式，仅含自定义预设（排版 + 页面设置），支持备份和分享 |
| 导入 Word 模板 | 解包 .docx 提取字体与页面设置（浅导入 v1） |

> **内置预设 vs 自定义预设**：上表是面向使用者的结论；两者的存储契约与覆盖范围的**口径单源**见 [`design/settings-ia.md`「1.5 预设的两种形态」](design/settings-ia.md)。要点：两种预设都不含自动目录开关 / 目录模式、输出目录、导出后行为、PDF CSS、AI 清理、Obsidian 兼容、主题与语言——切换预设后这些保持当前值。

| 标题间距档位 | 紧凑 / 标准 / 舒展 |
| 首行缩进 | 正文段落首行缩进 2 字符（中文正文常见排版） |
| 对齐方式 | 左对齐 / 两端对齐 |

### 编号与目录

以下开关集中在「设置」抽屉「04 编号与目录」组：

| 设置 | 说明 |
| ---- | ---- |
| 章节编号 | 标题自动生成「1 / 1.1 / 1.1.1」编号 |
| 题注编号 | 图 / 表对象下方「图: 标题」「表: 标题」前缀行自动编号（见「题注说明」） |
| 公式编号 | 默认开；关闭后公式不编号，引用保持原文本 |
| 自动目录 | 默认开；在文首生成目录页，PDF 侧同样受此开关控制；正文没有标题时不生成目录（静默跳过） |
| 目录模式 | 静态目录（免更新，默认）/ Word 域目录（带页码）。**两种模式仅 Word 生效**，PDF 侧只有静态目录，其目录始终带页码 |
| H1 前分页 | 每个一级标题（`#` 标题）另起一页 |

### 页眉页脚

页眉页脚位于「设置」抽屉「03 页眉页脚与水印」组的上半部分。它随**内置预设**整体套用，自定义预设不含（覆盖范围见「[模板预设](#模板预设)」）：

| 设置 | 说明 |
| ---- | ---- |
| 页眉模式 | 默认（标题居中）/ 自定义（自定义文字 + 可选 logo）/ 无 |
| 自定义文字 | 页眉显示的固定文字（自定义模式下） |
| logo | 页眉左侧 logo 图片（支持常见位图；读取失败降级无 logo 并提示） |
| 布局 | 居中 / 左右分栏（logo 左 + 文字右） |
| 页脚开关 | 开启后在页脚显示「第 X / 共 X 页」页码 |

Word 与 PDF 双格式页眉页脚观感一致（字号/灰度对齐）。

### 文字水印

文字水印位于同一组的下半部分（水印文字 / 旋转角度 / 不透明度 / 浅灰经典观感），同样随内置预设整体套用、自定义预设不含：

| 设置 | 说明 |
| ---- | ---- |
| 水印文字 | 每页叠加的文字内容；置空则不显示水印 |
| 角度 | 水印旋转角度（默认对角） |
| 不透明度 | 水印透明度 |
| 浅灰 | 开启→浅灰经典观感，关闭→沿用正文字色 |

水印旋转置底，不遮挡正文；抽屉底部点「恢复默认」会把它复位为默认（空文字，即不显示水印）。

### 转换

「05 转换」组整组带「不入预设」标记，即这些项不随模板预设变动：

| 设置 | 说明 |
| ---- | ---- |
| AI 清理 | 默认关；开启后其下两个分档可分别开关：**保守规整**（统一引号与破折号、补齐列表标记后的空格、清理行尾空白与多余空行，不改内容）、**结构改写**（删除 `[1]` 式引用标记与 emoji、统一标题层级，**会改动正文内容**）。脚注、链接、代码块与正文符号不动 |

主题与界面语言在「设置」抽屉「06 应用」组（整组带「不入预设」标记）。

### 外观主题

跟随系统 / 浅色 / 深色 三态切换，即时生效并记忆；深色下界面整体变色（背景/文字/按钮/弹窗/列表），预览错误页配色同步适配。

### 界面语言

界面语言由内置语言注册表驱动，当前支持三种：中文 / English / 日本語。切换即时生效并记忆（下次启动保持上次选择）。三种语言的文案键集在编译期全量锁定（缺一个键就编译不过），所以正常不会出现缺键文案；运行期查表兜底也只是「当前语言 → 英文 → 键名」，不会显示乱码。

## 图片尺寸属性

在图片后紧跟属性可控制图片尺寸：

```markdown
![图片描述](图片路径){width=50%}
![图片描述](图片路径){width=300}
![图片描述](图片路径){height=200}
![图片描述](图片路径){width=50% height=30%}
```

- **百分比**：相对正文内容宽度
- **纯数字**：像素
- **只给一维**：另一维按原图宽高等比缩放
- **两维都给**：按给定值（不保持比例）
- **独立成段图片**：自动居中显示
- **非法值**：忽略属性并给出警告

## 题注说明

紧跟在含图片的段落或表格之后的独立段落，若以「图:」/「表:」开头（半角冒号 `:` 与全角冒号 `：` 都识别）即视为题注：

- 自动按类型编号。开启章节编号时是章节式编号（章节号 + 章内序号，如「图 1.1」，每遇一级标题重置章内序号）；关闭章节编号（或正文没有一级标题）时为纯「图 N」/「表 N」，全文档连续
- Word 中为静态文字，可直接编辑
- 如不想要编号，删除编号文字即可，或在「04 编号与目录」组关掉题注编号

## 在 Word / WPS 中

- **目录**：默认「静态目录」为转换时生成的静态内容，Word 打开即见、无页码、无需更新；「Word 域目录」模式下 Word/WPS 打开会提示更新域，点「更新域」后目录显示真实页码并可点击跳转
- **页码**：原生 Word 域（页眉页脚）
- **章节编号**：原生 Word 结构，可正常编辑
- **题注编号**：静态文字，直接可编辑
- **PDF 书签**：PDF 侧边栏自动带书签大纲，可直接跳转章节

## 常见问题

### 转换相关

**Q: 转换失败，提示「编码无法识别」？**
A: 支持 UTF-8 / UTF-16 / GBK（含 GB18030）常见编码，极少无法识别；可将文件另存为 UTF-8 后重试。

**Q: 输出到了奇怪的位置？**
A: 默认输出在源文件同目录；若源文件路径过长（超过约 250 字符）会回落输出到源文件所在目录并提示，可改用「输出目录」设置固定位置。

**Q: PDF 里的中文是方块？**
A: Windows 下会自动使用系统字体（微软雅黑），一般不会出现；若在极精简系统上异常，请安装中文字体。

**Q: 公式没有编号？**
A: 检查「设置 → 04 编号与目录 → 公式编号」是否开启（默认开）；只有 `$$...$$` 独立公式块参与自动编号，行内 `$...$` 不编号；关闭开关后引用也会保持原文本。

**Q: 图片没有显示在文档里？**
A: 转换完成后的警告列表会列出原因——本地图片请确认相对路径正确（相对于 md 文件所在目录），且**不要**用绝对路径、UNC、`file://` 或跳出该目录的 `..`（这些会被安全边界直接拒绝，见「图片增强」）；网络图片需可访问，下载失败时保留原文链接；无法识别格式的图片文件会被跳过并提示。

### 目录相关

**Q: 生成的 Word 打开时提示更新域？**
A: 仅当「设置 → 04 编号与目录 → 目录模式」选择「Word 域目录」时，Word/WPS 才会提示更新域（点「是」显示真实页码）；默认「静态目录」模式打开即见、无需更新。该模式选择只影响 Word，PDF 侧的目录始终是带页码的静态目录。页码本身为原生 Word 域（页眉页脚），章节编号为原生结构，均可正常编辑。

### 安装相关

**Q: 安装时 Windows 提示「已保护你的电脑」(SmartScreen)？**
A: 本应用未做代码签名（离线本地工具，不采集任何数据）。点击「更多信息」→「仍要运行」即可继续安装；也可只从 GitHub Releases 官方页面下载安装包。

**Q: 如何升级到新版本？**
A: 本软件暂未内置自动更新。前往 [GitHub Releases](https://github.com/chenchaodev/markdown-to-word/releases) 下载最新的 `MarkdownToWord-Setup-<版本>.exe`，运行安装向导覆盖安装即可；设置文件位于本机用户数据目录，重新安装不会清除，你的偏好会保留。

### 设置相关

**Q: 如何切换界面语言？**
A: 打开「设置」抽屉，在「06 应用」分组中找到「界面语言」，可选 中文 / English / 日本語；切换即时生效并自动记忆，下次启动保持上次选择。三种语言的文案键集在编译期全量锁定（缺键编译不过），回退英文只是兜底语义。

**Q: 设置保存在哪里？如何重置？**
A: 所有设置保存在本机用户数据目录的 `settings.json`（Windows 上通常位于 `%APPDATA%\markdown-to-word\settings.json`），不会上传。要复位：设置抽屉**底部**有一个统一的「恢复默认」按钮（不在任何分组里），点它把转换相关的各组设置一次性复位为默认值并立即保存，界面语言 / 外观主题与自定义预设会保留；想单项复位，目前只有「05 转换」组的输出目录旁有一个「恢复默认」（退回「与源文件相同目录」）。若要彻底重置，关闭软件后删除该 `settings.json`，下次启动会以默认设置重新生成（不影响安装目录）。

### 离线与隐私

**Q: 转换会联网上传我的文档吗？**
A: 不会。Word / PDF 的转换、排版与图片处理全部在本机完成，文档内容不上传到任何服务器，也不离开这台电脑；软件没有账号体系，也不采集使用数据。联网只在两处发生，且都不涉及你的文档内容：文档中引用了网络图片时按需下载该图片，以及打开「关于」页时自动查询一次 GitHub Releases 的更新信息。

## 已知限制

- **仅支持 Windows**：当前只发布 Windows 桌面版，无 macOS / Linux 构建。
- **安装包未签名**：安装包当前不做代码签名，Windows SmartScreen 可能提示「已保护你的电脑」，只从 GitHub Releases 官方页面下载即可放心安装；签名状态的完整记录、风险与缓解手段、以及状态变更时的同步修改清单，一律以 [发布供应链与「现阶段明确不签名」](adr/adr-013-发布供应链与明确不签名.md) 为准（本手册不重复转述）。
- **内联 HTML 仅白名单，块级 HTML 整块丢弃**：Markdown 中的内联 HTML 仅允许白名单内的无属性标签（`strong` `b` `em` `i` `u` `s` `del` `code` `kbd` `sub` `sup` `mark` `br` `span`），带属性的标签或白名单外的标签会被忽略；块级 HTML（如 `<div>` 这类整块结构）不支持，该块内容会被整块丢弃。复杂排版请改用原生 Markdown 语法。
- **合并源有规模上限**：一次合并的源文件个数与总体积都有上限，超限直接拒绝而非静默截断（常量与理由见 `src/main/converter/merge.ts` 顶部注释）。
- **单文档图片有规模上限**：单文档的图片张数与图片总体积都有上限，超限的图片按失败处理并给出警告（预算定义见 `src/core/resource-limits.ts`）。
- **网络图片依赖可达性**：网络图片在转换时下载嵌入，需可访问；下载失败时保留原链接并提示。
- **docx 侧任务列表无 checkbox 视觉**：设计如此（与 pdf ☐/☑ 字符替代不同）。
