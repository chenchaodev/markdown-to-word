# 命令行用法

除了图形界面，本程序还提供一个命令行入口，可在脚本、批处理与自动化流程里把 Markdown 转成 Word 或 PDF。

> **前提**：命令行入口需从源码检出运行，需要 Node.js >= 22.13 与已装齐的依赖，使用前先完成构建（见 [开发者手册](DEV-GUIDE.md) 的「命令」节）。Windows 安装版程序不含该入口。

## 快速开始

```bash
# 单个文件 → 同目录同名 .docx
node dist/cli/index.js 笔记.md

# 一条命令出两个格式
node dist/cli/index.js 笔记.md --format both

# 指定产物路径（逐字写入，路径已存在则失败）
node dist/cli/index.js 笔记.md -o 报告.docx

# 整个目录（递归收集 .md / .markdown）
node dist/cli/index.js ./文章目录

# 套用排版预设，并把结果输出为 JSON
node dist/cli/index.js 笔记.md --template paper --json
```

## 语法

```
node dist/cli/index.js <输入路径...> [选项]
```

输入路径可以给一个或多个，也可以给目录（目录会被递归收集其中的 Markdown 文件）。至少需要一个输入路径。

### 选项

| 选项 | 取值 | 说明 |
|---|---|---|
| `--format` | `docx` / `pdf` / `both` | 输出格式，默认 `docx`。`both` 表示一条命令依次产出两个格式 |
| `-o`, `--output` | 路径 | 指定产物的完整路径。只能配单个输入，且不能与 `--format both` 同时使用 |
| `--template` | 预设 id | 套用一个内置排版预设，见下方清单。省略则使用默认排版 |
| `--json` | 无 | 标准输出改为结构化结果数组，便于脚本解析 |
| `--help` | 无 | 显示用法说明 |

选项也支持 `--format=pdf` 这种等号写法。写错的选项名会直接报用法错误，不会被当成文件路径。

### 内置排版预设

| id | 名称 |
|---|---|
| `default` | 默认 |
| `paper` | 学术论文 |
| `business` | 商务简报 |
| `official-cn` | 中文公文 |
| `cn-reader` | 中文长文 |
| `cn-minimal` | 中文极简 |

预设与图形界面里的模板预设是同一套，产出的排版一致。

## 输出

成功时，产物路径逐行写到标准输出，一行一个，适合直接接后续命令：

```bash
node dist/cli/index.js 笔记.md | xargs -I{} echo "已生成 {}"
```

诊断信息（警告、进度、错误）写到标准错误，因此重定向标准输出不会混入提示文字。

### JSON 输出

加 `--json` 后，标准输出是一个结果数组，每项描述一个产物：

```json
[
  {
    "input": "/abs/path/笔记.md",
    "format": "docx",
    "ok": true,
    "outputPath": "/abs/path/笔记.docx",
    "warnings": [],
    "elapsedMs": 96
  }
]
```

| 字段 | 说明 |
|---|---|
| `input` | 输入文件的绝对路径 |
| `format` | 本项的输出格式 |
| `ok` | 是否成功 |
| `outputPath` | 产物的绝对路径；失败时没有该字段 |
| `warnings` | 警告标识列表，如 `warn.gbkEncoding` |
| `elapsedMs` | 本项耗时（毫秒） |
| `error` | 失败原因；成功时没有该字段 |

即使部分输入失败，已成功的那部分仍会产出产物，失败项在数组里以 `ok: false` 标出。

## 退出码

| 退出码 | 含义 |
|---|---|
| `0` | 全部成功 |
| `1` | 命令行写法有误（未知选项、缺取值、取值非法、没有输入路径等） |
| `2` | 输入读不到（路径不存在、不可读，或目录里没有 Markdown 文件） |
| `3` | 转换失败 |
| `4` | 产物写不出去（指定路径已被占用，或输出目录建不出来） |

脚本里可以据此判断是否需要处理：

```bash
node dist/cli/index.js 笔记.md --json > result.json || echo "转换未全部成功，退出码 $?"
```

## 行为说明

**产物同名时自动改名。** 默认情况下，若目标位置已有同名产物，会写成 `笔记 (2).docx`，不会覆盖既有文件。这与图形界面的行为一致。

**`-o` 指定的路径不会改名。** 显式指定产物路径时，若该路径已被占用，本次转换直接失败（退出码 `4`）而不是改名成另一个文件名——因为调用方点名要的就是这个路径，静默换名会让按固定名取产物的脚本取不到。既有文件保持原样，不会被覆盖或截断。

**不渲染 Mermaid 图表。** 命令行入口没有图表渲染宿主，` ```mermaid ` 围栏会按等宽代码块原样写入产物。需要图形请用图形界面转换。

**不自动打开产物。** 转换完成后程序不会打开文件夹或用默认程序打开文档（`afterConvert` 恒为「不执行」）。

**不读界面里的设置。** 命令行入口不读取用户在界面里保存的设置，每次转换的排版完全由本次命令的选项决定，因此结果跨机器、跨会话可复现。

## 常见问题

**提示「pdf 需要 Electron 宿主」。** PDF 打印依赖桌面宿主。命令行入口在开发检出下需要依赖已安装；若只处理 Word，去掉 `--format pdf` 即可。

**PDF 转换比 Word 慢。** PDF 需要启动一次宿主进程，通常比 Word 多花几秒。需要批处理速度时可只产出 Word。

**目录里部分文件没被转换。** 只收集 `.md` 与 `.markdown` 两种扩展名，其他扩展名的文件会被跳过。

**转换中文文件出现乱码。** 程序会自动识别常见中文编码。若识别失败会在警告里给出提示，可先用文本编辑器另存为 UTF-8。
