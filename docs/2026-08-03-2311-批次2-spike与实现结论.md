## 1. docx TOC:docx 9.7.1 内置 TableOfContents 类(fix-5)

- `ComplexField` 在 docx 9.x 已彻底移除;`SimpleField` 只能产出 `<w:fldSimple>` 单元素(内容仅限行内,装不下多段落的 TOC 结果,**不能用于 TOC**)
- docx 9.7.1 公开导出 `TableOfContents` 类,内部用 `w:fldChar begin/separate/end` 拼标准 TOC 复杂域并包在 `w:sdt` 中,与 Word 自身生成结构一致
- 主方案(已采用):`contentChildren` 放静态占位文案(域内 separate 与 end 之间),未更新前显示占位,F9 更新后被替换;begin 带 `w:dirty="true"`(Word 打开即提示更新)
- 降级方案(同一 API):`cachedEntries: [{title, level, page, href?}]` 生成 TOC1-9 样式段落 + dot leader + 页码 + 书签超链接
- 坑:
  - TOC1-9 样式不会自动注册:cachedEntries 段落引用 `w:pStyle w:val="TOC1"` 但 styles.xml 无定义,需自行注册(basedOn Heading1-9);占位方案不需要
  - cachedEntries 超链接需逐条给 `href`(书签 anchor),`hyperlink: true` 只是开关
  - 库怪癖:`cachedEntries.length <= 1` 时额外补一个只含 end fldChar 的空段落(不致命)
- 最小代码:
  ```js
  new TableOfContents("目录", {
    hyperlink: true, headingStyleRange: "1-3",
    useAppliedParagraphOutlineLevel: true, hideTabAndPageNumbersInWebView: true,
    contentChildren: [new Paragraph({ children: [new TextRun("(目录占位:请在 Word/WPS 中右键 → 更新域 生成目录)")] })],
  })
  ```
- 关键 XML:`<w:instrText xml:space="preserve">TOC \h \o "1-3" \u \z</w:instrText>`(开关顺序库固定,与手写顺序不同但等价)

## 2. printToPDF 保留页内锚点链接(fix-9,Spike B 实测)

- 结论:**Electron printToPDF() 完整保留 HTML 内部锚点链接为 PDF 可点击链接,且跨页链接正常**
- 证据:两页各有 `/Type /Annot /Subtype /Link`,用命名目标:`/Dest /sec2`、`/Dest /sec1`;每页 `/Page` 字典带 `/Annots [...]`
- 命名目标字典 `/Dests 13 0 R`:`/sec1 [2 0 R /XYZ 6 827.13 0]`(第 1 页)、`/sec2 [8 0 R /XYZ 6 769.38 0]`(第 2 页)——双向跨页正确
- 结论:PDF 目录可用「无页码 + 锚点链接」方案;生成方式:`href="#id"` → 目标元素带 `id`,无需额外处理
- 注:Chromium 用命名目标字典(/Dests + Catalog /Dests)而非 /GoTo action,标准有效

## 3. 分页空白页 bug 与修复(fix-10 实测)

- **现象**:`breakBeforeH1: true` 时,封面/目录页尾的 `<div class="page-break"></div>` 与正文第一个 `h1 { break-before: page }` 叠加,Chromium printToPDF 产生 1 个空白页(相邻 break-before **不合并**,实测 F 场景 3 页=预期 2)
- 根因:批次 1 例外规则 `body > h1:first-child { break-before: auto }` 只覆盖"正文首个元素即 h1";封面/目录使正文第一个 h1 不再是 body 首元素,例外失效
- 修复(已验证):CSS 加 `.page-break + h1 { break-before: auto; }`(无条件;breakBeforeH1 关闭时 h1 无 break-before,规则无副作用)
- 修复后实测:F=2、G(封面)=3、D(封面+3章)=5、R1(无封面3章)=4(目录1+3章,多章必生成目录)、R2=2、R3(显式分页符+h1)=3,6/6 PASS
- 教训:Chromium 中相邻 `break-before: page` 不合并,分页符后紧跟强制分页元素必须显式例外

## 4. Electron 43 ESM 主入口:顶层 await 挂起(自查实测)

- electron 43 下,入口 `.mjs` 使用**顶层 await(如 `await app.whenReady()`)会挂起**(模块初始化被阻塞,事件循环活着但 ready 永不 resolve,30s/90s 超时保护可触发)
- 必须用 `app.whenReady().then(async () => {...}).catch(...)` 链
- 症状:脚本无任何输出、不退出;`npx electron` 还会额外触发网络检查(优先 `node_modules/.bin/electron.cmd` 直调)

## 5. core 实现要点(fix-7/fix-8)

- frontmatter 手写解析(零依赖):`/^[ \t]*---[ \t]*\r?\n([\s\S]*?)\r?\n---[ \t]*(?:\r?\n|$)/`;key 只取 title/author/date;引号剥离;任何异常返回空 metadata + 原样 body(不丢内容)
- 封面:docx 空段落撑顶距 + 居中 22pt 加粗 + 灰色 author/date + PageBreak(普通段落,不进标题层级);pdf `.cover` padding-top 80mm + 28pt 标题 + `.cover-meta` + page-break div
- pdf 外链图:渲染后收集 `<img src="https?://">` → 并发 3 下载 → data URL 内嵌(mimeFromBuffer 魔数判断 png/jpeg/gif/webp);失败保留原 URL + `warnings.push("外链图片下载失败: URL")`
- main 下载器:`createImageResolver(baseDir)` — 本地读文件 + http(s) fetch(AbortSignal.timeout(10000)、仅 2xx、失败返 null)+ 同 URL 并发去重(Map 缓存)
- 预览窗口:`preview:open` IPC → convert(pdf) → 临时 HTML → 可见 BrowserWindow 900×1100 loadFile → closed 事件清理
- title 优先级:metadata.title > context.title;docx/pdf 均如此
