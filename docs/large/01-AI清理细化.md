## 为什么做

本项目主打「AI 生成的 Markdown 直接付印」。但现在只有 3 组清理规则（引号破折号归一 / 列表标记补空格 / 行尾空白与空行折叠），而 AI 输出的真正痛点一个都没覆盖：

- **引用标记残留**：ChatGPT 之类会留下 `[1]` `[1,2]` 这类裸数字标记，付印后指向空气
- **装饰 emoji 满天飞**：AI 惯用 🎯✅📌 开头结尾，破坏「冷灰纸 + 朱砂红」的版面
- **标题层级错乱**：直接从 `##` 起（无 h1）或 h1 跳 h3，导致章节编号与目录从 1.1 开始
- **静默丢内容**：AI 输出的 `\(x\)` 定界符、`<table>` 块级标签、未闭合围栏会**无声渲染不出来**——用户付印后才发现公式和表格没了

第 4 项性质与前三项不同：它不是「清理」，是**检测告警**——因为内容已经丢了，清理无从谈起，只能在转换前告诉用户。

### 三条规则的口径（2026-09-27 用户拍板）

| 规则 | 口径 | 为何这么定 |
|---|---|---|
| 清数字型引用标记 | 只清**裸内联**标记：`[1]` `[1,2]` `[1-3]` `【1】`。**不碰** `[^n]` 脚注的定义与引用点、**不碰** `[text](url)` 链接、**不碰** `[n]: url` 链接定义、**不碰** `(Smith, 2020)` 作者-年份式 | 脚注在 pdf 路线是**真功能**（`@mdit/plugin-footnote`，`pdf/render.ts:201` 的 `md.use(footnote)`），删定义会毁掉真内容；链接与链接定义是正文的一部分。裸标记无定义可依，渲染出来就是字面量垃圾，删掉是净收益。`完整 CSL` 已于 2026-08-16 否决，轻量清理并入本需求（否决理由见 [LOG.md](../LOG.md)「判断依据」的 REQ-012 行） |
| 去 emoji | **全部**删除，含变体选择符与 ZWJ 序列（如 👨‍👩‍👧） | 规则可预测 > 判断精细。「只删装饰性」需要主观判断，同一输入结果不稳定 |
| 重整标题层级 | 全文无 h1（直接从 h2 起）→ 整体上移一级；有跳级（h1→h3）→ 补齐。**不做**按出现顺序全部重编号 | 只修异常，不推翻用户手写的层级意图 |

### 步 #01 实测确认的已知边界（规则按上表口径实现，这些形态**未**处理）

| 边界 | 表现 | 为何不修 |
|---|---|---|
| 纯文本里的 URL 含 `[1]` | `见 http://a.com/[1] 报道` → `[1]` 被清 | 保护区机制按 mdast 保护区切片替换，纯文本里的裸 URL 没有语法信息可用；加启发式（前一字符是 `://` 之类）会连带误伤 |
| 链接定义行的目标含 `[1]` | `[ref]: http://a.com/[1]` 里的 `[1]` 被清 | 同上；`[text][ref]` 本身不被当引用标记（已断言），只是其目标 URL 未纳入保护 |
| 嵌套链接形态 | `[见 [x](y) 标签](http://a.com/[1])` 的 `[1]` 被清 | CommonMark 下嵌套链接本就非法，外层括号在任何渲染器里都不是链接，remark 会把 `[1]` 重新归入 URL；**渲染结果不受影响**，属病理输入，不给破坏性规则加脆弱兜底 |
| 链接 destination 内的方括号 | `[下载](http://a.com/[1])` | **已修**：link / image 节点的 destination 源码区间已并入保护区（对全部规则生效），含 `<...>` 包裹与 title 形式 |
| setext 标题 | `===` / `---` 下划线式标题不参与层级判定，也不被上移 | 没有 `#` 可改，判定要跨行配对，误伤风险高于收益 |
| 引用块内标题 | `> ## A` 不参与判定也不改写 | 不在口径内 |
| 删后留空 | 删标记/emoji 后不补空格（`你好 👋 世界` → `你好  世界`）；整行只剩 `[1]` 时该行变空 | 各规则互不越界，空格与空行归整是 `trimBlankLines` 的职责 |

## 怎么回滚

四步各自独立可回退，按步 `git revert` 即可，无需改回他步：

- #01 revert 后 `ai-cleanup.ts` 回到三规则版本，`AiCleanupOptions` 的 per-rule 选项同时消失（`preprocess.ts` 是唯一生产调用方，revert 两文件即闭环）
- #02 revert 后 settings 少两个字段，`persist/settings.ts` 的白名单/校验/回填/合并四处同步回退；已落盘的旧 settings 缺该两字段时走 `DEFAULT_SETTINGS` 兜底路径，**不产生数据损坏**（回填是逐键取值，缺键取默认）
- #03 revert 后 precheck 回到三类检查，纯增量删除，转换链路无残留
- #04 只动文档
