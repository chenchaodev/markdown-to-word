# 脚注实现调研报告(markdown-it / remark / docx / PDF)

- 调研时间:2026-08-05
- 调研代理:@librarian(lib-2)
- 结论先行:PDF 侧装 `@mdit/plugin-footnote@^1.0.2`(与 tasklist 同源,peer 显式支持 markdown-it ^14.2.0)+ 约 6 行 CSS;docx 侧零新依赖,用 9.7.1 自带 Document `footnotes` 配置 + `FootnoteReferenceRun(id)`;remark 侧零新依赖,remark-gfm 4.0.1 已解析脚注;实现时统一处理全局编号与「内联脚注双格式不对称」两点。

## 一、markdown-it 侧脚注插件选型

**选 @mdit/plugin-footnote(1.0.2),不用 markdown-it-footnote。**

| 对比项 | @mdit/plugin-footnote 1.0.2 | markdown-it-footnote 4.0.0 |
|---|---|---|
| markdown-it 14 兼容 | peerDependencies 显式 `markdown-it: ^14.2.0`(npm registry 实测),项目 14.3.0 ✓ | 无显式 14 声明,devDeps 停在 ^13.0.2 |
| 维护状态 | 活跃(0.8.0 起支持 markdown-it v14,后迁移 ESM-only) | 4.0.0 发布于 2023-12-06 后无新版本 |
| 多行脚注(定义双缩进) | ✓ | ✓ |
| 内联脚注 `^[...]` | ✓(inline ruler footnote_inline) | ✓(同源同规则) |
| 重复引用 | ✓(subId 机制,编号 `[2:1]`) | ✓ |
| 合并防冲突 | **✓ env.docId 锚点前缀** | ✗ |
| 锚点方案 | `footnote-N` / `footnote-ref-N` | `fn-N` / `fnref-N` |

渲染输出 HTML 形态(tarball dist/index.js 渲染模板逐字提取):

```html
<sup class="footnote-ref"><a href="#footnote1">[1]</a><a class="footnote-anchor" id="footnote-ref1"></a></sup>
<hr class="footnotes-sep">
<section class="footnotes">
<ol class="footnotes-list">
<li id="footnote1" class="footnote-item">
<p>脚注内容 <a href="#footnote-ref1" class="footnote-backref">↩︎</a></p>
</li>
</ol>
</section>
```

重复引用时 caption 与锚点带 `:N` 后缀(`[2:1]`);`env.docId` 后锚点变 `#footnote-{docId}-N`;renderer 规则 `footnote_caption`/`footnote_anchor_name` 可覆盖。

最小启用样板:

```ts
import MarkdownIt from "markdown-it";
import { footnote } from "@mdit/plugin-footnote"; // 命名导出

const md = new MarkdownIt({ html: true, linkify: true });
md.use(footnote);
// 项目接入点:src/core/pdf/render.ts 的 buildMarkdownIt() 中,md.use(tasklist) 旁加一行
```

## 二、remark 侧脚注解析

**remark-gfm 4.x 已原生解析脚注,无需 remark-footnotes(已弃用)。** 脚注支持自 remark-gfm 3.0.0 加入,4.x 继承,默认开启。

mdast 节点形态:

```ts
// 引用(phrasing 内容)
{ type: "footnoteReference", identifier: "alpha", label: "alpha" }
// 定义(flow 内容,children 是完整块级树)
{ type: "footnoteDefinition", identifier: "alpha", children: [paragraph...] }
```

**注意不对称**:micromark-extension-gfm-footnote 语法 ABNF 只有 `[^id]` 引用与 `[^id]:` 定义,**不支持内联脚注 `^[...]`**,mdast 无 `footnote` 节点 → 同一份 md,docx 侧解析不到内联脚注,PDF 侧能 → 需决策(docx 把 `^[...]` 当字面量 / 自行扩展 / 文档标注)。

## 三、docx 9.7.1 FootNotes API(本地类型定义实测)

三步:① `Document` 构造器加 `footnotes` 属性(键=id 字符串,值=`{ children: Paragraph[] }`);② 正文段落 children 插 `new FootnoteReferenceRun(id)`;③ 分隔线/编号自动。

**注意:9.7.1 中 footnotes 只挂 Document 级,不在 section 级**(网上旧文档有 section 级示例,为过期内容)。

- IPropertiesOptions 第 1605 行:`readonly footnotes?: Readonly<Record<string, { readonly children: readonly Paragraph[] }>>`
- FootnoteReferenceRun(第 756 行):`constructor(id: number)`
- **id 规则**:FootNotes 构造时自动创建 id=-1 分隔线(SeperatorRun)与 id=0 续接分隔线,用户 id 从 1 起且须唯一
- **编号自动**:正文引用生成 w:footnoteReference,内容开头自动 w:footnoteRef,显示编号由 Word 按引用出现顺序自动生成;FootnoteReferenceRun 自动上标
- 内容支持多段、ImageRun、编号列表(需 Document 级 numbering)
- 样式可定制:styles.default 支持 footnoteReference(字符)/ footnoteText / footnoteTextChar(段落)

最小样板(官方 docs/usage/footnotes.md 已验证):

```ts
const doc = new Document({
  footnotes: {
    "1": { children: [new Paragraph("脚注一内容,可多段")] },
    "2": { children: [new Paragraph("脚注二内容")] },
  },
  sections: [{
    children: [
      new Paragraph({
        children: [
          new TextRun("正文开始"),
          new FootnoteReferenceRun(1),
          new TextRun("继续正文"),
          new FootnoteReferenceRun(2),
        ],
      }),
    ],
  }],
});
```

落地形态(渲染时统一编号,天然支持合并):维护 `footnotes: Record<string, { children: Paragraph[] }>` 与递增计数器;遇到 footnoteReference → `const id = ++counter; footnotes[String(id)] = { children: [...] }`,当前段落 push FootnoteReferenceRun(id);最后 `new Document({ ..., footnotes, sections })`。footnoteDefinition 内容可能嵌套引用,需递归且共用计数器。

## 四、PDF 侧脚注渲染

少量 CSS,无特殊逻辑;无溢出风险。**固有行为:Chromium 不支持 CSS float: footnote(GCPM),脚注不会落在页脚,而是按文档流集中在内容末尾渲染**——HTML→PDF 通用差异,验收时明确此预期。

- 锚点是文档内链接,printToPDF 保留为 PDF 内部链接,正文编号可点击跳脚注、↩︎ 跳回正文
- 插件输出走 renderer 规则,不受 overrideHtmlRules 白名单影响,直接可用
- 需补 CSS(接入 buildCss 内联样式块,现有 li.task-list-item 规则旁):

```css
.footnotes { font-size: 9pt; }
hr.footnotes-sep { border: none; border-top: 1px solid #d0d7de; margin: 16px 0 8px; }
ol.footnotes-list { padding-left: 22px; }
li.footnote-item { break-inside: avoid; }
sup.footnote-ref a { text-decoration: none; color: inherit; }
a.footnote-backref { text-decoration: none; margin-left: 2px; }
```

- 中文脚注无特殊处理,字体继承现有管线;返回箭头 `↩︎`(\u21A9\uFE0E)常见字体均含
- 多文件合并:项目是 md 拼接后单实例渲染,锚点天然唯一;未来分实例渲染用 env.docId

## 五、风险点

1. 中文脚注:无特殊问题。低风险。
2. **多文件合并编号冲突**:docx footnotes 是 Document 级全局表,id 必须全局唯一;项目 md 拼接 → 渲染时全局递增计数器统一编号,切忌按文件重置。
3. docx 脚注与 TOC/书签交互:若脚注引用出现在标题段落,TOC 域会把上标编号带进目录条目文本 → 建议脚注引用不放标题行;书签是 Bookmark 组件包裹标题 runs,与 FootnoteReferenceRun 不同元素,无冲突。
4. **重复引用同一脚注的语义差异**:GFM `[^2]` 出现两次 → markdown-it 渲染两个独立编号([2] 与 [2:1]);docx 若映射同一 id 的两个引用,Word 显示两次相同编号。**建议 docx 按引用次数逐个编号(与 markdown-it 对齐),而非按定义去重。**
5. **remark/markdown-it 语法不对称**:内联脚注 `^[...]` 只有 PDF 侧生效,docx 侧 mdast 无对应节点 → 需求层面决策(支持范围标注或 docx 自行扩展)。
6. OOXML 脚注是标准特性,Word/WPS 原生支持,保持「脚注 Word/WPS 双实测」验收红线。
