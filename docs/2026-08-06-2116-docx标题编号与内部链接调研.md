# docx 标题章节编号 + 内部链接跳转调研报告

- 调研时间:2026-08-05(会话延续,时间戳 2026-08-06-2116 落盘)
- 调研代理:@librarian(lib-1)
- 结论先行:标题编号用「1 个 reference + 3 级 levels + 标题段落直接挂 numbering」静态生效、零域依赖;内部链接用 9.7.1 的 `InternalHyperlink({ anchor })` 直指现有 Bookmark id,`ExternalHyperlink({ link })` 替换假链接。

## 一、标题章节自动编号(1 / 1.1 / 1.1.1)

### 首选方案:段落级 numbering

在标题 Paragraph 上直接挂 `numbering: { reference, level }`。理由:
1. 与现有 md-list 模式完全同构(render.ts 已是 `numbering: { reference, level }`),改动面最小
2. 9.7.1 实证:`numbering` 与 `heading` 并存时**不会**注入 ListParagraph 样式(cjs:17927-17931 被 `if (!options.style && !options.heading)` 挡住),pStyle(Heading1)+ numPr 并存无冲突
3. 编号静态渲染(w:numPr 直接写进段落),打开 Word/WPS **无需 F9** 即显示(硬需求);TOC 域仍需 F9,但目录更新后条目自动含编号文本
4. 样式挂钩(方案 B)可行但是全局副作用,不如段落级显式可控

### 多级「1.1.1」写法

- **只需 1 个 reference**,levels 定义 0-2(要 h4-h6 就定义到 5 级)。同一 reference 内多级共享计数器,低级别在高一级递增时自动归零重启(OOXML 原生)
- text 模板:level 0 = `"%1"`,level 1 = `"%1.%2"`,level 2 = `"%1.%2.%3"`(`%n` 只能引用 ≤ 自身级别;`%1` 在 level 1 里引用 level 0 计数器)
- 各 level:`format: "decimal"`,start 默认 1,`alignment: AlignmentType.LEFT`
- 缩进建议 `style.paragraph.indent: { left: 360, hanging: 360 }`(编号贴左边距、文字 360 twips 起;suffix 默认 tab 时 Word 在 hanging 位置放隐式制表位,经典「1.1.1⇥标题」)

### 坑:混合格式(第一章 + 1.1)

Word 中 `%n` 占位符按**被引用级别自己的 numFmt** 渲染。level 0 用 chineseCounting、level 1 用 decimal 时结果是「一.1」而非「1.1」。要「第一章 + 1.1」需在 level 1/2 开 `isLegalNumberingStyle: true`(w:isLgl),使被包含的高层计数器以阿拉伯数字渲染。渲染行为在 Word/WPS 端,建议出包实测。

### 9.7.1 最小样板

```ts
// 方案 A:段落级
function headingNumberingOptions(): INumberingOptions {
  const textFor = (level: number) =>
    Array.from({ length: level + 1 }, (_, i) => `%${i + 1}`).join(".");
  const levels = [0, 1, 2].map((level) => ({
    level,
    format: "decimal" as const,
    text: textFor(level),
    alignment: AlignmentType.LEFT,
    start: 1,
    style: { paragraph: { indent: { left: 360, hanging: 360 } } },
  }));
  return { config: [{ reference: "md-heading", levels }] };
}
// renderDocx:numbering: { config: [...numberingOptions().config, ...headingNumberingOptions().config] }

// renderHeading(depth 1-3 挂编号;h4+ 不编号):
new Paragraph({
  heading: levels[node.depth] ?? HeadingLevel.HEADING_6,
  numbering: node.depth <= 3 ? { reference: "md-heading", level: node.depth - 1 } : undefined,
  spacing: { before: 240, after: 120 },
  pageBreakBefore: node.depth === 1 && ctx.breakBeforeH1 === true,
  children: id ? [new Bookmark({ id: docxBookmarkId(id), children: runs })] : runs,
});
```

中文变体:「第一章 / 1.1 / 1.1.1」→ level 0 `format: "chineseCounting", text: "第%1章"` + level 1/2 `isLegalNumberingStyle: true`。「1.1 节」→ level 1 text `"%1.%2 节"`。编号后不想跟 tab:text 带尾随空格 + `suffix: "space"`。

### 坑与注意

1. heading + numbering + Bookmark 三者不冲突(pStyle / numPr / 段落内容三层)
2. TOC `\o "1-3"` 按内建标题样式名收集;9.7.1 Heading 样式不带 outlineLvl,Word 靠样式名识别;若想对 WPS 更稳可显式补 `paragraph: { outlineLevel: N-1 }`(纯附加)
3. 编号后 TOC 条目自动含编号(更新域后);标题处编号静态生效与 F9 无关
4. spacing/页边距不影响编号缩进(由 level 的 pPr ind 决定);不设 indent 会跳默认制表位(~1.27cm)
5. suffix 默认 tab;LevelFormat 枚举是小写字符串字面量,可直接 `"decimal" as const`
6. start 语义:concrete numId 的 startOverride 取 level 0 的 start;章节重启编号用 `instance: N`

## 二、docx 内部链接跳转

### 结论

**9.7.1 没有 `Hyperlink` 类了**(9.x 拆分):用 **`InternalHyperlink`**(内部跳转)与 **`ExternalHyperlink`**(外链),两者都是 ParagraphChild(d.ts:2515),可直接放段落 children。参数名是 `anchor`(不是 internalAnchor)。

| 事实 | 位置 |
|---|---|
| `IInternalHyperlinkOptions = { children: ParagraphChild[]; anchor: string }` | d.ts:1276-1279 |
| `class InternalHyperlink extends ConcreteHyperlink` | d.ts:1474-1476 |
| `IExternalHyperlinkOptions = { children: ParagraphChild[]; link: string }` | d.ts:1194-1197 |
| `class ExternalHyperlink` | d.ts:638-640 |
| ConcreteHyperlink 生成 `<w:hyperlink w:anchor="...">`(anchor 时无 r:id) | cjs:16800-16813 |
| HyperlinkType 常量存在但**不参与构造** | d.ts:900-903 |
| Bookmark 组件:bookmarkStart w:name = id + bookmarkEnd 自动成对 | cjs:17024-17035 |

**跳转目标**:anchor 指向 Bookmark 的字符串 id(w:name)。现有标题 `new Bookmark({ id: docxBookmarkId(slug), children: runs })` 已生成可链接目标;链接侧用同一 `docxBookmarkId(...)` 即可。

### 9.7.1 最小样板

```ts
import { ExternalHyperlink, InternalHyperlink } from "docx";

// pushRuns 的 "link" 分支替换:
case "link": {
  const text = node.children.map((c) => ("value" in c ? (c as { value: string }).value : "")).join("");
  const url = node.url;
  if (url.startsWith("#")) {
    runs.push(new InternalHyperlink({
      anchor: docxBookmarkId(url.slice(1)), // 必须与标题 Bookmark 的 id 完全一致
      children: [new TextRun({ text, color: LINK_COLOR, underline: {}, ...style })],
    }));
    break;
  }
  if (/^https?:/i.test(url)) {
    runs.push(new ExternalHyperlink({
      link: url,
      children: [new TextRun({ text, color: LINK_COLOR, underline: {}, ...style })],
    }));
    break;
  }
  runs.push(new TextRun({ text, color: LINK_COLOR, underline: {}, ...style })); // 相对路径:假链接
  break;
}
```

同步版 pushRunsSync(标题内联场景)同样替换。

### 坑与注意

1. anchor 与书签 id **字符串精确匹配**,两侧都必须走 docxBookmarkId(slug.ts:29-33:数字开头加 h-、≤40 字符);slug 去重后缀链接侧需同样解析(项目 slug 管线职责)
2. 库有默认 Hyperlink 字符样式但**不会自动应用**,children 里 TextRun 仍需手动 color/underline
3. 脚注不冲突:ParagraphChild 联合类型里与 FootnoteReferenceRun 并列,同段落可混排
4. 嵌套样式 `[*text*](#a)`:可递归 renderPhrasing 保样式(返回 TextRun 满足 ParagraphChild)
5. 悬空锚点 Word 不报错,点击无跳转(可预扫过滤,非必需)
6. TOC 域 \h 生成的目录条目本身是 InternalHyperlink 指书签,与本机制同源互不干扰
