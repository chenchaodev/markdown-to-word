1. docx@9.7.1 原生支持 OMML 数学(完整模块 src/file/paragraph/math/),无需注入原始 XML —— 红线「OMML 不承诺交付」可上调为「结构化子集 + 降级兜底」
2. 项目已用 @mdit/plugin-footnote / @mdit/plugin-tasklist(mdit-plugins 家族),该家族有现成 @mdit/plugin-katex,与 markdown-it 14.3 完全兼容,是 PDF 侧最优解

## A. PDF 侧 KaTeX(markdown-it 生态)

### A1. 插件选型
- 主流选项:@mdit/plugin-katex v1.0.1(推荐)与 @vscode/markdown-it-katex v1.1.2;老牌 markdown-it-katex 停止维护锁老版本,不可用;KaTeX 官方无 markdown-it 集成
- @mdit/plugin-katex:peer markdown-it ^14.2.0(兼容 14.3,与 footnote/tasklist 同族同维护者);基于 @mdit/plugin-tex,支持 $...$ / $$...$$、\(...\) / \[...\]、mathFence(```math);内部依赖 katex ^0.17.0(锁定 0.17.x);文档最后更新 2026-07-30 维护活跃;需自行引入 katex/dist/katex.min.css
- 备选 @vscode/markdown-it-katex:微软维护,可注入自定义 katex 实例,last published 约 2025-10

### A2. KaTeX 版本、渲染产物与本地离线嵌入
- 最新稳定 0.18.1(2026-07-19);0.18.0 BREAKING:内部 CSS 类名前缀化(如 strut → katex-strut),只影响外部自定义 CSS 选择器,项目不涉及
- 渲染产物:katex.renderToString(tex, options) 输出 <span class="katex">…</span>,默认 htmlAndMathml 双输出;output: 'mathml' 可单独输出 MathML(docx 侧免费福利)
- katex.min.css 用相对路径 url("fonts/KaTeX_AMS-Regular.woff2") 引用字体,fonts/ 必须与 CSS 同级,移动/改名即坏
- file:// 下 @font-face 相对路径:可用;win.loadFile() 场景相对路径正常;data: URL 加载 HTML 则相对路径全失效
- 字体清单(node_modules/katex/dist/fonts/ woff2 共 21 个,每个 6.7-31.6KB):
  KaTeX_AMS-Regular(27K)/Caligraphic-Bold/Caligraphic-Regular/Fraktur-Bold/Fraktur-Regular/Main-Bold/Main-BoldItalic/Main-Italic/Main-Regular(31.6K)/Math-Bold/Math-BoldItalic/Math-Italic/Math-Regular/SansSerif-Bold/SansSerif-Italic/SansSerif-Regular/Script-Bold/Script-Regular/Size1-Regular/Size2-Regular/Size3-Regular/Size4-Regular/Typewriter-Regular
- 最佳实践:复制 katex.min.css + 仅 woff2(Chromium 全支持,可删 ttf/woff 减体积)到应用资源目录,css 与 fonts/ 同级;HTML 模板用绝对 file:// 路径或复制到临时 html 同目录。不推荐 data URI 内嵌(~400KB 字体 base64 ~533KB 塞进每个 HTML)。构建期 copy(仿 scripts/copy-renderer.mjs)即可,运行时零依赖

### A3. Electron printToPDF 已知坑
1. 字体加载时序(头号坑):printToPDF 在字体加载完成前调用会得缺字形 PDF;可靠做法 did-finish-load 后 await win.webContents.executeJavaScript('document.fonts.ready') 再调 printToPDF
2. 背景丢失:必须 printBackground: true + CSS print-color-adjust: exact,否则公式边框/底色消失
3. display mode 不自动换行,超宽公式溢出页面宽度(KaTeX 固有),CSS 处理或接受截断;display 公式自带上下 margin
4. 字体替换:不要依赖系统字体,@font-face 打包字体后上述等待即可

## B. docx 侧 OMML

### B1. docx@9.7.1 数学支持
- 原生支持完整模块:src/file/paragraph/math/,官方文档 docs/usage/math.md + demo/55-math.ts
- 已确认组件:Math(容器,Paragraph children)、MathRun(文本)、MathFraction(numerator/denominator)、MathRadical(+degree)、MathSuperScript、MathSubScript、MathSubSuperScript、MathFunction(name+children)、MathSum、MathIntegral、MathLimit(n-ary 族)、MathRoundBrackets 等括号族
- 用法示例:new Paragraph({ children: [new Math({ children: [new MathFraction({ numerator: [new MathRun("1")], denominator: [new MathRun("2")] })] })] })
- 不需要注入原始 XML;Accent/Matrix 存在性需 spike 时本地 d.ts 确认

### B2. OMML 生成来源
- @mdit/plugin-katex 输出 KaTeX HTML(htmlAndMathml 双输出);KaTeX 可直接 output: 'mathml' → 最便宜 OMML 上游
- MathML→OMML 三路:
  1. 推荐:MathML → docx Math 组件树(自研 walker);开源先例 vace/markdown-docx 的 src/extensions/mathml-to-docx.ts(~130 行),直接参考
  2. npm mathml2omml(fiduswriter v0.5.0):纯 JS 输出 OMML XML 字符串,与 docx 组件 API 不直接对接,不推荐
  3. 微软官方 MML2OMML.XSL(Office16/):需 XSLT 引擎 + 依赖用户装 Office,便携工具排除
- 自研子集难度:中等偏低;走 MathML 路线完全不需要解析 TeX——KaTeX 免费给出正确结构树,自研只剩 MathML 节点 → docx 组件映射(walker 覆盖 msqrt/mfrac/msub/msup/msubsup/mrow/mo/mi/mn/mtext 等约 10 种节点)

### B3. 降级方案
- 降级线:「MathML 子集 + 纯文本源码兜底」;walker 覆盖不到或 KaTeX 转换失败 → TeX 源码以 MathRun(等宽样式)输出,不抛错不丢内容
- MathML 子集方向值得做:KaTeX output:'mathml' 零成本,walker 只 ~10 种节点映射;纯源码方案仅作失败路径,不作主方案

- remark-math 最新 6.0.0(2023-09);"works with unified 6+ and remark 14+",与项目 remark@15.0.1 + remark-gfm@4 兼容(remark-lint 官方仓库即用该组合);ESM only,Node 16+
- docx 侧只取其 mdast 解析(mdast math 节点带 value + data),渲染自研,不引入 rehype-katex

## 推荐实现路径
- PDF 侧(约 1 天):@mdit/plugin-katex(md.use(katex) 一行接入,与 footnote/tasklist 顺序一致);构建脚本仿 copy-renderer.mjs 复制 katex.min.css + 21 woff2 到资源目录;printToPDF 流程 did-finish-load 后 await document.fonts.ready 再打印,printBackground: true + print-color-adjust: exact
- docx 侧(spike 1-2 天 + 降级):remark-math@6 解析;spike: katex.renderToString(tex, { output: 'mathml', throwOnError: false }) 取 MathML → 自研 walker(参考 vace/markdown-docx mathml-to-docx.ts)覆盖 ~10 节点 → docx Math 组件;inline 公式为 Paragraph children 里的 Math,display 独立段落居中;降级:walker 未覆盖/KaTeX 报错 → TeX 源码 MathRun 等宽输出 + warning
- 双格式同源:PDF 与 docx 都从同一 mdast math 节点(TeX 源)出发,PDF 走 KaTeX HTML,docx 走 KaTeX MathML
