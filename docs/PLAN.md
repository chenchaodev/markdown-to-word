## 完成标准

- [ ] `npm run check:geometry`（链内）能判定设置抽屉的 43 个控件：全部存在且可见、组归属正确、组内顺序与声明一致、无水平溢出/裁切。**新增判据自证会红**（注入一次故障演示，见下）
- [ ] 逐控件断言 hydrate（回填值）/ bind（change 写回）/ reset（恢复默认）三条，覆盖**全部 43 个控件**，不是抽样 —— 自动断言见 `test/renderer/` 下的新增段
- [ ] 现有的 2 条**源码正则**门控守护（`test/renderer/ui-interaction-guards.test.js` 里对回填与接线的文本存在性断言）已改为**行为断言**，正则本身不作为护栏留下
- [ ] 控件 id 拼错能在**测试期**暴露：refs 的 id 集合与 `index.html` 的 id 集合做交叉比对，拼错即判红（当前 `as` 断言抹掉 null，且 radio 组查询拼错会静默得到空 `NodeList`、回填与绑定双双空转、连错误都不报）
- [ ] 截图工具补上「设置抽屉」状态，`npm run ui:shots` 能拍到抽屉（顺带关掉 REQ-074 的一半）；`DEV-GUIDE.md` 的门禁接入点表登记到位

## 修复项复测

- [ ] 护栏自证有效：新增的抽屉几何判据与逐控件断言，各注入一次故障（如把某控件的 `data-group` 改到别组、打乱组内顺序、把一个控件的 id 拼错）后**必须变红**，逐条贴出真实输出
- [ ] 「把源码正则改成行为断言」不得降低覆盖率 —— 原正则覆盖的 2 个键（`aiCleanup` 与 `tocMode`）在行为断言里必须有对应条目
- [ ] 3 个手写门控的既有行为逐个断言守护（页眉自定义折叠 + inert / AI 清理分档灰禁 / 目录模式 `.hidden` 整块移除），且**关闭态与开启态双向**都要断言（这是步 01 与顺手项的成果，不能被本步的护栏改动碰掉）
