# 波次 3 — 测试树临时清理收口（REQ-078）

> 本文件是**波次 3 的唯一状态载体**，主会话写。执行方**不写** `docs/**` 下任何文件，也不做任何 git 写操作。
> **验证基线**：见 [DEV-GUIDE.md](DEV-GUIDE.md)「验证基线」节（本文件不复述命令）。

## 相关 ADR（一行结论）

- 全局 `AGENTS.md`「回归守护分层」—— **本波命中「不得省全量」第 ① 条**：动了 `test/common/**` · `scripts/**`（共享测试设施），跨段污染只有全量暴露
- 本波**不建 ADR**：`removeFile` 是测试夹具的内部增量，不改 `src/`、不改对外接口、不改持久化结构

## 目标

三个子项，把测试树的临时清理真正收口 —— **当前状态是「白名单盖住了它们」，不是「清理了它们」**。

- **3a 目录收口（7 处）**：8 处裸 `rmSync(recursive)` 里 `test/main/input-budget.test.js:189-200` 因 junction 环**不可收口**（门禁已登记白名单），故实际能收 7 处
- **3b 单文件收口（27~28 处）**：`removeTree` **只吃目录**，删单个文件是另一类改动点。实现决定 = 给 `test/common/temp-resource.js` **增 `removeFile`**，与 `removeTree` 同一套 EBUSY/EPERM 退避重试 + 删后复查语义，**而不是各处补裸重试**
- **3c 补门禁缺项**：台账标题里的「参数完备性门禁」在 `check-temp-cleanup.mjs` 里**没有对应规则**（脚本现只管「裸 recursive 目录删除」）。助手有可选参数却无人校验调用点用法

## 下一步

等执行方返回后逐条核对完成标准，回填 [large/01](large/01-非功能需求排期.md) 波次 3 的「结果」列。

## 完成标准

1. 裸写法 0 处，**除**白名单登记项与 `input-budget` 那处硬阻塞；后者留白名单并在注释写明**为何不可收口**（junction 环）。
2. `removeFile` 落地且与 `removeTree` 共用同一套重试语义；**删除单个文件这一类改动点从此只有一个入口**。
3. 参数完备性规则能判红：**注入一处非法调用点 → `check:temp-cleanup` 判红 → 移除后绿**（贴两次输出）。规则的确切定义由执行方提出并说明理由。
4. **白名单 6 类「刻意保留裸写法」逐条仍成立、且未被连带改掉**（占用夹具复现删不掉 · 喂非法重试参数 · Electron fs 层绕行 · 错误码字面量等，见 [archive/](archive/20260928-183819-测试树临时清理写法盘点.md)）。
5. `npm run check:temp-cleanup` · `npm run check:gates` · `npm run typecheck` · `npm run lint` · **`npm run test` 全量** 全绿，贴输出。**全量不得省**。
