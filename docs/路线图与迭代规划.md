## 选型结论
| 项 | 方案 | 理由 |
| --- | ---- | ---- |
| GUI | Electron(43.x) | 主进程即 Node,现有 TS 管线直接复用;自带 Chromium 一份两用 |
| docx | `docx`(9.x)+ remark 自研渲染管线 | 中文 eastAsia 完全可控(硬需求) |
| pdf | markdown-it + HTML 模板 + `webContents.printToPDF()` | 复用 Electron Chromium,免 puppeteer 双份体积(~300MB) |

## 架构设计
- 分层:
  ```
  src/
    core/            # 纯逻辑,无 IO,可测试
      parse.ts       # remark + remark-gfm → AST
      docx/render.ts # AST → docx
      docx/theme.ts  # 字体/样式集中配置
      pdf/render.ts  # markdown-it → HTML 模板 → printToPDF
      convert.ts     # 格式注册表:convert(md, format, options) => Promise<Buffer>
    main/            # Electron 主进程:窗口、dialog、IPC、执行转换
    renderer/        # GUI UI
    cli/index.ts     # 调试/回归通道(非交付物)
  ```
- 转换在主进程执行(docx 库为 Node 原生;printToPDF 走系统字体,中文零配置)
- renderer:vanilla TS + 原生 DOM(UI 极简,不引前端框架,避免引入构建复杂度)
- IPC:`contextIsolation` + preload 白名单;`invoke('convert', ...)` + 进度经 `webContents.send` 推送;拖放由 renderer 直接取 `File.path` 校验
- 未来扩展格式只需在注册表登记 renderer

## 中文/字体策略
- docx:`theme.ts` 集中配置 `font: { ascii: 'Calibri', eastAsia: '微软雅黑', hAnsi: 'Calibri' }` 挂 Normal 样式;CLI/程序内可覆盖;宋体作备选配置项
- pdf:Windows 系统字体零配置(自动命中微软雅黑);Linux 部署时用 CSS `@font-face` 内嵌 noto-cjk(后置)

## 风险与缓解
- Electron 体积(100-250MB):asar + 压缩;不引第二个 Chromium 即最优解
- 国内网络:electron 二进制与 builder 辅助件双镜像(`ELECTRON_MIRROR` / `ELECTRON_BUILDER_BINARIES_MIRROR`),写死勿回退
- printToPDF 中文:与 md-to-pdf 同机制,Win 下微软雅黑零配置;仅 Linux 部署需 @font-face 内嵌
- 打包:ESM 主进程需确认 electron-builder 的 entry/asarUnpack 配置;Windows 路径含空格/编码统一处理
