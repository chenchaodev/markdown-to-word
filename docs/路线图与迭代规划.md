# 路线图与迭代规划

> 2026-08-02 制定。输入:库调研(2026-08-02 实查,见 docs/研究结论.md)+ @oracle 架构评审(见 docs/架构决策.md)。

## 需求范围
- 命令行工具:markdown → .docx / .pdf
- 中文内容排版可控(硬需求)
- 架构预留其他格式扩展(「等」)

## 选型结论
| 输出 | 方案 | 理由 |
| ---- | ---- | ---- |
| docx | `docx`(9.7)+ remark 自研渲染管线 | 中文 eastAsia 完全可控;现成 `@mohtasham/md-to-docx` 无独立 eastAsia 选项且维护史短,留作回退 |
| pdf | `md-to-pdf`(5.2.5)薄封装 | 一行 API 内置 markdown-it + 语法高亮 + 分页;Windows 系统字体即可支持中文 |

## 架构设计
- **非对称架构**:docx 走 remark AST 管线(为中文可控),pdf 走 md-to-pdf 现成管线(避免重写 markdown-it 全套)
- 目录结构:
  ```
  src/
    core/            # 纯逻辑,无 IO,可测试
      parse.ts       # remark + remark-gfm → AST
      docx/render.ts # AST → docx
      docx/theme.ts  # 字体/样式集中配置
      pdf/render.ts  # md-to-pdf 薄封装
      convert.ts     # 格式注册表:convert(md, format, options) => Promise<Buffer>
    cli/index.ts     # 参数解析 + 文件 IO,薄壳
  ```
- 未来扩展格式只需在注册表登记 renderer

## 中文/字体策略
- docx:`theme.ts` 集中配置 `font: { ascii: 'Calibri', eastAsia: '微软雅黑', hAnsi: 'Calibri' }` 挂 Normal 样式全局生效;CLI 可覆盖;宋体作备选配置项
- pdf:默认系统字体(Windows 零配置,自动命中微软雅黑);跨平台/部署 Linux 时用 CSS `@font-face` 内嵌 noto-cjk(选项开启,避免默认输出体积膨胀)

## 风险与缓解
- md-to-pdf 捆绑 Chromium(~300MB):列为可选依赖 + 延迟导入,仅 pdf 转换时加载
- md-to-pdf 9 个月无更新 / docx 9.x 大版本变动:两者都封装在 `core/` 一层后面,替换成本低
- 自研 docx 渲染器工作量:先覆盖 80% 场景,脚注等高阶语法延后或标记不支持
- 中文样式回归:验收样例固定含中英混排,手动打开检查纳入验证基线
