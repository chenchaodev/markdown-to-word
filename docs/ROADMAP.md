## 候选区

> 登记即分配编号,连号不跳号(`REQ`/`REF` 各自独立计数);**先改文末「编号台账」,再插本行**。分类可调整,**号永不动**。
> **每个 ### 子节内按 ID 升序**(`REQ` 段在前、`REF` 段恒在其后)。晋升/处置 = **把该行移到对应子节并改处置格**,候选区行永不删除;
> 2026-09-26 自一份已废止的项目级候选池文件迁入:那份文件同时充当需求入口与处置记录,与「单一入口」冲突,已废除;历史候选此前无号,本次统一分配(内容与处置逐条保留,未做增删)。

> **处置取值**:待拍板 / 进行中 / 暂缓 / 已明确不做 / **已拆分** / 已完成
> **取值 → 所在子节**:`活跃` = 待拍板 + 进行中 ｜ `不做` = 暂缓 + 已明确不做 + 已拆分 ｜ `已完成` = 已完成(墓碑,行不删)
> **价值**:高/中/低 ｜ **工作量**:S(≤3 文件·天级)/ M(周级)/ L(多周或有架构风险)｜ **分类**:功能新增 / 体验优化 / 架构优化·技术债 / 内部改进·代码质量 / 内部改进·文档 / 防御·安全
> **规则**:「已明确不做」保留行不删(可重新晋升且**沿用原号**);「已完成」保留行作墓碑。**「对外名」列**发版写 CHANGELOG 时回填一次(写法 → 全局配置目录 @PUBLISH-GUIDE.md)。
