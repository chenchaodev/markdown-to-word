## C1. 拖放舞台是祖先级 `role="button"`，其键盘与点击处理吞并内部按钮

**路径**

- `src/renderer/index.html:93-101`
- `src/renderer/index.html:118-178`
- `src/renderer/convert/events/selection.ts:82-149`
- `src/renderer/convert/events/selection.ts:182-210`
- `src/renderer/ui/first-run-guide.ts:19-38`
- `src/renderer/settings/settings-bindings.ts:41-50`

**类别**：[功能缺陷] [硬性规范]

**现状 / 影响**

`#dropZone` 同时是 `role="button"`、`tabindex="0"`，并在祖先上监听 Enter/Space；内部又包含选择、粘贴、向导、预览、追加、清空、引导按钮和大量表单控件。处理函数没有判断事件目标是否来自当前元素，也没有统一阻止内部按钮的 `keydown` 冒泡，只有部分入口停止 `click`。

具体影响：

- 在“粘贴转换”“成书向导”“预览”“清空”等内部按钮上按 Enter/Space，事件会先被祖先识别为“打开拖放区”，并 `preventDefault()`，导致原按钮动作被取消或走错动作。
- 首启引导按钮只处理自身 `click`，没有阻止冒泡：
  - 点击“选预设”会先聚焦预设，又继续冒泡打开文件选择框；
  - 点击“成书向导”会打开向导，又继续打开文件选择框；
  - 点击“知道了”会关闭引导，又打开文件选择框。
- `role="button"` 内嵌 radio、select、button，对屏幕阅读器形成非法或高度误导的交互树。

这不是单一无障碍瑕疵，而是核心空态操作和首启路径的鼠标、键盘双重故障。

**优化方向**

优先取消整个舞台的按钮角色，把舞台改为 `role="region"` 或普通容器：

- 文件选择通过明确的“选择文件”按钮完成；
- 舞台空白区域如仍需点击打开选择器，使用不包裹交互控件的独立背景层；
- 至少应让祖先 `keydown` 只在 `event.target === dropZone` 时响应；
- 所有内部交互控件统一阻止会触发祖先语义的 Enter/Space/click 冒泡。

**验证方式**

- 在 640×560 与常规窗口逐个用鼠标、Enter、Space 操作：选择、粘贴、向导、首启三步、预览、追加、清空。
- 检查任一内部控件操作时只发生一个动作、一个系统对话框。
- 用 Accessibility Tree 确认舞台不再显示为包含交互后代的单一 Button。

## H2. 切换语言会用静态字典覆盖真实路径、Logo、CSS 状态和预设提示

**路径**

- `src/core/i18n.ts:164-187`

- `src/renderer/index.html:640`
- `src/renderer/index.html:810`
- `src/renderer/settings/settings-bindings-app.ts:69-80`

**类别**：[功能缺陷]

**现状 / 影响**

`applyStaticTexts()` 会把所有带 `data-i18n` 的节点直接重写为字典值。但以下节点既是动态状态，又保留了 `data-i18n`：

- 快速栏输出目录；
- 页眉 Logo 状态；
- 模板预设说明；
- PDF CSS 状态。

用户设置真实输出目录或 Logo 后切换语言，界面会重新显示：

- “与源文件相同目录”；
- “未选择 Logo”；
- 通用“选择模板将覆盖……”；

实际状态仍保留在 `state.settings`，因此最严重的情况是：**界面声称输出到源目录，实际转换仍写到自定义目录。** PDF 状态也会与仍可见的“清除”按钮矛盾。

- 默认值和当前值分开渲染；
- 语言切换后从状态重新生成所有动态文案；
- 预设说明也应从当前预设重新计算，而不是退回固定标题。

**验证方式**

依次设置长输出目录、Logo、导入 CSS、选择预设，切换中/英/日三语，确认显示值与真实状态始终一致。

## H7. 预检缺少运行锁和模态隔离，重复触发会丢失 Promise，键盘也无法完整退出/浏览
