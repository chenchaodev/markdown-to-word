## 1. TableOfContents 组件(8a 官方推荐路径)
- 存在,官方文档明确要求配合 `features.updateFields: true` 使用
- 文档: github.com/dolanmiu/docx/blob/master/docs/usage/table-of-contents.md
- 源码: src/file/table-of-contents/table-of-contents.ts + table-of-contents-properties.ts
- 构造: `new TableOfContents(alias = "Table of Contents", options)`
  - 域开关映射: hyperlink(\h)、headingStyleRange(\o "1-3")、useAppliedParagraphOutlineLevel(\u)、hideTabAndPageNumbersInWebView(\z)、entryAndPageNumberSeparator(\p)、captionLabel(\a)/captionLabelIncludingNumbers(\c)、seqFieldIdentifierForPrefix(\s)、stylesWithLevels(\t)、entriesFromBookmark(\b)、tcFieldIdentifier/tcFieldLevelRange(\f/\l)、pageNumbersEntryLevelsRange(\n)、preserveTabInEntries/preserveNewLineInEntries(\w/\x)
  - 渲染层附加: contentChildren(separate 之后 end 之前的占位内容)、cachedEntries({title, level, page?, href?}[])、beginDirty(默认 true → begin 带 w:dirty)
- 最小用法:
  ```ts
  const doc = new Document({
      features: { updateFields: true },   // 官方文档:必须开
      sections: [{ children: [
          new TableOfContents("目录", { hyperlink: true, headingStyleRange: "1-3" }),
          new Paragraph({ text: "第一章", heading: HeadingLevel.HEADING_1, pageBreakBefore: true }),
      ]}],
  });
  ```
- 生成结构: w:sdt > sdtContent,内部 begin(dirty=true) → w:instrText("TOC \o "1-3" \h ...") → separate → [contentChildren 或 cachedEntries 段落] → end
- **组件本身就是手拼域的封装**,TOC 是复杂域,fldSimple 无法容纳多段目录条目,SimpleField 只能插行内域
- cachedEntries 按 level 套用 TOC1..TOC9 样式 + 右对齐点线制表位(硬编码 pageWidth=9025 twip)

## 2. 任意域插入:SimpleField 与手拼复杂域
- **docx 9.x 无 ComplexField 类**(全库搜索零结果);库内复杂域只有专用组件(SequentialIdentifier/PageNumber/PageReference/TableOfContents),其余需手拼
- SimpleField(行内简单域,官方文档推荐):
  ```ts
  export class SimpleField extends XmlComponent {
      public constructor(instruction: string, cachedValue?: string)
  }
  // 生成 <w:fldSimple w:instr="...">[cached TextRun]</w:fldSimple>
  ```
- SEQ 域示例(instruction 反斜杠在 TS 写 `\\`):
  ```ts
  new Paragraph({ children: [
      new TextRun("图 "),
      new SimpleField(" SEQ Figure \\* ARABIC \\s 1 ", "1"),
  ]});
  ```
- 转义规则: XML 层无需转义反斜杠(w:instrText 是文本节点);w:instr 属性双引号由序列化器自动转 &quot;;唯一要处理的是 TS 字符串里的 `\\`
- **空格是关键**: Word 解析域指令要求开关前有空格,惯例首尾各留一个空格 `" SEQ Figure \\* ARABIC "`
- 开关语法: `\* ARABIC`(格式)、`\* ROMAN`、`\* CHINESENUM1`(中文数字)、`\s <大纲级别>`(按标题 N 重新编号)、`\h`(REF 超链接)、`\n` 等照 OOXML 规范
- **坑**: SimpleField 无 dirty 属性(源码 FldSimpleAttrs 仅 { instr });未更新时只显示 cachedValue;不给 cachedValue 则一片空白
- 手拼复杂域: Run + RawFldChar(begin/instrText/separate/end)(issue #3480 工作区代码,Word 实测可用);库内置 SequentialIdentifier 即该结构封装,但只支持裸 identifier、无开关、无缓存值 → 带 `\* ARABIC \s 1` 的题注仍要 SimpleField 或手拼

## 3. 章节号前缀题注「图 1.1」
- **docx 库不提供 heading 自动编号**,「图 1.1」章节号来自 **STYLEREF 域**(动态,Word 原生题注机制),不是渲染期静态注入——但二者共存前提:标题编号必须走 w:numPr 自动编号,而非文本注入
- docx 默认 Heading1-9 只是 pStyle(styleId=Heading1),不含 w:numPr;自动编号需 Numbering 组件 + 段落级 numbering
- Word 原生「包含章节号」题注域组合(Word 硬编码 1=Heading 1 styleId 简写):
  ```
  图 { STYLEREF 1 \s }-{ SEQ 图 \* ARABIC \s 1 }
  ```
  参考: learn.microsoft.com/en-us/answers/questions/4781279/ 、/4995246/;`\s` 剥离章节标题非数字文本(「Section 2.」→「2」);STYLEREF 参数可写 styleId 或加引号样式名(MS KB 176540)
- **docx 无 STYLEREF 包装类**,必须 SimpleField 手插;docx 标题 styleId 是 `Heading1` 而非 Word 内置 `1`,指令必须写本文档 styles.xml 真实存在的 id:
  ```ts
  new SimpleField(" STYLEREF Heading1 \\s ", "1")   // 按 styleId,与语言版本无关,推荐
  // 或按样式名: new SimpleField(" STYLEREF \"heading 1\" \\s ", "1")
  ```
- **与 5b 静态渲染共存**: STYLEREF \s 读的是标题段落自动编号渲染值(numPr);若章节号是「手打文本」注入,STYLEREF 取不到值 → 两条路线必须二选一:编号 numPr 化(域路线)或纯文本化(静态路线)
- **WPS**: STYLEREF 在 WPS 官方博客列为支持域(TOC/SEQ/STYLEREF 等,plus.wps.cn/blog/p114770.html),官方称大部分常用域代码兼容良好;按 OOXML 标准解析 styleId,与 Word 同机制

## 4. Bookmark / REF
- Bookmark(对象字面量构造,src/file/paragraph/links/bookmark.ts):
  ```ts
  new Bookmark({ id: "figure_1", children: [/* ParagraphChild[] */] })
  // 生成 <w:bookmarkStart w:name="figure_1"/> + children + <w:bookmarkEnd/>
  // 空书签: children: []
  ```
- REF 域内置包装 NumberedItemReference(extends SimpleField,src/file/paragraph/links/numbered-item-ref.ts):
  ```ts
  new NumberedItemReference("heading_1_bookmark", "1.2.3", {
    hyperlink: true,                    // 默认 true → \h
    referenceFormat: NumberedItemReferenceFormat.FULL_CONTEXT,  // \w;NO_CONTEXT→\n;RELATIVE→\r
  });
  // 生成指令: REF heading_1_bookmark \h \w
  ```
- 纯文本引用手写: `new SimpleField(" REF 书签名 \\h ", "默认文本")`
- PAGEREF 包装: PageReference(bookmarkId, { hyperlink })(docx.js.org/api/classes/PageReference.html)
- 注意: 书签名不可含空格;REF 引用书签包围的文本,编号引用用 NumberedItemReference

## 5. 打开时自动更新域(features.updateFields)
- 位置: `Document.features`,产出 `<w:updateFields w:val="true"/>`(settings.xml)
- 用法: `new Document({ features: { updateFields: true }, ... })`(docs/usage/document.md + troubleshooting.md;源码 settings.ts: options.updateFields !== undefined → OnOffElement("w:updateFields"))
- **生效范围**: Word 打开弹提示「此文档包含可能引用其他文件的域。是否更新此文档中的域?」,确认后更新**全部域**——TOC/SEQ/STYLEREF/REF 都在内,不限于 TOC(issue #1212、docs/usage/table-of-contents.md)
- 打开自动更新 vs F9: updateFields = 打开时提示并全量更新;F9/Ctrl+A+F9 = 手动全量更新;重算范围一致,差异只在触发时机与提示;域级 w:dirty="true" 也会触发打开提示(SO 529607、c-rex.net OOXML fldSimple)
- **WPS**: 官方博客称域「打开文档或手动更新时自动刷新」、TOC/SEQ/STYLEREF 兼容良好(p114765.html),但**未明确背书 updateFields 设置项**;社区实测 WPS 更新域(F9)弹「WPS安全声明:可共享数据字段…启用此文件中所有字段的更新」(bbs.wps.cn/topic/44288);dolanmiu/docx discussion #1643 有用户称 TOC demo 在 WPS 不兼容,maintainer 实测「no issues」——**存在争议,需在目标 WPS 版本实测**;Google Docs/LibreOffice 忽略 updateFields,打开为空白需手动刷新(issue #2673)

## 6. 已知坑
- **TOC 未更新时显示**: 无缓存内容 → Word/WPS 显示**空白**;有 cachedEntries → 打开即显示缓存条目,更新后替换;contentChildren 可放占位文本;更新后无匹配条目 → 显示「错误!未找到目录项」
- **WPS 引号 bug**: WPS 12.8 之前对 `TOC \o "1-3" \h \z \u` 的英文引号有兼容 bug(触发「未找到目录项」),12.8.0.15233 修复,旧文件需重存(gi-wps.com/blogs/640620432)
- **docx TableOfContents 已知 issue**:
  - #380/#2673: TOC 空白;Google Docs 中 updateFields 无效需手动刷新
  - #1212: updateFields:true 或 dirty="true" 的提示**无法消除**,任何域更新方案都弹
  - #885/#2102: OOXML 无「页」概念,cachedEntries 的页码无法精确计算(官方明言 approximate)
  - cachedEntries 条目引用 TOC${level} 段落样式,docx 默认样式不含 TOC1-TOC9,缩进需自定义样式或靠 Word 内置;库自带制表位 right 9025 twip + dot leader + clear(硬编码 pageWidth)
  - beginDirty 默认 true → 域标记 dirty,Word 打开必提示;免提示需显式 beginDirty: false
- **SimpleField 无 dirty**: SEQ/STYLEREF/REF 等 w:fldSimple 域默认不脏,Word 打开不会自动更新 SEQ(除非全局 updateFields:true 或 F9);不传 cachedValue 时域结果为空 → 更新前看不到任何数字;规避:传占位默认值 + 全局 updateFields
- **F9 提示文案惯例**: Word 右键「更新域」;TOC 右键→更新域→「只更新页码/更新整个目录」;Ctrl+A+F9 全文档更新;WPS 全选+F9 弹「WPS安全声明」信任提示

## 7. 推荐实现路径
### 8a TOC 域开关化 → 推荐 TableOfContents 组件(非手拼)
- 理由: 组件生成完整 w:sdt + begin(可 dirty)/separate/end + FieldInstruction 自动拼域指令;手拼 SimpleField 只能写字符串,无 cachedEntries/beginDirty,且缺 sdt 包装(WPS 兼容性更差)
- 最小骨架:
  ```ts
  const children = [
    ...(enableToc ? [new TableOfContents("目录", {
      hyperlink: true, headingStyleRange: "1-3",
      beginDirty: !staticSnapshot,                    // 免更新路线关掉 dirty
      cachedEntries: staticSnapshot ? snapshotEntries : undefined,
    })] : []),
    ...bodyChildren,
  ];
  const doc = new Document({
    features: enableToc && !staticSnapshot ? { updateFields: true } : {},
    sections: [{ children }],
  });
  ```
- 两条路线代价:
  - **需更新(updateFields)**: Word/WPS 打开弹域更新提示(一次确认全量修正,内容精确,后续改标题可同步);WPS 支持度未官方背书需实测;离线预览/Google Docs 显示缓存或空白
  - **免更新(beginDirty:false + cachedEntries 静态)**: 零提示、打开即见;但页码无法精确(#885)、条目随文档修改过期;cachedEntries 不带 page 的纯超链接目录可完全免页码,是免更新路线唯一「精确」形态;适合定稿导出场景

### 8b 图/表题注 SEQ 编号 → 两条路线二选一,**与 8a 必须同路线**
- **域路线**(与 8a 更新路线配套,与 Word 原生题注同构): SequentialIdentifier("图") = SEQ 域(渲染 `SEQ 图`,begin dirty=true);章节号用 STYLEREF:
  ```ts
  new Paragraph({ style: "Caption", children: [
      new TextRun("图 "),
      new SimpleField(" STYLEREF Heading1 \\s ", "1"),   // 章节号 ← 标题必须 numPr 自动编号
      new TextRun("."),
      new SequentialIdentifier("图"),                     // 图序 ← SEQ 图 \* ARABIC
  ]})
  ```
  要求: 标题编号改为 numPr 化(5b 的 numbering 静态渲染若已是 numPr 则直接兼容;若是文本注入则必须改造,否则 STYLEREF 取不到章节号)
- **静态路线**(与 8a 免更新路线配套): 渲染期从 markdown heading 树计算章节号 + 图序,直接写文本「图 1.1」,无任何域:
  ```ts
  new Paragraph({ style: "Caption", children: [new TextRun(`图 ${chapterNum}.${figureIndex}`)] })
  ```
- 代价对比:
  | | 需更新路线(域:STYLEREF+SEQ) | 免更新路线(静态注入) |
  |---|---|---|
  | 打开行为 | Word/WPS 弹更新提示(一次全量) | 零提示、全端一致 |
  | 精确性 | 更新后完全准确 | 导出即准,改动标题后陈旧 |
  | 用户编辑 | 改标题/增删图后 F9 即同步 | 需重新导出 |
  | 适用场景 | 交付后仍会编辑的长文档 | 一次性定稿导出 |
- **明确推荐**: markdown→Word 一次性生成工具,若目标用户会用 Word 继续编辑 → 走**更新路线**(8a updateFields:true + 8b STYLEREF+SEQ,与 Word 原生机制一致);若纯「导出即定稿」→ 走**免更新路线**(8a 纯超链接 cachedEntries 或手拼静态目录 + 8b 静态注入)。**严禁混用**(目录是域、题注是静态 → 编号体系割裂)
