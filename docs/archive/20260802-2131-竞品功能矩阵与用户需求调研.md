## 二、高频用户需求(社区/GitHub issues 证据)

1. **中文/CJK 排版是行业顽疾** —— 连 Pandoc 都在反复修:eastAsia 字体提示缺失([#9817](https://github.com/jgm/pandoc/issues/9817))、中英混排标点宽度错误([#9909](https://github.com/jgm/pandoc/issues/9909))、禁用 eastAsia 的需求([#9910](https://github.com/jgm/pandoc/issues/9910))、`lang: zh-CN` 导致西文字体被锁死([#7022](https://github.com/jgm/pandoc/issues/7022)),直到 [PR #10901](https://github.com/jgm/pandoc/pull/10901)(2025 年)才把默认 eastAsia 语言改为 zh-CN。markdown-pdf 同样一堆中/日/韩字体 issue([#88](https://github.com/yzane/vscode-markdown-pdf/issues/88)、[#148](https://github.com/yzane/vscode-markdown-pdf/issues/148)、[#83](https://github.com/yzane/vscode-markdown-pdf/issues/83))。→ **「中文不乱、字体可控」就是最大的差异化**。
2. **图片丢失/路径问题是 #1 转换投诉** —— [markdowntoword.pro 故障指南](https://markdowntoword.pro/blog/markdown-conversion-troubleshooting)列 15 个高频问题,图片占 3 席并称"the #1 conversion complaint";Typora 用户大量求助导出 Word 图片不显示([ty-md.com 专文](https://ty-md.com/notes/typora-word-5-post-5ed1eb24.html))。
3. **表格转换错乱/直接失败** —— Typora + Pandoc 导出 Word 遇表格报 `couldn't read native`,用户只能删表格再手动补([CSDN 多篇](https://blog.csdn.net/m0_59415345/article/details/140496714))。
4. **大文件/大图导致转换失败** —— Typora PDF 导出大文档报 undefined(内存溢出、大图未压缩,[CSDN 文库](https://wenku.csdn.net/answer/338ju6j2ci));在线工具普遍 20MB/5MB 上限([conholdate](https://products.conholdate.app/conversion/md-to-word)、[markdown-to-word.online](https://www.markdown-to-word.online/markdown-to-word-troubleshooting/))。
5. **批量转换呼声极高** —— MarkText 的 docx 需求 issue([#2739](https://github.com/marktext/marktext/issues/2739))、Markdown All in One 的批量 print、Obsidian 批量导出成为 Better Export PDF 核心卖点、Typora 用户要靠第三方插件才能批量([typora-export-plugin 生态](https://wenku.csdn.net/answer/338ju6j2ci))。
6. **PDF 直出需求** —— Markdown All in One 至今只到 HTML,PDF 导出 issue 挂了多年没实现([#270](https://github.com/yzhang-gh/vscode-markdown/issues/270));说明"从 md 一步到 PDF"是有真实需求的。
7. **TOC/目录** —— md2docx 需提示用户在 Word 里按 F9 更新域([tomarkdown 同样](https://tomarkdown.dev/tools/markdown-to-word));Better Export PDF 把"书签大纲"作为对原生导出的增量价值 → 用户想要可导航文档。
8. **HTML-rename 假 docx 的觉醒** —— 用户开始用"导航窗格有无标题、能否改样式"来判别真 docx([UDT 指南](https://ultimatedesigntools.com/blog/how-to-convert-markdown-to-word/));合规场景会直接拒绝伪 docx。
9. **隐私/离线诉求** —— 在线转换器"上传即泄露"是普遍顾虑,本地处理被反复强调为卖点([DigitalToolPad](https://www.digitaltoolpad.com/blog/markdown-to-word)、[Unmarkdown 对比表](https://unmarkdown.com/blog/best-free-markdown-to-word-converter))。

## 五、UX 改进清单(聚焦转换类工具通用体验)

1. **转换前预检并给出可行动清单**:md2docx 在"Images 标签页"标红缺失图片并允许上传替换 —— 我们已有缺失图片警告,升级为"转换前汇总:缺失图片 N 张、外链图片 M 张(将下载)、不支持的语法 X 处",一次点击处理([tomarkdown](https://tomarkdown.dev/tools/markdown-to-word))。
2. **错误提示可定位、可行动**:竞品最差体验是 `couldn't read native` 这种黑盒报错([CSDN](https://blog.csdn.net/m0_59415345/article/details/140496714));我们可定位到"哪个元素/第几行",并给出修复建议(md2docx 的[limitations 对策页](https://md2docx.app/limitations)思路)。
3. **大文件/大图预警**:Typora 大图内存溢出坑([CSDN 文库](https://wenku.csdn.net/answer/338ju6j2ci));转换前检测超大图片,提示压缩或继续。
4. **"用上次的选项"模式**:Obsidian Mobile PDF Exporter 的 "Use last export options" 默认开启,被用户认可([插件页](https://community.obsidian.md/plugins/mobile-pdf-exporter));我们的输出目录/格式选择同样适用。
5. **"重新导出并覆盖上次"**:Typora 的 Export and Overwrite with Previous,写作迭代场景高频([Typora Export](https://support.typora.io/Export/))。
6. **完成后行为可选**:成功弹窗保留现有"复制路径",增加"打开所在文件夹"一键(Typora after-export 标配([What's-New-0.10](https://support.typora.io/What's-New-0.10/))。
7. **默认输出位置可设**:同目录是默认好选择,但给"固定输出目录"选项(Typora 默认导出文件夹([Export](https://support.typora.io/Export/))。
8. **拖放扩展**:支持拖入文件夹(批量前置)与多文件(Markdown All in One 的批量 print 命令即"多文件"心智)。
9. **转换进度不要只转圈**:现有三段式(解析→渲染→打印)很好,建议对长文档显示当前阶段与文件名;取消按钮(markdown-pdf 曾有"export does nothing"卡死反馈([issues 列表](https://github.com/yzane/vscode-markdown-pdf/issues))。
10. **结果一致性承诺**:在"完成弹窗/关于页"明示"原生 docx(非 HTML 改名),Word 导航窗格可见标题" —— 直接回应 UDT 提出的伪 docx 判别标准([UDT](https://ultimatedesigntools.com/blog/how-to-convert-markdown-to-word/))。

## 六、差异化机会总结(基于「GUI + 中文排版可控 + 本地离线」)

**性价比高的护城河**:
- **中文排版正确性本身就是卖点**:Pandoc 修了 4 年还在修 eastAsia(#7022→#10901),markdown-pdf 至今靠用户手写 CSS 救场;我们 G1 已实测 `font: { ascii, eastAsia, hAnsi }` 正确写入 —— 这是可公开宣传、竞品短期追不上的点。
- **真 docx 与本地离线组合**:同时满足"合规要的真 OOXML"与"隐私要的不上传",这是所有在线工具的硬伤区([UDT](https://ultimatedesigntools.com/blog/how-to-convert-markdown-to-word/)、[DigitalToolPad](https://www.digitaltoolpad.com/blog/markdown-to-word))。
- **缺失图片警告已领先多数小工具**,外链下载补齐后即成完整闭环。

**硬骨头(确认延后合理)**:PDF 书签注入(需后处理)、docx OMML 公式、Mermaid 嵌入 docx、多文件合并分节、reference-doc 式模板系统 —— 这些对应 Pandoc/Obsidian 插件多年积累,不应在二期前投入。

## 七、结论摘要(换会话仍会用到的部分)

- Pandoc eastAsia 历史问题(#7022→#10901,2025 年才默认 zh-CN)→ 中文可控是我们已验证的护城河
