### 1.3 核心分界线

> **`adr/` = 会被取代的 · `evidence/` = 不会变的**

不是按「有没有决定」分。判据是**可变性**：

| | 规则 | 例 |
|---|---|---|
| `adr/` | 旧条不改动**只标取代** | 模板导入做浅导入 → 后来范围扩大 |
| `evidence/` | 只增不改 | 2026-08-14 查到的 OOXML 机制就是那样 |

两者规则**同源**（「不改历史」），差别在**会不会有后继**。这也是为什么 `evidence/` 装不下决定 —— 一旦决定被推翻，改的就是「方案取舍」，而 [adr-031](../adr/adr-031-归档只读层的边界重划.md) 已把「方案取舍与否决理由」划进**不可覆写的分析正文**。

### 1.4 `evidence/` 的四个非阅读用途（保留它的理由）

| 用途 | git 能否替代 |
|---|---|
| **① 负面知识：走过的错路** | ❌ 结构上不能 —— git 只存最终状态。错的东西从未进代码，commit 里只有「修好了」 |
| **② 主题粒度：一次调研的完整快照** | ❌ 不能 —— git 粒度是**提交**，一次审计散在几十个 commit 里 |
| **③ 长证据：实测数据 / 探针输出** | ⚠️ 能，但违反 commit message 形态约定（≤50 字首行 + `- ` 要点） |
| **④ 派发时的「别重复查」锚点** | ⚠️ 能（`git log --grep`），但要先知道 commit 在哪 |

**改名理由**：

| 候选 | 判断 |
|---|---|
| `archive/` | ❌ 「归档」= 收起来不再管，与「会被引用」矛盾 |
| `history/` | ❌ 那是 git 的活，会误导 |
| `records/` | △ 太中性，不回答「为什么保留」 |
| **`evidence/`** | ✅ 三个用途直接是「证据」；且与头部字段「结论去向 → ADR-NNN」自然接上 |

## 2. 工作流

### 2.1 小需求

```
提出    REQ.md 登记「待拍板」+ 取号（标题 ≤20 字一次写对，R8 兜底）
        ↓
开工    扫 REQ「待拍板」节 → 命中则只改状态为「在办」，沿用原号
        读该行「为什么停在这」+「什么条件下重看」—— 同一个文件，同一行
        需要更多就跳「分析在哪」列指向的 adr / evidence
        ↓
开发    范围外发现 → REQ.md 加「待拍板」行（不塞进当前任务）
        踩坑 / 判断被推翻 → commit message 正文（过程）
        提炼出跨号教训 → LESSONS.md 主题小节加一条（≤100 字）
        ↓
收尾    移动该行到「已完成」节 + 状态列 + 交付时确认了什么（≤100 字）
        删 PLAN.md（完成标准逐条划完后）
```

**相对现状唯一的变化**：查「为什么」从「先找节、再找行」变成「同一行」。新增一步「提炼教训」。

### 2.2 大型需求

```
① 用户确认 → REQ 状态改「在办」（沿用原号）
② 建 PLAN.md，除常规三节外加：
   ## 步序与泳道     ← 泳道表只在这里（现 PLAN 与 large/01 各存一份）
   ## 整体完成标准   ← 与「完成标准」区分：这一节划完才允许删本文件
   ## 怎么回滚       ← 现只有大型需求强制写
③ 逐步走「常规」：每步一个 PLAN.md
④ 每步收尾跑该步全部门禁 → 结果填「步序与泳道」表的结果列（唯一载体）
⑤ 步序变更只改 PLAN.md 的「步序与泳道」节
⑥ 收尾：ADR 记整体决策 → CHANGELOG 按步边界写 → evidence 落过程
   → 未升 ADR/evidence 的先补升 → PLAN.md 原文入 evidence → 删 PLAN.md
```

**变化**：泳道表唯一；「回滚」对所有规模强制；发版前置从三项减为两项。

## 6. 追加范围（2026-09-29 用户追加）：存量全量迁移

> 本节**追加**于终稿之后，**不改** §1–§5 任何结论。它把 §4.2 的 M3 / M4 从「补缺口」扩为「**全量过一遍**」：不是只补 68 份头部 + 19 份背景行，而是 `docs/adr/` 31 份 + `docs/archive/` 84 份**逐份分类识别位置 + 补对应需求编号与 ADR 编号**。

### 6.1 范围与规模

| 载体 | 份数 | 现状缺口 |
|---|---|---|
| `docs/adr/` → `ADR-0NN-*.md` | **31** | 背景行带 evidence 链接的仅 12 份；工作项号 0 份 |
| `docs/archive/` → `evidence/` | **84** | 头部带「结论去向」的仅 16 份；`INDEX.md` 工作项ID 列非 `—` 的仅 3 份 |
| **合计** | **115** | 逐份判定 |

### 6.2 两条轴

**轴一 · 类型**（这份文件在体系中是什么位置）——词表须先定稿，否则各桶分类口径不一：

`决定` · `调研` · `审计` · `验收` · `事实` · `盘点` · `诊断` · `评审` · `勘察` · `方案` · `计划` · `裁决` · `台账` · `设计稿` · `索引`

**轴二 · 归属**（它服务于哪条工作项 / 哪份决策）：

`REQ-0NN` · `ADR-0NN` · `无`

### 6.3 机械优先（按全局 `WORKFLOW.md` 九「判据要落到一条命令 + 一个文件内容」）

| 判据 | 机械来源 | 现状覆盖 |
|---|---|---|
| 文件名已含工作项ID | `WORK_ITEM_RE = /(?:REQ\|REF)-\d+/`（`scripts/gen-archive-index.mjs:41` 同一正则） | 3 / 84 |
| 正文可反查工作项ID | 全文搜 `REQ-\d{3}` / `REF-\d{3}` | 待扫 |
| 类型 | 文件名主题词（`事实-` `验收-` `审计` `调研` `评审` `勘察` `盘点` `诊断` `方案` `计划` `裁决` `台账` `设计稿`） | 约 80 / 84 可机械判定 |
| 结论去向 | 头部「结论去向 / 归档注记 / 性质 / 分流指针」 | 16 / 84 |
| ADR 的 evidence 背景链接 | `adr/*.md` 内出现 `archive/` | 12 / 31 |
| ADR 的取代关系 | 状态行「被 X 取代」+ 关系行「取代 X」 | 4 条链（adr-001←002 · adr-020←022 · adr-020←031 · adr-026←027） |

**机械能判的直接落；判不出的进人工队列。** 人工队列的规模由「类型词表 ∩ 文件名」的差集决定，收尾时填实际数字。

### 6.4 「若不存在则不补」的判据

**可指认原则**：能指出「这份文件服务 `REQ.md` 的哪一行，或 `adr/` 的哪一份」⇒ 补；**指不出 ⇒ 留 `—`**。

明确禁止：

| 禁止 | 理由 |
|---|---|
| 为无归属的文件新造工作项号 | 号永不复用；凭空登记会让台账多出从未发生的需求 |
| 用主题词相似度补归属 | `evidence/INDEX.md` 头部已明写**禁止**（「那类指针不可复现，索引就退化成手写表」） |
| 拿「看起来相关」当归属 | 不可复现，下一个人无法重跑 |

**留 `—` 的份数必须记进 ADR-032 后果节** —— 它是「有多少历史材料无法归位」的量化事实，比事后猜测有用。

### 6.5 补到哪里

| 载体 | 补什么 | 形式 | 门禁 |
|---|---|---|---|
| evidence **文件名** | 工作项ID（有才加） | `YYYYMMDD-HHMMSS-REQ-0NN-主题.md` | `check:archive-index` 形态断言 |
| evidence **头部** | 结论去向（REQ + ADR + 全文去向） | 正文前加一行，**不动正文** | G5 |
| ADR **头部** | 来源工作项号（有才加） | 「来源：REQ-0NN」 | — |
| ADR **背景段** | evidence 链接（有才填） | `[evidence/xxx](evidence/xxx)` | G4 |
| `evidence/INDEX.md` | 工作项ID / 分流去向两列 | **脚本重算，不手改** | `check:archive-index` |

> 文件名补号之所以可行：`gen-archive-index.mjs` 的工作项ID 列**就是从文件名解析的**（形态见 `scripts/gen-archive-index.mjs:38`），改名即自动进索引，无需改脚本。

### 6.6 合法性（依 `ADR-031` 边界重划）

判据一句话是「**改的是『指向哪个文件』还是『说了什么』**」：

| 动作 | 归类 | 可否 |
|---|---|---|
| 目录改名 `archive/` → `evidence/` · 文件改名（补工作项ID） | 目录维护类（ADR-031 明列「载体改名 / 移层后的指向」） | ✅ 可改 |
| 头部加「结论去向 / 来源工作项号」 | 元信息，不在分析正文内（正文 = 结论、数值、判断、方案取舍、步序、否决理由） | ✅ 可加 |
| **分析正文的任何一个字** | 分析正文 | ❌ **不动** |
| 裸文件名引用（不断言位置的历史引用） | ADR-031 明划在只读侧之外 | ❌ 不动 |

有先例：`20260925-130122-技术债处置计划.md` 的「归档注记」就加在正文之前。

### 6.7 派工与顺序

115 份**可并行**：按时间桶或类型词表切成 N 个**写范围互不重叠**的桶，每桶一名写者（沿用波次 1 的泳道模式）。

**但词表与判据必须先由主会话定稿**（§6.2 / §6.3 / §6.4 三张表），否则各桶分类口径会漂 —— 这正是本次改造要消灭的那类问题，不能在执行时重犯。

顺序调整（替换 §4.2 的 M3 / M4）：

| 步 | 内容 |
|---|---|
| **M3** | 目录改名 + `ADR` 大写（**win32 大小写不敏感 ⇒ 两步改名**）+ 全仓链接按 ADR-031 边界重划 |
| **M3.5**（新增） | **类型词表定稿 + 机械扫描脚本**（输出「115 份 × 类型 × 可反查号」的初始矩阵） |
