来源:lib-1(本地 node_modules 源码勘察 + 官方 GitHub discussions)。摘要已入 docs/RESEARCH.md,本文档为自查原文。

## 任务 1:docx 库(本地 9.7.1)—— 不支持加密

**版本**:`node_modules/docx/package.json` → 9.7.1(npm 最新版,2026-05 更新)

**结论:docx 库没有任何文档密码加密 API。**

证据链:
1. `dist/index.d.ts` 全量搜索 `encrypt|Encryption|password|Password` → 零匹配,无相关导出/类型
2. dist JS 里搜到的 `isEncrypted`(`dist/index.mjs:29274`)是 JSZip 解压 zip 时的检查(`Encrypted zip are not supported`,29292 行),与文档加密无关
3. 官方 maintainer dolanmiu 在 Discussion #1066(2021-07)明确回复:"Not yet im afraid, is there OOXML documentation for this feature?"——不支持,且指出密码保护 Word 文档不是 OOXML 标准(ECMA-376)的一部分,是 Microsoft 专有扩展(Agile Encryption / Standard Encryption,即 docx 外层 zip 整体加密 + EncryptionInfo 流)
4. Discussion #1339 连「编辑保护(documentProtection)」也不支持,maintainer 欢迎 PR——至今未实现

### 替代方案(后处理加密,即 Packer.toBuffer() 之后对产物加密)

| 库 | 版本/状态 | docx 加密 | 备注 |
|---|---|---|---|
| `officecrypto-tool` | 0.0.19(2025-08 更新) | ✅ ECMA-376 Agile/Standard(AES-256/SHA-512,Word 2007-2016) | CJS 老库,依赖 cfb/xml2js/crypto-js;API:`officeCrypto.encrypt(buffer, { password })` |
| `office-crypto` | 0.1.0(2026-05) | 🚧 加密未完成("CFB writer ported, top-level wiring pending") | msoffcrypto-tool 的 TS 移植,目前只有解密可用 |
| `ooxml-encryption` | 新 | ❌ 仅支持 xlsx/xlsm | 不适用 |
| ConvertAPI | 云服务 | ✅ | 需 API token + 外发文档,不适合本地工具 |

## 任务 2:pdf-lib(本地 1.17.1)—— 不支持写入加密

**版本**:`node_modules/pdf-lib/package.json` → 1.17.1

**结论:pdf-lib 不支持 PDF 加密,只有读取侧的检测能力。**

证据链:
1. README.md:1406-1408 官方声明:"pdf-lib does not currently support encrypted documents. You should not use pdf-lib with encrypted documents."
2. 全部 API 只有读取侧:
   - `cjs/api/PDFDocument.d.ts:78` → `isEncrypted` 属性(检测文档是否加密)
   - `cjs/api/PDFDocumentOptions.d.ts:21` → `load(bytes, { ignoreEncryption: true })`(忽略加密强行加载,但加载后内容不可用)
   - `cjs/api/PDFDocument.d.ts:754` → `save(options?)` 无任何加密选项
3. 无 `encrypt()`、无 `EncryptionOptions`、无 `userPassword/ownerPassword` 导出

### 与书签注入叠加可行性:可行,但顺序固定——先注入后加密

项目现有链路(`src/core/pdf/bookmarks.ts:205-212` + `src/main/converter.ts:304-312`):
```
printToPDF → injectBookmarks(pdf-lib load→setOutline→save) → setPdfMetadata(pdf-lib 重存) → 落盘
```
- pdf-lib 无法 load 加密文档(抛 EncryptedPDFError),所以加密必须放在 pdf-lib 所有后处理之后,作为 pdf 链路最后一步
- 加密工具选 qpdf(content-preserving 变换,不破坏书签大纲/元数据):
  - `node-qpdf2`(npm):node-qpdf 的 fork,Promise + TS 类型,`await encrypt({ input, output, password, keyLength: 256 })`,支持 user/owner 双密码
  - 或直接调 qpdf 命令行:`qpdf --encrypt user owner 256 -- in.pdf out.pdf`(AES-256)
- ⚠️ qpdf 是原生二进制,需随 Electron 应用分发(electron-builder extraResources 带 qpdf.exe)或要求系统安装;Windows 下需处理镜像下载

## 任务 3:Electron printToPDF —— 确认无加密选项

官方 PrintToPDFOptions 完整选项:landscape / displayHeaderFooter / printBackground / scale / pageSize / margins / pageRanges / headerTemplate / footerTemplate / preferCSSPageSize / generateTaggedPDF / generateDocumentOutline——无 password/encrypt 相关选项,确认不支持。

## 推荐实现路径

**docx 侧**(Packer.toBuffer(doc) 之后后处理):
```
Packer.toBuffer(doc) → officecrypto-tool.encrypt(buffer, { password }) → 写盘
```
- 首选 officecrypto-tool(唯一可用的 docx 加密 JS 库,Agile AES-256 与 Word 2007+ 兼容)
- 风险点:CJS 老库(ESM 项目需 `import officeCrypto from 'officecrypto-tool'` 默认导入验证)、需实测 Word/WPS 打开 + 密码验证;office-crypto 加密功能完成后可作升级候选

**pdf 侧**(追加到现有链路末尾):
```
printToPDF → injectBookmarks → setPdfMetadata → qpdf 加密(最后一步) → 落盘
```
- 首选 node-qpdf2(Promise + TS),keyLength 256(AES-256);密码可只设 user(打开密码),owner 留空需 --allow-insecure 或同密码
- 顺序不可颠倒:pdf-lib 后处理必须在加密前(加密后 pdf-lib 无法 load);qpdf 加密不破坏书签/元数据

**共同注意**:密码来自 GUI 设置(新增设置项),需注意密码不入日志/不入产物;加密后 runAfterConvert(打开文件)行为不受影响。
