## 总体评价

这是一个纪律性显著高于平均水平的代码库：

- 依赖方向有明文且被执行（converter/ipc/persist/services/windows 五域 + renderer 六域，无反向依赖违规）；
- 全库零 `any`，非空断言几乎每处带依据注释；magic number 命名纪律好；
- IPC 面单源（channels.ts）+ 恒等测试守护；preload 最小暴露面；四窗口统一安全加固；
- 注释承载大量决策考古（批次号 + 排除方案记录 + win32 坑），头注释普遍解释「为什么」而非「是什么」;
- 测试断言文化极强：45 段抽查无一例弱断言（精确色值 / EMU / 负向断言 / 回归锚注释）；Electron 单进程模型已是该场景较优解。

主要欠账集中在四类：**目录重组（1.2.0）后的同步债**（DEV-GUIDE 代码地图、10 处过期注释、文档数字漂移）、**双管线三处人肉镜像**（标题编号等）、**fixtures 校验机制系统性损坏**（CRLF + 无 .gitattributes + CI 不调用）、**发布链短板**（签名缺失、lockfile 失同步、sourcemap 打包）。

## 各维度要点

### 1. 目录结构与分层 —— 基本合理，局部调整
- 唯一越界：`windows/main-window.ts:15` 反向 import `ipc/register.js` 的 ctxByWebContents → 注册表宜下沉独立模块。
- `ipc/register.ts`（343 行）三个导入 handler 同构模板可抽 helper 收缩约 90 行。
- renderer `state/utils.ts` re-export 过渡层使命已完成应退役；`recent-files.ts` 顶层监听与其余域 bind*Events 范式并存。

### 2. 拆分 / 合并 / 公共提取
- **docx/render.ts 467 行是唯一超胖文件**（页面几何 + numbering 配置 + Ctx 组装 + renderHeading/renderTable 五种职责），拆后可降至 <300 行。
- **标题编号计数三份镜像**（docx prescan / pdf xref 扫描 / pdf CSS counter）为最大漂移面，前两份 JS 计数可提共享纯函数。
- 契约正则族未收尽（eq label ×2、xref href ×2、题注前缀 ×2）应并入 cross-ref.ts。
- mermaid 警告对象逐字重复两份（code-block.ts ≡ pdf/mermaid.ts），是警告通道唯二没工厂化的 key。
- renderer 缺 errorMessage() 单源导致 15 处内联归一化；md 扩展名判定四套拼写；buildConvertContext 构造样板 single ≡ merge。

### 3. 一致性守护缺口（新增维度）—— 已知双源却无恒等测试
1. pure.ts STAGE_TEXT 中文文案 ↔ i18n-dict 逐字重复，零对照测试；
2. MAX_RECENT_FILES 双侧定义，零恒等断言；
3. preload api 方法签名手工第三镜像，channel 名有恒等测试但方法形状没有；
4. 设置默认值防御性合并双侧各一份；
5. 行内 HTML 白名单表达式扫描双份算法靠单向注释互指。

### 4. 测试体系 —— 断言强，框架层有硬伤
- runner 无单段筛选（改一个 handler 只能全量跑）；死环境变量 M2W_SEGMENT_TIMEOUT_MS；看门狗超时不杀段。
- **gen-fixtures --check 系统性损坏**：无 .gitattributes，Windows autocrlf 下 checkout 后 CRLF≠生成器 LF，实测全部 fixture 报差异第 1 行；CI 不调用它，坏了两版无人发现。
- 覆盖缺口：temp-html.ts、web-hardening.ts 唯二无专属测试的服务；mdast-utils 无直测；register.ts 仅 smoke 兜底。
- 死代码：common/png-utils.js 整文件零引用；pdf-css-sample.css 孤儿 fixture。

### 5. 注释质量 —— 水准高，10 处过期失准待勘误
core 5 处（pdf/render.ts:3 与 bookmarks.ts:6 指向不存在的 docs/研究结论.md、image-warning.ts 旧路径、render.ts「理论不可达」失实、inline-html.ts 描述拆分前状态）；main/renderer 5 处批③重组遗留；scripts/copy-renderer.mjs d.ts 注释失真。详见子报告与待办清单。

### 6. 文档 vs 实际 —— 结构性脱节集中在重组后
- DEV-GUIDE 代码地图大面积过时，基本需要重写；
- 测试段数字三处打架（README 40 / STATUS 顶部 45 / STATUS 基线 32，实际 45）；
- 暗色模式（1.2.0 主打）README 与 USER-GUIDE 均一字未提；
- USER-GUIDE 最近条目交互描述与行为相反（单击加载/双击重转 vs 文档写点击一键重转）；
- ROADMAP B14 七项已完成全部未勾选；STATUS 日志区与 CHANGELOG 大量重复且首标题悬挂；
- ACCEPTANCE 批次 14 违反自身规则（纯自动化项入册）、12 个 H1 结构混乱。

### 7. 安全（新增维度）—— posture 好，两处实质加固点
- image-downloader SSRF 面：无私网过滤、无响应体大小上限、跟随重定向；
- shell.openPath 接受 renderer 任意路径；
- 低风险记录项：temp-html Math.random 非 CSPRNG 且无启动期清扫；预览/打印窗 webPreferences 显式度不一。

### 8. 工程化与发布链（新增维度）—— 发布短板最实质
- 高：发布签名全程缺失（SmartScreen 必拦截）；package-lock.json 仍是 0.5.1（三统一漏了 lockfile 第四处）+ 工作区有未提交修复；
- 中：86 个 sourcemap 打进安装包（archive 已规划排除未落地）；Node 版本错位（CI 22 / engines ≥20.19 / @types/node ^26）致地板兼容性无守卫;
- 低：npm start 无新鲜度守卫；copy-renderer 对 lang-bootstrap 清理不对称；eslint/tsbuildinfo/.vscode 卫生项。

### 9. 性能（新增维度）
- PDF 路线重复解析（convert.ts:98 ast 未被 pdf 分支消费，remark 解析白做）——一行级修复；
- 其余性能面健康。

### 10. 类型与死代码卫生（新增维度）
- 死导出清单：ImageResolver re-export ×2、escapeHtml/decodeEntities re-export、getLanguage()、Language re-export、字典死键 preset.* ×3；
- ConvertFormat 平行类型定义两处；Ctx 可选性风格不一；t() key 无编译期检查；warnings 缺省即丢弃 footgun。
