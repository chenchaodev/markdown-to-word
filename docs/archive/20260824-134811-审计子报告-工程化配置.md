## 维度 1：tsconfig.json

**目标与模块设置**：target ES2022、module/moduleResolution NodeNext，与 ESM 及 Electron 43 匹配，无问题。

**strict 全开情况**：strict:true 之外还叠加 noUnusedLocals、noUnusedParameters、noImplicitOverride、noFallthroughCasesInSwitch、noUncheckedIndexedAccess、forceConsistentCasingInFileNames。除 skipLibCheck（务实取舍）外，推荐严格项全部开启。**结论：是。**

**include/exclude 范围**：include:["src"]——test 与 scripts 都不在 typecheck 范围。lint 管 test/scripts 而 typecheck 不管——这是有意设计而非遗漏（eslint.config.js:14-18 注释明确记录），但代价是 test/scripts 只有 lint 级（含两条类型感知规则）保障，无完整类型检查。

**incremental/tsbuildinfo 是否入库**：incremental:true。交叉验证 git ls-files → 零输出，均未被跟踪；磁盘 tsconfig.tsbuildinfo 被 .gitignore 双模式覆盖。

小瑕疵：copy-renderer.mjs:6 注释称「tsc 只产出 .js/.d.ts/.js.map」，实际未开 declaration，dist 中 0 个 .d.ts——注释失真（无害）。

## 维度 3：eslint.config.js

**ignore 范围**：dist/output/release/node_modules——缺 coverage/**（c8 产物），因 CLI 参数限定 src/ test/ scripts/ 暂无实害，属卫生瑕疵。

**规则集**：recommended（非类型感知）+ 类型感知的 no-floating-promises/no-misused-promises（补 tsc strict 不覆盖的异步盲区）+ eqeqeq/no-constant-condition/no-empty。纯 correctness 导向，无风格噪音。

**side-by-side TS6/TS7 实现质量**：整体高质量——npm 别名双装、projectService + allowDefaultProject 显式枚举目录 glob 并注明禁止 ** 通配的性能护栏原因。维护暗坑：未来在 test 下新增子目录必须手动补进枚举列表，注释提了一半，没有给出「新增目录时记得同步此清单」的操作提示。

## 维度 4：scripts/ 三个 mjs

**copy-renderer.mjs**：
- 全量拷贝（非增量）量小可接受；亮点是先递归清理 dist 内旧 html/css 再拷贝防陈旧资源混入安装包，且明确处理混合目录陷阱；
- **边界缺口：lang-bootstrap.js 清理不对称**——清理循环只覆盖 html/css，bootstrap 走条件拷贝；若将来从 src 删除该文件，dist 里旧副本不会被清掉会打进安装包。

**check-build-fresh.mjs**：
- 原理：src 与 dist 各自最大 mtime 比较。作为启发式守卫合格但有已知盲区：(a) 只比时间不比文件集合，删除 src 文件不触发过期告警；(b) 构建中途失败的半成品可能蒙混过关；(c) stat 失败静默跳过。均有注释兜底意识，属文档化取舍。

**svg-to-ico.mjs**：
- sharp density 300 栅格化后缩放六档 PNG 合成 ico，先高精度渲染再降采样做法正确。够用。
