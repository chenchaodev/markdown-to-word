# 台账（`docs/REQ.md`）组织形式诊断

2026-09-29 用户对 `docs/REQ.md` 的组织形式提出怀疑：**可读性一般，且有膨胀倾向**。本文件是对该怀疑的实测核查，不是改造方案的实施记录。

## 结论先行

膨胀源**不是行数，是每行的字数在长大**。登记表 100 行本身还好（表格形态可扫读）；真正吃掉可读性的是「一句话标题」列已经不再是一句话，以及与全局模板重复的散文区。

推荐路径是**方案 A：不动结构、删字 + 加门禁**（详见下文）。方案 B（已完成行归档）需要把号段模型从单文件序列改成跨文件序列，成本高一档，本轮不评估。

## 一、四个可量化的病灶

### 病灶 ① 标题列已不是标题

| 指标 | 实测值 |
|---|---|
| 登记表行数 | 100 |
| 标题列总字符 | 3173 |
| **平均字数** | **31.7** |
| **最长字数** | **178**（REQ-083） |
| > 20 字的行数 | 55 / 100 |
| > 40 字的行数 | 26 / 100 |

分状态看：`已完成` 平均 36.4 字（最长 140）、`待拍板` 平均 28.9 字（最长 178）、`已作废` 平均 16.7 字（最长 38）。

违反的是模板规则 6「一行一号、**无自由文本**」——`templates/docs-init/REQ.md` 规则 6 原文是「长度由需求条数决定（每条需求都占一行是这条设计的必然结果）」，而实测长度由**每条需求的解释欲**决定。登记表 100 行占全文 67.5% 字符，标题列独占其中 3173 字符。

### 病灶 ② 膨胀有明确的时间斜率

按登记日期分组统计平均标题字数：

| 登记日期 | 行数 | 平均标题字数 |
|---|---|---|
| 2026-09-26 | 49 | **12.1** |
| 2026-09-27 | 27 | **41.8** |
| 2026-09-28 | 7 | **83.3** |
| 2026-09-29 | 17 | **51.2** |

**同一个文件里并存两套写法**：09-26 那 49 行是合规的短标题；此后 51 行走的是「发现即登记、把分析顺手写进标题列」。这不是偶发，是稳定的行为漂移，且**每轮开发都在把它推得更高**。

34 / 100 行的标题里含「理由 / 状态 / 时间」类词（原因、根因、未、待、因为、已、不、裁决、收尾、排期、实测、门禁、覆盖）——这些是判断依据，按全局 AGENTS.md 六「写入判据③」本该在 `LOG.md`，不该在台账标题里。

### 病灶 ③ 散文区复述全局规则 + 含手工维护的可运行数字

| 区段 | 字符数 | 占全文 |
|---|---|---|
| 头部 + 填写提示 | 745 | 6.8% |
| 「读表五件事」 | 1649 | 15.2% |
| 「规则」6 条 | 774 | 7.1% |
| **散文合计** | **3168** | **29.1%** |

两个问题叠加：

1. **复述全局规则**：「规则」区 6 条与 `~/.config/opencode/templates/docs-init/REQ.md` 规则 1–6 逐条重复，「填写提示」是模板第 7 行的复制。违反全局 AGENTS.md 五「单一来源不复制」。
2. **可运行数字进了文档**：「读表五件事」5 条各带一个手工行数（`待拍板`（36 行）/`在办`（1 行）/`已完成`（53 行）/`已作废`（10 行）/`未开工`（0 行））。这些数字随每次状态流转变化，按全局 AGENTS.md 三.4「判据 = 改代码会不会让这个数字变：会变 → 指针」**只能写指针**。本次登记 REQ-101 时就实测到了代价：新增一行「待拍板」需要手工同步改 4 处行数 + 1 处状态描述。

### 病灶 ④ 状态双源，已漂移 36 处

`REQ.md` 登记表有「状态」列，`LOG.md` 又按状态分了 5 个小节（「待拍板——还没决定做不做」/「待拍板——已决定推迟」/「在办」/「已作废」/「新增墓碑」）。同一状态存在两处，且**已实际漂移**：

| 冲突形态 | 处数 |
|---|---|
| `REQ.md` = 已完成，但 `LOG.md` 那行仍挂在「待拍板——还没决定做不做」节 | **33** |
| `REQ.md` = 已作废（墓碑），但 `LOG.md` 那行挂在「已决定推迟」节 | 2（REQ-042 / REQ-050） |
| `REQ.md` = 已完成，但 `LOG.md` 那行挂在「已决定推迟」节 | 1（REQ-057） |
| **合计** | **36** |

**根因是结构性的，不是笔误**：`LOG.md` 文件头声明「本文件只追加：不删行、不改已记的事实」，而「按状态分节」要求状态变化时**移动行**。两条规则互斥 ⇒ 状态一变，节就必然错位；而不移动又违反「只追加」。这不是「谁忘了改」，是**当前组织形式无法同时满足这两个约束**。

## 二、顺带查实的两处缺陷

### 缺陷 ① 规则 5 与「读表五件事」第 5 条直接互斥

同一文件内：

- **规则 5**（`docs/REQ.md:136`）：「状态词表 = 全局 v8.2 的五个值 …… **本台账追加 `未开工`** …… 取值只有这五个，**不得自造**」
- **「读表五件事」第 5 条**（`docs/REQ.md:128`）：「`未开工`（0 行）= 全局 v8.1 曾用、**v8.2 已取消**的值 …… 保留本行只为说明它为何消失；**再出现即为误用**」

一处说它是词表成员且不得自造，一处说它已取消且出现即误用。**同文件互斥**。

裁决依据：全局 `tools/check-pointers.mjs` 的 `LEDGER_STATUS` 仍为 `['待拍板', '未开工', '在办', '已完成', '已作废']`（含 `未开工`），`templates/docs-init/REQ.md` 规则 4 也仍列 `未开工` 并给出流转边。**两处载体都保留它** ⇒ 「读表五件事」第 5 条那句「v8.2 已取消」是过期文本。但本轮不修（属病灶 ③ 的裁剪范围，且改动会触及状态取值域口径）。

### 缺陷 ② `LOG.md` 判断依据表的列数错位 —— 写了白写

## 三、门禁覆盖现状：R1–R7 零条涉及形态

全局 `tools/check-pointers.mjs` 的台账判据共 7 条（`LEDGER_RULES`）：

`R1 号唯一` · `R2 状态取值域` · `R3 号形态` · `R4 已用最大号` · `R5 下一个可用号` · `R6 号段连续` · `R7 墓碑⇔划掉`

**全部是「台账内不变量」，只需读 `docs/REQ.md` 一个文件**。其中：

- **零条**约束标题列长度 ⇒ 178 字的标题判绿
- **零条**比对 `REQ.md` 与 `LOG.md` 的状态一致性 ⇒ 36 处漂移判绿
- **零条**校验 `LOG.md` 表头/表体列数一致 ⇒ 缺陷 ② 判绿

即：本项目的「可读性」与「两文件一致性」**目前完全没有门禁覆盖**，全靠写文档的人自觉。

## 四、方案对比

### 方案 A（推荐）：不动结构，删字 + 加门禁

核心判断：**收体积要收在「字」上，不收在「行」上**。已完成的行有 git 兜底（commit message 尾部带 `(REQ-0NN)`，`REQ.md:15` 已写明反查方法），重复存一份价值有限；而 100 行表格本身是好的形态。

三条动作：

1. **标题列设硬上限并门禁化**（防复发的关键）
   在全局 `check-pointers.mjs` 的台账判据加 **R8「标题列超长」**，阈值作为可调参数。理由进 `LOG.md`，不许进标题列。
   **2026-09-29 用户裁决：阈值 20 字**（与 09-26 那批合规写法的平均 12.1 字同量级，裁后表格基本一行一事）。裁剪量：标题列 3173 → 约 2000 字符。
2. **删「读表五件事」整节 + 「规则」区压到 ≤5 行指针**
   全文 −约 2400 字符（−22%），顺带消掉 4 个手工行数与缺陷 ①。指针指向全局 `AGENTS.md` 六 + `templates/docs-init/REQ.md`。
3. **`LOG.md` 取消「按状态分节」，改一张按号排序的单表**，状态由 `REQ.md` 独家持有
   ⇒ 病灶 ④ 的结构性来源消失。同时把表头补到与表体一致的列数，修掉缺陷 ②。

**门禁联动要求**：R8 与「表头列数」两档都落在**全局配置仓**（`tools/check-pointers.mjs` + `tools/ledger.test.mjs` + 两个模板），本仓 `scripts/check-docs.mjs` 只是薄包装（仓内不持有第二份逻辑）。故 R8 本仓 revert 不覆盖。

**验证要求（先证伪再信绿）**：故意写一条 >20 字标题 → 必须判红；写一条刚好 ≤20 字 → 必须判绿。边界闭合才算数，不能只看 exit 0。

**迁移完整性**：裁掉的 3173−2000 ≈ 1173 字符是**判断依据不是废话**，必须逐条确认在 `LOG.md` 里找得到 —— 这是本方案唯一真风险点。

### 方案 B（不推荐现在做）：已完成行归档，台账只留活跃行

把「已完成」行进 `docs/archive/`，登记表只留待拍板 + 在办 + 墓碑。

**不是不可行，但要求把号段模型从单文件序列改成跨文件序列**：

- `R6 号段连续` 扫不到归档文件 ⇒ 判红（这是有价值的门禁，不是形式主义）
- 号段表只有「已用最大号」「下一个可用号」2 格，**不表达「号分布在两个文件」**
- 门禁 + 模板 + ADR 三处同改

成本高一档。若方案 A 落地后表格仍嫌长，再评估。

### 明确否决：按主题 / 按模块分表

台账若按主题拆成多张表，「号段连续」判据失去全局视野，且一个需求跨多个主题时无法归属。**否决**。
