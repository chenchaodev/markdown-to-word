## 一、竞品/同类工具功能矩阵现状

### 1.2 竞品最弱项确认:中文排版(eastAsia)

- Pandoc 直到 3.2.1(2024-06)才为 docx 输出加 w:hint="eastAsia" 字体提示,且中英混排引号仍有 bug(issue #9817 后续:英文引号被错误加宽)。连「祖师爷」都刚修完,说明这是整个赛道的系统性短板。
- 知乎高赞结论:「中文文档转出来,正文字体是 Cambria,中文字符靠系统 fallback 渲染,首行缩进没有,段间距不对。你需要自己做一个 reference docx 模板」——这正是我们的护城河,也是营销话术点。

### 1.3 2026 年市场新动向(值得注意)

1. 「AI 生成内容转换」成为新卖点:多篇 2026 年文章(腾讯云/阿里云开发者社区)都把「DeepSeek/ChatGPT 输出 → Word」列为高频痛点,新工具(DS随心转、AI2Word、PasteMD)全以此为切入点。核心诉求 = 不规范 Markdown 容错 + 公式 + Mermaid + 表格。
2. Mermaid 从「加分项」变成「标配」:2026 年新上线/更新的转换工具(mdclaudy、markdowntoword.pro、markdowntoword.app、mdtoword.org、markdowntoimage.cn、PyPI md-to-docx)几乎全部宣传 Mermaid 渲染。我们还没有。
3. Agent Skill 化:2026 年出现大量「md→docx 排版 skill」(md2docx_skill、ninestep docx-format、TRAE 大赛项目 MD to DOCX),说明中文学术排版需求在 AI 工作流中爆发,但这些都是脚本级质量,桌面产品仍有空间。
4. WPS 用户群被单独服务:2026-05 出现专为 WPS 打造的公式转换工具(WPS-LaTex2Equation-tool),明确「WPS 上 VBA+OMaths 不稳定」「符合国内专利排版习惯(公式居中+编号居右)」。中国市场 WPS 占有率意味着 docx 输出必须过 WPS 兼容关。

### 2.3 中文社区(知乎/V2EX/CSDN/少数派)

- 知乎(markdown→word 相关问题长期热):「正文字体 Cambria、无首行缩进、段间距不对」;「全网找不到满意的 Markdown 转 Docx 模板,那就自己动手吧」——模板自定义是中文用户高频自建需求;「AI 内容粘贴进 Word 标题格式乱、公式消失」持续有回答。
- V2EX:2025-07 有人用 cursor 做 md↔word 工具;2026-06 有人做 doc→md 工具,评论直接要「markdown 转 pdf word 功能」——需求端活跃。
- 少数派 2025-07:VLOOK™(Typora 增强插件)主打「图片自动编号、自动题注」+ 插图索引——中文用户对图片题注自动编号需求强烈,且 Typora 导出时 CSS 题注不生效(essay_cn 主题同样承认),正是我们 docx 路线能做而 Typora 做不了的点。
- TRAE 大赛(2026-07)MD to DOCX 项目:明确痛点「现有工具对中文学术规范支持不足:字体、脚注、公式、目录细节经常出错」,目标=宋体正文/黑体标题/楷体引用/首行缩进2字符/自动目录/脚注/公式/页码。与我们的预设模板包完全同向。
- cqu-thesis-markdown(重庆大学论文方案,47★,275 commits):一份真实的中文学位论文需求清单——分节符、双语题注(图1.3+Fig 1.3)、域代码交叉引用、图目录/表目录、GB/T 7714 参考文献、公式编号表格;自认未解决:表格合并单元格、脚注分隔线、多级列表+首行缩进冲突、子图。
- WPS 侧:WPS/Word 公式兼容官方文章(2026-07)反复强调 OMML/字体/域兼容注意事项;2026-05 的 WPS 公式工具把「题注/目录一体化」列为未做项——WPS 兼容性 + 题注目录是双缺口。

## 三、候选功能清单(按价值/成本排序)

> 成本基于本项目技术栈推断(docx 9.x 已内置的能力 = 低;需自研/引入重型依赖 = 中高;PDF 路线 markdown-it+Electron 已具备的能力 = 低)。

### 第一梯队:证据强 + 我们技术栈顺路

**1. Mermaid 图表渲染导出**
- 证据:2026 年几乎所有新工具标配(mdclaudy、markdowntoword.pro、mdtoword.org、PyPI md-to-docx);知乎/CSDN 2026 年多篇「Mermaid 转 Word」教程(说明全是手动折腾 pandoc+mermaid-filter);ruanyf/weekly 自荐 issue(#9799)
- 价值:**高**。AI 生成内容标配 Mermaid,竞品全有;对我们是「补课」而非差异化
- 成本:**中**。PDF 路线(HTML 模板)几乎白送;docx 路线需渲染 SVG/PNG 嵌入(docx 库图片嵌入已有,主要成本在渲染管线与尺寸处理)

**2. Word 原生目录域(TOC field,可 F9 更新)**
- 证据:pandoc --toc 输出的是静态文本目录,用户要域得写 Lua filter;cqu-thesis 全程在折腾「打开后 Ctrl+A → F9 → 更新整个目录」
- 价值:**高**。目录是 Word 文档「专业感」的第一印象,也是中文论文/报告的刚需
- 成本:**低**。docx 库原生支持 TOC field(含 useAppliedParagraphOutlineLevel 等选项);已有标题结构,直接映射

**3. 图片/表格题注自动编号(SEQ 域,带章节号)+ 图表目录**
- 证据:pandoc #7451(2025 年还在问中文「图」前缀);VLOOK 卖点;essay_cn 主题「图片编号在导出文件中暂无法显示」= Typora 用户真实痛点;WPS-LaTex2Equation-tool 明说未做
- 价值:**高**。中文论文/技术文档标配「图1.1」,且 Typora/Pandoc 都做不到位,差异化明显
- 成本:**中**。已有章节自动编号管线(编号计算可复用);SEQ 域 + 题注样式 docx 库支持;双语题注、图目录稍加量

**4. 公式自动编号(带章节号)与交叉引用域**
- 证据:tex2word 1.0 的核心卖点「live fields 公式编号/交叉引用」;LaTeXSnipper(2026-06,280★)全套公式编号/章节分隔符/交叉引用;WPS 公式工具用制表位做「居中+编号居右」
- 价值:**高**。我们已有 KaTeX MathML→OMML,补上编号域 = 对齐 tex2word 级卖点
- 成本:**中**。编号=表格/制表位方案(OMML 段落内嵌编号域),docx 库有 Field/SEQ;交叉引用需 bookmark+ref 域,工作量可控

**5. 代码块语法高亮写入 docx**
- 证据:ToWord 插件(2025-10)把「VS Code Default Light 高亮」当核心卖点;@mohtasham/md-to-docx 支持可选高亮;Reddit 2026-02 抱怨「导出后是灰色等宽 blob」;Pactify 数据:AI 输出 15% 代码块缺语言标识
- 价值:**中高**。技术文档场景感知度强,实现有成熟库(highlight.js 同栈)
- 成本:**低-中**。颜色以字符样式(TextRun color)写入,docx 库直接支持;缺语言标识时的回退策略要设计

### 第二梯队:价值明确但成本/边界需斟酌

**6. 自定义 docx 模板导入(reference-doc 模式)**
- 证据:知乎「全网找不到满意模板」;mdclaudy 自认缺口;Obsidian 用户为传 reference-doc 折腾 file:/// URI(StackOverflow 2025-06);Typora 生态全靠 pandoc reference-doc 打工
- 价值:**高**。企业/学校场景的硬需求,是我们模板包的升级路径
- 成本:**中-高**。参考 pandoc 模式:只读样式/属性,忽略正文;但 docx 库是生成式 API,读入外部 docx 样式需要自研解析(或先产出一个基础 docx 再由 Patcher 合并);值得先做「导出到模板」而非「从模板导入」的 MVP

**7. 批注与审阅(HTML 注释 → Word 批注;修订追踪)**
- 证据:pandoc #2994 已实现(生态 13★ filter 证明需求);docx 库原生支持 Comments + trackRevisions;tex2word 支持「接受 Word 修订」
- 价值:**中**。技术写作团队 Git+Word 协作场景;国内审阅场景靠 WPS 批注,需求次之
- 成本:**低**。docx 库 ICommentsOptions + CommentRangeStart/End 直接可用;remark 管线解析 HTML 注释即可

**8. WPS 兼容性适配(公式/域/字体验证矩阵)**
- 证据:2026-07 WPS 官方发文讲 docx 互转注意点;WPS 公式工具/CSDN 大量「WPS 打开 OMML 公式、目录域不更新」求助帖;国内用户大量 WPS
- 价值:**高(对中国市场)**。这是「本地离线中文工具」定位的隐性前提,也是差异化叙事
- 成本:**低**。主要是测试矩阵 + 少量兼容修正(如域更新提示、eastAsia 字体双写);无新开发量,但需 WPS 环境验证

**9. 页眉页脚高级(奇偶页/首页不同)**
- 证据:cqu-thesis 需要分节符实现不同页眉;docx 库 evenAndOddHeaderAndFooters + first/even header 原生支持
- 价值:**中**。书籍/论文排版场景
- 成本:**低**。库原生能力,UI 加开关即可

**10. 文档水印(文字/图片)**
- 证据:docx 库自 8.5.0 起内置 Watermark 类;V2EX 有「给 PDF 加水印」求助;公文场景常用
- 价值:**中**。锦上添花;对 docx/PDF 双路线均可做
- 成本:**低**。docx 路线用库自带;PDF 路线可在 HTML 模板加 CSS 水印

**11. 多栏布局**
- 证据:docx 库 SectionType.CONTINUOUS + column 原生支持;公文/期刊场景;essay_cn 主题的 column-count 2 在导出时出问题(证明有需求但没人做好)
- 价值:**低-中**。低频但零成本可实现
- 成本:**低**

**12. 参考文献管理(简化版:BibTeX/CSL YAML → 文献列表;进阶:Zotero 域)**
- 证据:tex2word 把「Zotero 可编辑域 + 真 CSL 引擎」列为 opt-in 卖点;cqu-thesis 配 GB/T 7714 CSL;Quarto 生态(少数派 2025-03)全配 CSL
- 价值:**中-高(学术人群)**,但全量 CSL 引擎(citeproc)是重依赖
- 成本:**高**(完整 CSL);**中**(仅支持 GB/T 7714 数字制式简化版)
- 建议:先做简化版(数字制式 [1] 上标 + 文献表),完整 CSL 延后

**13. AI 辅助(改写/总结/一键排版)**
- 证据:mdclaudy 卖 AI;PasteMD/DS随心转全打 AI 场景;WPS/Word 都在加 AI
- 价值:**中**。与「本地离线」定位冲突(需本地 LLM 或用户自配 key);做得好是差异化,做不好是噱头
- 成本:**高**。建议暂缓或只做「AI 输出 Markdown 容错解析」(低配版:修复不规范表格/代码块语言标识),这个反而是实测高频痛点

**14. 图片处理增强(压缩/按页宽约束/居中选项)**
- 证据:markdowntoimage.cn 广告「图片尺寸优化」;ToWord 支持 ![[img|447]] 尺寸语法;CSDN 教程「图片缩放乱码」
- 价值:**中**。AI 文档常带大图
- 成本:**中**。docx 库 transformation 支持缩放;压缩需 sharp(预编译二进制,Electron 环境有镜像经验);尺寸语法解析要设计

**15. 表格增强(合并单元格/三线表/网格表格)**
- 证据:pandoc #8990 至今不支持 colspan;cqu-thesis 自认受限;DS随心转拿「合并单元格」当卖点
- 价值:**中**。学术/报告场景,但语法层面(如 pipe_tables 扩展)需要自研扩展
- 成本:**高**。语法定义 + 渲染器扩展 + 回归风险;建议用 raw HTML 白名单(已有)过渡

## 四、推荐下一批次候选(8 个)+ 理由

| # | 候选 | 理由 |
|---|---|---|
| 1 | **Mermaid 渲染导出** | 2026 年市场标配,所有新竞品都有;AI 生成文档高频携带;PDF 路线成本低,docx 路线可复用图片嵌入;不做会被直接比下去 |
| 2 | **Word 原生 TOC 域** | docx 库原生支持,成本最低的高价值项;Pandoc/Typora 用户长期痛点(静态目录),是「真 docx」叙事的天然延伸 |
| 3 | **图片/表格题注自动编号(SEQ 域+章节号)** | Typora 生态承认做不了(essay_cn/VLOOK),pandoc #7451 三年未解决中文前缀;我们已有章节编号管线,顺路;中文排版差异化的最强单点 |
| 4 | **公式编号与交叉引用域** | 已有 KaTeX→OMML,补齐即对齐 tex2word 卖点;学术用户验收「可编辑公式」时第二个问题就是「编号呢」 |
| 5 | **自定义 docx 模板导入** | 中文社区呼声最高的自建需求;mdclaudy 自认缺口;建议先做「从外部 docx 提取样式应用」MVP,可先于完整双向模板 |
| 6 | **代码块语法高亮** | 2025-2026 新竞品(ToWord、md-to-docx)的共同卖点;技术文档场景感知强;highlight.js 同栈成本低 |
| 7 | **批注/审阅(HTML 注释→Word 批注)** | pandoc 已证明可行且有 filter 生态;docx 库原生支持;成本低,为后续 Git+Word 协作场景铺路 |
