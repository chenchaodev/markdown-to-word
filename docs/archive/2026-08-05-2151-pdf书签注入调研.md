# pdf-lib 为已有 PDF 注入书签大纲(Outline)调研报告

- 调研时间:2026-08-05
- 调研代理:@librarian(lib-1)
- 结论先行:方案完全可行。pdf-lib **无高层大纲 API**(官方确认),但底层 API 足够完成"读 /Dests → 注入多级中文大纲 → 保存",且保存不破坏原文档其他内容。

## 一、核心结论

1. **pdf-lib 1.17.1 为最新稳定版**,项目 package.json 原已依赖 `^1.17.1`
2. 无高层 outline API → 用底层 PDFName/PDFDict/PDFArray/PDFHexString/PDFRef 自行构建大纲树
3. 中文标题必须 `PDFHexString.fromText(text)`(UTF-16BE);PDFString 按 PDFDocEncoding 解码会乱码(pdf-lib issue #516)
4. Dest 数组第 0 元素必须是页面 **PDFRef**(不能是页码);命名目标数组可直接复用
5. 子项 Count 为负 = 折叠(-1 实测正确)
6. `doc.save()` 不破坏原 Link 注释/字体/图片(实测)
7. **命名目标无高层读取 API**,需自写约 30 行 name-tree 遍历:
   - catalog `/Names` → `/Dests` → `/Names` 成对数组
   - key 可为 PDFString/PDFHexString/PDFName
   - 值可为 PDFArray(显式 dest)或 PDFDict(间接目标,取 `/D`)
8. ESM 导入:**只用包名导入** `import { ... } from "pdf-lib"`;**勿碰 `pdf-lib/es/index.js`**(无扩展名相对导入,Node ESM 抛 ERR_MODULE_NOT_FOUND)
9. 样板来源:
   - marp-cli `setOutline`(issue #1151):完整大纲树构建样板,含嵌套 First/Last/Count、F 标志、页面 ref 收集
   - obsidian-pdf-plus:命名目标(name tree)解析样板

## 二、实测验证

- 实验全部通过,临时文件已清理
- 验证了中文标题 hex 编码、命名目标复用、多级嵌套、保存后原有内容完整性

## 三、实现要点(注入 bookmarks.ts 时遵循)

- `lookupNamedDest`:解析命名目标,返回 dest 数组(第 0 元素即页面 PDFRef)
- `setOutline`:marp setOutline 样板,构建 Outlines 树挂到 catalog
- 命名目标解析失败的名字回退首页,不抛错

## 四、与后续实测发现的差异(2026-08-05 自查实测补充)

- printToPDF 产物**无 /Names 名称树,而是旧式直接 `/Dests` 字典**(catalog /Dests → {key: dest}),需兼容两种结构
- pdf-lib 的 `dict.lookup(key, type)` 在 key 缺失时**抛 UnexpectedObjectTypeError 而非返回 undefined**,必须用 `dict.get()` + 手动 `context.lookup(ref)` 解引用
- 旧式字典 key 为 PDFName 百分号编码 UTF-8(如 `%E7%9B%AE%E6%A0%87`=「目标」),需 `decodeURIComponent(name.asString())`;PDFName.decodeText 走 PDFDocEncoding 会把 UTF-8 中文解成乱码(勿用)
