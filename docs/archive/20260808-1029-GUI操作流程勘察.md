# GUI 操作流程勘察报告(@explorer,2026-08-08)

> 勘察范围:`src/renderer/`(index.html、style.css、renderer.ts)、`src/main/index.ts`、`src/main/preload.cts`、`src/main/settings.ts`、`src/core/convert.ts`、`src/core/typography.ts`、package.json、docs/ 相关文档。视角:第一次使用本软件的用户。仅记录现状,不改代码。

## 一、完整操作路径清单

### 启动
- 安装包为 NSIS 向导式安装(产品名 MarkdownToWord,package.json:43-47),启动后进入单窗口应用:`900×640`、标题「Markdown 转换工具」、菜单栏自动隐藏(src/main/index.ts:66-81)。无「关于」、无设置入口之外的任何菜单。
- 启动不接收命令行参数/文件关联(仅识别 `--smoke` 自测标志,index.ts:17),不支持「用此应用打开」;每次必须先进应用再选文件。

### 路径 A:单文件转 Word(docx)——最简流程,4 次点击
| 步骤 | 操作 | 点击/输入次数 | 代码位置 |
|---|---|---|---|
| 1 | 点击拖放区(或「选择文件」按钮)→ 系统对话框 | 1 次点击 | renderer.ts:906-918;index.html:23-51 |
| 2 | 对话框内选中 1 个 .md 文件并确定 | 1-2 次(点选+确定) | main/index.ts:370-377(openFile+multiSelections) |
| 3 | 点「开始转换」 | 1 次点击 | renderer.ts:1211-1218 |
| 4 | 完成弹窗出现,点「确定」(或按 Esc)关闭 | 1 次点击 | renderer.ts:1272-1276 |

- 拖放变体:把文件直接拖进拖放区(0 点击),再点「开始转换」+「确定」,共 2 次点击。
- 输出:与源文件同目录、同名换扩展名(.md → .docx,main/index.ts:117;PDF 同规则 :125)。无输出目录选项——设置模型(AppSettings,settings.ts:16-26)里没有输出目录字段。用户只能从完成弹窗里读到输出路径。
- 转换中状态区依次显示「正在转换…/正在读取文件…/正在渲染文档…/正在完成…」(renderer.ts:604-608,1253-1257),无进度条、无取消按钮(转换期间所有按钮禁用,renderer.ts:548-556)。

### 路径 B:转 PDF
- 与路径 A 完全相同,第 0 步先在底部「输出格式」单选里选 PDF(index.html:263-273)。格式选择持久化(renderer.ts:1054-1061),下次启动沿用。
- 区别在转换耗时:主进程要写临时 HTML → 隐藏窗口 printToPDF → 注入书签/元数据(main/index.ts:136-173),用户看到的只是多停几秒的阶段文字。

### 路径 C:批量转换(≥2 个文件)
| 步骤 | 操作 | 代码位置 |
|---|---|---|
| 1 | 对话框多选 或 拖入多个文件/整个文件夹(文件夹递归收集 .md,.git 等点开头目录跳过,字典序排序) | main/index.ts:271-305 |
| 2 | 选中 ≥2 个后,拖放区变为「已选择 N 个 Markdown 文件」+ 可滚动列表,底部按钮变为「批量转换」(主)+「合并转换」(次) | renderer.ts:419-442、545-556;index.html:274-298 |
| 3 | 点「批量转换」;状态区实时显示「第 i / N 个:文件名 · 阶段」 | renderer.ts:1259-1263 |
| 4 | 汇总弹窗逐条展示 ✓/✗ + 警告/错误,可「打开所在文件夹」(只定位第一个成功项)/ 确定 | renderer.ts:837-903、1233-1243 |

- 批量跳过「导出后」设置(skipAfterConvert,main/index.ts:213)——若用户设置了「打开文件」,批量后不会自动打开,且无任何说明。
- 文件顺序可调:每行上移/下移按钮 + 拖拽排序(renderer.ts:445-516、938-1003),顺序影响合并文档章节顺序。

### 路径 D:合并转换(≥2 个文件)
- 与批量同入口,点「合并转换」→ 输出为 `{首个文件名}-合并.{ext}`,与首个文件同目录(main/index.ts:251-254)。按钮 title 有说明「输出文件名含「-合并」」(index.html:292)。

### 转换后的动作
- 完成后弹出对话框(单文件/合并):显示输出完整路径(等宽字体、可选中复制、长路径滚动)+「预览 / 打开所在文件夹 / 打开文件 / 确定」四个按钮(index.html:303-333)。
- 「预览」用源 md 重新走一遍 PDF 渲染开独立窗口(renderer.ts:1166-1183;main/index.ts:312-356),即「先转换成功、才能预览」,没有转换前预览。
- 「导出后」设置默认「不执行(仅弹窗提示)」(DEFAULT_SETTINGS.afterConvert="none"),可选「打开所在文件夹 / 打开文件」(index.html:132-148)。

### 设置面板现状(两个可折叠面板,均默认收起,改动即时生效自动保存)
- 页面设置(index.html:73-152):纸张(5 种:默认 A4)、方向(纵向/横向)、边距 4 个数字输入(单位 mm,默认 上25/下25/左32/右32,近似 Word 默认)、「每个一级标题前分页」开关(默认关)、「导出后」三选一(默认「不执行」)。
- 排版(index.html:155-259):模板预设下拉(默认/学术论文/商务简报,提示「选择模板将覆盖排版与页面设置」)、西文字体(文本框+datalist,默认 Calibri)、中文字体(默认微软雅黑)、正文字号(8-24pt,默认 12)、行距(1.0-2.5 倍,默认 1.5)、首行缩进 2 字符(默认开)、两端对齐(默认开)、章节自动编号(默认开)。
- 默认值整体合理(近似 Word 常规文档);模板预设套用后仍可微调,但微调后模板下拉会静默回退「默认」(matchesPreset 精确比对,renderer.ts:749-755),无任何提示。

## 二、每次操作的认知成本

1. 「输出到哪了?」是最大隐性成本:输出位置 = 源文件同目录,全程无一处明示(仅完成弹窗里显示路径)。用户若不看弹窗,默认以为会弹出保存对话框或输出到固定目录。竞品调研中「输出目录/记忆上次选项」本就是高频需求(docs/研究结论.md 竞品调研节)。
2. 格式状态靠记忆:输出格式是底部一个单选组 + 已持久化。用户上次选了 PDF,这次打开界面仍是 PDF 选中态(可见,尚可),但界面没有「当前默认格式」这类汇总提示。
3. 「合并转换」需要额外理解:多选后两个按钮同时出现(主/次视觉区分 + title 说明),「合并」的语义、输出命名规则(`-合并`)、顺序即章节顺序,都靠用户自己理解;批量跳过「导出后」设置也无提示。
4. 设置术语整体接地气,但几处需要思考:
   - 「西文字体(正文中的字母与数字)」「中文字体(正文中的汉字)」— 有 hint,尚可;
   - 「边距 (mm)」数值输入 — 用户可能不习惯 mm 单位(Word 默认显示厘米),但单位已标注;
   - 「行距(倍数)」— 有 hint,可接受;
   - 「导出后」的「不执行(仅弹窗提示)」措辞略绕。
5. 非法输入静默回退:边距输错(非数字/超范围)、字号行距出界、字体清空,控件会静默恢复原值(renderer.ts:783-812、1097-1117),无任何提示,用户以为输入生效了。
6. 字体拼写无校验:字体是自由文本+datalist,输入不存在的字体(如拼错)转换照样成功,产物里静默降级,用户无法得知。
7. 没有「恢复默认设置」按钮:改乱了只能手动逐项改回;设置文件位置(userData/settings.json)也不对用户可见。
8. 无转换前预览:要看排版效果必须先转一次(完成弹窗里的「预览」是转换后才有的)。
9. 批量失败项无定位按钮:汇总弹窗逐条列了失败原因,但「打开所在文件夹」只定位第一个成功项;失败文件要自己记路径。

## 四、状态一致性

1. 错误处理:
   - 选择非 md 文件:红字「仅支持 .md / .markdown 文件」+ 拖放区 1.4s 红色描边(renderer.ts:407-415);拖入文件夹无 md:红字说明跳过了几个非 Markdown 项。
   - 转换失败(单/合并):状态区红字「转换失败:具体错误」,无弹窗;批量:汇总弹窗逐条红/黄标注,状态区黄色「成功 x / 失败 y」。
   - 打开文件/预览失败:在弹窗内显示错误行,不打断弹窗(renderer.ts:831-834)——设计一致,体验良好。
2. 文件列表状态:选择后列表常驻,转换完成后不清空(可反复转换);转换中禁用一切入口防重复点击(renderer.ts:548-556,545-556);批量/合并按钮随文件数切换显示。唯一断点即 S1(无法增删单项)。
3. 设置持久化表现:
   - 每次控件变更即写盘(userData/settings.json,原子写 rename),启动回填;格式、页面、排版、导出后全部持久化——一致性良好。
   - 旧版本 settings.json 缺 typography 字段时防御性合并兜底(renderer.ts:718-724、settings.ts:92-95),不报错。
   - 设置与转换链路一致:convertImpl 每次实时读 loadSettings()(main/index.ts:97),不会出现「界面改了但转换没生效」的错位。
   - 不足:版本号恒为 1,无迁移机制(整文件校验失败即整体回退默认并不写盘——意味着下次启动还会再回退一次,行为可复现但用户无感知)。

## 五、给后续「简化操作」工作的几条主线建议

1. 主流程本身已很短(2-4 次点击即可完成一次转换),瓶颈不在步骤数,而在:选择集管理(S1)、输出位置透明度(S2)、转换过程反馈(S3)、失败可见性(S4/S5)。
2. 已做得好的、应保留的:默认值贴近 Word 常规;设置即时生效且持久化;拖放/多选/文件夹递归;批量失败逐条汇总;弹窗路径可复制;键盘可达(Enter/Space 开选择、Esc 关弹窗、aria 标注齐全)。
3. 术语总体通俗,最需要打磨的是「合并转换」与「导出后-不执行」两处文案,以及非法输入/模板回退的静默行为(S6/S9)。
