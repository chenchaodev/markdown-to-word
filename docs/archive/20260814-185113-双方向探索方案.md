## 方向 A:界面易用性评审与改进方案(@designer des-1 全文)

### 1. 当前界面主要问题(20 项 P1-P20,均基于代码事实)

- **P1 主操作按钮可能被推出视口**:DOM 顺序 拖放区→状态→进度→汇总→最近→两个设置面板→底部操作栏(index.html:181-458);两面板展开(各约 300px 高)后「开始转换/批量转换」按钮和进度条被推到折叠线以下;窗口默认仅 640px 高(main/index.ts:87-88),默认尺寸下就会发生
- **P2 拖放区高度弹性无上限**:`.file-area { flex: 1; min-height: 240px }`(style.css:77-79),最大化时可撑到数百像素空白
- **P3 模板预设(最高杠杆控件)埋得最深**:位于第二个折叠面板「排版」内部(index.html:290-313),两面板视觉权重一致(style.css:387-392),难以发现「先选模板」最快路径
- **P4 批量/合并按钮层级**:合并输出文件名含「-合并」语义只在 title(index.html:451)
- **P5 单文件态拖放区浪费空间**:`.drop-file` 在 ≥240px 区域垂直居中(style.css:79, 157-161),内容仅文件名+路径+两小按钮
- **P6 大窗口无布局上限**:`.app` 无 max-width(style.css:45-55),最大化 1920px 拉满,设置栅格固定 2 列(style.css:452)
- **P7 快捷键仅存在于 hover title**:Ctrl+O(index.html:52)、Ctrl+Enter(index.html:433, 442)只在 title;footer 可见 hint「输出格式:Word / PDF」(index.html:456)与单选标签重复,浪费唯一可见提示位
- **P8 双击预览等能力无可见提示**:多文件行「双击预览」只在行 title(file-list.ts:66)
- **P9(重要)点击拖放区行为与文案不一致**:点击统一走 `openDialog()` 默认 `append=false` 即**替换**整个选择(renderer.ts:175, 222);但文案写「点击或拖入可继续添加文件」(index.html:63, 98)——声称点击=追加。实际:单文件态点击=换文件;多文件态点击头部空白区=**整个列表被替换**(列表本身有 stopPropagation, renderer.ts:259,头部/空白区没有),误触即丢失全部选择且无确认。拖入才是追加(renderer.ts:208)
- **P10 状态行长错误被截断**:`#status` 单行省略号截断(style.css:373-375),错误信息往往较长(renderer.ts:162);title 只在 applySelection 里设置(file-list.ts:202),错误路径可能无法查看完整信息
- **P11 自定义预设达上限时静默丢弃**:保存用 `[...].slice(0, MAX_CUSTOM_PRESETS)`(settings-panel.ts:226),超限静默丢弃但弹窗照常走「保存成功」路径(settings-panel.ts:228-232)
- **P12 弹窗无焦点陷阱**:三个弹窗 `aria-modal="true"`(index.html:465, 506, 538)但 Tab 可逃逸;焦点落默认按钮(dialogs.ts:109, 137)、Esc 关闭后归还(renderer.ts:627-638)已做对
- **P13 多文件行键盘路径弱 + 疑似死代码**:排序只能靠上移/下移按钮(file-list.ts:104-133);`.multi-item.selected` 样式存在(style.css:349-351,注释「Del 键移除的前置动作」)但未见任何选中/删除逻辑——需核实是否悬空
- **P14 批量进度读屏刷屏**:`#status` aria-live="polite"(index.html:104),批量逐文件刷新(renderer.ts:583-591)读屏连续播报
- **P15 最近条目只有「一键重转」一条路**:点击即加载并立即转换(recent-files.ts:124-132),想先改设置的用户只能取消后手动选
- **P16 主窗口无最小尺寸**:BrowserWindow 未设 minWidth/minHeight(main/index.ts:86-88)
- **P17 无任何 @media 查询**:style.css 全文件无媒体查询,窄窗口 2 列栅格(style.css:452)靠 flex-wrap 兜底
- **P18 全角/半角标点混用**:半角括号(index.html:28)、半角分号(index.html:98)与全角冒号句号(renderer.ts:162)并存
- **P19 「设置即时生效并自动保存」重复两条**(index.html:285, 410)
- **P20 「源文件所在目录」(index.html:275)语义略含糊**:实际指「与源文件相同目录」

### 3. 推荐实施顺序

- **Phase 0 速赢**(无依赖,纯文案/CSS/单点 JS,每项独立提交):C11 → C4 → C1 → C5 → C6 → C7 → C3。理由:全部低风险可独立回退;C1 涉及行为语义最先确认取向(追加 vs 无操作)
- **Phase 1 布局与反馈**:C2 → C10 → C9(C2 与 C7 都动拖放区/底部,C7 先做减少 C2 回归面)
- **Phase 2 结构**:C8 → C12(可选;动 DOM 结构需回归面板展开态记忆与预设联动)

### 4. 明确不建议做

- 引入任何 UI 库/框架(国内网络风险)、深色模式/主题切换、主布局重构(双栏/三栏)、合并或移除「完成弹窗+常驻汇总条」双反馈、拖放区动画堆砌、系统托盘/通知/全局快捷键、新增设置项、无边框自定义标题栏、常驻日志面板

## 工具链国内镜像核查(@librarian lib-1 事实,均经 npm registry API 实测)

- **Node 18 硬决策点**:c8 12.0.0 / nyc 18.0.0 / eslint 10.8.1 / knip 6.32.2 全部要求 Node 20.19+;保持 Node 18 需锁旧线(c8 10.1.3 / eslint 9.39.x)。Node 18 已于 2025-04-30 EOL
- **eslint 10 硬分水岭**(2026-02-06 起):flat config 唯一方式,eslintrc/.eslintignore/ESLINT_USE_FLAT_CONFIG 全移除;v9 已 EOL(2026-08-06);typescript-eslint v8(8.67.0)已对齐 ESLint 10
- **depcheck 1.4.7 事实性停维护**(2023-10 后无更新,官方 README 声明推荐转 knip);knip 极活跃(6.32.2,需 Node 20.19+ 与 peer typescript)
- **c8 12.x** 基于 V8 覆盖率零插桩,ESM 原生支持;TS 需 source map;12.x engines ^20.19 || ^22.12 || >=23
- **prettier 3.9.6** v3 起 ESM 优先,官方建议锁精确版本
- 以上全部纯 JS、无二进制、无 postinstall 下载 → **npmmirror 无特殊坑**(新版本可能有分钟级同步延迟);Electron 本体/electron-builder 走既有 ELECTRON_MIRROR/ELECTRON_BUILDER_BINARIES_MIRROR,无需新增镜像变量
- **Electron 原生能力足够,UI 侧零新依赖**:快捷键 = Menu accelerator(CommandOrControl+O/Return,F1 支持;须 Menu.setApplicationMenu 生效);深色模式 = `@media (prefers-color-scheme)` + nativeTheme.themeSource 三态(官方 Dark Mode 教程,示例已更新至 v43.4.0,与本项目 Electron 43 同代)
