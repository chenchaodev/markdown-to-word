# 后续功能方向调研(2026-08-03 @librarian)

来源:lib-1(web 检索 2025-2026 竞品/用户需求)。摘要已入 docs/研究结论.md 与路线图,本文档为自查原文。

## 趋势判断
2025-2026 该赛道竞争集中在三件事:**批量与合并**、**长文档可编辑性**(页眉页脚/页码/脚注/公式)、**模板化输出**(样式一致性)。PDF 书签已从「加分项」变「刚需」(Obsidian Better Export PDF 30 万+下载,核心卖点即书签+页码+批量)。printToPDF 无法生成书签是 Chromium 上游限制,后处理注入(pdf-lib)是唯一路线,已验证可行。

## 值得做(按 ROI)
1. **页眉页脚+页码**——竞品最痛缺口(mdclaudy「五问题」之首);docx.js 原生 Header/Footer/PageNumber;PDF 侧模板字符串即得。成本低-中
2. **样式模板/主题**——Pandoc --reference-doc 已成行业标准;mdclaudy 靠 3 模板立产品;markdown-to-word.com 4 主题+设置保存/分享。成本中(复用现有排版设置)
3. **公式 OMML**——docx.js 原生 Math API 但需 LaTeX→OMML 转换(docx-math-converter/texmath);2026 新品 tex2word 以「原生 OMML+自动编号域」为卖点。成本中
4. **多级编号**——docx numbering 配置即可;Pandoc 3.6.3 修列表重启 bug、Markdown All in One 节编号标 DANGER、python-md2docx 用户抱怨四级标题降级——做时放开标题深度。成本低-中
5. **导出选项记忆/最近文件/拖放文件夹**——markdown-to-word.com 已做设置保存;低价值但成本极低,顺手做

## 批次 3 内部确认
PDF 书签(pdf-lib 无高层 API,按 issue #786 样板手写 outline 树,中成本;md-to-pdf-converter 已证支持中文书签)、批量转换(队列+并发 3+失败不中断+进度汇总+ZIP,中成本)、多文件合并(按序号/侧栏/TOC 顺序,中成本)、脚注(docx 原生 FootNotes;PDF 用 markdown-it-footnote,均低成本)——方向正确。

## 延后/砍
- 延后:docx 代码高亮(逐 token 着色或图片化,中高成本;PDF 侧 highlight.js 低,可先做 PDF)、模板导入系统(用户上传 docx/CSS,中成本,排在样式模板后)
- 砍:PDF 多栏(无竞品证据)、批量重命名(无需求信号)、pagedjs 美化(竞品 TODO 未落地)

## 机会点
Typora 至今无 Word 导出(仅 PDF/HTML),Obsidian 需 pandoc 插件——桌面工具「md→docx」是二者空白,中文用户尤其(Obsidian 论坛书签诉求有明确中文用户 +1)。
