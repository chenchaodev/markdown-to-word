# 功能候选调研与迭代排期(2026-08-25 18:20:36)

> 背景:2.0.0 发版后启动下一阶段功能开发。双路调研:@explorer 代码库能力盘点 + @librarian 竞品对标;用户拍板选型与排期授权。本文为排期依据存档,摘要见 RESEARCH.md 同日条目。

## 一、竞品调研核心结论(@librarian)

### 用户高频痛点排序(证据强度)
1. 格式错乱(表格错位/嵌套列表拍平)——几乎所有评测第一条
2. LaTeX 公式变纯文本/低清图片——学术场景第一痛点(**本产品已解决**:OMML+KaTeX 双格式)
3. Mermaid 图丢失——AI 内容时代上升(**已解决**)
4. 图片处理(相对路径失效/位置错乱)——高
5. 样式定制(中文字体/模板套用)——高
6. 页码/页眉页脚/目录页码——Typora PDF 页码 issue #608 118+ 赞多年未解;MarkText 明确不做页码(issue #1746 称 essential)
7. 代码高亮进 Word(**已解决**)、批量转换(**已解决**,竞品仅 Pandoc)、隐私(本地转换天然优势)

### 差异化机会
- 「易用性」与「正式交付能力」不可兼得是竞品格局关键裂缝:易用的(Typora/MarkText/在线工具)缺交付要素;能力强的(Pandoc)门槛极高。V2EX 典型帖(#1098305):「几级标题加 1.2.3 序号、生成目录、每页底下页码、上面公司 Logo、最前面封面」——本产品序号✅目录✅页码✅封面✅,**仅剩 Logo 页眉**
- 水印:企业场景刚需,GUI 竞品几乎空白
- 转换预检/诊断报告:无任何竞品做;AI 生成不规范 md 是新时代格式错乱最大来源
- 合并+总目录:手册/合集场景真空地带

## 二、代码库能力盘点核心结论(@explorer)

### 已支持能力(节选)
语法面:标题/表格(列对齐)/公式(编号+交叉引用)/Mermaid/脚注/任务列表/HTML 白名单(14 无属性内联标签)/交叉引用(fig/tab/sec/eq)/题注编号/静态 TOC/封面/批注/分页符/标题编号/书签/代码高亮。导出面:docx/pdf/批量(并发 2)/合并/页面设置/排版 8 字段/预设体系/PDF CSS。GUI 面:拖放/预览/最近文件/i18n(zh/en/ja)/暗色三态/设置抽屉。

### 架构扩展点(新功能低成本落点)
1. docx 节点处理器:`core/docx/handlers/` 11 文件 + render.ts switch 分发;预扫五轮模式可复制
2. pdf rules 数组:`core/pdf/rules/` 7 个 override 规则,新扩展=新文件+一行挂载
3. CROSS_REF_KINDS 表驱动(cross-ref.ts):加引用类别=加一项
4. ConvertContext 只增不改协议(onStage/warnings 向后兼容)
5. 预设系统 TEMPLATE_PRESETS + PRESET_COMPARE_FIELDS(keyof 守卫)
6. i18n 注册表(zh 键集唯一事实源)

### 关键约束
- **双管线有意不合并**:docx=remark/mdast,pdf=markdown-it/HTML——新语法双侧各实现一次并保持语义对齐(成本双倍,有双格式断言守护)
- docx 库 9.x 边界:TableOfContents 静态注入(D1 免更新路线);landscape 尺寸传原始值;comments author 固定
- pdf 路线本质 HTML 打印(Chromium 打印限制);core 层零 IO 零 Electron(resolver 注入)
- 依赖钉死:markdown-it 14.3/docx 9.x/electron-builder 26.15.3 等

### 盘点发现的真实缺口
图片无宽度控制(固定缩放逻辑,width 属性被丢弃)、题注靠前缀行约定非 figure 语义、HTML 白名单过窄(块级/带属性一律静默丢弃)、表格列宽不可控、标题字号不可分级调、页眉页脚内容固定(仅页码)、frontmatter 仅 title/author/date、任务列表 docx 无 checkbox 视觉(设计如此)。

## 六、技术路线调研结论(@librarian 同日补,2026-08-25)

### F9 docx 模板导入
- **npm 生态无现成库**:docxtemplater(占位符填充,样式模块付费)/html-to-docx(不能读外部模板)/officegen(停维护)均不符;「读取任意 .docx 模板套用样式」本无捷径,原裁决方向性判断成立
- **Pandoc reference-doc 原理**(唯一大规模验证实现):部件级选择性搬运——styles.xml 整体替换/numbering.xml 合并(numId≥1000 魔数隔离冲突)/settings.xml 白名单搬运(~90 元素名)/rels 与 Content_Types 刻意自建防损坏。已知坑:numbering numId 断链(#1305)/settings 整搬致损坏(#9522)/表格 Compact 样式覆盖(#6670 多年未解)
- **浅导入 vs 深导入**:浅导入(jszip 解包读 styles.xml 关键 rPr→映射现有 settings/theme 字段)3-5 天低风险,覆盖约 80% 诉求,与 theme.ts 集中字体配置硬约束天然契合;深导入(Pandoc 式部件套用)2-4 周+长期维护负担
- **推荐**:浅导入作 v1,深导入列后续独立候选(解析层是真子集,可演进不锁死)

### F7 目录带页码
- **Word TOC 域路线**:docx 库 TableOfContents+updateFields=true → Word 打开弹「是否更新域」提示(**该弹窗无法关闭**,docx 库 issue #1212 结论);WPS 可能不响应自动更新须手动刷新(与本项目 WPS-COMPAT 关注点一致,落地须双实测);新版库 cachedEntries 可预填占位条目避免空白
- **docx 静态页码不可行**:OOXML 无 page 实体,分页由渲染引擎决定;二遍法需 LibreOffice/Word COM 外部依赖,不建议
- **pdf 两遍法可行且干净**:第一遍标题锚点+占位等高目录(保证两遍布局一致)→printToPDF→PDF.js getTextContent 匹配标题定位页码(fallback:pdf-lib 低层解析 outline,无高层读取 API)→第二遍注入静态页码目录。工作量约 4-6 天。Typora「技术原因难支持」难在 WebKit 单遍打印流+Chromium 不支持 CSS Paged Media 页码——本产品控制整条管线可做两遍,**独占差异化**
- **推荐混合路线**:①PDF 两遍法静态页码(独立卖点);②docx 默认维持静态目录(D1 不变),新增 opt-in「Word 域目录」开关(TOC 域+updateFields+cachedEntries 预填),把弹窗权衡交用户;WPS 行为纳入实测清单
