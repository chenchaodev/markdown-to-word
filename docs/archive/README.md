# archive/ 长分析原文存档（面向开发者）

> 本目录存调研、排查、方案对比的**原文**（含失败尝试），供追溯「为什么采用此结论」。
> 主会话不读、不登记、不加入 `docs/` 索引；本目录**只增不改**。

- **命名**：`YYYYMMDD-HHMMSS-<主题>.md`（`HH` 用大写 24 小时制，主题里不出现冒号）。时间戳是**归档时间**，不是原文写作时间（原文的写作时间在文件头）。**例外**：`user-guide-vX.Y.md` 是用户指南归档专用名，不由时间戳命名。
- **每份文件头写一行结论去向**：升 `docs/adr/` / 升 `docs/LOG.md` / 未升。
- **清单 → [`INDEX.md`](INDEX.md)**（生成式，**不手工登记**）：一行一文件，给出主题与**分流去向**；回捞路径 = 该列指向的常驻条目。由 `npm run gen:archive-index` 生成、`npm run check:archive-index` 逐字节比对（已接入 `verify:ci`）。
- **2026-09-27 起本目录另收进两层历史材料**（原 `docs/acceptance/` 的已闭环人工验收明细、原 `docs/research/` 的技术事实域文件，见 [adr-020](../adr/adr-020-文档体系迁移.md)）：**按只读历史对待** —— 需要查事实时按文件名检索，不要改写、不要往里加新条目。
- **本目录不是泄压阀**：常驻文档超限时默认动作是条目级外迁，只有**整份文档生命周期结束**（或用户裁决整层归入）才进本目录 —— 泄压过来等于制造不可达内容。

> 结论摘要的落点：决策 → `docs/adr/`；「想做但没做」→ [LOG.md](../LOG.md)；工作项的号与状态 → [REQ.md](../REQ.md)。来源：全局配置目录 `AGENTS.md`「文档体系」与「落盘格式」两节。
