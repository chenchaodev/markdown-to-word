## 一、mermaid 包现状(2026-08)

- **版本 11.16.1**(dist-tags: latest=11.16.1;另有 backport=10.9.8)
- **ESM-only 包**(`main: null`,exports 仅 import → `./dist/mermaid.core.mjs`),`require('mermaid')` v10 起已坏;dist 内附 IIFE 产物 `mermaid.min.js`(3.5MB)/`mermaid.js`(8.2MB),v11 起 UMD 移除
- **完全自包含**:d3/dompurify/cytoscape/katex/roughjs 全为 npm dependencies 打进 dist,运行时零 CDN;v11 ESM 入口(52KB)是瘦加载器,图表代码在 `dist/chunks/` 按需懒加载(206 chunk)
- **体积**:包解包 83.5MB/1171 文件,node_modules 合计约 120-130MB;electron-builder 进 asar 压缩,JS 可压 60-70%
- **Node 无 DOM 不能直接渲染**(mermaidAPI.render 直接用 document.* 与 DOMPurify;jsdom 垫片布局全毁)——必须 Electron 隐藏窗口 / puppeteer / 垫片

## 二、mermaid API

- `mermaid.initialize({ startOnLoad: false, securityLevel: 'strict', theme: 'default', ... })`,v11 返回 Promise;**mermaidAPI 已废弃**
- `const { svg, diagramType, bindFunctions? } = await mermaid.render(id, text, svgContainingElement?)` — id 须唯一,svg 为完整 SVG 字符串
- `mermaid.render` 内部**串行队列**(并发调用自动排队,批量渲染无需自建锁)
- 语法错误:render 的 promise reject;推荐 `mermaid.parse(code, { suppressErrors: true })` 预检返回 false
- securityLevel: strict(默认,HTML 转义+禁 click)/ antiscript / loose(XSS 风险)/ sandbox;`secure` 数组禁止图内 `%%{init}%%` 覆盖安全项 → **导出场景用 strict**
- `run()` 是 DOM 批处理用法,本场景不需要(编程式拿 SVG 用 render)

## 三、Electron 集成方案(推荐)

**隐藏 BrowserWindow + executeJavaScript 拿 SVG + 同窗口 canvas 光栅化 PNG**(零新依赖,生产先例:markdown-confluence mermaid-electron-renderer,Apache-2.0)

```
main ──ipc──▶ 隐藏 BrowserWindow (show:false, sandbox:true, contextIsolation:true,
              nodeIntegration:false, backgroundThrottling:false)
              │ 加载本地 HTML:IIFE dist/mermaid.min.js(规避 file:// 模块 CORS——v11 ESM 入口含动态 import chunk)
              │ initialize({startOnLoad:false, securityLevel:'strict', theme:'default',
              │   fontFamily:'"Microsoft YaHei",sans-serif'})
              │ → await mermaid.render(id, code) → 注入 #graphDiv
              │ → await document.fonts.ready → canvas 2x 光栅化
              │ → toDataURL('image/png') + getBoundingClientRect 尺寸
              └── 返回 { pngBuffer, widthPx, heightPx } ◀── 主进程
```

- **加载细节坑**:① v11 ESM 动态 import 撞 file:// 模块 CORS → 用 IIFE 产物或自定义协议;② 隐藏窗口默认节流 → `backgroundThrottling: false`,否则 capturePage/布局拿未完成帧
- **SVG→PNG 三方案**:① 隐藏窗口 canvas 光栅化(推荐:零依赖、支持 foreignObject、2x 高清、中文系统字体自动可用、需等 document.fonts.ready);② capturePage(像素级所见即所得,但 resize 窗口/慢/代码繁);③ resvg-js(快但**不支持 foreignObject** 需 htmlLabels:false + asarUnpack,字体需配置)
- **SVG 直接嵌入 docx 不可靠**(docx 9.x 支持 type:'svg'+fallback 但 Word 2019+/M365 才渲染且有 issue #3227 bug)→ **docx 用 PNG**

## 四、docx 9.x 图片嵌入

- ImageRun 支持 JPG/PNG/GIF/BMP/SVG;SVG 9.7.1 起需 fallback,Word 2019+/M365 才渲染,LibreOffice 显示 fallback → **docx 端用 PNG 最稳**
- **transformation 的 width/height 必须同时显式给**(单位 px);type 必须与实际数据格式一致
- 打印清晰度:2x 像素密度 PNG + 按 1x 逻辑尺寸设 transformation(Word 按 96dpi 折算 EMU)

## 五、主题/字体

- 内置主题 default/base/dark/neo-dark/forest/neutral/neo;打印用 **default 或 neutral**(浅色),避免 dark 系
- 中文:Chromium 路径系统字体回退自动生效(Windows 微软雅黑),建议显式 `fontFamily: '"Microsoft YaHei","PingFang SC",sans-serif'` 跨平台一致;光栅化前 `await document.fonts.ready`

## 六、安全与已知坑

- **XSS 高危**:loose + innerHTML = 存储型 XSS(click 指令可执行任意 JS,CVSS 7.6);思源笔记 2026-04 通报 mermaid 标签零点击 NTLM 窃取 → **strict + DOMPurify**
- **本应用额外建议**:隐藏窗口 HTML 加 `<meta http-equiv="Content-Security-Policy" content="default-src 'none'; img-src data:; style-src 'unsafe-inline'">` 断网 → 保证离线隐私承诺(标签内 `<img src="http://...">` 发不出去)
- v11 breaking:ESM-only / mermaidAPI 废弃 / ELK 布局拆 @mermaid-js/layout-elk(不注册则 layout:elk 静默降级 dagre,不用 ELK 无影响)
- 11.x 标签默认按 markdown 解析(与 10.x 渲染差异)
- `maxTextSize` 默认 50000,超大图拒绝渲染(可 initialize 调大,在 secure 列表)

## 七、推荐技术方案(已拍板)

| 包 | 版本 | 用途 |
|---|---|---|
| mermaid | **11.16.1**(钉死,镜像安装) | 图表渲染;electron-builder files 排除 dist/**/*.map、*.d.ts 瘦身 |
| docx | 9.7.1(现有) | 图片嵌入,PNG |
| 无新增转换依赖 | — | 光栅化走隐藏窗口 canvas,避免 resvg-js 的 asarUnpack + foreignObject 问题 |

- **docx 端**:`new ImageRun({ type:'png', data, transformation: { width: widthPx/2, height: heightPx/2 } })`(逻辑 1x、像素 2x);不用 SVG 嵌入
- **pdf 端**:SVG 字符串直接内联进 HTML(矢量、Chromium 原生渲染、零光栅化);`<!-- page-break -->` 分页逻辑不变;同一份 SVG 同时喂 docx(光栅化)和 pdf(内联)
- **降级策略**:① parse 预检失败 → docx/pdf 均输出等宽代码块原文 + 警告(不中断转换);② render/executeJavaScript 超时或崩溃 → 同上降级 + 日志;③ 窗口一次性预热(首次加载 mermaid.min.js 3.5MB 解析),之后复用;④ %%{init}%% 默认信任(secure 项无法覆盖 securityLevel);⑤ CSP 断网 + strict 兜底
- **不建议**:@mermaid-js/mermaid-cli(puppeteer + 下载 Chromium,离线/镜像痛苦)、Kroki 在线服务(违反离线卖点)、jsdom 垫片(布局全毁)
