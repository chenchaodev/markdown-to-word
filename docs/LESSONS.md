> 用途：**「下次别再犯什么」**。一条一句话（≤100 字）· **按主题分组，不按工作项号分组** —— 跨号可复用的教训挂不到任何单个工作项上，按号分组会让本文件退化成台账的附庸。收录判据 = **挂不到任何工作项号**、换个项目还会犯的那类；挂得上号的具体判断在 [REQ.md](REQ.md) 同一行（「为什么停在这」列），一次性过程流水在 git，排查与评审全文在 [evidence/](evidence/INDEX.md)。**永久，任务做完也不删。**

# 教训

> 体例：`- ` 条目，一行一条；每条末尾注明来源 `<归档快照名>:NN` —— 行号对应**迁移前**的旧台账载体，那个载体已删除、全文存于该 evidence 快照，**行号未漂移**。**行号必须写在代码跨度内部** —— 挪到代码跨度外面，那个片段会被指针门禁当成对已删文件的悬空引用判红（本文件已实测）。**正文里不得出现不带行号的该文件裸名，也不引用 `docs/large/`**（同批删除的载体）。**这条体例是本仓专属** —— 它来自本仓 evidence 批量迁移 + `check:docs` 指针门禁那条约束链，别的项目没有，不外传。

## 门禁与断言

- **「门禁全绿」只覆盖实际跑过的那几道**。测试命令不含类型检查、两道各跑各的 ⇒ 不能据「全绿」推断类型检查那道也绿。来源：`docs/evidence/20260930-075956-台账判断依据与否决台账.md:26`
- **「载体不可达就 exit 0」的静默跳过是「以为被查过」的形态**。验收判据要先证伪再信绿 —— 对本仓一条故意写坏的指针跑一遍，看它是否真判红。来源：`docs/evidence/20260930-075956-台账判断依据与否决台账.md:54`
- **判据要落在改动进树之后跑**，跑在提交之前等于没验这次新增的行；子代理报告的门禁结果与实际有过不符，关闭步次前必须自己复核。来源：`docs/evidence/20260930-075956-台账判断依据与否决台账.md:66`
- **白名单/豁免盖住的项，在台账上仍显示为「已完成」**。核实时要问「白名单放行的」还是「真做的」—— 前者门禁一直绿，而问题一直在。来源：`docs/evidence/20260930-075956-台账判断依据与否决台账.md:84`
- **估一道门禁的常驻成本前先查它在链内哪条命令下跑**（我预设与实测差一个数量级）；**旁路探针调用能判红，才证明探针不是空过**。来源：`docs/evidence/20260930-075956-台账判断依据与否决台账.md:41`
- **解析器宽容 ≠ 能看见破损**。没断言「表头→分隔行→数据行」时，插错位的行会被**静默吸收**：真分隔行当普通行跳过、错位行当数据读，**行数照样对得上、门禁照样 exit 0**。宽容为免误报，结构坏了须另配判据。
- **夹具计数用「恰好压下限」写的，删一个条目就跌破下限** —— 判红会报在「与本次改动无关」的名下。改声明面时把配额的算式连同上限一起重算，别只改键名。
- **「生成式索引 + 手工指针」的组合，索引会因指针改指向而失效** —— 「在哪」列从 A 改为 B 后 A 的按名引用消失，须重跑生成器。判据是逐字节比对时，它要到下次收尾才红。
- **表形状要有人读的规则，不能只活在门禁代码里**。空行会断表，「表头→分隔行→数据行」必须三段紧邻；只留机器判据，下个会话看到某节多一个空行会当成不一致顺手改回去，而空节那种改法两种形状都不判红。
- **判定模块顶层不可自执行** —— 段跑在 Electron 下,`process.execPath` 是 electron.exe,门禁 import 即起 GUI 进程挂死。

## 测试工程

- **源文本/正则断言只能发现「文本被改」，发现不了「行为被改」** —— 把被守护的函数改成永不调用，源文本一字不变而断言照样绿。来源：`docs/evidence/20260930-075956-台账判断依据与否决台账.md:63`
- **验映射关系的测试必须取能区分两种读法的取值**（端点）：两种语义在中点取值完全相同，取中点等于没测。来源：`docs/evidence/20260930-075956-台账判断依据与否决台账.md:22`
- **断言恒真常源于夹具初值自带期望态**（桩的 classList 初值含 hidden，「关掉时应隐藏」恒真）；须补一条反向断言才真能红。来源：`docs/evidence/20260930-075956-台账判断依据与否决台账.md:60`
- **行为等价重构的前提是「有东西能证明等价」**。探测器几乎不存在时先补护栏再动结构，否则「等价」只是一句声明。来源：`docs/evidence/20260930-075956-台账判断依据与否决台账.md:99`
- **等值断言证不了「同一性」修复** —— 工厂改成直接返回默认值，「与默认值逐字段等值」仍绿；判红只能来自引用身份断言。只写等值对拍的修复无法被证伪。来源：`docs/evidence/20260930-075956-台账判断依据与否决台账.md:64`
- **固定时长的等待两头上限都不对**（实测 66ms/1281ms）⇒ 换状态表达式；压时长停不住无限动画，须补 `animation-iteration-count:1`。来源：`docs/evidence/20260930-075956-台账判断依据与否决台账.md:56`
- **只跑受影响筛段，会漏掉「不在筛词里但已被前一步改坏」的段** —— 筛词按自己的判断列，坏在被你没想到的那一处。判据是筛段全绿却从没跑过全量。改动段发现机制本身时，全量不是保险而是必需品。

## 取证与排查

- **产物级缺陷先解包再下结论**：「形态相似」不构成证据；用户说「问题还在」时先重新取证，而不是换一个未经验证的新假设。来源：`docs/evidence/20260930-075956-台账判断依据与否决台账.md:25`
- **注释/文档对第三方 API 行为的描述可能与实际相反**（头注把「愿望」写成了「事实」）；声称的能力要用最小实测证实，否则错误会被后来者当权威。来源：`docs/evidence/20260930-075956-台账判断依据与否决台账.md:91`
- **只读审计 / 静态分析的结论必须回代码复核** —— 本轮两轮审计有三处结论与代码不符。带比例的断言尤其：写「21 处多合法」，实测 17 处命中里 16 处是真违规 —— 数量对不代表组成对。
- **探针的恢复必须放 `finally`，不能当末尾顺序语句**。顺序写 mutate→probe→restore 时，探针超时/被打断就跳过恢复，注入值留在工作区。改跑导出的纯函数（毫秒级）而非整段。

## 影响面与改动面

- **按长相分类必错,须查消费方** —— `print-env-fingerprint` 看似报告器,实则被 `gates/`、`test/` import 且被 workflow 裸调。
- **移动文件后必须重跑边界门禁,且要连带改它自身的相对引用** —— 本次只改外部引用点,漏了被移文件自己的 `../shared/paths.js`(根下一层变嵌套两层),靠边界门禁当场抓出层级错才拦住。
- **单源规则要覆盖全仓,不能只补被发现的那棵树** —— ADR-040 只给 `gates/` 套了 `shared/paths.js`,漏了 `dev/`,于是搬目录时那边照样算错。
- **下沉到机制层时，别把原属主模块的私有常量一起搬** —— 机制层一旦写死某个使用者的参数表，所有复用者都拿到一段与自己无关的说明，耦合搬到机制侧且更难摘。判据：新模块里出现只有原主人能读懂的名字。
- **改「被调用方不再自己剥离」这类契约时，必查所有把整串喂进来的调用方** —— 尤其「按设计保留原文」的路径：它们不报错，只静默产出坏文档。来源：`docs/evidence/20260930-075956-台账判断依据与否决台账.md:51`
- **预判「扩散面大/小」前先读那一处的现有读法，别按名字猜** —— 我判 ctx 需改签名，实测该字段本就在 `CtxConfig` 上，扩散面为 0。来源：`docs/evidence/20260930-075956-台账判断依据与否决台账.md:42`

## 编排与并行

- **「可写文件不重叠」≠ 可并行** —— 判据漏了构建产物这层共享可变状态，一条泳道构建会编进别的泳道的半成品。补两条：都不改进入构建产物的源 · 无共享可变状态。来源：`docs/evidence/20260930-075956-台账判断依据与否决台账.md:177`
- **并发写文件时跑全量检查，会读到中间态**。报错是**真阳性**——读取那刻文件不自洽；「带缓存红／不带绿」是两次运行**采样时刻不同**（带缓存快 20 倍易撞上编辑窗口），不是缓存陈旧。判据：连跑三次报错内容都不同。 来源：`docs/evidence/20260930-075956-台账判断依据与否决台账.md:91`
- **派工单里写「已核实,只有 N 处」仍须自己复核** —— 实测三处错：消费点数说 2 实为 8（经基准目录解析，字面量 grep 找不到）、文档「未提及」实有活路径、段「仍绿」实已红。
