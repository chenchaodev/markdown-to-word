## 规则

1. **单序列、固定三位零填充。** 全部工作项共用一个序列，形如 `REQ-003`；不按类型另起序列，也不跳号补空。旧 `REF-*` 号已按「原号」列顺延合并进本序列，合并后不再使用 `REF-` 前缀。
2. **号永不复用。** 作废或范围收缩的号在登记表里用 `~~` 划掉**保留**，不回收、不复用；范围收缩时子集另拿新号，原号留墓碑（收缩不把原号退回池子）。旧双序列的号同受此保护。
3. **登记即分配，开工只改状态。** 在登记表加一行，号就归这条需求；追溯查本表即可，不必去别处找。**开工时先查本表**：已有该需求 → 只把状态改成「在办」并沿用原号（这是「号永不复用」的直接推论，另取新号会让 `git log --grep` 指向一个从未开工的号）；没有该需求（如「直接做」路径冒出来的一次性活）→ 才取新号。
4. **收尾时改状态。** 任务做完把本工作项那一行的状态改成「已完成」；任务中途放弃改成「已作废」并用 `~~` 划掉保留（号仍不复用）。
5. **状态词表 = 全局 v8.2 的五个值。** `待拍板` / `在办` / `已完成` / `已作废` 沿用全局定义；**本台账追加 `未开工`**（2026-09-27，理由见 [adr-020](adr/adr-020-文档体系迁移.md)「决定 3」：33 条从未开工的项在三值词表里没有对应值，写成「已作废」会把仍活的需求误标成已否决）。取值只有这五个，**不得自造**。
6. **永久文件：只增不删，也不切分。** 任务做完也不删——`docs/PLAN.md` 做完即删，本台账正相反，删掉等于把序列清零、已用过的号会被再发一次。**不设长度上限也不切分**：一行一号、无自由文本，长度由工作项个数决定，不长到需要切分。
