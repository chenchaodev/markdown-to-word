## 规则

1. **单序列、固定三位零填充。** 全部需求共用一个序列，形如 `REQ-003`；不按类型另起序列，也不跳号补空。号在**登记那一刻**分配，此后不再更换。

2. **号永不复用 —— 只管墓碑号。** 已作废与范围收缩的号用 `~~` 划掉**保留**在「已作废」节里，不回收、不复用；范围收缩时子集另拿新号，原号留墓碑（收缩不把原号退回池子）。

3. **状态取值域五个、流转边七条**，取值与边分别见本节末尾的「状态取值域」与「状态流转边」两节 —— 全局规则点名「见该文件」的那部分纪律，本文件就是它的载体。

4. **标题列 ≤20 字。** 表格要能扫读，标题写长了整张表就废了。**写不下不等于丢掉**：超出的部分进该号在 `docs/evidence/` 的分析，或升 `docs/adr/ADR-0NN-*.md`（是决定就升 ADR，是过程就落 evidence），「分析在哪」列指过去。

5. **判断依据两列有上限。** 「为什么停在这」≤200 字，「已完成」行 ≤100 字（终态只需交代交付时确认了什么）。要展开就写 `docs/evidence/` —— 那是长分析的载体，本表只留结论与指针。

6. **一号一行。** 一条需求一行，五个字段各写各的；不要一行塞两条需求，也不要一条需求拆成两行。

7. **永久文件：只增不删，也不切分。** 任务做完也不删 —— 做完即删的是 `docs/PLAN.md`，本台账正相反，删掉等于把序列清零、已用过的号会被再发一次。**不设长度上限也不切分**：长度由需求条数决定，而分节已经让开工扫池只需读两节。

8. **「有哪些事」与「为什么停在这」必须同刻被同一人读到。** 这条是本文件存在的理由，也是旧结构（判断依据另立一份文件）被废除的原因：两处必然漂移。**跨工作项的可复用教训不进本表** —— 教训挂不到任何单个工作项号上，按号塞进来会让本表重新膨胀，正是 2026-09-30 改版要治的病；教训去 [`LESSONS.md`](LESSONS.md)（按主题分组）。

9. **表形状是硬约束，不是排版偏好。** 每张表严格是「表头行 → 分隔行 → 连续数据行」，**中间不得夹空行** —— Markdown 在空行处断开表，空行之后的数据行不再属于本表，扫读时只当正文看。搬行只做两件事：**删源行** ＋ 在目标表**最后一个数据行之后**插入；目标表还没有数据行时才锚分隔行的下一行。**绝不能锚在表头行之后** —— 那会把分隔行顶到表中间，整节退化成正文。搬空一节后只留表头 ＋ 分隔行，后接一个空行再接下一个 `## `。门禁侧有结构判据兜底，但它只对「表头含号且含状态」的表块生效，且**空节的两种形状都判绿** —— 本条是唯一能挡住「顺手改回去」的东西。

## 状态取值域

| 状态 | 含义 |
|---|---|
| `待拍板` | 有人提了，还没决定要不要做 |
| `未开工` | 已决定要做，还没排到（与「待拍板」同处一节，用状态列区分） |
| `在办` | 正在做 |
| `已完成` | 做完（终态） |
| `已作废` | 决定不做 / 中途放弃（终态，墓碑） |

## 状态流转边

只有下面这些边合法，其余流转即错：

| 从 | 到 | 触发 |
|---|---|---|
| 待拍板 | 未开工 | 拍板要做，还没排到 |
| 待拍板 | 已作废 | 决定不做 |
| 未开工 | 在办 | 开工 |
| 未开工 | 已完成 | 走「直接做」，不必经过在办 |
| 未开工 | 已作废 | 开工前被否 |
| 在办 | 已完成 | 做完 |
| 在办 | 已作废 | 中途放弃 |

**任何行最终都要落到「已完成」或「已作废」** —— 长期停在待拍板 / 未开工 / 在办就是没关账，开工扫池时该重排的砍掉。状态流转只改状态列与所在节，**号永不更换**。
